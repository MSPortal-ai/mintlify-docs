This guide walks you through creating an Acronis API client and connecting your Acronis Cyber Protect Cloud instance to MSPortal.ai. Setup is for MSP staff with integration management permission and authorized credentials for the intended Acronis account.

## Overview

Acronis Cyber Protect Cloud provides unified backup, disaster recovery, and cyber protection for MSPs. By integrating Acronis with MSPortal.ai, you can:

- Sync backup status and protection data across all your managed clients
- Monitor backup alerts and notifications in a centralized dashboard
- Map Acronis tenants to MSPortal companies for organized data tracking
- Include backup metrics in client reports

## Prerequisites

Before you begin, ensure you have:

- Active Acronis Cyber Protect Cloud account with administrative access
- MSPortal.ai account with integration management permissions
- Companies already set up in MSPortal (from your PSA integration or manually created)

<Note>
The Acronis integration maps tenants to existing companies in MSPortal. Import your companies from your PSA integration first, or create them manually before setting up Acronis.
</Note>

## Part 1: Generate API Credentials in Acronis

Before connecting to MSPortal.ai, you need to create an API client in Acronis Cyber Protect Cloud. Create it in the Acronis tenant that can access the customer tenants you want to sync. An API client's access depends on where it was created, so a successful test does not prove it can see every customer. See [Acronis's API client authentication guidance](https://developer.acronis.com/doc/account-management/v2/guide/getting-started/authenticating.html) for more detail.

<Steps>
  <Step title="Log into Acronis Management Console">
    Access your Acronis Cyber Protect Cloud management console using your administrator credentials.
  </Step>

  <Step title="Navigate to API Clients">
    Go to **Settings** > **API Clients** (this may also appear under **Manage your account** > **API clients** depending on your console version).
  </Step>

  <Step title="Create a New API Client">
    Click **Create API Client** to begin generating your credentials.

    Enter a descriptive name for the client:

    | Field | Recommended Value |
    |-------|-------------------|
    | **Name** | `MSPortal Integration` |
  </Step>

  <Step title="Copy Client ID and Client Secret">
    After creating the API client, the console will display your **Client ID** and **Client Secret**.

    <Warning>
      **Copy the Client Secret immediately!** It is only displayed once. If you close the dialog without copying it, you will need to create a new API client. Store both values securely for use in MSPortal.ai.
    </Warning>
  </Step>

  <Step title="Note Your Datacenter URL">
    Identify your Acronis datacenter URL. This is visible in the address bar of your Acronis portal and varies by region. Common examples include:

    | Region | Example Datacenter URL |
    |--------|------------------------|
    | US | `https://us5-cloud.acronis.com` |
    | EU | `https://eu2-cloud.acronis.com` |
    | AU | `https://au-cloud.acronis.com` |

    <Tip>
      Your datacenter URL is the base URL you see when logged into the Acronis management console, without any trailing path segments. For example, if your browser shows `https://us5-cloud.acronis.com/mc/dashboard`, the datacenter URL is `https://us5-cloud.acronis.com`.
    </Tip>
  </Step>
</Steps>

### Required Information

Before proceeding to MSPortal, ensure you have the following:

| Information | Description |
|-------------|-------------|
| **Datacenter** | Your Acronis datacenter region (MSPortal provides a dropdown of known datacenters, with a **Custom URL** option) |
| **Client ID** | The client identifier generated when creating the API client |
| **Client Secret** | The secret generated when creating the API client |

## Part 2: Connect Acronis in MSPortal

The Acronis connection page has three setup tasks: **Connect**, **Import or match tenants** and **Review**. Select a task in the **Setup guide** to return to it at any time.

### Open the connection

<Steps>
  <Step title="Navigate to Integrations">
    In MSPortal.ai, go to **Settings** > **Integrations**.
  </Step>

  <Step title="Start Setup">
    Find **Acronis Cyber Protect** and select **Connect**. To change an existing connection, open that connection instead.

    <Info>
      Acronis supports more than one connection. If you manage several Acronis accounts, add each one as its own connection, and check that you opened the intended one before you change anything.
    </Info>
  </Step>
</Steps>

### Connect

<Steps>
  <Step title="Enter API Credentials">
    Fill in the following fields:

    | Field | Description |
    |-------|-------------|
    | **Datacenter** | Select the datacenter that belongs to this Acronis account. If it is not listed, choose **Custom URL** and enter the base URL in **Datacenter URL**. Do not guess a region. |
    | **Client ID** | The client identifier from your Acronis API client |
    | **Client Secret** | The secret from your Acronis API client |

    <Frame>
      <img src="/images/product/acronis-connection-fields.png" alt="Blank Acronis Client Secret field and its explanation in MSPortal setup." width="892" height="172" />
    </Frame>

    <Note>
      Your credentials are stored securely using encrypted vault storage. They are never exposed in logs or API responses.
    </Note>
  </Step>

  <Step title="Test the connection">
    Select **Test connection**. MSPortal uses your Client ID and Client Secret to authenticate with the Acronis API and read your root tenant. When the test passes, **Connection verified** appears with your root tenant name.

    If the connection fails:
    - Verify you selected the correct datacenter from the dropdown (or entered the correct custom URL)
    - Check that the Client ID and Client Secret are copied exactly, without extra spaces
    - Ensure the API client has not been revoked or deleted in Acronis
    - Confirm your Acronis account has administrative access
  </Step>

  <Step title="Save and continue">
    Once the test passes, select **Save and continue** to save the connection. MSPortal also requests the first tenant sync in the background. The connection can be saved even if that first sync request fails, so check the tenant list before assuming tenants are available.

    <Note>
      **Test connection** does not save anything. If you change a field after testing, test again before you save.
    </Note>
  </Step>
</Steps>

### Import or match tenants

Map Acronis tenants (your customers) to MSPortal companies. This determines which company each tenant's backup data appears under.

<Steps>
  <Step title="Load tenants">
    Open **Import or match tenants**. If no tenants appear, select **Sync tenants** and wait for the background sync. The first sync can take a few minutes depending on the number of tenants.
  </Step>

  <Step title="Review suggestions">
    Use **Suggested** to review proposed matches. Each suggestion shows its confidence. Select **Accept** on a row to save that match, or use the **Accept strong matches** button to accept every pair with 90% confidence or more. Untick any pair you want to review yourself.
  </Step>

  <Step title="Match the rest">
    Use **Import** to find tenants without a match. Select **Choose company…** to pick an existing MSPortal company, or select **Import** on the row to create the company from the tenant and match it. **Import companies** imports several tenants at once; existing companies with the same name are matched instead of duplicated. Check for an existing company first to avoid duplicates.
  </Step>

  <Step title="Check saved matches">
    Use **Matched** to review saved links. To unlink a tenant, select **Change** and choose **Remove match**; it takes effect immediately. Use **Ignore** for tenants you never want to map.
  </Step>
</Steps>

Matches save as soon as you apply them; wait for the confirmation before you rely on a link. Matching does not create an Acronis customer or start a backup job.

<Info>
  Only data from mapped tenants syncs to MSPortal. You can return to add more mappings at any time.
</Info>

### Review

Open **Review** and select **Finish setup** once the required tasks are done. Finishing setup does not mean backup data has loaded; data for mapped tenants arrives over the next sync cycles.

## What Gets Synced

The Acronis integration syncs the following data types to MSPortal:

| Data Type | Sync Direction | Description |
|-----------|----------------|-------------|
| **Tenants** | Acronis -> MSPortal | Tenant and customer information used for company mapping |
| **Resources** | Acronis -> MSPortal | Protected machines, backup agents, and managed resources |
| **Alerts** | Acronis -> MSPortal | Backup alerts, status notifications, and protection warnings |
| **Activities** | Acronis -> MSPortal | Backup activity and task history, including resource, plan, and result details |
| **Incidents** | Acronis -> MSPortal | EDR/MDR incidents, synced only for tenants with EDR or MDR enabled in Acronis |

### Tenants

Customer and organization data from your Acronis environment, including:
- Tenant name and identifier
- Tenant hierarchy and relationships
- Used for mapping to MSPortal companies

### Resources

Protected machine and backup resource data:
- Machine names and identifiers
- Protection plan assignments
- Backup agent status
- Associated tenant information

### Alerts

Backup and protection alert data:
- Alert type and severity
- Affected resource details
- Alert status and timestamps
- Protection status notifications

## Synchronization Schedule

After initial setup, data syncs automatically:

| Data Type | Sync Frequency |
|-----------|----------------|
| Tenants | Every 4 hours |
| Resources | Every 6 hours (at :10) |
| Alerts | Every 15 minutes (at :05, :20, :35, and :50) |
| Activities | Every hour (at :18) |
| Incidents | Every hour (at :20) |

<Note>
You can request a sync at any time from the Acronis connection page with **Run sync**. Choose **All data** or a single data type.
</Note>

## Managing Your Integration

After setup, manage the integration from its connection page:

| Action | Description |
|--------|-------------|
| **Setup guide** tasks | Reopen **Connect** to retest the connection, or **Import or match tenants** to update mappings |
| **Run sync** | Request a fresh sync of all data, or one data type, from Acronis |
| **More actions** > **Rename** | Label the connection |
| **More actions** > **Disconnect…** | Remove the stored credentials, tenant matches and synced data after confirmation. This cannot be undone. |

### Checking Your Credentials

After the integration is created, the credentials are shown read-only. You can test them again, but you cannot change them here.

<Steps>
  <Step title="Open the connection">
    Go to **Settings** > **Integrations** and open the Acronis Cyber Protect connection.
  </Step>

  <Step title="Retest the Connection">
    Open **Connect** and select **Test connection**. The stored secret is used for the test.
  </Step>
</Steps>

<Warning>
  A successful retest does not save a new secret. To use a different API client, disconnect and connect again, which removes the connection's matches and synced data. To keep them, contact support@msportal.ai before you delete the old API client in Acronis.
</Warning>

### Adding More Tenant Mappings

As you onboard new clients in Acronis:

<Steps>
  <Step title="Open the connection">
    Go to **Settings** > **Integrations** and open the Acronis Cyber Protect connection.
  </Step>

  <Step title="Open the tenant task">
    Select **Import or match tenants** in the **Setup guide**.
  </Step>

  <Step title="Sync New Tenants">
    Use **Run sync** to fetch any new tenants from Acronis.
  </Step>

  <Step title="Map New Tenants">
    Accept suggestions or choose companies manually to connect new tenants to MSPortal companies.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Connection test fails">
    **Causes:**
    - Incorrect Datacenter selection, Client ID, or Client Secret
    - API client has been revoked or deleted in Acronis
    - Insufficient account permissions

    **Solutions:**
    1. Verify you selected the correct datacenter from the dropdown, or entered the correct custom URL. The datacenter must belong to the Client ID.
    2. Confirm the Client ID and Client Secret are copied exactly, without extra spaces or missing characters
    3. Log into Acronis and verify the API client still exists under **Settings** > **API Clients**
    4. Ensure your Acronis account has administrative privileges
    5. If credentials are lost, create a new API client in Acronis and contact support@msportal.ai to move the integration to it
  </Accordion>

  <Accordion title="No tenants appear in the tenant task">
    **Causes:**
    - Initial sync still in progress
    - API client lacks sufficient permissions

    **Solutions:**
    1. Select **Sync tenants** or use **Run sync**, and wait a few minutes for the background sync to complete
    2. Verify that your Acronis API client can access the tenant. Creating companies in MSPortal will not fix provider visibility.
    3. Confirm that your Acronis environment has sub-tenants configured (if you only have a root tenant, there may be nothing to map)
  </Accordion>

  <Accordion title="Data not syncing after setup">
    **Causes:**
    - Tenants are not mapped to MSPortal companies
    - Sync has not completed yet
    - Credentials have expired or been revoked

    **Solutions:**
    1. Ensure at least one tenant is mapped to a company. Only data from mapped tenants syncs
    2. Wait for the current sync to complete before you request another, then check again
    3. Open **Connect** on the Acronis connection page and select **Test connection** to confirm the stored credentials still work
  </Accordion>

  <Accordion title="Missing alerts or resources">
    **Causes:**
    - The affected tenant is not mapped to a company
    - Sync for that data type has not run yet

    **Solutions:**
    1. Verify the tenant is matched in **Import or match tenants**
    2. Use **Run sync** on the Acronis connection page to request a fresh sync
  </Accordion>

  <Accordion title="Data appears under the wrong company">
    Review the saved match for the correct connection in **Import or match tenants** before you change it. Removing a saved match takes effect immediately.
  </Accordion>

  <Accordion title="Wrong datacenter selected">
    **Causes:**
    - Selected the wrong datacenter from the dropdown, or entered an incorrect custom URL

    **Solutions:**
    1. Log into your Acronis management console and check the URL in your browser address bar
    2. For a new connection, select the matching datacenter from the dropdown, or use **Custom URL** and enter the base domain only (e.g., `https://us5-cloud.acronis.com`), not a full page path
    3. Test the connection again after updating. The datacenter of a saved connection cannot be changed, so disconnect and connect again if it is wrong.
  </Accordion>
</AccordionGroup>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Test connection save the integration?">
    No. For a new connection, wait for a successful test, then choose **Save and continue**. That action saves the connection; synchronization is separate.
  </Accordion>
  <Accordion title="Does Connection verified mean a new check just ran?">
    An existing integration can open with its saved verified state. Use **Test connection** when you need a current connection check, then inspect the result.
  </Accordion>
  <Accordion title="Do suggestions create companies or save every proposed match?">
    Suggestions wait for review. Accepting a suggestion saves that match. Importing a tenant as a company also saves the new company and its match, so check for an existing company first.
  </Accordion>
  <Accordion title="Why is backup data still missing after Finish setup?">
    **Finish setup** records that setup is complete; matches save separately. Check the correct connection, saved tenant matches, provider access and the sync result. A setup-success message does not mean backup data has finished loading.
  </Accordion>
  <Accordion title="Is removing a saved company match only a draft?">
    No. Removing a saved match takes effect immediately. Verify the company and the Acronis tenant before you remove it.
  </Accordion>
</AccordionGroup>

## Security and Privacy

- **Credential Storage**: Your Client ID and Client Secret are encrypted using vault storage and never exposed in logs or responses
- **Data Isolation**: All synced data is tenant-isolated and only visible to your organization
- **Read-Only Access**: MSPortal only reads data from Acronis; it does not modify your Acronis configuration or protection plans
- **Token Management**: Authentication tokens are automatically refreshed, so you do not need to manage token expiration manually
