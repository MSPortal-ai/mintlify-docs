Connect Spanning Backup through UniView to discover Microsoft 365 tenants, synchronize protected users, and report backup health in MSPortal.ai.

<Note>
Spanning Backup is currently a pilot integration. If the integration is not available in **Settings > Integrations**, contact support@msportal.ai.
</Note>

## Prerequisites

- Access to the Spanning UniView portal
- A UniView API client ID and client secret
- MSPortal.ai integration management permission
- MSPortal companies to map to the discovered Microsoft 365 tenants

## Connect Spanning Backup

<Steps>
  <Step title="Create UniView credentials">
    In UniView, open **API Access**, create a client for MSPortal, and copy its client ID and client secret.
  </Step>
  <Step title="Open the setup page">
    In MSPortal, go to **Settings > Integrations**, find the **Spanning Backup** row, and click **Connect** (or **Configure** if it is already connected). The wizard has four steps: **Connect**, **Configure Sync**, **Map Tenants**, and **Status**.
  </Step>
  <Step title="Test the connection">
    Enter the **UniView Client ID** and **UniView Client Secret**, then click **Test Connection**. MSPortal confirms how many Microsoft 365 tenants the client can access, for example "UniView accepted these credentials and returned 12 Microsoft 365 tenants."

    <Frame>
      <img src="/images/product/spanning-setup-connection.png" alt="Spanning connection form with blank credential fields and test and save controls" width="1344" height="920" />
    </Frame>
  </Step>
  <Step title="Save the credentials">
    Click **Create Integration** after the connection test succeeds. The credentials are stored securely in Vault, and the first tenant discovery starts automatically.

    <Note>
      **Test Connection** does not save anything. If you change a field after testing, test again before you click **Create Integration**.
    </Note>
  </Step>
  <Step title="Continue">
    Click **Next** to move to **Configure Sync**.
  </Step>
</Steps>

One UniView connection discovers every Spanning Microsoft 365 tenant the API client can access. You do not need a separate connection per client.

## Configure Synchronization

Microsoft 365 tenant discovery is always enabled because it is required for company mapping. In the **Configure Sync** step, choose whether MSPortal also synchronizes:

- Protected and archived user inventory
- Seven-day backup health for Exchange, OneDrive, SharePoint, and Teams

Click **Save sync settings**, then click **Next**. The switches are not saved until you click **Save sync settings**.

## Map Tenants

<Steps>
  <Step title="Review discovered tenants">
    The mapping table shows each Microsoft 365 tenant returned by UniView, including its primary domain, protected-user count, and backup status. Discovery normally completes in less than a minute. If no tenants appear, click **Sync Tenants** (or **Sync** above the list).
  </Step>
  <Step title="Match tenants to companies">
    Click **Quick Match** to suggest company mappings by name, or use the **Select company...** dropdown to choose the correct MSPortal company manually. If the company does not exist yet, click the **+** button next to the dropdown to create it.
  </Step>
  <Step title="Save the mappings">
    New matches show as **Pending** until you save them. Click **Import Selected** to save them, then click **Next**. **Next** also saves any pending mappings and starts a detailed sync for the mapped tenants.

    Removing a saved mapping takes effect immediately.
  </Step>
</Steps>

## Review Status

The **Status** step shows mapped tenants, protected users, backed-up services, workload summaries, the latest synchronization time, and any current sync error. Mapped tenants synchronize automatically every hour.

Use **View backup health** to open the Spanning Microsoft 365 backup view after the first detailed synchronization completes, or **Manage mappings** to adjust company mappings later. Click **Complete Setup** to close the wizard.

## Managing Your Integration

After setup, manage the integration from **Settings > Integrations**:

| Action | Description |
|--------|-------------|
| **Configure** | Re-open the wizard to replace credentials, change sync settings, or adjust tenant mappings |
| **Resync** | Trigger a fresh sync of all mapped tenants |
| **Rename** / **Disconnect** | In the row's **...** menu |
| **Disconnect** | Also in the wizard footer. Removes the connection, synchronized Spanning data, and the stored Vault credentials. This cannot be undone |

### Replacing Your UniView Credentials

<Steps>
  <Step title="Open the Connect step">
    Click **Configure** on the Spanning Backup row. The wizard opens on **Connect**.
  </Step>
  <Step title="Enter and test the new credentials">
    Enter the new **UniView Client ID** and **UniView Client Secret**, then click **Test Connection**.
  </Step>
  <Step title="Save the credentials">
    Click **Save credentials**. MSPortal stores the new values and starts a fresh sync.
  </Step>
</Steps>

## Troubleshooting

| Issue | Solution |
|-------|----------|
| UniView rejects the credentials | Confirm the API client is active and copy both values from the same UniView client. |
| No tenants appear | Confirm the API client can access the expected Microsoft 365 tenants and allow the initial discovery to complete. |
| Backup health remains pending | Map at least one tenant and enable **Backup health and history**, then allow the first detailed sync to finish. |
| Data appears under the wrong company | Reopen the **Map Tenants** step and correct the tenant-to-company mapping. |
