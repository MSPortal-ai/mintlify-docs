Connect Spanning Backup through UniView to discover Microsoft 365 tenants, synchronize protected users, and report backup health in MSPortal.ai.

<Note>
Spanning Backup is currently a pilot integration. If the integration is not available in **Settings > Integrations**, contact support@msportal.ai.
</Note>

## Prerequisites

- Access to the Spanning UniView portal
- A UniView API client ID and client secret
- MSPortal.ai integration management permission
- MSPortal companies to map to the discovered Microsoft 365 tenants

## Connect Spanning Backup

<Steps>
  <Step title="Create UniView credentials">
    In UniView, open **API Access**, create a client for MSPortal, and copy its client ID and client secret.
  </Step>
  <Step title="Open the connection page">
    In MSPortal, go to **Settings > Integrations**, open the **Directory** tab, find **Spanning Backup**, and select **Connect**. To return to an existing connection, select **Open** on its row in **Active**. The **Setup guide** lists **Connect**, **Choose data**, **Import or match companies** and **Review**.
  </Step>
  <Step title="Test the connection">
    In **Connect**, enter the **UniView Client ID** and **UniView Client Secret**, then select **Test connection**. MSPortal confirms how many Microsoft 365 tenants the client can access, for example "UniView accepted these credentials and returned 12 Microsoft 365 tenants." A successful test can still return no tenants; confirm the client has the intended scope.
  </Step>
  <Step title="Save the credentials">
    Select **Save and continue** after the connection test succeeds. Credentials are stored in the vault and never shown again, and the first tenant discovery starts automatically.

    <Note>
      **Test connection** does not save anything. If you change a field after testing, select **Test again** before you save.
    </Note>
  </Step>
</Steps>

One UniView connection discovers every Spanning Microsoft 365 tenant the API client can access. You do not need a separate connection per client.

## Choose the data to synchronize

Microsoft 365 tenant discovery is always on because it is required for company mapping. In **Choose data**, choose whether MSPortal also synchronizes:

- **Protected user inventory**: the standard and archived users UniView returns for each tenant
- **Backup health and history**: the rolling seven-day status for Exchange, OneDrive, SharePoint and Teams

Each switch saves as soon as you change it. Wait for the save to finish and resolve any error before you leave the task. Both switches start on for a new connection, so this task is optional.

## Import or match tenants to companies

<Steps>
  <Step title="Review discovered tenants">
    Open **Import or match companies**. The list shows each Microsoft 365 tenant returned by UniView, including its primary domain, protected-user count and backup status. Discovery normally completes in less than a minute. If no tenants appear, use **Run sync** in the connection header, then check the list again.
  </Step>
  <Step title="Match tenants to companies">
    Review **Suggested** matches and select **Accept** for each correct one, or **Change** to pick a different company. **Accept N strong matches** accepts every suggestion with 90% confidence or more after you confirm the list. For a tenant in **Import**, which lists tenants that are not matched yet, use **Choose company…** to pick the correct MSPortal company. If the company does not exist yet, check for duplicates, then select **Import** to create it and save the match. Use **Ignore** for tenants you do not want to map, and **Restore** to bring them back.
  </Step>
  <Step title="Check the saved matches">
    Accepted and chosen matches save immediately. Review them in **Matched**, where **Change** lets you pick a different company or **Remove match**. Removing a match takes effect immediately.
  </Step>
</Steps>

Company matches determine where synchronized backup data appears. They do not create a Spanning customer or start a backup job.

## Finish setup

Open **Review** and select **Finish setup** when the required tasks are complete. Finishing does not guarantee that every workload has synchronized. Mapped tenants synchronize automatically every hour.

Use **Overview** and **Sync activity** to check the connection and recent synchronization. After the first detailed sync completes, open the Backup module to review protected users and workload health. If data is still preparing, check company matches, enabled datasets and the first detailed sync before reading missing records as healthy.

## Managing Your Integration

Open the connection from **Settings > Integrations > Active**. Then use:

| Action | Description |
|--------|-------------|
| **Connect** | Replace the UniView credentials |
| **Choose data** | Turn protected users or backup health on or off |
| **Import or match companies** | Adjust tenant-to-company matches |
| **Run sync** | Start a fresh sync of all data or one dataset |
| **More actions > Rename** | Give the connection a nickname |
| **More actions > Disconnect…** | Removes the stored credentials, the matches between Spanning tenants and your companies, and synced Spanning data. This cannot be undone |

### Replacing Your UniView Credentials

<Steps>
  <Step title="Open the Connect task">
    Open the Spanning Backup connection and select **Connect** in the **Setup guide**.
  </Step>
  <Step title="Enter and test the new credentials">
    Enter the new **UniView Client ID** and **UniView Client Secret**, then select **Test connection**.
  </Step>
  <Step title="Save the credentials">
    Select **Save changes**. MSPortal stores the new values and starts a fresh sync.
  </Step>
</Steps>

Do not regenerate UniView credentials just to retry a page load.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| UniView rejects the credentials | Confirm the API client is active and copy both values from the same UniView client. |
| No tenants appear | Confirm the API client can access the expected Microsoft 365 tenants and allow the initial discovery to complete. |
| Backup health remains pending | Match at least one tenant and turn on **Backup health and history** in **Choose data**, then allow the first detailed sync to finish. |
| Data appears under the wrong company | Open **Import or match companies** and correct the tenant-to-company match. |
| A change did not persist | Credentials save only with **Save and continue** or **Save changes**. Sync switches and matching actions save when applied; check for a reported failure. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Test connection save the credentials?">
    No. Use **Save and continue** for a new connection or **Save changes** for a tested replacement.
  </Accordion>
  <Accordion title="Does changing a sync switch save immediately?">
    Yes. Each switch in **Choose data** saves when changed. Wait for the save to finish.
  </Accordion>
  <Accordion title="Are suggested matches already saved?">
    No. Review each suggestion, then accept it to save the match. Removing a saved match also takes effect immediately.
  </Accordion>
  <Accordion title="Can I restore a backup from this connection page?">
    No. This connection configures reporting. Perform recovery in Spanning.
  </Accordion>
  <Accordion title="Does missing backup data mean everything is healthy?">
    No. Check matches, source coverage and sync errors before drawing a conclusion. Backup health records the rolling seven-day workload status supplied by UniView for Exchange, OneDrive, SharePoint and Teams. A captured trend is not a guarantee of complete historical restore-point coverage. Use Spanning for restore operations and provider-level investigation.
  </Accordion>
</AccordionGroup>
