Use this page to find the setup guide for your provider. Connecting an integration is an **MSP staff** task. Company users should ask their MSP to connect or change a service.

## Before you start

- You can open **Settings > Integrations** and have permission to manage integrations.
- You have the provider's credentials, such as an API key or an admin sign-in.
- Your companies exist in MSPortal, or you can import them, so you can match each provider organization to one.

## Connect an integration

<Steps>
  <Step title="Open Integrations">
    Go to **Settings > Integrations** and check the existing connections on the **Active** tab before you add another one.
  </Step>
  <Step title="Start the setup">
    On the **Directory** tab, find the provider and select **Connect**. To change a connection you already have, select **Open** on its row in **Active**.
  </Step>
  <Step title="Follow the provider guide">
    Pick your provider in the table below. Each guide lists the credentials, settings and permissions that provider needs.
  </Step>
  <Step title="Import or match companies">
    Link each provider organization or customer to the MSPortal company it belongs to.
  </Step>
  <Step title="Check the results">
    Confirm the integration shows as connected, then check that data synced and appears for the right companies. Connecting does not turn on every data area, so review what the provider syncs.
  </Step>
</Steps>

Some controls save as soon as you change them, while credential forms, mapping suggestions and imports save on their own buttons. Read the provider guide before you continue, especially for writeback, bulk imports and disconnecting. Review company mappings and user-role rules before you turn on automatic imports.

## Move around a connection

On desktop, the **Setup guide** menu on the left and the task on the right scroll independently. Scroll the task to reach its remaining settings and **Back** or **Continue** buttons; the connection header stays in place. Scroll the menu to reach steps farther down the list. You can collapse or expand the menu with the button beside **Setup guide**.

On a phone, tap **Setup guide** above the task to open the steps, then select the page you want to visit.

A connection page keeps its tasks in one place. Select a task in the **Setup guide** to return to it; the available tasks depend on the provider.

| Task | What to do |
| --- | --- |
| **Connect** | Enter credentials or complete the provider sign-in. Where a test is available, test the connection before selecting **Save and continue**. A successful test alone does not save typed credentials. |
| **Permissions** | For PSA providers, check required and recommended access. Resolve required failures and select **Re-check**. |
| **Choose data** | Choose supported datasets, scope filters, invoice visibility and automatic imports in one place. Enable a dataset to reveal its dependent settings; disabling it hides those settings without clearing saved choices. Switches and selectors save as you change them. Start the initial sync when offered and inspect its result. |
| **Import or match companies** | The first view, **Import**, includes unlinked records with or without suggestions. Use **Suggested** to review proposed links. Use a row’s **Import** action or open **Import companies** to select the current page or all pages of matching source records. Confirm the selection to import; existing companies with the same name are reused. Choosing an existing company or accepting a suggestion saves that match immediately. The workspace identifies the provider’s source records, such as sites or organizations. |
| **Import or match users** | Import PSA contacts in place with a row’s **Import** action, or select contacts and use **Import selected**. Use the header checkbox to select the current page, click it again to select all pages matching the current filters, and click again to clear the selection. Use row checkboxes for individual contacts. **Select all with email** replaces the selection with contacts that have an email address across all pages matching the current filters, leaving out contacts with missing emails. Review the selection, then choose **Import selected**. Choose a Company role and review the counts before confirming; contacts without an email address are skipped. You can also link existing portal users. |
| **Import devices** | Match each provider type to a device type, then import or link the records you need. See [Import devices](/user-guides/integrations/import-devices). |
| **Configure …** | Configure how synchronized data works in MSPortal, such as ticket behavior, opportunity defaults, warranty write-back or appointment features. Optional tasks can be deferred. |
| **Review** | Resolve the remaining required tasks, then select **Finish setup**. Check actual sync/import results and client access separately. |

For selection limits, email review and save behavior, see [Import companies](/user-guides/integrations/import-companies) and [Import users](/user-guides/integrations/import-users). Import or match at least one company to open its contacts and devices. You can return to import more records without resolving every company or contact; other companies can wait.

The same provider tasks open inside [Launch Center](/user-guides/getting-started/launch-center) when connection pages are enabled. Company-specific connections and provider consent screens can have their own flow.

Some text forms have an explicit save action, while switches, pickers and matching actions save immediately. Wait for each result before leaving. A connection, completed setup or accepted match does not itself prove client visibility. Review company links, user roles and automatic import settings before enabling client access.

### Return to an existing connection

Use **Overview** for its status and **Sync activity** to inspect synchronization. Open the relevant task to change saved settings. Supported credential updates use **Test connection** and **Save changes**; a masked credential means a value is stored. Changing the vendor URL can require entering the secret again.

Use **Run sync**, where the provider offers it, when you intend to request a new synchronization. **Disconnect…**, under **More actions** in the connection header, removes the connection's stored credentials, matches and synced data after confirmation. Vendor-side credential revocation is separate.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does every provider have the same setup steps?">
    No. Sign-in, company mapping, sync and supported actions differ by provider. Follow the provider's own guide.
  </Accordion>
  <Accordion title="Can my clients see the data once a provider is connected?">
    Not automatically. Data must sync and be mapped to the right company, and the client's role must allow it. Check each.
  </Accordion>
  <Accordion title="Should I add another connection when data is missing?">
    No. Check the existing connection's permissions, scope and company mapping first. A second connection can duplicate records.
  </Accordion>
  <Accordion title="Where do I go when data is missing?">
    Start with the [Integrations FAQ](/user-guides/integrations/faq).
  </Accordion>
</AccordionGroup>
