Connect N-able N-central to MSPortal.ai to synchronize customers, match them to MSPortal companies, and import managed devices.

<Note>
N-central setup is available only for MSP tenants where it has been enabled. If **N-able N-central** does not appear in **Settings > Integrations**, contact support@msportal.ai.
</Note>

## Prerequisites

- An N-central account with permission to create an API-only user and generate an API token
- The HTTPS URL for your N-central server
- MSPortal.ai integration management permission
- Companies in MSPortal to map to N-central customers

## Create an N-central API Token

<Steps>
  <Step title="Create an API-only user">
    In N-central, create a dedicated API-only user for MSPortal. Disable MFA for this API user and use a non-expiring password so scheduled synchronization can continue. Give the user access to the customers you want to sync.
  </Step>
  <Step title="Open API Access">
    Go to **Administration > User Management > Users**, open the API user, and select **API Access**.
  </Step>
  <Step title="Generate the token">
    Click **Generate JSON Web Token** and copy the token. Store it securely until you enter it in MSPortal.
  </Step>
</Steps>

## Connect N-central in MSPortal

Go to **Settings > Integrations**, open the **Directory** tab, find **N-able N-central**, and select **Connect**. To work on an existing connection, open it from the **Active** tab with **Open**.

The connection page lists its tasks in the **Setup guide**. Under **Setup** you will find **Connect**, **Choose data**, **Import or match companies**, **Import devices**, and **Review**. Under **Manage** you will find **Overview** and **Sync activity**. Select a task to open it.

<Steps>
  <Step title="Enter the connection details">
    In **Connect**, enter your **Server URL**, such as `https://ncentral.example.com`, and the **API Token (JWT)** generated in N-central. Credentials are stored in the vault and never shown again.
  </Step>
  <Step title="Test the connection">
    Select **Test connection**. Resolve any authentication or server URL error before continuing.
  </Step>
  <Step title="Save the connection">
    After the test succeeds, select **Save and continue**. MSPortal stores the token securely. A successful test alone does not save the connection.
  </Step>
</Steps>

## Choose Data

N-central syncs all of its customer and device data, so **Choose data** has no dataset switches. The task is done once the first sync has run.

## Match Customers and Import Devices

<Steps>
  <Step title="Wait for customers to load">
    Open **Import or match companies**. The workspace is titled **Import or match N-able N-central customers** and lists your N-central customers once they have synced. If the list is empty, select **Sync customers** and wait for them to arrive.
  </Step>
  <Step title="Review suggested matches">
    Open **Suggested** to review proposed matches and their confidence. Select **Accept** to save a match, or **Change** to choose a different company. **Accept N strong matches** accepts every suggestion with 90% confidence or more at once.
  </Step>
  <Step title="Match the remaining customers">
    In **Import**, the view the workspace opens on, choose the MSPortal company each remaining customer belongs to. If the company does not exist yet, select **Import company**, after checking for duplicates. Select **Ignore** for customers you don't want to sync; you can **Restore** them later from **Ignored**.
  </Step>
  <Step title="Check your matches">
    Review **Matched**. Accepting or choosing a company saves the match immediately. **Remove match** also takes effect immediately. Devices for newly matched customers arrive with the next device sync.
  </Step>
  <Step title="Match device types">
    Open **Import devices**. Under **Match device types**, choose the MSPortal device type for each N-central device category. Use **Match all suggested** or **Match the rest with AI** to speed this up. Turn on **Auto-import** for types you always want imported, and ignore types you never want.
  </Step>
  <Step title="Import devices">
    Under **Staged devices**, select **Import all matched**, or select devices and use **Import N selected**. Only devices belonging to matched customers can be associated with the correct MSPortal company. Every change saves immediately.
  </Step>
  <Step title="Finish setup">
    Open **Review** and select **Finish setup** once the required tasks are done. Finishing setup does not mean every background sync or import has finished. Check **Import devices** and the resulting **Devices** records.
  </Step>
</Steps>

See [Import Devices](/user-guides/integrations/import-devices) for more on device type matching and imports.

## Sync Schedule

| Sync Type | Schedule | Details |
|-----------|----------|---------|
| Customer Sync | Daily at 2:20 AM UTC | Refreshes the list of N-central customers |
| Device Sync | Daily at 3:35 AM UTC | Syncs devices from matched customers, then auto-imports types with **Auto-import** on |
| Auto-Import Catch-Up | Daily at 2:55 AM UTC | Imports any auto-import devices that were missed |

N-central connections do not offer **Run sync**. To refresh the customer list sooner, select **Sync customers** when **Import or match companies** is empty. Use **Sync activity** to check recent results. A scheduled time does not guarantee a successful run.

## Managing the Connection

Open the N-central connection from the **Active** tab in **Settings > Integrations**. Select any task in the **Setup guide** to return to it. Use **Overview** for the connection's status and **Sync activity** to inspect synchronization and errors.

To replace the server URL or token:

<Steps>
  <Step title="Open Connect">
    Open the N-central connection and select **Connect** in the **Setup guide**.
  </Step>
  <Step title="Enter the replacement values">
    Update the **Server URL** if needed, and enter the replacement token in **API Token (JWT)**. Leave the masked token unchanged to keep the stored one. If you change the server URL, enter the token again; a stored token is only sent to the URL it was saved with.
  </Step>
  <Step title="Test the connection">
    Select **Test connection** and wait for **Connection verified**.
  </Step>
  <Step title="Save changes">
    Select **Save changes** to store the new server URL or token. Testing alone does not save replacements.
  </Step>
</Steps>

Return to **Import devices** at any time to review newly discovered devices or adjust device type matches.

To rename the connection, use **Rename** under **More actions** in the connection header. **Disconnect…**, also under **More actions**, removes the stored credentials, the matches between N-central customers and companies, and synced data after you confirm. It does not revoke the token in N-central.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Connection test fails | Confirm the server URL uses HTTPS and points to the root of your N-central server. Then generate a new JSON Web Token for the API user. |
| Authentication stops working | Confirm the API user is still active, MFA remains disabled for that API-only account, and its password has not expired. |
| Customers are missing | Select **Sync customers** in **Import or match companies** and allow the customer sync to finish. Confirm the API user can see those customers in N-central. |
| A match disappeared | Check the result of the last matching action, then reopen **Import or match companies** to verify the saved state. |
| Devices cannot be imported | Match the device's N-central customer to an MSPortal company first. Then check device type matches, ignored types and the import result. |
| Inventory is old | Check **Sync activity** for the last successful sync and any connection errors. |

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="Does Test connection save the integration?">
    No. For a new connection, test successfully and then select **Save and continue**. For an existing connection, select **Save changes** to store replacement values.
  </Accordion>
  <Accordion title="Are suggested matches saved automatically?">
    No. Suggestions wait for your review. Accepting a suggestion saves its match immediately; removing a saved match also takes effect immediately.
  </Accordion>
  <Accordion title="Does Finish setup mean all devices are imported?">
    No. Device sync, saved matches and device imports have separate results. Check **Import devices** and the resulting inventory.
  </Accordion>
  <Accordion title="Can a company user configure this provider?">
    No. Provider setup is an MSP settings task. Company access to resulting data depends on portal permissions and company scope.
  </Accordion>
  <Accordion title="Why are customers visible but devices missing?">
    Customer sync, company matching, device sync and device import are separate stages. Check the saved customer match and the device sync result in **Sync activity** before importing.
  </Accordion>
</AccordionGroup>
