NinjaOne Ticketing currently provides a pilot connection for testing and storing API-client credentials. It does **not** yet provide ticket synchronization, mapping or ticket reporting through this setup. NinjaOne RMM device synchronization is a [separate integration](/user-guides/integrations/enable-ninjaone-integration).

## Before you start

This is an MSP staff task requiring integration management permission, NinjaOne administrator access and access to the tenant's pilot. If **NinjaOne Ticketing** is absent from **Settings > Integrations**, ask MSPortal support about availability rather than assuming a saved RMM connection enables it.

## Test and save the connection

<Steps>
  <Step title="Prepare the API client">
    In NinjaOne, open **Administration > Apps > API**. Create an **API Services (machine-to-machine)** client using the **Client Credentials** grant. The MSPortal setup asks for Monitoring and Management scopes. Retain the client ID, client secret and your HTTPS instance URL. See [NinjaOne's client-credentials reference](https://app.ninjaone.com/apidocs-beta/authorization/flows/client-credentials-flow).
  </Step>
  <Step title="Enter the connection details">
    In **Settings > Integrations**, open NinjaOne Ticketing and enter **Instance URL**, **Client ID** and **Client secret**. Use the supported NinjaOne instance URL, not a ticket link or arbitrary API endpoint.


  </Step>
  <Step title="Test API access">
    Click **Test Connection**. A successful result reports API access and, when available, the number of ticket boards returned. This is connection verification, not a ticket import.
  </Step>
  <Step title="Save explicitly">
    Click **Connect** after the test succeeds. When editing an existing connection, test changed values and click **Save Changes**. A passing test does not persist those edits. The form masks saved client credentials.
  </Step>
</Steps>

## Recheck or disconnect

Reopen the intended connection. **Retest Connection** makes a new test request; simply seeing the saved connection does not prove current access. Keep masked credential values unchanged to retain them, or replace them and test before saving. Changing a field invalidates the earlier test.

**Disconnect** opens a confirmation dialog. Confirming removes the MSPortal connection and its stored credentials. It does not revoke the NinjaOne API client; manage that client separately in NinjaOne when appropriate.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Instance URL is rejected | Use the HTTPS NinjaOne instance URL accepted by the setup, without a ticket or API path. |
| Authentication fails | Check the API Services client, Client Credentials grant, scopes and complete credential values. |
| No boards are reported | Verify ticketing availability and API access in NinjaOne. Board counts do not establish imported tickets. |
| Save is unavailable after an edit | Complete all fields and run the test again before saving. |
| No tickets appear after connecting | The current pilot stores and verifies credentials only. |
| Controls are read-only | Integration management permission is required to test, change or disconnect. |

## Frequently asked questions

<Accordion title="Does the NinjaOne Ticketing pilot sync tickets?">

No. The current pilot tests and stores the connection; it does not provide ticket sync, mapping or reporting.

</Accordion>

<Accordion title="Does NinjaOne RMM setup also enable this ticketing pilot?">

No. NinjaOne RMM device synchronization is a separate integration.

</Accordion>

<Accordion title="Does Test Connection save NinjaOne credentials?">

No. Click **Connect** for a new connection or **Save Changes** after testing replacements.

</Accordion>

<Accordion title="Does a ticket-board count prove tickets were imported?">

No. It is a connection-test result only.

</Accordion>

<Accordion title="Why is NinjaOne Ticketing missing from Integrations?">

It is tenant-gated pilot functionality. Check availability with MSPortal support and your MSP permissions.

</Accordion>

<Accordion title="Can I leave existing NinjaOne credentials blank to retain them?">

Keep the masked saved values unchanged. Blank required fields disable the test/save flow.

</Accordion>

<Accordion title="Does Disconnect revoke the NinjaOne API application?">

No. It removes the MSPortal connection and stored credentials; provider-client revocation is separate.

</Accordion>
