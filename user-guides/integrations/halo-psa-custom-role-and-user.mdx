This guide walks you through creating a dedicated role and API-only agent in Halo PSA for the MSPortal.ai integration. Use the permission tables below as the checklist for the role, then link the agent to the MSPortal API application.

## Prerequisites

- Administrator access to your Halo PSA instance
- Access to the Configuration area in Halo PSA

<Info>
Creating a dedicated MSPortal role and API-only agent is **recommended** for security best practices. This ensures the integration has only the permissions it needs and provides clear audit trails.
</Info>

## Create the MSPortal Role

<Steps>
  <Step title="Navigate to Agent Roles">
    In Halo PSA, go to **Configuration** → **Teams & Agents** → **Roles**.

    ![Navigate to Roles](https://colony-recorder.s3.amazonaws.com/files/2025-12-16/158beb82-87a4-4d6e-bd98-0d10ca022cb2/stack_animation.webp)
  </Step>

  <Step title="Create New Role">
    1. Click **New**
    2. Enter **MSPortal** as the role name
    3. Click **Submit**
  </Step>

    Under the **Permissions** section, configure the following settings:

## Create the API-Only Agent

<Steps>
  <Step title="Navigate to Agents">
    Go to **Configuration** → **Teams & Agents** → **Agents**.

    ![Navigate to Agents](https://colony-recorder.s3.amazonaws.com/files/2025-12-16/efce8d3a-7c8b-42e6-909f-b69bb70253bc/stack_animation.webp)
  </Step>

  <Step title="Create New Agent">
    1. Click **New**
    2. Enter **MSPortal** as the agent name
    3. Check **Is an API-only Agent**
    4. Select **MSPortal** from the **Role** dropdown

    <Tip>
    API-only agents don't require a password or email address since they're used exclusively for API access.
    </Tip>
  </Step>

  <Step title="Save the Agent">
    Click **Submit** to create the agent.
  </Step>
</Steps>

## Assign Departments and Teams to the Role

<Warning>
This step is required for the MSPortal integration to access tickets, customers, and other data. The API agent will only be able to see data from departments and teams assigned to the role.
</Warning>

<Steps>
  <Step title="Open the MSPortal Role">
    Go to **Configuration** → **Teams & Agents** → **Roles**, then click on the **MSPortal** role to edit it.
  </Step>

  <Step title="Navigate to Departments & Teams Tab">
    Click on the **Departments & Teams** tab within the role settings.
  </Step>

  <Step title="Add Departments and Teams">
    Add all the departments and teams that you want MSPortal to have access to:

    1. Add each department whose data should be visible in MSPortal
    2. Add each team whose tickets and data should be visible in MSPortal
    3. Click **Submit** to save the role
  </Step>
</Steps>

<Info>
If you skip this step, the MSPortal integration may not be able to see tickets, customers, or other data associated with those departments and teams.
</Info>

## Link the Agent to Your API Application

<Steps>
  <Step title="Open API Applications">
    Navigate to **Configuration** → **Integrations** → **Halo PSA API** → **View Applications**.
  </Step>

  <Step title="Open the MSPortal Application">
    If you already connected MSPortal, open the **MSPortal.ai** application. Otherwise click **New**, name it **MSPortal.ai** and choose **Client ID and Secret (Services)** as the authentication method.
  </Step>

  <Step title="Select the Agent">
    In the **Agent to Log in as** dropdown, select the **MSPortal** API-only agent you just created.
  </Step>

  <Step title="Grant the API Permissions">
    Open the application's **Permissions** tab and grant the permissions below. The role controls what the agent can do in Halo. These permissions control which parts of the API MSPortal can call.

    | Application permission | MSPortal feature | Required |
    |------------------------|------------------|----------|
    | `read:customers` | Companies, users and agents | **Yes** |
    | `read:tickets` | Tickets, teams, statuses, priorities and ticket types | **Yes** |
    | `read:assets` | Devices | Optional |
    | `read:opportunities` | Opportunities | Optional |
    | `read:items` | Product catalog | Optional |
    | `read:invoices` | Invoices | Optional |
    | `read:contracts` | Customer agreements | Optional |
    | `read:projects` | Projects | Optional |
    | `read:timesheets` | Time entries | Optional |
    | `read:feedback` | Satisfaction ratings (CSAT) | Optional |
    | Change access (`all` covers it) | Change management calendar | Optional |

    To create tickets, notes and time entries from MSPortal, also grant **Ticket Modify**. To manage Halo projects from MSPortal, also grant **Project Read** and **Project Modify** (see [Project Management](#project-management) below).
  </Step>

  <Step title="Save and Copy the Credentials">
    Click **Submit**. For a new application, copy the **Client ID** and **Client Secret** now, because Halo shows the secret only once.
  </Step>
</Steps>

## Check Permissions in MSPortal

<Steps>
  <Step title="Open the Halo PSA Setup">
    In MSPortal, go to **Settings** → **Integrations** → **Halo PSA**. For a new connection, enter your Halo URL, Client ID and Client Secret, then click **Test Connection**. The full walkthrough is in [Connect Halo PSA](/user-guides/integrations/enable-halo-integration).
  </Step>

  <Step title="Review the Permissions Step">
    Each required check must pass before you can continue. Optional checks that fail only turn off that feature.
  </Step>

  <Step title="Fix and Re-check">
    If a check fails, grant the permission it names in Halo, save, then click **Re-check** in MSPortal.
  </Step>
</Steps>

<Note>
The Permissions step tests read access. Confirm write actions, like creating a ticket or logging time, by trying them once on a test record.
</Note>

## Project Management

Skip this section unless you will create or update Halo projects from MSPortal.

<Steps>
  <Step title="Grant Project and Ticket Access on the Application">
    On the **MSPortal.ai** application, grant **Project Read**, **Project Modify**, **Ticket Read** and **Ticket Modify**.
  </Step>

  <Step title="Confirm the Agent's Ticket Permissions">
    The **Tickets** permissions in the role table above cover child tickets, notes, time and to-do items. Make sure the agent's teams, clients and ticket types include your project ticket types.
  </Step>

  <Step title="Test on a Project">
    Create a test project from MSPortal, add a note with time and complete a checklist item. The [project management permission table](/user-guides/integrations/enable-halo-integration#project-management-permissions) lists each operation and current Halo limits.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication works, but tickets or teams are missing">
    The agent can only see data from the departments and teams on its role. Add them on the role's **Departments & Teams** tab, and confirm **Allow use of all Ticket Types** and **Allow use of all Customers** are set. Then select **Re-check** on the MSPortal Permissions step.
  </Accordion>
  <Accordion title="An optional feature shows as denied">
    Grant the matching application permission from the table above only if you want that feature. Otherwise leave its sync turned off.
  </Accordion>
  <Accordion title="A check timed out or could not be verified">
    A timeout is not a permission denial. Retry before changing the role.
  </Accordion>
</AccordionGroup>
