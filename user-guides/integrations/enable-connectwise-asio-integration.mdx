ConnectWise Asio (formerly ConnectWise RMM) is a remote monitoring and management platform. This guide is for MSP staff who connect Asio so its companies, devices, hypervisors and network devices appear in MSPortal. On the Asio connection page, the **Setup guide** lists **Connect**, **Choose data**, **Import or match companies**, **Locations** (optional), **Import devices** and **Review**.

## Before you start

- You are MSP staff with permission to manage integrations. Company users cannot set this up.
- You have admin access to ConnectWise Asio.
- Your companies already exist in MSPortal, usually from your PSA integration. Asio companies are mapped to those existing companies.
- ConnectWise PSA keys do not work here. Asio uses its own API Client ID and Client Secret.

<Note>
The first sync can take hours, or even days, for a large account. Companies appear on **Import or match companies** as they sync, and devices appear in staging as the sync progresses.
</Note>

## Create API credentials in Asio

<Steps>
  <Step title="Open API Access">
    Sign in to ConnectWise Asio as an admin and go to **Integrations > API Access**.
  </Step>
  <Step title="Add an API key">
    Select **Generate API Access** (or **+ Add** if you already have keys) and enter **MSPortal** as the **API Key Name**.
  </Step>
  <Step title="Choose the scopes">
    Grant these scopes.

    | Scope | Permission |
    | --- | --- |
    | Platform - Agent | Read |
    | Platform - Assets | Read |
    | Platform - Companies | Read |
    | Platform - Custom Fields values | Read |
    | Platform - DataMapping | Read |
    | Platform - DeviceGroups | Read |
    | Platform - Devices | Read |
    | Platform - Sites | Read |
    | Platform - Tickets | Create, Read and Update |
  </Step>
  <Step title="Save and copy the credentials">
    Select **Save**. Copy the **Client ID** and **Client Secret** now. Asio does not show them again after you close the dialog.
  </Step>
</Steps>

## Connect Asio to MSPortal

<Steps>
  <Step title="Start the setup">
    In MSPortal, go to **Settings > Integrations**, choose **Directory**, find **ConnectWise Asio** and select **Connect**. To change an existing connection, open it from your active integrations instead.
  </Step>
  <Step title="Enter the connection details">
    On **Connect**, fill in these fields.

    | Field | What to enter |
    | --- | --- |
    | **Environment** | The region your Asio account runs in: **Production (NA)**, **Production (EU)**, **Production (AU)** or **QA**. |
    | **Client ID** | The Client ID you copied. It must start with the prefix for your environment: NA `0e30`, EU `0e31`, AU `0e32`, QA `0e11`. |
    | **Client Secret** | The matching Client Secret. |
  </Step>
  <Step title="Test the connection">
    Select **Test connection**. If it fails, check the environment, the Client ID prefix, the secret and the scopes.
  </Step>
  <Step title="Save the connection">
    Select **Save and continue**. This saves the connection and starts discovery. A successful test alone does not save the connection. The secret is stored in encrypted vault storage.
  </Step>
</Steps>

## Choose data

Open **Choose data** to pick which data to import. The choices are **Companies**, **Locations**, **Devices**, **Networks**, **Tickets** and **Software**. Changes save as you make them. Turning a category off stops future syncs of it. Turning **Software** off removes that integration's software inventory, and turning it back on starts a new inventory sync. Devices, networks and software use your existing company mappings, so keep **Companies** on to discover new companies to map.

## Map companies

<Steps>
  <Step title="Open Import or match companies">
    The list shows each Asio company and whether it is matched. Companies appear after discovery has returned them from Asio.
  </Step>
  <Step title="Match companies">
    Accept a suggested match, or choose the MSPortal company on each row. **Accept strong matches** accepts every high-confidence suggestion at once after you review them. **Ignore** hides an Asio company that is not a client's.
  </Step>
  <Step title="Check the saved links">
    Each accepted match saves immediately. Check that the rows show saved links before you continue.
  </Step>
</Steps>

<Tip>
Map Asio companies to companies you already have. **Import company** creates a new MSPortal company immediately, so check for an existing one first.
</Tip>

Removing a saved link takes effect immediately. Saved matches decide which company receives Asio data.

## Map locations (optional)

<Steps>
  <Step title="Open Locations">
    Only locations for matched companies appear. If you do not need location mapping, skip this task.
  </Step>
  <Step title="Match locations">
    Accept a suggestion, choose one of the company's locations, or create one from the row. Every change saves immediately.
  </Step>
</Steps>

Matching alone does not create missing locations. If no locations appear, check the company match and that discovery has finished.

## Import devices

<Steps>
  <Step title="Open Import devices">
    Open **Import devices** on the connection page. Staged devices and type mappings are on the same page.
  </Step>
  <Step title="Match device types">
    In **Match device types**, choose the MSPortal device type each Asio type becomes. Turn on **Auto-import** for types you want imported automatically. Every change saves immediately.
  </Step>
  <Step title="Import the devices you want">
    In **Staged devices**, select the devices and import them, or use **Import all matched**. Devices whose company is not matched yet show **Match company first**.
  </Step>
  <Step title="Finish setup">
    Open **Review** and select **Finish setup** once the required tasks are complete.
  </Step>
</Steps>

For selections, type mappings and results, see [Import Devices](/user-guides/integrations/import-devices).

## Manage an existing connection

- **Update the secret:** open **Connect**, enter the new Client Secret, select **Test connection**, then **Save changes**. Leave the masked secret unchanged to keep it. The saved environment and Client ID are locked; to change them, connect a new Asio API client.
- **Check status:** use **Overview** and **Sync activity** to see the connection status, sync runs and errors.
- **Sync now:** select **Run sync** on the connection page.
- **Disconnect:** open **More actions** and choose **Disconnect…**. This removes the stored credentials, the company matches and the data synced from Asio. It does not revoke the API key in Asio, so remove that key in Asio yourself.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| Connection test fails | Check the **Environment**, the Client ID prefix, the Client Secret and that every scope above is granted. Check that the credentials have not been revoked in Asio. |
| No companies on **Import or match companies** | Wait for the first sync to progress, and confirm the API key has the **Platform - Companies** Read scope. Avoid creating the connection again. |
| A mapping disappeared | Reopen **Import or match companies** and check which rows show a saved link. |
| Devices are missing | Check that the company is matched, the first sync has finished, the device type is matched and not ignored, and the devices were imported from **Staged devices**. |
| Inventory is old | Check the last successful sync in **Sync activity** and any paused or error state on the connection. A scheduled time does not guarantee a successful run. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Test connection save the integration?">
    No. After a successful test, select **Save and continue** for a new connection, or **Save changes** for an existing one.
  </Accordion>
  <Accordion title="Are suggested links saved automatically?">
    No. Suggestions wait for your review. Accepting a suggestion saves its link immediately; removing a saved link also takes effect immediately.
  </Accordion>
  <Accordion title="Does Finish setup mean every device is imported?">
    No. Device sync and import run separately. Check **Import devices** and the resulting inventory.
  </Accordion>
  <Accordion title="Can a company user set up Asio?">
    No. Setup is an MSP staff task.
  </Accordion>
  <Accordion title="Does Asio replace my ConnectWise PSA setup?">
    No. Asio is the RMM connection. ConnectWise PSA has its own setup for tickets and company imports.
  </Accordion>
</AccordionGroup>
