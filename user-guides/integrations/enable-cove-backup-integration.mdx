This guide walks you through connecting your Cove (N-able Backup) instance to MSPortal.ai. It is for **MSP staff** with integration management access and authorized credentials for the intended Cove account.

## Prerequisites

- Active Cove (N-able Backup) account with administrative access
- MSPortal.ai account with integration management permissions

## Part 1: Configure Cove

Before connecting to MSPortal.ai, you need to create an API user in Cove with the appropriate permissions.

### Create API User

<Steps>
  <Step title="Access User Management">
    Log into your Cove (N-able Backup) management console and navigate to **Users** in the main menu.
  </Step>

  <Step title="Navigate to API Users">
    Click on **API Users** to access the API user management section.
  </Step>

  <Step title="Add New API User">
    Click **Add API Users** to begin creating your API user.
  </Step>

  <Step title="Select Customer">
    In the customer selection dropdown, select your **top-level reseller name** (the account at the very top of the Customer hierarchy), not an individual client. This is the account that the API user will be associated with, and it gives the API user visibility into all of your sub-customers.
  </Step>

  <Step title="Configure User Details">
    Configure the following settings:

    | Field | Value |
    |-------|-------|
    | **Login Name** | `MSPortal` (or any descriptive name) |
    | **Role** | `Supporter` |

    <Tip>
      The Supporter role provides the necessary read permissions for MSPortal to sync your backup data without granting excessive access.
    </Tip>
  </Step>

  <Step title="Save and Copy Token">
    Click **Save** to create the API user. The system will generate an API token.

    <Warning>
      **Copy the API token immediately!** You will not be able to retrieve it again after leaving this page. Store it securely for use in MSPortal.ai.
    </Warning>
  </Step>
</Steps>

### Required Information

Before proceeding to MSPortal, ensure you have the following:

| Information | Description |
|-------------|-------------|
| **Partner Name** | Your **top-level reseller name** exactly as shown in the Cove management console (see below) |
| **API User Name** | The login name you created (e.g., `MSPortal`) |
| **API Token** | The token generated when creating the API user |

#### Finding your Partner Name

The Partner Name is your **top-level reseller account**, found at the top of the **Customer** dropdown in the Cove management console. It is the parent account that your individual clients are nested under, not one of those clients.

In the example below, the Partner Name is `MSPortal.ai` (the top-level reseller). `Acme Corp` is a sub-customer nested beneath it and would **not** be used as the Partner Name.

<Frame>
  <img src="/images/Cove/Cove Company.png" alt="Cove management console Customer dropdown showing the top-level reseller name above its nested sub-customers" />
</Frame>

<Warning>
  Enter the **top-level reseller name**, not an individual client name. Using a sub-customer name is the most common cause of a failed connection test.
</Warning>

## Part 2: Connect Cove in MSPortal

The Cove Data Protection connection page lists its tasks in the **Setup guide**: **Connect**, **Import or match companies** and **Review**. See [Connect and manage integrations](/user-guides/integrations/index) for the tasks every connection shares.

### Connect

<Steps>
  <Step title="Open the connection page">
    In MSPortal.ai, go to **Settings** > **Integrations**. On the **Directory** tab, find **Cove Data Protection** and click **Connect**. If several Cove connections exist, open the intended one from your active integrations instead.
  </Step>

  <Step title="Enter API Credentials">
    Fill in the following fields:

    | Field | Description |
    |-------|-------------|
    | **Partner Name** | Your **top-level reseller name** exactly as shown at the top of the Customer hierarchy in the Cove management console (e.g., `MSPortal.ai`), not an individual client |
    | **API User Name** | The login name of your API user (e.g., `MSPortal`) |
    | **API Token** | The token you copied when creating the API user |

    <Frame>
      <img src="/images/product/cove-connection-fields.png" alt="Blank Cove API Token field and its explanation in MSPortal setup." width="892" height="172" />
    </Frame>

    <Note>
      The Partner Name is your top-level reseller account, not one of your individual clients. The API User Name is the login name you created, not an email address.
    </Note>
  </Step>

  <Step title="Test the connection">
    Click **Test connection** to verify your credentials. You'll see **Connection verified** when the test passes.

    If the connection fails:
    - Verify your Partner Name is your **top-level reseller name** (not an individual client) and matches exactly as shown in Cove
    - Check that your API User Name is correct (the login name, not email)
    - Ensure the API token is copied correctly without extra spaces
    - Verify the API user has the Supporter role
  </Step>

  <Step title="Save and continue">
    Once the connection test passes, click **Save and continue** to save your credentials and move to **Import or match companies**.

    <Note>
      **Test connection** does not save anything. If you change a field after testing, test again before you save. Creating the connection does not mean partner or backup data has been imported.
    </Note>
  </Step>
</Steps>

### Import or match companies

Match Cove partners (clients/customers) to your MSPortal companies. This determines which backup data syncs to which company.

<Steps>
  <Step title="Load partners">
    If the list is empty, click **Sync companies** to fetch partners from your Cove account. The first sync may take a few minutes depending on your account size. You can also use **Run sync** in the connection header and check the result.
  </Step>

  <Step title="Review suggestions">
    Open **Suggested** to review proposed matches based on name similarity, then click **Accept** on each correct one. **Accept strong matches** accepts every suggestion with 90% confidence or more after you review the list.
  </Step>

  <Step title="Match the rest">
    For partners that weren't matched or need adjustment, choose the correct MSPortal company in the row. Each match saves when you apply it; wait for success before relying on the link.

    To remove a match, use **Remove match**. Removing a saved match takes effect immediately.
  </Step>

  <Step title="Import missing companies">
    If the company does not exist yet, click **Import company** in the partner's row to create it and match the partner in one go. MSPortal creates the company right away, so check for an existing company first to avoid duplicates.
  </Step>
</Steps>

<Info>
  Only backup data from matched partners syncs to MSPortal. Company matches determine where synchronized backup data appears. They do not create a Cove customer or start a backup job. You can return to add more matches at any time.
</Info>

### Review and finish setup

Open **Review** and select **Finish setup** once the required tasks are complete. Each match saves on its own, and background synchronization continues after you finish, so check the sync result separately.

## Managing Your Integration

Open the Cove connection from **Settings** > **Integrations** to manage it:

| Action | Description |
|--------|-------------|
| **Connect** | Test or update credentials |
| **Import or match companies** | Add more partner matches |
| **Overview** and **Sync activity** | Review connection status and sync results |
| **Run sync** | Trigger a manual sync of data from Cove |
| **Rename** / **Disconnect…** | Under **More actions**. Rename labels the connection. Disconnect removes the stored credentials, partner matches and synced data, and cannot be undone. |

Cove supports more than one connection, so you can add a second Cove account as its own connection.

### Updating Your Credentials

After the connection is created, the **Partner Name** is locked. You can change the **API User Name** and **API Token** on **Connect**, for example to rotate the token or move the connection to a new API user.

<Steps>
  <Step title="Open Connect">
    In **Settings** > **Integrations**, open the Cove connection and select **Connect**. The stored token appears masked.
  </Step>
  <Step title="Enter the new values">
    Enter the new **API User Name**, **API Token**, or both. When you change the API User Name, enter that user's token as well.
  </Step>
  <Step title="Test the connection">
    Click **Test connection** and wait for it to pass. **Save changes** stays unavailable until the test passes.
  </Step>
  <Step title="Save">
    Click **Save changes**. Partner matches and settings are kept.
  </Step>
</Steps>

To check the stored credentials without changing them, click **Test connection** on **Connect**. The verified state shown when you open an existing connection is not a new test.

<Warning>
  Save the new API user in MSPortal before you delete the old API user in Cove, so syncs keep running.
</Warning>

### When Credentials Are Missing

If the stored credentials for a connection are lost, the connection shows **Needs attention** and its overview lists **Credentials are missing**. Nothing syncs until they are entered again. Someone with integration management permission clicks **Re-enter**, fills in the **Partner Name**, **API User Name** and **API Token**, clicks **Test connection**, then **Save changes**. Partner matches and settings are kept.

## Synchronization Process

### Initial Sync
- Partner data syncs when you first click **Sync companies** on **Import or match companies**, or at the next scheduled partner sync
- Backup data syncs separately and may take a few minutes
- Only backup data from matched partners syncs to MSPortal

### Ongoing Sync

| Data Type | Sync Frequency |
|-----------|----------------|
| Partners | Every 4 hours |
| Devices | Every 30 minutes (at :10 and :40) |
| Backup statistics | Every 30 minutes (at :15 and :45) |

- Partner matches persist until you change them
- New partners appear after the next partner sync, or right away if you click **Run sync**

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Connection test fails | Verify Partner Name (your top-level reseller name, not a client), API User Name, and Token are correct |
| No partners appear | Click **Sync companies** on **Import or match companies**, or **Run sync**, to fetch data from Cove |
| Backup data not showing | Ensure the partner is matched to a company first, then check the correct connection and its sync result |
| No suggestion for a partner | Choose the company in the row for partners with different names in Cove and MSPortal |
| Token expired/invalid | Create a new API token or API user in Cove, then [update your credentials](#updating-your-credentials) on **Connect** |
| Backup data still missing after **Finish setup** | Finishing records setup readiness only. Check company matches, Cove access and the sync result. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Test connection save the integration?">
    No. For a new connection, wait for a successful test, then choose **Save and continue**. For an existing connection, choose **Save changes**. Synchronization is separate.
  </Accordion>
  <Accordion title="Do suggestions create companies or save every proposed match?">
    No. Suggestions wait for review. Accepting a suggestion saves that match. **Import company** is also a saved action; check for an existing company first.
  </Accordion>
  <Accordion title="Is removing a saved company match only a draft?">
    No. Removing a saved match persists immediately. Verify the company and Cove partner before removing it.
  </Accordion>
</AccordionGroup>

## Important Notes

- **Token Security**: Store your API token securely. If compromised, create a new API user in Cove, [update your credentials](#updating-your-credentials) in MSPortal, then delete the old API user
- **Partner Matching**: Only backup data from matched partners will sync to MSPortal
- **Role Permissions**: The Supporter role provides read-only access, which is sufficient for MSPortal integration
- **Sync Timing**: Initial synchronization may take several minutes depending on your account size
