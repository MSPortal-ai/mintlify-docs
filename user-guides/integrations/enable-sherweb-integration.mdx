This guide walks you through connecting your Sherweb distributor account to MSPortal.ai. Setup happens on the Sherweb connection page, where the **Setup guide** lists three tasks: **Connect**, **Import or match companies** and **Review**. The Sherweb integration is currently in Beta. It is configured by MSP staff with integration management permission; company users do not administer the distributor connection. See [Connect and manage integrations](/user-guides/integrations/index#connect-match-and-verify) for the shared connection tasks.

## Overview

Sherweb is a cloud solutions distributor for MSPs. By integrating Sherweb with MSPortal.ai, you can:

- View every client's Sherweb subscriptions alongside the rest of their data
- Sync each customer's offer catalog, including pricing, from Sherweb
- Power the Storefront with a curated, client-facing product catalog
- Keep subscription and catalog data refreshed automatically every day

## Prerequisites

- Active Sherweb partner account with access to the Sherweb Partner Portal (cumulus.sherweb.com)
- MSPortal.ai account with integration management permissions
- Sherweb API credentials: a Client ID, Client Secret, and Subscription Key

## Part 1: Generate Sherweb API Credentials

Before connecting to MSPortal.ai, you need API credentials from the Sherweb Partner Portal.

<Steps>
  <Step title="Log into the Sherweb Partner Portal">
    Access the Sherweb Partner Portal at [cumulus.sherweb.com](https://cumulus.sherweb.com).
  </Step>

  <Step title="Navigate to API Management">
    Go to **Security > APIs** in the Partner Portal. The guide beside the **Connect** task in MSPortal shows this path too.
  </Step>

  <Step title="Create Service Provider API Credentials">
    Create credentials for the **Service Provider API**. Sherweb issues three values that MSPortal needs:

    | Value | Purpose |
    |-------|---------|
    | **Client ID** | Identifies your API client |
    | **Client Secret** | Authenticates your API client |
    | **Subscription Key** | The `Ocp-Apim-Subscription-Key` value that authorizes access to the Service Provider API |
  </Step>

  <Step title="Copy All Three Values">
    Copy the Client ID, Client Secret, and Subscription Key.

    <Warning>
      **Store the Client Secret securely.** You may not be able to view it again after leaving the page. If you lose it, generate new credentials in the Partner Portal.
    </Warning>
  </Step>
</Steps>

## Part 2: Connect Sherweb in MSPortal

### Open the connection page

<Steps>
  <Step title="Navigate to Integrations">
    In MSPortal.ai, go to **Settings > Integrations**.
  </Step>

  <Step title="Find Sherweb">
    On the **Directory** tab, find **Sherweb** in the list of available integrations.
  </Step>

  <Step title="Start Setup">
    Select **Connect** to open the Sherweb connection page. To continue an existing connection, open it from the **Active** tab instead.
  </Step>
</Steps>

---

### Task 1: Connect

Enter your Sherweb API credentials to establish the connection. All three values are required.

<Steps>
  <Step title="Enter Credentials">
    Fill in the three fields:

    - **Client ID**
    - **Client Secret**
    - **Subscription Key**

    <Note>
      Credentials are stored in the vault and never shown again. They are never exposed in logs or API responses.
    </Note>
  </Step>

  <Step title="Test Connection">
    Select **Test connection** to verify your credentials. You must test before you can save.

    If the test fails:
    - Verify you copied each value in full, without extra spaces
    - Confirm the values came from **Security > APIs** in the Sherweb Partner Portal
    - Ensure the credentials have not been revoked
  </Step>

  <Step title="Save and Continue">
    Select **Save and continue** to create the integration. A passing test does not save anything on its own.

    MSPortal immediately starts fetching your Sherweb customer list in the background, so it is ready for the next task.
  </Step>
</Steps>

---

### Task 2: Import or match companies

Match Sherweb customers to your MSPortal companies. This determines which data syncs to which company. The workspace is titled **Import or match Sherweb customers**.

<Steps>
  <Step title="Wait for Customers to Appear">
    The customer list fills in as the initial sync completes. If the list stays empty, select **Sync customers** to start the sync again.

    <Info>
      The initial customer sync usually finishes within a couple of minutes.
    </Info>
  </Step>

  <Step title="Accept Suggestions">
    The workspace opens on the **Import** view, which lists every customer that still needs a company. **Suggested** narrows it to proposed matches. Select **Accept N strong matches** to review and accept every suggestion with 90% confidence or more, or select **Accept** on a single row. Suggestions are based on name similarity, so review them before accepting.
  </Step>

  <Step title="Manual Matching">
    For customers that were not automatically matched:

    1. In the **Import** view, find the customer
    2. Select **Choose company…**
    3. Search for and select the correct MSPortal company
  </Step>

  <Step title="Import New Companies">
    If a Sherweb customer does not have a corresponding MSPortal company, select **Import** on its row to create one. New companies are matched to their Sherweb customers right away. Search for an existing company first.
  </Step>

  <Step title="Continue">
    Each match saves immediately, and removing a match also saves immediately. Select **Continue to Review** when you are done.

    <Warning>
      Subscriptions and catalog data are only synced for matched customers.
    </Warning>
  </Step>
</Steps>

---

### Task 3: Review

<Steps>
  <Step title="Finish Setup">
    Select **Finish setup** once the required tasks are complete. This records that setup is complete. It does not wait for, or start, a sync.
  </Step>

  <Step title="Run a Full Sync">
    In the connection page header, select **Run sync** to pull your Sherweb customers, then the subscriptions and offer catalog for every matched customer. Newly matched customers get their subscriptions and catalog on this sync or the next daily sync.

    The sync runs in the background. Check **Sync activity** for the outcome, then check the customer's subscriptions and catalog in the [Storefront](/user-guides/storefront/index).
  </Step>
</Steps>

## What Gets Synced

The Sherweb integration syncs the following data:

### Customers

Every customer under your Sherweb account, ready to be matched to MSPortal companies.

### Subscriptions

Subscription details and pricing for each **mapped** customer, including quantities, status, and billing information. Subscriptions appear in the [Storefront](/user-guides/storefront/index) under Subscriptions.

### Catalog Items

Each mapped customer's offer catalog from Sherweb, including product names, SKUs, and pricing. You control which catalog items clients can see: go to **Settings > Storefront** to mark Sherweb catalog items as **Visible** or **Featured**.

<Note>
  Sherweb subscriptions and catalogs are customer-scoped, so only data for customers mapped to an MSPortal company is stored.
</Note>

## Synchronization Schedule

After initial setup, data syncs automatically:

| Data Type | Sync Frequency |
|-----------|----------------|
| Customers | Daily at 07:00 UTC |
| Subscriptions | Daily at 07:00 UTC |
| Catalog Items | Daily at 07:00 UTC |

The daily sync runs customers first, then subscriptions, then catalogs, so subscription and catalog data always reflects your latest customer mappings.

<Note>
You can trigger a manual sync at any time: select **Run sync** on the Sherweb connection page, or on the Sherweb row on the **Active** tab of **Settings > Integrations**.
</Note>

## Managing Your Integration

After setup, open your Sherweb connection from the **Active** tab in **Settings > Integrations**:

| Action | Description |
|--------|-------------|
| **Setup guide** | Return to **Connect** to rotate credentials, or **Import or match companies** to adjust customer matches |
| **Test connection** | On **Connect**, leave all three masked fields unchanged and select **Test connection** to verify your saved credentials |
| **Run sync** | Trigger a full data refresh |
| **More actions > Rename** | Give the connection a nickname |
| **More actions > Disconnect…** | Remove the integration |

### Rotating Your Credentials

If you need to update your Sherweb API credentials:

<Steps>
  <Step title="Open Connect">
    Go to **Settings > Integrations**, open your Sherweb connection and select **Connect** in the **Setup guide**. The saved values appear masked.
  </Step>
  <Step title="Enter New Values">
    Enter only the values you want to change. Leave a masked field unchanged to keep its current value.
  </Step>
  <Step title="Test the New Values">
    Select **Test connection**. The test checks your replacements combined with the stored values for unchanged fields.
  </Step>
  <Step title="Save Changes">
    Select **Save changes**. MSPortal checks the combined credentials again before saving them. A test alone does not save them.
  </Step>
</Steps>

### Managing Customer Mappings

Manage your Sherweb customer-to-company matches at any time:

- Open the connection and select **Import or match companies** in the **Setup guide**, or
- Select **Map companies** on **Settings > Integrations** to manage matches alongside your other integrations

### Disconnecting the Integration

Select **More actions > Disconnect…** and confirm. This removes your stored credentials, the customer matches, and the data synced from Sherweb. It cannot be undone. It does not cancel any subscriptions in Sherweb or revoke the API credentials there. You can reconnect at any time.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Connection test fails | Verify all three values (Client ID, Client Secret, Subscription Key) are correct and copied in full |
| Test asks you to fill in or clear the fields | A new connection needs all three values. On an existing connection, keep the masks for unchanged values and enter only the replacements |
| No customers appear in **Import or match companies** | The initial sync can take a few minutes. Select **Sync customers** to retry, and check **Sync activity** for a connection error |
| Subscriptions or catalog missing | Only matched customers sync; match the customer to a company, then select **Run sync** |
| Catalog items not visible to clients | Check item visibility under Settings > Storefront |
| Stale data | Select **Run sync**, or wait for the daily 07:00 UTC sync. Saving the connection or finishing setup does not mean a sync has completed |

## Security & Privacy

- **Credential Storage**: Your Sherweb Client ID, Client Secret, and Subscription Key are encrypted using Supabase Vault and never exposed in logs or responses
- **Data Isolation**: All synced data is tenant-isolated and only visible to your organization
- **Read-Only Access**: MSPortal only reads data from Sherweb; it never modifies your Sherweb subscriptions or places orders

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="How do I test the saved credentials?">
    Open **Connect**, leave all three masked fields unchanged and select **Test connection**.
  </Accordion>
  <Accordion title="Can I test a replacement for only one value?">
    Yes. Enter the value to replace and keep the other fields unchanged. The test uses the replacement combined with the stored values.
  </Accordion>
  <Accordion title="Can I update only the Sherweb subscription key?">
    Yes. Enter that value, test, and select **Save changes**. Unchanged masked fields keep their stored values. The update checks the combined set before saving.
  </Accordion>
  <Accordion title="Does testing Sherweb save the connection?">
    No. Use **Save and continue** for a new connection or **Save changes** for replacements.
  </Accordion>
  <Accordion title="Are new Sherweb customer matches saved immediately?">
    Yes. Manual choices, accepted suggestions and removed matches save immediately. Suggestions need your review before you accept them.
  </Accordion>
  <Accordion title="Is a Sherweb customer catalog the same for every company?">
    No. Catalogs are customer-specific. Check the intended company and its matched Sherweb customer.
  </Accordion>
  <Accordion title="Does Finish setup prove the Sherweb sync finished?">
    No. Check **Sync activity** and the actual subscriptions and catalog after the background work runs.
  </Accordion>
</AccordionGroup>
