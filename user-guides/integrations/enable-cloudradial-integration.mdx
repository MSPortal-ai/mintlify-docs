Import selected CloudRadial service catalog items as MSPortal ticket templates. This is an on-demand import configured by MSP staff, with integration access plus permission to write Ticket Settings for the import itself. It is not Company self-service setup.

<Warning>
Import creates templates immediately. Repeating an import can create additional templates with renamed identities. Do not assume previously imported items are skipped or updated in place.
</Warning>

## Connect CloudRadial

<Steps>
  <Step title="Prepare CloudRadial API keys">
    In CloudRadial, open **Partner > Settings**, select **Integrations** in the Configuration column, then **API** and **+Add API Key**. Copy the public/private pair before leaving; the private key is not shown again. See [CloudRadial's API instructions](https://support.cloudradial.com/hc/en-us/articles/360050153571-Using-the-CloudRadial-API).
  </Step>
  <Step title="Test the intended region">
    In **Settings > Integrations**, open CloudRadial setup. Select the hosting **Region** and enter **Public Key** and **Private Key**. Supported choices are United States, Canada, United Kingdom, Australia and Europe. Confirm the displayed endpoint belongs to your region, then click **Test Connection**.

    <Frame caption="MSP setup example; no credentials entered.">
      <img src="/images/product/cloudradial-region-fields.png" alt="CloudRadial region and blank key fields with separate Test Connection and Create Integration controls." width="1720" height="724" />
    </Frame>
  </Step>
  <Step title="Save the connection">
    Click **Create Integration** after the test passes, then **Next**. For an existing connection, test changed values and click **Update Integration**. Keep the masked private-key value unchanged when retaining the saved key. A test or navigation alone does not save changed credentials.
  </Step>
</Steps>

## Select and import templates

| View | What it contains |
| --- | --- |
| **All Items** | Catalog items grouped across companies by their name, category and template pack. This is not a row for every company assignment. |
| **Client-Specific** | Items found for one CloudRadial company, with that company's name. |

Search and sort the active view, then select only the intended items. **Export** downloads the filtered active view, not just checked items. **Refresh** requests the catalog again. Switching views clears selection and search.

<Warning>
Search does not clear earlier selections. Clear the search and review the selected count before **Import** so hidden selected items are not included accidentally.
</Warning>

Click **Import** to create the selected templates. Review every result; successful templates remain even if another item fails. Before retrying, inspect existing templates and select only the items that still need work. **Complete Setup** exits the wizard; it does not undo an import.

## Review routing and company access before use

Open [Ticket Templates](/user-guides/ticketing/how-to-create-a-ticket-template) after importing. Review the template name, fields and sections, defaults, PSA routing and enabled/company settings. Conversion is a starting point for your MSPortal form, not a guarantee that every source rule or provider-specific option behaves identically.

Client-specific assignment relies on a matching MSPortal company name. A missing or ambiguous match must be resolved before relying on the restriction. An import success can also occur without a successful company-assignment save. Verify the template's actual company defaults and assignments; imported templates are active, so do not treat the result as an unpublished draft.

The integration reads CloudRadial catalog data and creates MSPortal templates. It does not maintain an automatic recurring catalog sync. When source items change, review the corresponding MSPortal template rather than blindly re-importing it.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Connection fails | Verify region, both keys and API access. Retest after changes, then save. |
| Import is forbidden | Check permission to write Ticket Settings as well as integration access. |
| Catalog is empty | Clear search, check the active view and confirm the source account contains accessible items. |
| Only some items imported | Inspect per-item results and existing templates before retrying failures. |
| Duplicate or renamed templates appear | Repeated imports can create copies; review and manage those templates in Ticket Settings. |
| Client-specific access looks wrong | Inspect matching company names and actual template company settings before client use. |

## Frequently asked questions

<Accordion title="Does CloudRadial automatically keep templates synchronized?">

No. Catalog import is on demand. Review later source changes in the MSPortal template.

</Accordion>

<Accordion title="Is it safe to import the same CloudRadial item again?">

Do not assume it is skipped. Re-importing can create a renamed copy; inspect existing templates first.

</Accordion>

<Accordion title="Does Client-Specific guarantee only that company can use the template?">

No. Verify the matching company and actual enabled/default assignments after import. A successful import does not prove assignment succeeded.

</Accordion>

<Accordion title="Does CloudRadial search clear selected items?">

No. Previously selected items can remain hidden by search. Clear the search and review the count before importing.

</Accordion>

<Accordion title="What does CloudRadial Export download?">

The filtered active catalog view, not just selected items.

</Accordion>

<Accordion title="Does a failed CloudRadial batch undo successful templates?">

No. Inspect per-item results; successful creations remain. Check before retrying failures.

</Accordion>

<Accordion title="Are imported CloudRadial templates inactive drafts?">

No. Review active state, fields, PSA routing and company settings immediately after import.

</Accordion>

<Accordion title="Which permission controls CloudRadial template import?">

MSP staff need permission to write Ticket Settings in addition to the required integration access.

</Accordion>

<Accordion title="Does Update Integration save automatically after a test?">

No. Test the changes, then explicitly click **Update Integration**. Keep the masked private key unchanged to retain it.

</Accordion>
