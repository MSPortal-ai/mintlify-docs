This guide walks you through connecting your CloudRadial account to MSPortal.ai and importing selected service catalog items as ticket templates. The import is on demand and is set up by MSP staff with integration access plus permission to write Ticket Settings. It is not a company self-service setup.

## Overview

CloudRadial is a client portal platform where many MSPs maintain a service catalog of request forms. By integrating CloudRadial with MSPortal.ai, you can:

- Import CloudRadial service catalog items directly as MSPortal ticket templates
- Preserve each item's name, description, category, and PSA routing details
- Import client-specific catalog items and assign them to the matching company
- Choose exactly which items to bring over, one time or in batches

On the CloudRadial connection page, the **Setup guide** has three tasks: **Connect**, **Choose data** (optional, where you pick and import catalog items) and **Review**.

## Prerequisites

- Active CloudRadial partner account with API access
- CloudRadial public and private API keys
- MSPortal.ai account with integration management permissions
- Permission to write Ticket Settings, which the import itself requires

## Part 1: Generate CloudRadial API Keys

Before connecting to MSPortal.ai, you need API credentials from CloudRadial. See [CloudRadial's API instructions](https://support.cloudradial.com/hc/en-us/articles/360050153571-Using-the-CloudRadial-API).

<Steps>
  <Step title="Log into CloudRadial">
    Access your CloudRadial Partner Portal.
  </Step>

  <Step title="Open the API integration">
    Go to **Partner > Settings**, select **Integrations** in the **Configuration** column, then select **API**.
  </Step>

  <Step title="Create an API Key">
    Click **+Add API Key** and give the key a name. CloudRadial issues a **Public Key** and a **Private Key** pair; MSPortal needs both.
  </Step>

  <Step title="Copy Both Keys">
    Copy the public and private keys before you leave the page. CloudRadial does not show the private key again.

    <Warning>
      **Store the private key securely!** Treat it like a password. If you lose it, create a new key pair.
    </Warning>

    <Tip>
      Note which region your CloudRadial account is hosted in (United States, Canada, United Kingdom, Australia, or Europe). You will select this region in MSPortal so requests go to the correct API endpoint.
    </Tip>
  </Step>
</Steps>

---

## Part 2: Connect in MSPortal

<Steps>
  <Step title="Open CloudRadial">
    In MSPortal.ai, go to **Settings > Integrations**, choose **Directory**, find **CloudRadial**, and choose **Connect**.
  </Step>

  <Step title="Select Your Region">
    Choose your CloudRadial hosting region from the **Region** dropdown: United States, Canada, United Kingdom, Australia, or Europe.
  </Step>

  <Step title="Enter Your Keys">
    Paste your credentials into the **Public Key** and **Private Key** fields.

    <Note>
      Your private key is stored securely using Supabase Vault encryption. It is never exposed in logs or API responses.
    </Note>
  </Step>

  <Step title="Test Connection">
    Choose **Test connection** to verify your credentials.

    If the connection fails:
    - Verify both keys were copied fully without extra spaces
    - Confirm you selected the region that matches your CloudRadial account
    - Check that the API key has not been revoked in CloudRadial
  </Step>

  <Step title="Save">
    Once the test passes, choose **Save and continue**. A successful test on its own does not save anything.
  </Step>
</Steps>

## Part 3: Import Catalog Items

Open **Choose data** on the connection page and select the catalog items you want to bring into MSPortal as ticket templates.

<Steps>
  <Step title="Choose a View">
    Two views control which items you see:

    | View | Description |
    |------|-------------|
    | **All items** | Catalog items grouped across companies by name, category and template pack. This is not a row for every company assignment |
    | **Client-specific** | Items that exist for only one CloudRadial company, with that company's name; imports from this view assign the template to the matching company |

    Switching views clears your selection.
  </Step>

  <Step title="Select Items">
    Use **Search catalog items** to filter by name, category or company. Check the items you want, or use **Select all shown** to select the visible results. Items flagged as partner managed show a **Partner** badge.

    <Warning>
      Searching does not clear items you already checked. Clear the search and review the selected count before you import, so hidden items are not imported by accident.
    </Warning>
  </Step>

  <Step title="Import">
    Choose **Import** to convert the selected items into ticket templates. Imported templates are active right away.

    Each row then shows **Imported** or **Not imported**, with the reason for a failure. Templates that imported successfully stay in place even if other items in the batch fail.

    <Warning>
      Importing an item again does not skip it. If a template with the same name already exists, MSPortal creates a renamed copy. Check your existing templates before you re-import.
    </Warning>
  </Step>

  <Step title="Review the Imported Templates">
    Open your [ticket templates](/user-guides/ticketing/how-to-create-a-ticket-template) and check each imported template's fields, defaults, PSA routing, and company settings before clients use it. Conversion is a starting point for your MSPortal form, not a guarantee that every CloudRadial rule behaves the same way.
  </Step>

  <Step title="Finish Setup">
    Open **Review** and choose **Finish setup**. Finishing setup does not undo any import.
  </Step>
</Steps>

## What Gets Imported

CloudRadial catalog items are imported as MSPortal ticket templates, including:

- Item name and description
- Category and template pack
- PSA routing details: board, type, subtype, status, and priority
- Company assignment for client-specific items

Client-specific items are assigned to the MSPortal company whose name matches the CloudRadial company name (ignoring case). The template is turned off for every other company. If no company name matches, the template imports with no company restriction and is available to every company, so check its company settings after import.

<Note>
The import creates templates in MSPortal; it does not modify anything in CloudRadial.
</Note>

## Synchronization Schedule

CloudRadial is an on-demand import, not a recurring sync:

| Data Type | Sync Frequency |
|-----------|----------------|
| Catalog items | On demand, when you choose **Import** in **Choose data** |

<Note>
When you add new catalog items in CloudRadial, open the CloudRadial connection again, open **Choose data**, and import only the new items. Re-importing an existing item creates a renamed copy. When an item changes in CloudRadial, edit the matching MSPortal template instead of importing it again.
</Note>

## Managing Your Integration

After setup, open the CloudRadial connection from **Settings > Integrations**.

### Updating Your API Keys

<Steps>
  <Step title="Open Connect">
    Open the CloudRadial connection and select **Connect**.
  </Step>
  <Step title="Enter New Keys">
    Enter the new public key. Leave the masked private key unchanged to keep the saved one, or enter a new private key to replace it. Changing the region clears the private key, so enter it again.
  </Step>
  <Step title="Test and Save">
    Choose **Test connection**, then **Save changes**. Testing alone does not save changed credentials.
  </Step>
</Steps>

### Disconnecting

To remove the connection, open **More actions** on the connection page and choose **Disconnect…**. Disconnecting changes nothing in CloudRadial; delete the API key there when you no longer need it.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Connection test fails | Verify both keys are correct and the selected region matches your CloudRadial account |
| No catalog items found | Clear the search, check the active view, and confirm your CloudRadial account has catalog items |
| Duplicate or renamed templates appear | The item was imported more than once. Delete the extra copies in Ticket Templates and edit the original instead of re-importing |
| Import fails with a permission error | You need permission to write Ticket Settings in addition to integration access |
| A client-specific template is available to every company | No MSPortal company name matched the CloudRadial company name. Restrict the template to the right company in its settings |
| Some items failed to import | Check the reason on each **Not imported** row, then re-select and re-import only the failed items |

## Security & Privacy

- **Credential Storage**: Your CloudRadial private key is encrypted using Supabase Vault and never exposed in logs or responses
- **Data Isolation**: All imported templates are tenant-isolated and only visible to your organization
- **Read-Only Access**: MSPortal only reads your CloudRadial catalog; it never modifies your CloudRadial configuration
