This guide walks you through connecting your ConnectWise Manage instance to MSPortal.ai using our streamlined setup wizard.

## Prerequisites

Before you begin, ensure you have:
- Admin access to both ConnectWise Manage and MSPortal.ai
- Your ConnectWise company ID (visible on the ConnectWise login screen)
- Access to create API members and security roles in ConnectWise

## Part 1: Configure ConnectWise Manage

Before connecting to MSPortal.ai, you need to create an API member and security role in ConnectWise.

### Create Security Role

<Steps>
  <Step title="Access System Settings">
    Login to ConnectWise Manage and navigate to **System > Security Roles**.
  </Step>

  <Step title="Create Security Role">
    Create a security role named "MSPortal" with the following permissions. These permissions enable MSPortal to sync companies, contacts, tickets, opportunities, agreements, and related data.

    For **every category** listed below, set **Add Level**, **Edit Level**, and **Inquire Level** to **All**. Leave **Delete Level** as **None**.

    | Category | Add | Edit | Delete | Inquire |
    |----------|-----|------|--------|---------|
    | Companies | All | All | None | All |
    | Finance | All | All | None | All |
    | Marketing | All | All | None | All |
    | Procurement | All | All | None | All |
    | Project | All | All | None | All |
    | Sales | All | All | None | All |
    | Service Desk | All | All | None | All |
    | System | All | All | None | All |
    | Time & Expense | All | All | None | All |

    <Tip>
      The easiest way to configure this is to expand each category and set all sub-permissions to **All** for Add, Edit, and Inquire. You can leave Delete as **None** for all categories.
    </Tip>

    Click **Save and Close** to finalize the security role settings.
  </Step>
</Steps>

### Create API Member

<Steps>
  <Step title="Navigate to API Members">
    1. Go to **System > Members**
    2. Click the **API Members** tab
    3. Click **+** to create a new API member
  </Step>

  <Step title="Configure API Member">
    1. Name it "MSPortal"
    2. Select the **MSPortal** security role you created
    3. Enter your **Business Unit** and **Location**
    4. Click **Save**
  </Step>

  <Step title="Generate API Keys">
    1. With the API member open, click the **API Keys** tab
    2. Click **+** to add a new key
    3. Name it "MSPortal" and click **Save**
    4. **Important:** Copy the **Public Key** and **Private Key** immediately

    <Warning>
      The API keys cannot be retrieved again after closing this dialog. Make sure to save them securely before proceeding.
    </Warning>
  </Step>
</Steps>

## Project management permissions

Skip this section unless you will create or update ConnectWise projects from MSPortal. If you set every Project permission to **All** in the role above, you only need to confirm these levels.

The settings go on the role of the **API member that owns the keys saved in MSPortal**. Your staff member's personal ConnectWise role does not give the integration any access.

<Steps>
  <Step title="Open the API member's role">
    In ConnectWise, go to **System > Members > API Members**, open the MSPortal API member and note its security role. Then open that role under **System > Security Roles**.
  </Step>

  <Step title="Set the Project permissions">
    Expand **Project** and set the levels below. Use **All**, not **My**, because **My** can stop the integration from updating work assigned to someone else.

    | Project permission | Required levels | Used for |
    |--------------------|-----------------|----------|
    | **Project Headers** | Inquire: All; Add: All; Edit: All | Sync projects, create PSA projects, and update project status, dates and mapped fields |
    | **Project Phase** | Inquire: All; Add: All; Edit: All | Read phases, create phases when launching or applying a template, and update phase names and dates |
    | **Project Tickets** | Inquire: All; Add: All; Edit: All | Read and create project tickets, and update their status, owner, priority, summary, budget hours, dates and mapped fields |
    | **Close Projects** | Inquire: All; Add: None; Edit: All | Move a project into a closed status |
    | **Close Project Tickets** | Inquire: All; Add: None; Edit: All | Move a project ticket into a closed status |
    | **Project Notes** | Inquire: All; Add: All; Edit: All | Read and add project notes. Project ticket comments also need access to the parent Project Tickets record. |
    | **Project Teams** | Inquire: All; Add: All; Edit: All | Read project team members and fill assignment choices |
    | **Project Ticket Tasks** | Inquire: All; Add: All; Edit: All | Read and add checklist items, change completion and update checklist progress notes. This is separate from Project Tickets. |
    | **Project Templates** | Inquire: All | Import project templates into **Settings** > **Projects** > **Templates** |

    Project ticket status changes need **Project Tickets** > **Edit Level: All**. **Project Ticket Tasks** Edit only covers checklist changes.
  </Step>

  <Step title="Set the supporting permissions">
    Project management also uses records outside the Project module. Keep the wizard's required company, contact, member and lookup permissions, and set these for the features you use:

    | Area | Access | Used for |
    |------|--------|----------|
    | **Companies** > **Company Maintenance** and **Contacts** | Inquire: All | Select the project's company and contact |
    | **System** > **Member Maintenance** | Inquire: All | Resolve project managers, ticket owners and time entry authors |
    | **System** > **Table Setup** | Inquire: All | Fill boards, statuses, types, priorities, work types and work roles. A missing lookup can block a write even when the project is editable. |
    | **Time & Expense** > **Time Entry** | Inquire: All; Add: All when logging time | Sync project effort and create project ticket time entries |
    | **Finance** > **Billing View Time** | Inquire: All; Edit: All when logging billable time | Read and record billable time |
    | **Time & Expense** > **Time Entry Billable Option** | Inquire and Edit: All when choosing billable or non-billable time | Set the billing option on time entries |
    | **Finance** > **Agreements** | Inquire: All when using agreement time settings | Resolve agreement references for time entry |

    These permissions do not override ConnectWise validation, board restrictions, closed record rules or required fields.
  </Step>

  <Step title="Decide on checklist deletion">
    Read, create and update work does not need Delete access. To use **Delete checklist item**, also set **Project** > **Project Ticket Tasks** > **Delete Level: All**. Leave Delete off on other project records.
  </Step>

  <Step title="Save and re-check">
    Save the role. In MSPortal, go to **Settings** > **Integrations** > **ConnectWise Manage** > **Configure** > **Permissions** and click **Re-check**.
  </Step>
</Steps>

<Note>
MSPortal-only projects, portal templates and project registers use MSPortal permissions only. ConnectWise access never grants a staff or client user access inside MSPortal.
</Note>

### Allow project checklist changes

Adding a checklist item or changing its completion writes to ConnectWise as the API member. The staff member needs the MSPortal project permission, and the API member separately needs ConnectWise access.

<Steps>
  <Step title="Find the API member">
    In ConnectWise, open **System > Members > API Members** and find the member that owns the public key saved in MSPortal.
  </Step>

  <Step title="Open its security role">
    Note the member's security role, then open it under **System > Security Roles**.
  </Step>

  <Step title="Set Project Ticket Tasks">
    Expand **Project** and set **Project Ticket Tasks**:

    | Level | Setting | Purpose |
    |-------|---------|---------|
    | **Inquire Level** | **All** | Read checklist items |
    | **Add Level** | **All** | Add checklist items |
    | **Edit Level** | **All** | Update checklist completion |

    Keep the role dedicated to MSPortal. If another integration shares it, check the effect on that integration first.
  </Step>

  <Step title="Re-check in MSPortal">
    Save the role, then go to **Settings** > **Integrations** > **ConnectWise Manage** > **Configure** > **Permissions** and click **Re-check**. Read the **Project checklist writes** result:

    | Result | Meaning |
    |--------|---------|
    | **Granted** | All three task permission levels are **All** |
    | **Not permitted** | The role denies at least one of the three levels |
    | **Could not verify** | MSPortal could not read the role, or a level is set to **My**. Review the role in ConnectWise. |
  </Step>
</Steps>

<Note>
**Projects** and **Project checklist writes** are separate checks. With Project Ticket Tasks at Inquire **All** and Add/Edit **None**, staff can view checklists but cannot add items or change completion. Project sync keeps running while you fix the write permissions.
</Note>

## Part 2: MSPortal Setup Wizard

MSPortal.ai provides a guided setup wizard that walks you through connecting and configuring your ConnectWise Manage integration in 5 easy steps.

### Starting the Wizard

<Steps>
  <Step title="Navigate to Integrations">
    In MSPortal.ai, go to **Settings** > **Integrations**.
  </Step>

  <Step title="Start Setup">
    Find **ConnectWise Manage** and click **Connect** (or **Configure** if previously connected) to launch the setup wizard.
  </Step>
</Steps>

---

### Step 1: Connect

Enter your ConnectWise API credentials to establish the connection.

<Steps>
  <Step title="Enter API Credentials">
    Fill in the following fields:

    | Field | Description | Example |
    |-------|-------------|---------|
    | **API URL** | Your ConnectWise API URL | `na.myconnectwise.net` or `eu.myconnectwise.net` |
    | **Company ID** | Your company identifier (shown on login screen) | `YourCompanyID` |
    | **Public Key** | API public key from API member | `abc123...` |
    | **Private Key** | API private key from API member | `xyz789...` |

    <Note>
      **API URL Examples:**
      - Cloud-hosted: `na.myconnectwise.net`, `aus.myconnectwise.net`, `eu.myconnectwise.net`
      - On-premise: `cw.yourcompany.com` (without https://)
    </Note>
  </Step>

  <Step title="Test Connection">
    Click **Test Connection** to verify your credentials. You'll see a green "Connected" status when successful.

    For a new connection, a successful test also creates and saves the integration. There is no separate create button.

    If the connection fails:
    - Verify your API URL is correct (no https:// prefix)
    - Check that your Company ID matches exactly
    - Confirm the API keys are copied correctly
    - Ensure the API member has the correct security role assigned
  </Step>

  <Step title="Proceed">
    Once connected, click **Next** to continue to the permission check.
  </Step>
</Steps>

---

### Step 2: Permissions

MSPortal checks which parts of ConnectWise your API member is allowed to read, and shows the result for each area of data.

<Frame caption="The setup wizard steps, with Permissions selected.">
  <img src="/images/product/connectwise-setup-steps.png" alt="ConnectWise setup steps with Permissions selected" width="1852" height="226" />
</Frame>

<Steps>
  <Step title="Review the results">
    The check runs automatically when you reach this step. Each area of data is listed as granted, not permitted or could not verify.

    Areas marked **Required** must be granted before you can continue: Companies, Contacts and staff, Tickets, and Boards and statuses. Without these the integration cannot function.

    Optional areas cover Configurations, Opportunities, Product catalog, Invoices, Agreements, Projects, Project checklist writes, and Time entries.

    Importing project templates from ConnectWise into **Settings > Projects > Templates** also needs **Project > Project Templates** with **Inquire Level: All**. If the import dialog reports that ConnectWise refused the request, add that permission to the MSPortal security role and try again.
  </Step>

  <Step title="Grant anything missing">
    Any area that is not permitted shows the exact ConnectWise security role setting to change, for example **Procurement -> Product Catalog (Inquire Level: All)**.

    Update the MSPortal security role in **System > Security Roles**, then come back and click **Re-check**.

    <Note>
      **Could not verify** usually means ConnectWise was slow or unavailable, not that a permission is missing. Click **Re-check** before you change the role.
    </Note>
  </Step>

  <Step title="Continue">
    You can continue with optional areas ungranted. Those syncs stay switched off and their toggles are locked on the next step until you grant the permission and re-check. **Project checklist writes** never turns off project sync.
  </Step>
</Steps>

<Tip>
  If a permission is removed later, MSPortal switches off the affected sync and notifies your integration admins rather than retrying against an endpoint it can no longer read.
</Tip>

---

### Step 3: Sync

Configure what data to sync from ConnectWise and set up company filters.

<Steps>
  <Step title="Configure Data Sync Options">
    Enable or disable the following sync options:

    | Option | Description |
    |--------|-------------|
    | **Sync Users** | Sync member data from ConnectWise |
    | **Sync Companies** | Sync company data from ConnectWise |
    | **Enable Ticket Sync** | Sync service tickets from ConnectWise |
    | **Enable Opportunity Sync** | Sync opportunities from ConnectWise |
    | **Enable Project Sync** | Sync projects from ConnectWise |
    | **Enable Invoice Sync** | Sync invoices from ConnectWise |
    | **Sync product catalog** | Import the product and service catalog for quoting and budgets |
    | **Enable change management** | Import ConnectWise changes into the change calendar |
    | **Warranty writeback** | Write warranty data back to ConnectWise configurations when MSPortal resolves a device's warranty |
  </Step>

  <Note>
    A toggle appears locked when the permission check found that your API member cannot read that data. Grant the permission named beside it in ConnectWise, then re-run the check on the Permissions step to unlock it.
  </Note>

  <Step title="Configure Contact Auto-Import">
    If you want contacts to be automatically imported when companies are added:

    1. Turn on **Enable Auto-Import** to automatically create user accounts for active contacts
    2. Select a **Default Role for Imported Contacts** (e.g., Viewer)
    3. Optionally, map specific ConnectWise contact types to other portal roles. Unmapped types use the default role.

    <Tip>
      We recommend choosing a role with minimal permissions if you plan to import all contacts.
    </Tip>
  </Step>

  <Step title="Configure Company Auto-Import">
    Under **Auto-Import Company Types**, select the company types to create in the portal automatically during sync. MSPortal asks you to confirm before it imports a new batch, because companies are a billed item.
  </Step>

  <Step title="Configure Company Filters">
    ConnectWise has additional filtering options under **Company & Data Sync Filters**:

    | Setting | Description |
    |---------|-------------|
    | **Skip Inactive Companies** | Only sync active companies (recommended) |
    | **Auto Import Locations** | Import synced sites as locations during each sync |
    | **Exclude Company Types** | Select company types to exclude from sync |
    | **Exclude Company Statuses** | Select company statuses to exclude from sync |
    | **Exclude Opportunity Types** | Select opportunity types to exclude from sync |
    | **Exclude Project Types** | Select project types to exclude from sync |
  </Step>

  <Step title="Configure Ticket Sync Scope">
    Define which tickets to sync:

    | Setting | Description |
    |---------|-------------|
    | **Boards to Sync** | Select which ConnectWise service boards' tickets to sync |
    | **Exclude Statuses** | Select ticket statuses to exclude from sync |

    <Info>
      When you proceed to the next step, data sync will begin in the background. This may take a few minutes depending on the amount of data in your ConnectWise instance.

      Syncs are automatically deduplicated - if you navigate back and forth between steps, the same sync will not run multiple times within a 2-minute window.
    </Info>
  </Step>

  <Step title="Proceed">
    Click **Next** to continue to ticket and opportunity configuration.
  </Step>
</Steps>

---

### Step 4: Configure

Set up ticket defaults, status mapping and opportunity defaults. These settings save automatically as you edit them. Wait for the saved indicator before you leave the step.

#### Ticket Settings

<Steps>
  <Step title="Review Ticket Defaults">
    **Ticket Defaults** sets the board and other PSA values used for new tickets created in the portal. These are the same defaults as **Settings** > **Tickets**, and editing them requires the Ticket Settings permission.
  </Step>

  <Step title="Configure Resolution Status Stepper">
    The Resolution Status Stepper provides a visual indicator of ticket progress. Click each stage, then map your ConnectWise statuses to it. Statuses are listed with their board name.

    | Stage | Description |
    |-------|-------------|
    | **New** | Tickets that are newly created or not yet triaged |
    | **Triaged** | Tickets that have been reviewed and prioritized |
    | **Working** | Tickets actively being worked on |
    | **Waiting** | Tickets waiting for customer response or approval |
    | **Resolved** | Tickets that are completed or closed |

    <Tip>
      You can map multiple ConnectWise statuses to each stage. The stepper will show the appropriate stage based on the ticket's current status. MSPortal warns you if a stage is still empty when you click **Next**.
    </Tip>
  </Step>

  <Step title="Sync Actions">
    Use these buttons to manage ticket sync:

    | Action | Description |
    |--------|-------------|
    | **Quick Sync** | Trigger an immediate sync of ticket data |
    | **Clear & Resync** | Delete this integration's synced tickets in MSPortal and perform a fresh sync (useful after major configuration changes). Tickets in ConnectWise are not affected. |

    See [Clear and Resync Integrations](/user-guides/integrations/clear-and-resync-integrations) before you use **Clear & Resync**.
  </Step>
</Steps>

#### Opportunity Settings

<Steps>
  <Step title="Configure Opportunity Defaults">
    Set default values for opportunities created from MSPortal:

    | Setting | Description |
    |---------|-------------|
    | **Default Stage** | The starting stage for new opportunities |
    | **Default Type** | The default opportunity type |
    | **Fallback Sales Rep** | Sales rep assigned when the user doesn't have a linked ConnectWise member |

    <Note>
      Opportunity sync can be enabled or disabled in the Sync step. These settings only apply when opportunity sync is enabled.
    </Note>
  </Step>

  <Step title="Configure Planner Auto-Import (Optional)">
    Turn on **Auto-import opportunities into the Planner** to create a planner item for each new ConnectWise opportunity. Use **Minimum opportunity value** and **Opportunity types to auto-import** to limit which ones come through. See [Importing PSA Opportunities](/user-guides/planner/index#importing-psa-opportunities).
  </Step>

  <Step title="Configure Invoice Display Settings">
    If invoice sync is on, use **Hide Invoice Statuses** to hide closed, voided or other statuses from the Invoices page. All invoices still sync.
  </Step>

  <Step title="Proceed">
    Click **Next** to continue to the import step.
  </Step>
</Steps>

---

### Step 5: Import (Optional)

Import users, companies, and locations from ConnectWise. This step is optional - you can skip it and import later from the respective settings pages. The step is organized into **Users**, **Companies**, and **Locations** tabs.

<Tabs>
  <Tab title="Users">
    Import members (your MSP staff) from ConnectWise to create user accounts.

    1. Select users from the list to create accounts for
    2. Choose a role for imported users

    <Note>
      Client contacts are not imported here. They can be managed via Company settings after companies are imported.
    </Note>
  </Tab>

  <Tab title="Companies">
    Import companies from ConnectWise to sync their data.

    1. Select companies to import or link to existing MSPortal companies

    <Tip>
      Companies will sync automatically based on your sync settings and filters. Use this tab if you want to import specific companies immediately.
    </Tip>
  </Tab>

  <Tab title="Locations">
    Import ConnectWise locations and map them to MSPortal locations. Only locations for mapped companies are shown.
  </Tab>
</Tabs>

---

### Complete Setup

Click **Complete Setup** to finish the wizard. MSPortal applies any pending company and user selections, then finishes setup. Imports and syncs keep running in the background.

<Note>
You can return to the setup wizard at any time by clicking **Configure** on the ConnectWise Manage integration. The wizard will resume with your current settings. Use **Save & Exit** to save your progress and leave the wizard part way through.
</Note>

## Managing Your Integration

After setup, you can manage your integration from **Settings** > **Integrations**:

- **Configure**: Re-open the setup wizard to modify settings
- **Resync**: Trigger a manual sync of data
- **Sync PSA Data**: Refresh configuration data (priorities, boards, statuses, types) from ConnectWise
- **Import Configurations**: Import device configurations from ConnectWise. The configurations import page lets you map ConnectWise configuration types to MSPortal device types, enable auto-sync, and ignore categories you don't need. See [Import Devices](/user-guides/integrations/import-devices) for the full guide.

To remove the integration, open the wizard and click **Delete Integration**. This deletes the integration and its settings in MSPortal. Delete the API keys in ConnectWise separately.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Connection test fails | Verify API URL format (no https://), Company ID, and API keys are correct |
| Missing companies after sync | Check if company types or statuses are excluded in sync settings |
| Permission errors | Verify the API member has the MSPortal security role assigned |
| Sync not starting | Ensure the integration shows "Connected" status before syncing |
| Tickets from wrong boards | Verify the correct boards are selected in Ticket Sync Scope |
| Contacts not importing | Verify **Enable Auto-Import** is on and a default role is selected in the Sync step |
| New boards or statuses are missing | Run [Sync PSA Data](/user-guides/integrations/connectwise-resync-psa-settings) |
| Changing a project ticket status fails with a security error | Check **Project Tickets** > **Edit Level** on the API member's role. **Project Ticket Tasks** Edit is a different permission. |
| Only closing a project or ticket fails | Check **Close Projects** or **Close Project Tickets** Edit access and ConnectWise's required closure fields |
| Creating a project or applying a template fails | Check Add access to **Project Headers**, **Project Phase** and **Project Tickets**, plus lookup access. Check records already created before retrying. |
| Checklist deletion is unavailable | Check **Project Ticket Tasks** > **Delete Level: All** and whether MSPortal can verify the API member's role |
| Adding a checklist item fails with a security error | Check **Project Ticket Tasks** > **Add Level** on the API member's role |
| Checklist completion changes fail | Check **Project Ticket Tasks** > **Edit Level** on the same role |
| Checklist permissions could not be verified | Review the API member's role in ConnectWise. Restricted access to security settings, **My** levels or a temporary API failure can block the check. |
