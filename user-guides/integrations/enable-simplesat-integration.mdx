Connect Simplesat to bring customer company names, surveys, questions and satisfaction responses into MSPortal. Setup is for MSP staff with integration management permission. The integration is beta; its availability and reporting visibility depend on your tenant and permissions.

## Connect and configure sync

<Steps>
  <Step title="Prepare and test an API key">
    Create a key with access to the required data in Simplesat's API-key settings. See [Simplesat's API documentation](https://developer.simplesat.io/api). In MSPortal, open **Settings > Integrations**, select Simplesat and paste the **API Key** on **Connect**. Click **Test Connection** and review the returned customer, survey and response counts.

    <Frame caption="MSP setup example; no credentials entered.">
      <img src="/images/product/simplesat-api-key-field.png" alt="Simplesat connection card with blank API Key field and separate test and creation buttons." width="1344" height="768" />
    </Frame>
  </Step>
  <Step title="Save the connection">
    Click **Create Integration** for a new connection. Initial company discovery runs in the background. For an existing connection, replace the key, retest, then click **Save connection**. Retain the masked value to keep the existing key; an empty field is not the retention control.
  </Step>
  <Step title="Choose response sync">
    On **Configure sync**, **Companies** is required for mapping. Choose whether to enable **Surveys and responses**, then click **Save sync settings**. The switch is a draft until that save. Saving requests the configured background syncs; it is not proof that responses have arrived.
  </Step>
  <Step title="Map companies">
    On **Map companies**, review **Quick Match** proposals or choose an MSPortal company manually. Save pending links with **Import Selected** or **Next**. Quick Match can consider more companies than the current filtered page, so review its own selection carefully.

    Creating a company saves the company immediately and stages its link. Removing an existing link saves immediately. Saved mappings also attach existing synchronized responses to the chosen company; leaving the mapping step can request response synchronization.
  </Step>
  <Step title="Review coverage">
    Open **Review** and check **Companies mapped**, **Surveys**, **Responses**, **CSAT responses**, **NPS responses**, **Unprojected responses** and the last company/response sync times. Read **Latest sync error** when present. Use **Open CSAT dashboard** to inspect reporting and **CSAT display settings** to review visibility.
  </Step>
</Steps>

## Interpret the result

Response totals, scoreable CSAT/NPS responses and company mapping coverage answer different questions. A connection test is a sample of API access, not a completed import. **Unprojected responses** means records have not been converted into reporting scores; check the rating question, survey data and sync outcome before assuming a zero or favorable score.

Disabling **Surveys and responses** and saving stops subsequent configured response sync work. It is not a promise to delete already imported feedback. Company discovery remains enabled.

The mapping step's sync control requests company discovery. Use the connection's integration-list sync action for the configured datasets when needed; check **Review** afterward. There is no universal **Sync now** button on every wizard step.

## Manage or troubleshoot the connection

Reopening an existing connection can resume at **Map companies**. Select **Connect** to test or change credentials and **Configure sync** to change the response setting. The saved connection indicator is not a fresh API test.

| Symptom | What to check |
| --- | --- |
| No companies appear | Allow discovery to finish; check the API key, sync error and company-discovery control. |
| Responses exist but a company has no score | Verify saved mappings and whether those responses can be scored. |
| Response sync is disabled | Enable **Surveys and responses** and click **Save sync settings** if you want those datasets. |
| Counts do not match the provider immediately | Check successful sync times, mapping and projection coverage; background imports are not instantaneous. |
| Controls are unavailable | Ask an MSP administrator to check integration management permission. |

**Delete** requires confirmation and removes the MSPortal connection, synchronized Simplesat data and mappings. It does not delete the original surveys or responses in Simplesat.

## Frequently asked questions

<Accordion title="Which button saves a new Simplesat connection?">

After a successful test, click **Create Integration**. **Save connection** is the existing-connection action.

</Accordion>

<Accordion title="Does the Simplesat response switch autosave?">

No. Click **Save sync settings** after changing **Surveys and responses**.

</Accordion>

<Accordion title="Can I disable Simplesat company discovery?">

Companies remains enabled because mapping depends on discovery. Response sync is optional.

</Accordion>

<Accordion title="Does disabling Simplesat response sync erase existing feedback?">

Do not assume deletion. The setting controls future configured response synchronization.

</Accordion>

<Accordion title="Can Simplesat mapping fix existing response attribution?">

Saved mappings attach existing synchronized responses to the selected company. Check actual reporting afterward.

</Accordion>

<Accordion title="Does the Simplesat mapping sync control fetch every dataset?">

It requests company discovery. Other configured response syncs have separate triggers; inspect Review for both timestamps.

</Accordion>

<Accordion title="What does Unprojected responses mean?">

Those responses have not been converted into reporting scores. Review rating/survey data and sync errors; do not treat them as favorable or zero scores.

</Accordion>

<Accordion title="Does a healthy Simplesat setup grant Company access to all feedback?">

No. Company scope, reporting permissions and CSAT display settings still apply.

</Accordion>
