Connect Hudu to synchronize company documentation, assets and procedures. Password sharing, Magic Dash and warranty writeback are separate choices. This setup is for **MSP staff with integration management permission**; publishing content to Company users also requires the appropriate Documentation settings access.

## Before you start

MSPortal permits one active documentation platform: **Hudu or IT Glue**. Review an existing connection before replacing it; deleting a working connection removes its synchronized data and credentials.

Have a publicly reachable HTTPS Hudu instance URL and an API key scoped to the companies and resources you need. In Hudu, an admin can create a key under **Admin > API Keys**. Password access and company scope are key-level choices. See [Hudu REST API setup](https://support.hudu.com/hc/en-us/articles/11422780787735-REST-API). A Magic Dash-only key is not sufficient for the full documentation integration.

## Connect and map

<Steps>
  <Step title="Open Hudu setup">
    Open **Settings > Integrations** and connect Hudu. Use **Configure** on a saved Hudu connection when maintaining it.
  </Step>
  <Step title="Test the new connection">
    On **Connect**, enter **Hudu Base URL**, such as `https://company.hudu.com`, without `/api/v1`. Enter **API Key** and select **Test Connection**. Review the result before continuing.
  </Step>
  <Step title="Create the connection">
    Select **Create Integration**, wait for success, then **Next**. Testing alone does not create it. Company discovery runs in the background.
  </Step>
  <Step title="Map companies">
    On **Map Companies**, review **Quick Match** proposals or select the intended MSPortal company manually. Save pending links with **Import Selected** or **Next**. Creating a missing MSPortal company saves it immediately, then stages its link. Removing an existing link saves immediately.
  </Step>
</Steps>

## Choose Documentation

Use **Knowledge Base Articles**, **Procedures** and the **Asset Layouts** switches to choose what synchronizes. Each change saves immediately. **Enable All** and **Disable All** affect all layouts for this connection, including layouts hidden by the search. Search narrows the list you see, not the scope of those bulk controls.

**Next** from the mapping and configuration steps can request background content synchronization. A successful toggle or wizard completion does not prove that articles have arrived. Inspect the synchronized content and its freshness afterward.

The **Warranty Writeback** card has a separate draft and **Save warranty settings** button. Its switch does not follow the immediate-save behavior of the content switches. See [warranty writeback](/user-guides/integrations/documentation-warranty-writeback) before enabling it.

## Configure Passwords

On **Passwords**, **Enable Password Sharing** saves immediately. It enables the integration's sharing feature and password-metadata synchronization. It does not grant every Company user access to every password.

Review **Settings > Documentation > Passwords** for folder and role visibility, and check that the Hudu key permits password access. Password values are requested from the provider when an authorized reveal is used; a synchronized password entry does not prove that reveal will succeed. Use the [password reader](/user-guides/documentation/shared-passwords) for the user workflow.

## Decide whether to enable Magic Dash

**Enable Magic Dash** saves immediately and requests a background push of available company compliance information to Hudu. It can start before **Complete Setup**. This changes Hudu; it is an optional outbound feature, separate from importing documentation.

Review the mapped companies and inspect the actual Hudu result before relying on it. Do not assume every security, patching or training metric is included simply because the setup card lists examples. Turning the feature off stops future enabled pushes; it does not serve as an undo for content already written to Hudu.

## Share content and maintain credentials

After synchronization, use **Settings > Documentation** to set the intended content and Company-role visibility. Connecting Hudu and enabling a layout do not by themselves complete client sharing. Some Hudu article-sharing actions also enable public sharing in Hudu; read the confirmation before proceeding.

For key rotation, reopen **Connect**, enter the replacement and use **Update API Key**. The existing Base URL is locked. An update-success message confirms storage; run **Retest Connection** afterward to verify the saved key against Hudu. A retest on its own does not store a replacement.

**Skip**, **Back** and **Complete Setup** are navigation controls, not an undo for settings already saved. The footer **Delete** confirmation disconnects the integration; it is not a way to revoke one client's content access.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Another documentation platform is active | Review the existing Hudu or IT Glue connection before planning a replacement. |
| Connection fails | Public HTTPS base URL without `/api/v1`, valid API key, and provider network restrictions. |
| No layouts or companies | Key scope, company discovery and the correct connection. |
| Content imported but Company users cannot see it | Documentation permissions, company mapping, and saved visibility rules. |
| Password name appears but reveal fails | Provider password access and availability, plus portal sharing and role access. |
| Magic Dash has no new result | Saved enablement, mapping, available compliance data and background sync outcome. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can Hudu and IT Glue both be active documentation providers?">
    MSPortal supports one active documentation platform. Review the existing connection before replacing it; deleting it removes synchronized data and credentials.
  </Accordion>
  <Accordion title="Does Test Connection save a new Hudu integration?">
    No. Test it, then select **Create Integration** and wait for success.
  </Accordion>
  <Accordion title="Do Hudu content and layout switches save immediately?">
    Yes. Each change saves immediately. **Enable All** and **Disable All** apply to all layouts for the connection, including search-hidden layouts.
  </Accordion>
  <Accordion title="Does Hudu password sharing grant access to every password?">
    No. Check provider key password access, portal permissions, company mapping and folder/role visibility in Documentation settings.
  </Accordion>
  <Accordion title="Does turning on Magic Dash wait until Complete Setup to write to Hudu?">
    No. The switch saves immediately and requests the background push. Review the companies and expected compliance content before enabling it.
  </Accordion>
  <Accordion title="Does Update API Key prove the new Hudu key works?">
    It confirms the credential update. Use **Retest Connection** afterward to verify the saved key against Hudu.
  </Accordion>
  <Accordion title="Does Skip undo changes to Hudu setup?">
    No. Content, sharing and Magic Dash switches already saved remain saved. Warranty mappings have their own explicit save.
  </Accordion>
  <Accordion title="Does enabling a Hudu asset layout publish it to Company users?">
    Sync selection and client visibility are separate. Configure the intended company and role access in Documentation settings.
  </Accordion>
</AccordionGroup>
