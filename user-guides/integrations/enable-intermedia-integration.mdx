Provide Partner API access for the MSPortal team to develop the Intermedia integration, which will map Intermedia customers to companies and show their services, seats and usage. This is a **credential intake**: the credentials are stored securely but are not tested yet, and nothing syncs until the integration ships.

Open **Settings > Integrations**, find **Intermedia** in the directory, and open its setup. You need an MSP staff account with permission to manage integrations, and the provider must be enabled for your portal. Company users should ask their MSP to connect the service.

<Note>
Intermedia is currently a **Pilot** integration available to selected tenants. If you don't see Intermedia in **Settings > Integrations**, contact support@msportal.ai. The pilot stores your Partner API credentials securely and notifies the MSPortal integration team. It does not sync customer, service or usage data yet; data sync features build on this access.
</Note>

## Before you start

1. In the Intermedia Partner Portal, open **Integrations > Public API** and select **Get Access to Partner API**. Intermedia confirms when access is on.
2. Select **Create a New API Client** with **Enable Client** checked.
3. Make sure your account contact has the **Public API** and **Billing Support** roles.
4. Copy your **Partner ID** (shown at the top of the side menu), the **Client ID** and the **Client Secret**.

## Submit your credentials

1. Open the Intermedia setup form.
2. Enter **Partner ID**, **Client ID** and **Client Secret**.
3. Select **Secure credentials**. MSPortal stores the Client ID and Client Secret only in Vault, and a successful first submission notifies the MSPortal integration team. They will contact you if more information is needed.

## Replace or remove access

Open the existing intake to replace credentials. Stored secrets stay masked; enter the replacements, then select **Update credentials**. A successful replacement notifies the integration team; saving unchanged values does not resubmit them.

To remove access, disconnect Intermedia and confirm in the **Remove Intermedia credentials?** dialog. This removes the intake record and its stored Vault credentials and cannot be undone. It does not revoke access at Intermedia; disable or delete the API client in the Partner Portal when it is no longer needed.

Users without integration management permission see the intake read-only.

## Troubleshooting

- **No test step:** expected. Intermedia publishes its Partner API reference only inside the Partner Portal, so MSPortal stores these credentials without testing them until the integration is built.
- **Cannot edit:** ask an MSP administrator for integration management access.
- **Missing data after submission:** data sync is not part of this intake yet.
