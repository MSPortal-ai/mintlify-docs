The import process is consistent across all supported integrations, allowing you to bring in team members individually or in bulk.

## Supported Integrations

MSPortal.ai supports importing users from the following integrations:

| Integration | User Type |
|-------------|-----------|
| ConnectWise Manage | Members (Users) |
| Halo PSA | Agents |
| Autotask PSA | Resources |
| Syncro | Technicians |
| Microsoft 365 | Users |

<Note>
The import process is the same regardless of which integration you use. The screenshots in this guide show ConnectWise Manage, but the steps apply to all integrations.
</Note>

Internal MSP staff and client contacts are imported in different places:

| People | Where to import |
|--------|-----------------|
| Internal MSP staff | **Settings** → **Users & Roles** → **Users** tab → **Import**, then the intended PSA. Provider labels include members, Halo agents, Autotask resources or Syncro technicians. |
| Client contacts (Company users) | **Settings** → **Users & Roles** → **Company Users** tab → **Import**, or **Import or match users** on a PSA connection page in **Settings** → **Integrations**. PSA and Microsoft 365 sources depend on active connections and company mappings. |

The steps below cover internal staff. Company users follow the same dialog; see [Import Company Users](#import-company-users). For the connection-page task, see [Import or match PSA contacts in the connection page](#import-or-match-psa-contacts-in-the-connection-page).

## Prerequisites

- At least one integration must be configured and active
- User roles must be created in MSPortal.ai
- You must have the **Manage Users** permission

    On the **Users** tab, click the **Import** button and select your integration from the dropdown menu (e.g., **Import from ConnectWise Manage**, **Import from Halo PSA**, etc.).

    <Frame caption="Choose a PSA from the Import menu on the Users tab.">
      <img src="/images/product/staff-import-provider-menu.png" alt="Import menu on the Users tab listing the available PSA integrations" width="480" height="276" />

  <Step title="Review Available Users">
    The import dialog displays all users from your integration in a table with the following columns:
    - **Name** - The user's name in the source system
    - **Email** - Email address (editable if missing)
    - **Job Title** - Job title (if available)
    - **Linked To** - The MSPortal.ai user this record is linked to, or a combobox to link one
    - **Status** - Whether the user is imported, linked, or pending

  <Step title="Select Users to Import">
    Select users to import by:
    - Clicking individual checkboxes to select users one by one
    - Using the header checkbox to select all unlinked users
    - Using the search box to filter users by name or email

    <Tip>
    Click the **Unlinked** stat tile above the table to filter the list to users who haven't been imported yet.
    </Tip>

    ![](https://ajeuwbhvhr.cloudimg.io/https://colony-recorder.s3.amazonaws.com/files/2025-09-04/8a0cc949-5715-4de9-a3eb-a275c9d7c3e1/ascreenshot.jpeg?tl_px=0,217&br_px=1719,1178&force_format=jpeg&q=100&width=1120.0&wat=1&wat_opacity=0.7&wat_gravity=northwest&wat_url=https://colony-recorder.s3.us-west-1.amazonaws.com/images/watermarks/FB923C_standard.png&wat_pad=245,276)
  </Step>

  <Step title="Link to Existing Users (Optional)">
    For users who already exist in MSPortal.ai (such as your admin account):

    1. Find the user in the list
    2. Click the **Link to user...** combobox in the "Linked To" column
    3. Select the matching MSPortal.ai user
    4. This links the integration record to the existing account instead of creating a duplicate

    <Tip>
    Use the **Quick Match** button to automatically propose links between integration users and existing MSPortal.ai users based on name and email similarity, then review and apply the proposed matches.
    </Tip>

    Links you choose here stay pending until you click **Import Selected**. Removing a link that is already saved takes effect immediately.

    ![](https://ajeuwbhvhr.cloudimg.io/https://colony-recorder.s3.amazonaws.com/files/2025-09-04/1416d54b-dbc1-429f-a061-8dac5e0e0802/ascreenshot.jpeg?tl_px=0,138&br_px=1719,1099&force_format=jpeg&q=100&width=1120.0&wat=1&wat_opacity=0.7&wat_gravity=northwest&wat_url=https://colony-recorder.s3.us-west-1.amazonaws.com/images/watermarks/FB923C_standard.png&wat_pad=246,277)
  </Step>

  <Step title="Select a Role">
    Choose the MSPortal.ai role to assign to all imported users using the **Role** dropdown above the table.

    ![](https://ajeuwbhvhr.cloudimg.io/https://colony-recorder.s3.amazonaws.com/files/2025-09-04/f72fb09a-e6bf-42b3-a095-75ece7bd0d1c/ascreenshot.jpeg?tl_px=260,243&br_px=1980,1205&force_format=jpeg&q=100&width=1120.0&wat=1&wat_opacity=0.7&wat_gravity=northwest&wat_url=https://colony-recorder.s3.us-west-1.amazonaws.com/images/watermarks/FB923C_standard.png&wat_pad=729,285)
  </Step>

  <Step title="Add Missing Email Addresses">
    <Warning>
    All users must have email addresses to be imported. Users without email addresses cannot be selected.
    </Warning>

    If a user lacks an email address:

    1. Find the user in the list (they'll have an empty email input field)
    2. Enter their email address in the **Email** field
    3. The email will be saved with their MSPortal.ai account. It does not change the email in your PSA.

    <Tip>
    Check **Hide missing email** to hide users who have no email address.
    </Tip>

    ![](https://ajeuwbhvhr.cloudimg.io/https://colony-recorder.s3.amazonaws.com/files/2025-09-04/af58d92d-571c-4150-aff6-ac1cb02512b8/ascreenshot.jpeg?tl_px=0,154&br_px=1719,1115&force_format=jpeg&q=100&width=1120.0&wat=1&wat_opacity=0.7&wat_gravity=northwest&wat_url=https://colony-recorder.s3.us-west-1.amazonaws.com/images/watermarks/FB923C_standard.png&wat_pad=477,277)
  </Step>

  <Step title="Complete the Import">
    1. Review the number of selected users and pending links shown on the **Import Selected** button
    2. Click **Import Selected**
    3. Wait for the confirmation message. It reports how many users were imported, linked, skipped, or failed.
    4. Imported users will appear in your Users list
  </Step>
</Steps>

## Import Company Users

Client contacts are imported as Company users, with a Company role.

<Frame caption="Company-user imports keep pagination visible when a search has no matches.">
  <img src="/images/product/import-company-users-mobile-preview.png" alt="Phone company-user import with an active filter and pagination showing zero users" width="390" height="844" />
</Frame>

1. Import and map the company first. See [Import Companies](./import-companies).
2. Go to **Settings** → **Users & Roles** → **Company Users**.
3. Click **Import** and choose your PSA or Microsoft 365.
4. Follow the same steps as above, choosing a Company role in the **Role** dropdown.

If contact-type role mappings or company default roles are configured for the integration, they decide the role for synced users. Explicit contact-type mappings can update roles on existing synced users.

For linked Company users, Microsoft 365 account status takes priority over PSA contact status. An enabled Microsoft 365 account can restore access after a recorded automatic disable; an explicit administrator disable or an access rule still prevents sign-in. Synchronization preserves established identity links when a contact email changes. Multiple existing login accounts are left for staff to review.

## Import or match PSA contacts in the connection page

Halo PSA, ConnectWise Manage, Autotask and Syncro offer **Import or match users** on their connection pages, and in Launch Center when it is embedded there. This imports Company users, not internal MSP staff.

<Tabs>
  <Tab title="Desktop">
    <Frame caption="Import or match contacts directly in the Autotask connection page.">
      <img src="/images/product/integration-users-import-preview-desktop.png" alt="Autotask contact import workspace with a visible row Import action and current-page and all-pages selection controls" width="1280" height="853" />
    </Frame>
  </Tab>
  <Tab title="Phone">
    <Frame caption="The same contact import and selection controls on a phone.">
      <img src="/images/product/integration-users-import-preview-mobile.png" alt="Autotask contact import on a phone with page selection controls, a row Import action and Import selected in the footer" width="780" height="1688" />
    </Frame>
  </Tab>
</Tabs>

1. Import or match at least one company, then open **Import or match users** in the intended PSA connection. Only contacts belonging to connected companies are available. You can return to import more users without importing or matching every company or contact.
2. The workspace opens on **Import**, including contacts with suggested matches. Use **Suggested** to review proposed links, or **Matched** and **Ignored** to revisit those records. Search and filter the contacts. Select **Import** beside one contact, or tick multiple contacts and choose **Import selected**. The button includes the selected count when contacts are selected.
3. Use the header checkbox to select the current page, click it again to select all pages matching the current filters, and click again to clear the selection. Use row checkboxes for individual contacts. **Select all with email** replaces the selection with contacts that have an email address across all pages matching the current filters, leaving out contacts with missing emails. Review the selection, then choose **Import selected**. Wait for the full selection to load and review its count before continuing. Large selections are processed in batches, so you do not need to import each page separately.
4. In the review panel, check the ready-to-import and skipped counts. Contacts without an email address are skipped. You can add an address for an individual contact to include it; correct invalid addresses or clear them to skip those contacts, and resolve duplicate addresses. The review list has pages for large selections. Email edits are submitted with the portal import; they do not change the upstream PSA contact's email.
5. Choose the intended Company role in **Role**. Review its permissions, then confirm with the **Import** button showing the user count and role.
6. Follow the processed/imported progress, then read the imported or matched and skipped results. Verify the actual users, company assignments and roles. A partial failure can leave some users imported; inspect the remaining contacts before retrying.

You can also choose an existing portal user or accept a reviewed suggestion. Those matching actions save immediately. Review name-only suggestions carefully. Ignoring a contact removes it from the active review list; restore it if it should be considered later.

Opening the review panel does not import users. The waiting count includes both suggested and unmatched contacts. Importing users does not automatically send portal invitations; review access and invitation delivery separately.

## Post-Import Tasks

After importing users:

- **Verify roles**: Confirm imported users have the correct roles and permissions
- **Send invitations**: Importing a user does not send an invitation. Use **Send Invitation Email** from the Users list when the user needs to sign in. Never send passwords manually.
- **Configure preferences**: Set up any user-specific settings
- **Enable 2FA**: Set up two-factor authentication for admin users

## Troubleshooting

Missing records can reflect source permissions, inactive accounts, company mapping, filters or synchronization. In the connection-page import, missing email skips that contact; an invalid nonblank email needs correction or clearing before confirmation. Other import screens may require missing emails to be supplied. If an account already exists, verify the identity and use linking where appropriate. If a role changes again after sync, review the provider's role rules instead of repeatedly overriding the same field.

### Common Issues

| Issue | Solution |
|-------|----------|
| **Missing users** | Verify your integration has proper API permissions and the users are active in the source system |
| **Email required error** | All users must have valid email addresses. Add email addresses using the input field in the list |
| **Role not selected** | Select a role from the dropdown before clicking Import |
| **Duplicate user error** | The user may already exist. Use the **Link to user...** combobox to connect accounts |
| **Cannot select user** | The user is either already linked or missing an email address |
| **Some users failed** | Check which users and links now exist before retrying. An import can partly succeed. |

### Integration-Specific Notes

<AccordionGroup>
  <Accordion title="ConnectWise Manage">
    - Only active members are shown in the import list
    - Users are synced by their Member ID
    - Email addresses are pulled from the member's primary email field
  </Accordion>

  <Accordion title="Halo PSA">
    - Only agents (support staff) are available for import
    - Client contacts are managed separately through company users
    - Agent status must be active in Halo PSA
  </Accordion>

  <Accordion title="Autotask PSA">
    - Resources (technicians) are available for import
    - Resource must have an active status in Autotask
    - Email synchronization uses the resource's primary email
  </Accordion>

  <Accordion title="Syncro">
    - Technicians are available for import
    - User must be active in your Syncro account
    - Ensure API permissions include user read access
  </Accordion>

  <Accordion title="Microsoft 365">
    - Available when importing company users
    - Syncs users from your connected M365 tenant
    - Requires active Microsoft 365 integration per company
  </Accordion>
</AccordionGroup>
