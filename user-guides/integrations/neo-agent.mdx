MSPortal and Neo Agent can participate in a shared-PSA workflow. MSPortal delivers a request to the PSA; Neo Agent can process eligible PSA tickets according to its own connection, triggers and workflow configuration. MSPortal has no direct Neo Agent setup card.

This is an **MSP staff** configuration task. Company users submit requests through their portal and do not configure Neo Agent or the PSA connection.

## Before you start

- Configure a supported PSA connection in MSPortal and verify company/requester mappings.
- Configure Neo Agent for that same PSA account and the intended ticket scope. Confirm current provider support in [Neo Agent’s integration documentation](https://docs.neoagent.io/integrations/intro).
- Review **Settings > Tickets** in MSPortal, including delivery method, selected PSA, routing defaults and template/company overrides.
- Review Neo Agent's workflow triggers, conditions and enabled state. Its [triggered workflow documentation](https://docs.neoagent.io/core/triggers-and-schedules/triggered-workflows) describes event-driven execution.

<Note>
No direct connector is required between the products, but both PSA connections and the relevant automation still need configuration. Compatibility does not guarantee that every ticket will trigger or complete an automation.
</Note>

## Check the ticket flow

<Steps>
  <Step title="Submit through the intended workflow">
    Company users should start with the Home AI Assistant and review the request before submitting. Tickets > New Ticket is the manual alternative; your configured template or workflow can also create requests.
  </Step>
  <Step title="Verify delivery to the PSA">
    Confirm the actual ticket exists in the intended PSA with the expected company, requester and routing. MSPortal also supports Email (SMTP) delivery and fallback email, so a portal submission is not proof that a PSA ticket was created directly.
  </Step>
  <Step title="Check automation eligibility in Neo Agent">
    Confirm the ticket meets the watched board/queue, type, status and other trigger conditions. A ticket being present in the PSA is only one prerequisite. Review the Neo Agent execution result separately.
  </Step>
  <Step title="Check returning updates">
    Verify the resulting PSA changes and allow the relevant MSPortal ticket/note synchronization to complete. Supported fields and visibility depend on the provider and portal permissions. A private PSA note does not become client-visible merely because it synchronized.
  </Step>
</Steps>

## Routing and data boundaries

Review the subject, description, company, requester, board/queue, status, priority and available classification fields on the actual PSA ticket. Fields vary by provider and request workflow; do not assume every ticket contains every classification or that generated wording is correct.

Template and company overrides can change routing from the General defaults. If Email (SMTP) is selected, any later email-to-ticket processing is a separate PSA workflow that must be verified.

MSPortal does not report Neo Agent's complete execution state or configure its automation from the integration catalog. Use Neo Agent and PSA logs for that part of the investigation.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| No Neo Agent integration card | Expected: this uses shared PSA data rather than a direct MSPortal connector. |
| Request is missing in the PSA | Delivery method, fallback email, provider errors and the actual submission outcome. |
| Ticket exists but Neo Agent does nothing | Same PSA account, watched board/queue, workflow trigger conditions and enabled state. |
| Automation changed the wrong classification | Actual PSA fields, provider support and template/company routing overrides. |
| Update exists in the PSA but not MSPortal | Ticket/note sync coverage, freshness, errors and role/display-group visibility. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Do I enter a Neo Agent API key in MSPortal?">
    No. There is no direct Neo Agent setup card. Configure each product's connection to the same supported PSA.
  </Accordion>
  <Accordion title="Does every MSPortal request create a PSA ticket?">
    No. Ticket delivery can use PSA Integration or Email (SMTP), and failures can use configured fallback delivery. Verify the actual PSA ticket before investigating automation.
  </Accordion>
  <Accordion title="Does a PSA ticket automatically prove Neo Agent ran?">
    No. The ticket must meet the enabled workflow's conditions. Check Neo Agent's execution result independently.
  </Accordion>
  <Accordion title="Does every ticket have the same type and subtype fields?">
    No. Available classifications and defaults depend on the PSA provider and creation workflow. Inspect the ticket that was actually created.
  </Accordion>
  <Accordion title="Will all Neo Agent updates immediately appear to Company users?">
    No. Returning updates depend on supported PSA synchronization and portal visibility. Private notes and restricted fields remain subject to those rules.
  </Accordion>
  <Accordion title="Where should Company users start a request?">
    Start with the Home AI Assistant and review before submission. Tickets > New Ticket is the manual alternative; the MSP manages delivery and automation setup.
  </Accordion>
</AccordionGroup>
