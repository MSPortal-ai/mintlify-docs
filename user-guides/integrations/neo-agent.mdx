MSPortal and Neo Agent work together through your PSA. MSPortal writes each ticket into the PSA, and Neo Agent picks up eligible tickets from the same PSA and runs its workflows. This guide is for MSP staff. Company users submit requests through their portal and do not set up Neo Agent or the PSA connection.

<Note>
You will not find a Neo Agent card under **Settings > Integrations**. Nothing connects directly between the two products, and you do not enter a Neo Agent API key in MSPortal.
</Note>

## Before you start

- A PSA integration is connected in MSPortal, and companies and requesters are mapped. See [Import Companies](/user-guides/integrations/import-companies).
- Neo Agent is connected to the same PSA account and watches the boards or queues you want. Set this up in Neo Agent.
- You reviewed **Settings > Tickets** in MSPortal: the delivery method, the selected PSA, the routing defaults and any template or company overrides.
- Neo Agent has a workflow whose trigger conditions match the tickets MSPortal creates, and it is enabled.

## How tickets flow

<Steps>
  <Step title="A ticket is created in MSPortal">
    Company users should start with the AI Assistant on **Home** and review the request before they submit. **Tickets > New Ticket** is the manual option. Ticket templates and forms can also create requests.
  </Step>
  <Step title="MSPortal writes the ticket to your PSA">
    With **PSA Integration** as the delivery method, the ticket lands in the PSA with its board or queue, type, status, priority, mapped company and requester. With **Email (SMTP)** delivery, or if the PSA is unavailable and a fallback email is set, the ticket is emailed instead. Email-to-ticket then works as a separate PSA workflow.
  </Step>
  <Step title="Neo Agent picks it up">
    Neo Agent sees the ticket on a board it watches and runs a matching workflow if the ticket meets its trigger conditions.
  </Step>
  <Step title="Updates sync back to MSPortal">
    Notes, status changes and resolutions Neo Agent writes to the PSA sync back through your PSA integration. Private PSA notes stay hidden from clients.
  </Step>
</Steps>

## Verify the flow end to end

<Steps>
  <Step title="Submit a test ticket">
    Create a ticket for a test company through the workflow your clients use.
  </Step>
  <Step title="Find it in the PSA">
    Confirm the ticket exists in the PSA with the right company, requester, board or queue, status and priority.
  </Step>
  <Step title="Check Neo Agent">
    In Neo Agent, confirm the workflow ran. If it did not, compare the ticket with the workflow's board, type, status and other trigger conditions.
  </Step>
  <Step title="Check the update in MSPortal">
    Wait for the next ticket and note sync, then open the ticket in MSPortal and look for Neo Agent's update.
  </Step>
</Steps>

## What each ticket carries

| Field | What MSPortal sends |
| --- | --- |
| **Summary** | A short subject line |
| **Description** | Details captured at creation, including requester context |
| **Board / Queue** | The board you configured, including template or company overrides |
| **Status and priority** | Set from your routing configuration |
| **Company** | The mapped PSA company |
| **Contact** | The requester, matched to a PSA contact |
| **Type and subtype** | Included where the PSA provider supports them |

Template and company overrides can change routing from the defaults on **Settings > Tickets**. Available classification fields vary by PSA provider.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| No Neo Agent card in Integrations | This is expected. There is no direct connector. |
| The ticket is missing in the PSA | Check the delivery method and fallback email on **Settings > Tickets**, and look for provider errors. |
| The ticket exists but Neo Agent does nothing | Check Neo Agent uses the same PSA account, watches that board or queue, and has an enabled workflow whose conditions match. |
| Neo Agent set the wrong classification | Check the fields on the PSA ticket and any template or company routing overrides. |
| A Neo Agent update is missing in MSPortal | Wait for the next sync, then check the ticket and note sync status and who can see that note. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Do I enter a Neo Agent API key in MSPortal?">
    No. Connect each product to the same PSA. There are no credentials to exchange between them.
  </Accordion>
  <Accordion title="Does every MSPortal request create a PSA ticket?">
    No. Delivery can be **PSA Integration** or **Email (SMTP)**, and a fallback email is used when the PSA is down. Check the PSA ticket before you investigate Neo Agent.
  </Accordion>
  <Accordion title="Does a ticket in the PSA mean Neo Agent ran?">
    No. The ticket must meet an enabled workflow's conditions. Check Neo Agent's own execution results.
  </Accordion>
  <Accordion title="Will clients see all of Neo Agent's updates?">
    Only updates that sync back and that their portal permissions allow. Private notes stay hidden.
  </Accordion>
  <Accordion title="Where should company users start a request?">
    With the AI Assistant on **Home**, or **Tickets > New Ticket**. The MSP manages delivery and automation.
  </Accordion>
</AccordionGroup>
