Connect CyberHoot to review customer awareness metrics, user compliance, HootScore and available HootPhish results. This is an **MSP integration management** workflow.

<Note>
  If CyberHoot does not appear in **Settings > Integrations**, contact support@msportal.ai to have it enabled for your account.
</Note>

## Overview

CyberHoot is a security awareness training and phishing simulation platform for MSPs. By integrating CyberHoot with MSPortal.ai, you can:

- View security awareness and compliance metrics for every client in one place
- Track HootScore and per-user training compliance
- Monitor HootPhish challenges and per-participant results
- Include security awareness metrics in client reports

## Prerequisites

- An active CyberHoot partner account
- Your CyberHoot API URL and API key
- MSPortal.ai account with integration management permissions

<Info>
  The CyberHoot API exposes endpoints based on the Power-Ups enabled for your account. MSPortal detects the available features automatically during connection, so you only see data your CyberHoot plan provides.
</Info>

## Part 1: Get Your CyberHoot API Credentials

Before connecting to MSPortal.ai, you need your API URL and API key from CyberHoot.

<Steps>
  <Step title="Log into CyberHoot">
    Sign in to your CyberHoot Partner portal with an administrator account.
  </Step>

  <Step title="Locate Your API Key">
    Open your partner settings and find the API key section. Copy the API key, or generate one if none exists.

    <Warning>
      **Store the API key securely!** Regenerating the key invalidates the previous one, so any other tools using the old key would stop working.
    </Warning>
  </Step>

  <Step title="Note Your API URL">
    Your API URL is based on your CyberHoot deployment and always ends with `/api`, for example:

    ```
    https://autopilot.cyberhoot.com/api
    ```

    The URL must use HTTPS on the standard port.
  </Step>
</Steps>

## Part 2: Connect CyberHoot in MSPortal

The CyberHoot connection page lists its tasks in the **Setup guide**: **Connect**, **Import or match companies** and **Review**. See [Connect and manage integrations](/user-guides/integrations/index) for the tasks every connection shares.

### Connect

<Steps>
  <Step title="Open the connection page">
    In MSPortal.ai, go to **Settings > Integrations**. On the **Directory** tab, find **CyberHoot** and click **Connect**. To continue a saved connection, open it from your active integrations instead.
  </Step>

  <Step title="Enter Credentials">
    Fill in the two fields:

    | Field | Value |
    |-------|-------|
    | **API URL** | Your CyberHoot API URL, e.g. `https://autopilot.cyberhoot.com/api` |
    | **API key** | The API key from your CyberHoot Partner portal |

    <Note>
      Your API key is stored securely using Supabase Vault encryption. It is never exposed in logs or API responses.
    </Note>
  </Step>

  <Step title="Test the connection">
    Click **Test connection** to verify your credentials. Testing does not save anything.

    On success, you'll see a confirmation showing your partner name and how many customers were found, for example "Connection verified for Acme MSP with 25 customers."

    If the connection fails:
    - Verify the API URL uses HTTPS and ends with `/api`
    - Verify the API key was copied without extra spaces
    - Ensure the key has not been regenerated since you copied it
  </Step>

  <Step title="Save and continue">
    Once the connection test passes, click **Save and continue** to save your credentials and create the connection. MSPortal immediately starts discovering your CyberHoot customers in the background.
  </Step>
</Steps>

### Import or match companies

This task opens **Import or match CyberHoot customers**. Match each CyberHoot customer to an MSPortal company. This determines which data syncs to which company. Only data from matched customers is synced to MSPortal.

<Steps>
  <Step title="Wait for customer discovery">
    Customer discovery starts automatically when you connect. If no customers appear yet, wait a moment and check again.

    The list includes each customer's **Domain** where CyberHoot provides one.
  </Step>

  <Step title="Review suggestions">
    Open **Suggested** to review matches based on name similarity, and accept the ones that look correct. A matching domain helps you confirm a match, but it is not proof; check the company name too.
  </Step>

  <Step title="Match the rest">
    For customers that weren't matched, choose the correct MSPortal company in the row. To remove a saved match, use **Remove match**. The removal takes effect immediately.
  </Step>

  <Step title="Import missing companies">
    If a CyberHoot customer doesn't have a corresponding MSPortal company, click **Import company** in its row. The new company is saved and matched immediately; check the resulting link.
  </Step>
</Steps>

Each accepted or chosen match saves straight away and requests a detailed sync of the affected customers. Match at least one customer before expecting customer-level reporting data. Closing setup does not undo saved matches.

### Review and finish setup

Open **Review** and select **Finish setup** once the required tasks are complete. Finishing does not wait for customer discovery, user data or challenge results. Check the actual data after background synchronization finishes.

## Check your data

Open Security Awareness or Reports to review customer scores, compliance and available HootPhish results. Metrics that your CyberHoot plan does not provide display as **Not provided**. That means no value is available. It is not a zero, a perfect score, or proof that there was no phishing activity.

## What Gets Synced

CyberHoot integration syncs the following data types to MSPortal for matched customers:

### Customers

Your CyberHoot customer inventory, including customer name and domain, used for matching and for customer-level metrics such as active user counts and HootScore.

### Users

Per-user records for each matched customer, including training compliance and user ranking data.

### Compliance Snapshots

Daily snapshots of customer-level compliance metrics, including HootScore and active user counts, so you can track security awareness trends over time.

### HootPhish Challenges

Phishing challenge records for each matched customer, including per-participant results linked to synced users where an email match exists.

<Info>
  Available data depends on the Power-Ups enabled in your CyberHoot account. MSPortal detects the available capabilities per customer and syncs what your plan provides.
</Info>

## Synchronization Schedule

After initial setup, data syncs automatically:

| Data Type | Sync Frequency |
|-----------|----------------|
| All mapped customer data | Daily (07:05 UTC) |

In addition to the daily schedule:

- Connecting or updating credentials triggers a customer discovery sync
- Saving customer matches triggers a detailed sync of the newly matched customers

## Managing Your Integration

Open the CyberHoot connection from **Settings > Integrations** to manage it:

| Action | Description |
|--------|-------------|
| **Connect** | Test the saved credentials or update the API URL or API key |
| **Import or match companies** | Update customer matches |
| **Overview** and **Sync activity** | Review connection status and background results |
| **Disconnect…** | Under **More actions**. Review the confirmation: disconnecting removes the integration, synced CyberHoot data, and stored credentials for this connection, and cannot be undone. It does not revoke the API key in CyberHoot. |

### Updating Your API Key

<Steps>
  <Step title="Open Connect">
    Go to **Settings > Integrations**, open the CyberHoot connection and select **Connect**.
  </Step>
  <Step title="Enter New Credentials">
    Update the API URL or API key. Leave the masked key unchanged to keep the stored one. Changing the API URL requires entering the key for that URL again.
  </Step>
  <Step title="Test and Save">
    Click **Test connection** to verify, then click **Save changes**. Testing a new key does not store it; only **Save changes** does.
  </Step>
  <Step title="Review Matches">
    Saving starts a fresh customer discovery. If you switched to a different CyberHoot account, review **Import or match companies** afterward.
  </Step>
</Steps>

## Troubleshooting

| Issue | Solution |
|-------|----------|
| CyberHoot not visible | Contact support@msportal.ai to enable CyberHoot for your account |
| Connection test fails | Verify the API URL ends with `/api`, uses HTTPS, and the API key is current |
| No customers to match | Customer discovery runs after connecting; wait a minute and check again |
| Data not syncing | Ensure customers are matched to companies; only matched customer data syncs |
| Metrics show "Not provided" | The corresponding CyberHoot Power-Up is not enabled for that customer |
| Stale data | Data refreshes daily at 07:05 UTC; re-saving a match triggers a fresh sync for that customer. If data stays stale, check the customer's Power-Ups and match, then contact support rather than re-saving credentials repeatedly |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can every tenant configure CyberHoot?">
    Setup requires MSP integration management permission. Ask your administrator or support if CyberHoot is not listed.
  </Accordion>
  <Accordion title="Does testing CyberHoot save the API key?">
    No. Use **Save and continue** for a new connection or **Save changes** for tested replacements.
  </Accordion>
  <Accordion title="Do CyberHoot suggestions guarantee the right company?">
    No. Review proposed names and any supplied Domain, then accept the intended matches. Each accepted match saves immediately.
  </Accordion>
  <Accordion title="Does Not provided mean a CyberHoot customer has no phishing issues?">
    No. It indicates missing applicable data or capability. Check the customer Power-Ups, match and sync outcome.
  </Accordion>
  <Accordion title="Does Finish setup finish the CyberHoot import?">
    No. Background work can continue. Revisit **Sync activity** and check the actual awareness or reporting view.
  </Accordion>
  <Accordion title="Can Company users manage CyberHoot matches?">
    No. The connection is an MSP integration management task. Company users see only the data and views made available through their portal access.
  </Accordion>
</AccordionGroup>

## Security & Privacy

- **API Key Storage**: Your CyberHoot API key is encrypted using Supabase Vault and never exposed in logs or responses
- **Data Isolation**: All synced data is tenant-isolated and only visible to your organization
- **Read-Only Access**: MSPortal only reads CyberHoot data; it never modifies your CyberHoot configuration
