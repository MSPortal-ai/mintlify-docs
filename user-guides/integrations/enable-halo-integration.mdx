This guide walks you through connecting your Halo PSA instance to MSPortal.ai using our streamlined setup wizard.

MSPortal can also import **HaloPSA native CSAT responses** into the **CSAT Dashboard**, custom dashboard widgets, report blocks and CSV exports. See [Import HaloPSA native CSAT for dashboards and reports](#import-halopsa-native-csat-for-dashboards-and-reports).

## Problems sync and reporting

<Note>
Branch preview: Problems sync and reporting are part of an upcoming update.
</Note>

Halo Problems use the same **read:tickets** API permission as tickets. Keep ticket sync enabled, link the client companies, and ensure the API agent can read the relevant teams, clients and ticket types. MSPortal uses Halo's **ITIL Ticket Type** classification rather than assuming a ticket type is named “Problem”.

The Problems sync includes recent activity and older unresolved records. Once synced, use the **Problems** source in **Reports > New Report > Full Report** or add the **Problems** block in **Builder**. See [Halo Problems in QBRs](/user-guides/reporting#halo-problems-in-qbrs) for period and backlog meanings.

## Prerequisites

- Administrator access to your Halo PSA instance
- Access to MSPortal.ai with integration management permissions
- (Recommended) [Custom MSPortal role and API-only agent](/user-guides/integrations/halo-psa-custom-role-and-user) created in Halo PSA

## Part 1: Configure Halo PSA

Before connecting to MSPortal.ai, you need to create an API application in Halo PSA.

<Steps>
  <Step title="Log in to Halo PSA">
    Navigate to your Halo PSA instance and log in with an administrator account.
  </Step>

  <Step title="Create the MSPortal Role and Agent">
    Create the **MSPortal** role and API-only agent first. Follow [Create Custom Halo PSA Role and API User](/user-guides/integrations/halo-psa-custom-role-and-user), which lists every role permission and the teams the agent needs.
  </Step>

  <Step title="Open Integrations">
    Click **Configuration** in the navigation menu, then select **Integrations** > **API**.
  </Step>

  <Step title="Create API Application">
    1. Click **View Applications**
    2. Create a new application named "MSPortal.ai"
    3. Select **Client ID and Secret (Services)** as the authentication method
    4. Save your **Client ID** and **Client Secret** - you'll need these in the wizard
    5. Select your **MSPortal** API-only agent in **Agent to Log in as**

    <Warning>
      Make sure to save your Client ID and Client Secret immediately. The secret cannot be retrieved after creation.
    </Warning>
  </Step>

  <Step title="Configure Permissions">
    Click **Permissions** and grant the application permissions listed in [Link the Agent to Your API Application](/user-guides/integrations/halo-psa-custom-role-and-user#link-the-agent-to-your-api-application). `read:customers` and `read:tickets` are required. The rest turn on optional features.
  </Step>

  <Step title="Configure CORS Whitelist">
    1. Click **Security**
    2. Add `app.msportal.ai` to the CORS whitelist
    3. Click **Submit** to save
  </Step>
</Steps>

## Project management permissions

Skip this section unless you will create or update Halo projects from MSPortal. Halo checks two things, the **MSPortal.ai** API application and the agent it logs in as. Application access cannot override a restriction on that agent.

<Steps>
  <Step title="Grant project and ticket access on the application">
    In Halo, go to **Configuration** > **Integrations** > **API** > **View Applications**, open **MSPortal.ai** and grant **Project Read**, **Project Modify**, **Ticket Read** and **Ticket Modify**.
  </Step>

  <Step title="Check the agent's permissions">
    Go to **Configuration** > **Teams & Agents**, open the MSPortal agent and its role, and confirm the access below. Halo projects are project records with child tickets and milestones, so project access alone does not cover child tickets, checklists or time.

    | Area | Read access | Create and update access |
    |------|-------------|--------------------------|
    | **Projects** | **Project Read** (`read:projects`) and agent access to the intended projects | **Project Modify** and agent permission to create and edit projects. Used to create a PSA project, update its status or mapped fields, and create or update its milestones. |
    | **Tickets** | **Ticket Read** (`read:tickets`), including child project tickets | **Ticket Modify** and agent permission to create and edit the intended ticket types. Used to create project tickets and edit their details. |
    | **Actions and time** | Read access to actions on the project and its child tickets | Agent access to add the relevant actions and record time. Used to post project ticket notes and time entries. Check action visibility, allowed outcomes and billing options on the agent. |
    | **Checklist (to-do) items** | Read the child ticket and its checklist | Permission to add and update the ticket's to-do items. Used to add checklist items and change completion. |
    | **Customers and agents** | **Customers Read** (`read:customers`) and visibility of the relevant agents | Not needed. Read access fills company, contact and staff choices. |
    | **Ticket configuration and templates** | Read the ticket types, statuses, priorities and project templates you use | Not needed for the source template. Creating work from a portal template uses the project and ticket permissions above. |
  </Step>

  <Step title="Widen the agent's scope">
    Add the agent to every department and team the integration should cover. Allow the clients and ticket types it needs, including the project type and child ticket types. To cover all of them, turn on **Allow All Clients** and **Allow All Ticket Types**. Also check access to internal actions, project templates and the actions used for time entry.
  </Step>

  <Step title="Save and re-check">
    Save the application and agent. In MSPortal, go to **Settings** > **Integrations** > **Halo PSA** > **Configure** > **Permissions** and click **Re-check**.
  </Step>

  <Step title="Test on a project">
    A green **Projects** result only confirms MSPortal can read projects. On a test project, create the project, edit a detail, complete a checklist item and add a note with time. If applying a template partly succeeds, check the records it created before you retry.
  </Step>
</Steps>

<Note>
Project ticket status changes from the Kanban board or ticket details write back to Halo and need **Ticket Modify**. Project ticket owner and priority changes, checklist progress note editing and checklist deletion are not available for Halo in MSPortal. Do not grant blanket Delete or administrator access for these workflows. MSPortal-only projects and templates use MSPortal permissions only.
</Note>

## Part 2: MSPortal Setup Wizard

MSPortal.ai provides a guided setup wizard that walks you through connecting and configuring your Halo PSA integration in 5 easy steps.

### Starting the Wizard

<Steps>
  <Step title="Navigate to Integrations">
    In MSPortal.ai, go to **Settings** > **Integrations**.
  </Step>

  <Step title="Start Setup">
    Find **Halo PSA** and click **Connect** (or **Configure** if previously connected) to launch the setup wizard.
  </Step>
</Steps>

---

### Step 1: Connect

Enter your Halo PSA API credentials to establish the connection.

<Steps>
  <Step title="Enter API Credentials">
    Fill in the following fields:

    | Field | Description |
    |-------|-------------|
    | **Halo URL** | Your Halo PSA instance URL without a trailing slash (e.g., `https://yourhalo.haloservicedesk.com`) |
    | **Client ID** | The Client ID from your Halo API application |
    | **Client Secret** | The Client Secret from your Halo API application |
  </Step>

  <Step title="Test Connection">
    Click **Test Connection** to verify your credentials. You'll see a green "Connected" status when successful.

    For a new connection, a successful test also creates and saves the integration. There is no separate create button.

    <Note>
      If the connection fails, double-check your credentials and ensure the CORS whitelist includes `app.msportal.ai`.
    </Note>
  </Step>

  <Step title="Proceed">
    Once connected, click **Next** to continue to the permission check.
  </Step>
</Steps>

---

### Step 2: Permissions

MSPortal checks what your Halo API application is allowed to read, and shows the result for each area of data.

<Frame caption="The setup wizard steps, with Permissions selected.">
  <img src="/images/product/halo-setup-steps.png" alt="Halo setup steps with Permissions selected" width="1852" height="226" />
</Frame>

<Steps>
  <Step title="Review the results">
    The check runs automatically when you reach this step. Each area of data is listed as granted, not permitted or could not verify.

    Areas marked **Required** must be granted before you can continue: Companies, Contacts and staff, Tickets, and Teams and statuses (statuses, priorities and ticket types). Without these the integration cannot function.

    Optional areas cover Assets, Opportunities, Product catalog, Invoices, Contracts, Projects, Time entries, Change management, and Satisfaction feedback.
  </Step>

  <Step title="Grant anything missing">
    Any area that is not permitted shows the exact Halo permission to grant, for example **read:items** for the product catalog.

    Open your MSPortal application under **Configuration > Integrations > API > Applications**, grant the permission (or the `all` scope), then come back and click **Re-check**. Tickets and statuses also depend on the API agent's team membership.

    <Note>
      Halo often refuses a scope-limited application at the token endpoint rather than per resource. If every area comes back unchecked with an authentication error, widen the application's permissions rather than chasing individual areas.
    </Note>
  </Step>

  <Step title="Continue">
    You can continue with optional areas ungranted. Those syncs stay switched off and their toggles are locked on the next step until you grant the permission and re-check.
  </Step>
</Steps>

<Tip>
  If a permission is removed later, MSPortal switches off the affected sync and notifies your integration admins rather than retrying against an endpoint it can no longer read.
</Tip>

---

### Step 3: Sync

Configure what data to sync from Halo PSA and set up automatic contact import.

<Steps>
  <Step title="Configure Data Sync Options">
    Enable or disable the following sync options:

    | Option | Description |
    |--------|-------------|
    | **Sync Users** | Sync user/contact data from Halo PSA |
    | **Sync Companies** | Sync company/client data from Halo PSA |
    | **Enable Ticket Sync** | Sync tickets from Halo PSA |
    | **Enable Opportunity Sync** | Sync opportunities from Halo PSA |
    | **Enable Project Sync** | Sync projects from Halo PSA. Use **Exclude Project Types** to skip projects of certain Halo ticket types. |
    | **Enable Invoice Sync** | Sync invoices from Halo PSA |
    | **Sync product catalog** | Import the product and service catalog for quoting and budgets |
    | **Enable asset sync** | Sync assets on a recurring schedule. Use **Asset statuses to exclude** to skip statuses. Inactive Halo assets are always excluded, and existing MSPortal devices are not deleted. |
    | **Enable change management** | Import Halo changes into the change calendar |
    | **Import satisfaction ratings** | Import Halo satisfaction feedback. See [Import HaloPSA native CSAT](#import-halopsa-native-csat-for-dashboards-and-reports). |
    | **Warranty writeback** | Write warranty data back to Halo assets when MSPortal resolves a device's warranty. Appears when **Enable asset sync** is on. |
  </Step>

  <Note>
    A toggle appears locked when the permission check found that your API application cannot read that data. Grant the permission named beside it in Halo, then re-run the check on the Permissions step to unlock it.
  </Note>

  <Step title="Configure Contact Auto-Import">
    If you want contacts to be automatically imported when companies are added:

    1. Turn on **Enable Auto-Import** to automatically create user accounts for active contacts
    2. Select a **Default Role for Imported Contacts** (e.g., Viewer)
    3. Optionally, use **Halo Role Mapping** to map Halo roles and the Important Contact flag to other portal roles. When a contact matches more than one mapping, the mapping highest in the list wins.

    <Tip>
      Contacts that match no mapping get the default role. You can change individual user roles later in Settings > Users.
    </Tip>
  </Step>

  <Step title="Configure Company Auto-Import">
    Under **Auto-Import Company Types**, select the Halo client types to create in the portal automatically during sync. MSPortal asks you to confirm before it imports a new batch, because companies are a billed item.
  </Step>

  <Step title="Configure Ticket Sync Scope">
    Define which tickets to sync:

    | Setting | Description |
    |---------|-------------|
    | **Teams to Sync** | Select which Halo teams' tickets to sync (only tickets from selected teams will appear in MSPortal) |
    | **Exclude Statuses** | Select ticket statuses to exclude from sync (e.g., Closed, Cancelled) |

    <Info>
      When you proceed to the next step, data sync will begin in the background. This may take a few minutes depending on the amount of data in your Halo PSA account.

      Syncs are automatically deduplicated - if you navigate back and forth between steps, the same sync will not run multiple times within a 2-minute window.
    </Info>
  </Step>

  <Step title="Proceed">
    Click **Next** to continue to ticket and opportunity configuration.
  </Step>
</Steps>

---

### Step 4: Configure

Set up ticket defaults, status mapping and opportunity defaults. These settings save automatically as you edit them. Wait for the saved indicator before you leave the step.

#### Ticket Settings

<Steps>
  <Step title="Review Ticket Defaults">
    **Ticket Defaults** sets the PSA values used for new tickets created in the portal. These are the same defaults as **Settings** > **Tickets**, and editing them requires the Ticket Settings permission.
  </Step>

  <Step title="Configure Status Settings">
    | Setting | Description |
    |---------|-------------|
    | **Closed Statuses** | Select statuses that indicate a ticket is closed |
    | **Client Comment Status** | Status to set when a client comments on a ticket (e.g., "Updated") |

    Both lists stay empty until you select teams in the Sync step.
  </Step>

  <Step title="Configure Resolution Status Stepper">
    The Resolution Status Stepper provides a visual indicator of ticket progress. Click each stage, then map your Halo statuses to it:

    | Stage | Description |
    |-------|-------------|
    | **New** | Tickets that are newly created or not yet triaged |
    | **Triaged** | Tickets that have been reviewed and prioritized |
    | **Working** | Tickets actively being worked on |
    | **Waiting** | Tickets waiting for customer response or approval |
    | **Resolved** | Tickets that are completed or closed |

    <Tip>
      You can map multiple Halo statuses to each stage. The stepper will show the appropriate stage based on the ticket's current status. MSPortal warns you if a stage is still empty when you click **Next**.
    </Tip>
  </Step>

  <Step title="Sync Actions">
    Use these buttons to manage ticket sync:

    | Action | Description |
    |--------|-------------|
    | **Quick Sync** | Trigger an immediate sync of ticket data |
    | **Clear & Resync** | Run a full ticket resync that reads the last 365 days of tickets from Halo again (useful after major configuration changes) |

    See [Clear and Resync Integrations](/user-guides/integrations/clear-and-resync-integrations) before you use **Clear & Resync**.
  </Step>
</Steps>

#### Opportunity Settings

<Steps>
  <Step title="Configure Opportunity Defaults">
    Set default values for opportunities created from MSPortal. Halo requires several fields on every opportunity, so configuring defaults here means the planner Create Opportunity action can post a complete opportunity to Halo without prompting for them every time.

    | Setting | Description |
    |---------|-------------|
    | **Default Workflow** | The Halo workflow new opportunities are placed into |
    | **Default Conversion Probability** | Starting probability percentage |
    | **Default Categories** (Category 1 - 4) | Halo's four category fields, each picked from a dropdown populated from your Halo instance. Required if your Halo instance marks any category as mandatory for opportunities. |

    <Tip>
      The workflow and category pickers read directly from your Halo instance, so the values you see are the same ones a Halo agent would see in the native UI. Any new workflow or category you add in Halo appears here on the next sync.
    </Tip>

    <Note>
      Opportunity sync can be enabled or disabled in the Sync step. These settings only apply when opportunity sync is enabled. When the planner posts a new opportunity, real Halo errors (missing Category 4, validation failures, etc.) surface in the planner UI instead of failing silently, so misconfigured defaults are easy to spot.
    </Note>
  </Step>

  <Step title="Configure Invoice Display Settings">
    If invoice sync is on, use **Hide Invoice Statuses** to hide closed, voided or other statuses from the Invoices page. All invoices still sync.
  </Step>

  <Step title="Proceed">
    Click **Next** to continue to the import step.
  </Step>
</Steps>

#### Auto-Import Opportunities (Optional)

If you want Halo opportunities to auto-create planner items as new ones land in Halo, use the **Auto-import to Planner** section of the Opportunity Settings card. Three controls scope which opportunities flow through:

| Setting | Description |
|---------|-------------|
| **Auto-import opportunities into the Planner** | Master toggle. When off, opportunities only come into the planner via the manual Import Opportunities dialog |
| **Minimum opportunity value** | Skip opportunities below a value threshold (useful for filtering out noise from small stub deals) |
| **Opportunity types to auto-import** | Multi-select list of Halo opportunity types. The picker is populated from the distinct `opp_type` values that have actually appeared in your Halo data, since Halo's `opptype` is free-text rather than a managed picklist. If none are selected, all types are eligible. |

Once enabled, every Halo sync auto-creates planner items for new matching opportunities and keeps existing PSA-managed planner items in sync. Use **Linked planner item refresh** to choose which planner fields each sync updates. See [Importing PSA Opportunities](/user-guides/planner/index#importing-psa-opportunities) in the Planner guide for the full sync behavior.

### Step 5: Import (Optional)

Import users and companies from Halo PSA. This step is optional - you can skip it and import later from the respective settings pages. The step is organized into **Users**, **Companies**, and **Assets** tabs.

<Tabs>
  <Tab title="Users">
    Import technicians and agents (your MSP staff) from Halo PSA to create user accounts.

    1. Select users from the list to create accounts for
    2. Choose a role for imported users

    <Note>
      Client contacts are not imported here. They can be managed via Company settings after companies are imported.
    </Note>
  </Tab>

  <Tab title="Companies">
    Import companies from Halo PSA to sync their data.

    1. Select companies to import or link to existing MSPortal companies

    <Tip>
      Companies will sync automatically based on your sync settings. Use this tab if you want to import specific companies immediately.
    </Tip>
  </Tab>

  <Tab title="Assets">
    Import Halo assets as devices in MSPortal. Make sure **Enable asset sync** is on in the Sync step, then click **Open Asset Import** to map asset types to MSPortal device types and select the assets to import.
  </Tab>
</Tabs>

### Complete Setup

Click **Complete Setup** to finish the wizard. MSPortal applies any pending company and user selections, then finishes setup. Imports and syncs keep running in the background.

<Note>
You can return to the setup wizard at any time by clicking **Configure** on the Halo integration. The wizard will resume with your current settings. Use **Save & Exit** to save your progress and leave the wizard part way through.
</Note>

## Managing Your Integration

After setup, you can manage your integration from **Settings** > **Integrations**:

- **Configure**: Re-open the setup wizard to modify settings
- **Resync**: Trigger a manual sync of data
- **Sync PSA Data**: Refresh configuration data from Halo PSA
- **Import Configurations**: Open the Halo asset import page. Map Halo asset types to MSPortal device types, enable auto-sync, and ignore categories you don't need. See [Import Devices](/user-guides/integrations/import-devices) for the full guide.

To remove the integration, open the wizard and click **Delete Integration**. This deletes the integration and its settings in MSPortal. Delete the API application in Halo separately.

### Additional Features

Once your integration is configured, MSPortal.ai will sync data from Halo PSA. You can:

- View synced tickets in the **Tickets** module
- Access customer data in the **Companies** module
- Create opportunities from the **Planner** module
- Link projects to planner items

## Import HaloPSA native CSAT for dashboards and reports

This imports satisfaction feedback already collected in Halo PSA. You do not need Simplesat or a new MSPortal survey. The import is off by default.

<Steps>
  <Step title="Grant feedback read access">
    In Halo, give the **MSPortal.ai** API application the `read:feedback` permission (or the `all` scope).
  </Step>

  <Step title="Re-check permissions">
    In MSPortal, open **Settings** > **Integrations** > **Halo PSA** > **Configure** > **Permissions**, click **Re-check** and confirm **Satisfaction feedback** is granted.
  </Step>

  <Step title="Turn on the import">
    Open **Sync** and turn on **Import satisfaction ratings**.
  </Step>

  <Step title="Set the rating scale">
    Set **Rating scale** to match the survey configured in Halo: **1 to 3**, **1 to 4**, **1 to 5** or **1 to 10**. The default is **1 to 5**. Halo sends the score without the scale, so the wrong scale changes every CSAT percentage. If your Halo survey rates its best response lowest, such as 1 for excellent, turn on **Lowest score is best**.
  </Step>

  <Step title="Save">
    Click **Next**, or **Save & Exit**, to save the setting. Imports then run hourly.
  </Step>

  <Step title="Check company links">
    Make sure the feedback's tickets have synced and their companies are linked to portal companies. A response whose ticket or company cannot be resolved yet will not appear in company-scoped CSAT results until a later sync resolves it.
  </Step>

  <Step title="Grant read access">
    Give intended readers **Surveys** > **Read** > **CSAT** in their role. Building dashboards and reports also needs the matching permissions.
  </Step>
</Steps>

### Present the imported feedback

| Where | How |
|-------|-----|
| **CSAT Dashboard** | Open **Surveys** > **CSAT Dashboard** to read scores, trends and feedback, or export responses. Halo feedback is grouped under **Halo PSA satisfaction**. See [Read and export support satisfaction feedback](/user-guides/surveys/read-csat-feedback). |
| **Custom dashboards** | Add **CSAT Overview**, **CSAT Trend**, **CSAT by Company** or **Recent CSAT Feedback** from the widget library, then save the dashboard. See [Create and edit a dashboard](/user-guides/dashboards/create-and-edit-dashboard). |
| **Reports** | Use the same CSAT blocks in the report builder, select the company and reporting period, and save. See [Reporting](/user-guides/reporting/index#native-psa-csat-in-reports). |

These CSAT views can include other connected feedback sources alongside Halo. Check the company selection, dates and survey filter before you read a total as Halo-only. Technician statistics depend on the ticket's technician mapping.

### If Halo CSAT is missing

Connecting Halo does not turn on the import by itself. Check that **Import satisfaction ratings** is saved, **Satisfaction feedback** is granted, the rating scale is right, the tickets have synced, the companies are linked and the reader has the CSAT permission. If the **Import satisfaction ratings** toggle does not appear at all, contact MSPortal support.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Connection test fails | Verify your Halo URL, Client ID, and Client Secret are correct. Ensure `app.msportal.ai` is in the CORS whitelist. |
| Tickets not syncing | Check that the correct teams are selected in Ticket Sync Scope, that ticket statuses aren't excluded, and that the API agent belongs to those teams. |
| Contacts not importing | Verify **Enable Auto-Import** is on and a default role is selected in the Sync step. |
| Permission errors | Review the API permissions in Halo PSA and ensure all required permissions are enabled. See [Create Custom Halo PSA Role and API User](/user-guides/integrations/halo-psa-custom-role-and-user). |
| Projects load, but creating or editing one fails | Check **Project Modify** on the application and the agent's project access. |
| A project loads, but its child ticket, checklist or note cannot be changed | Check ticket write, action and to-do access, ticket type access and team or client restrictions on the API agent. |
| Logging project time fails | Check permission to add the time recording action, the agent mapping and billing options. The **Time entries** check only tests read access. |
| Halo satisfaction feedback is missing from CSAT views | Check the saved **Import satisfaction ratings** toggle, `read:feedback`, the rating scale, company links and the reader's CSAT permission. |
