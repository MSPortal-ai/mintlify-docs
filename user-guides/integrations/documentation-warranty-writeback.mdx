Warranty writeback copies eligible MSPortal device warranty dates into **Hudu assets** or **IT Glue flexible assets**. It is an optional **MSP integration management** task that changes the connected provider.

<Note>
For IT Glue, configurations are the usual target and need no field mapping. See [Warranty writeback to IT Glue configurations](/user-guides/integrations/itglue-configuration-warranty-writeback). This guide covers Hudu assets and IT Glue flexible assets.
</Note>

## Hudu assets and IT Glue flexible assets

Use this when warranty dates live in Hudu assets, or in IT Glue flexible assets instead of configurations. In IT Glue, open **Flexible assets (optional)** on the same card.

Confirm the documentation connection is active, companies are mapped correctly, and its key can update the intended assets. You need synchronized asset layouts or flexible asset types with usable serial and warranty fields, plus MSPortal device types and devices with successful warranty checks and an expiration date.

Matching uses a unique serial number within the mapped company and selected asset type. It does not fall back to hostname. Missing, placeholder or ambiguous serials are skipped. These checks reduce bad matches; correct company and field mappings are still essential.

<Steps>
  <Step title="Open Warranty Writeback">
    Open **Settings > Integrations > Configure** for Hudu or IT Glue. In Hudu use **Documentation**; in IT Glue use **Sync & Sharing** and expand **Flexible assets (optional)**.
  </Step>
  <Step title="Choose device and asset types">
    In **Device and warranty field mappings**, map each intended MSPortal device type to a Hudu asset layout or IT Glue flexible asset type. **Not mapped** excludes that device type.
  </Step>
  <Step title="Review each field">
    Choose a **Serial number field** and **Warranty expiration field**. **Warranty start field** is optional and must differ from expiration. Hudu can offer **Primary serial**. Review suggested fields; their names are suggestions, not proof that they contain the intended values.
  </Step>
  <Step title="Enable and save deliberately">
    Turn on **Enable warranty writeback** (in IT Glue, **Write warranty dates to flexible assets**), then select **Save warranty settings**. The switches and mapping selectors are drafts until this button succeeds. At least one complete mapping is required to enable it.
  </Step>
</Steps>

<Warning>
Saving with asset writeback enabled requests an immediate background asset sync and provider writeback. It does not wait until the next daily run. This save also enables synchronization for mapped asset types; review those content choices and client visibility separately.
</Warning>

If multiple device types share an asset type, they must use the same serial and warranty fields. Changing those fields for one row updates the other rows using that asset type in the draft. Review all affected rows before saving.

## Verify the result

Wait for the background outcome, then inspect a known matching asset in Hudu or IT Glue. Confirm the company, serial, selected fields and resulting dates. A settings-save message confirms configuration storage; it does not establish that every external update succeeded.

Writeback uses devices with successful warranty checks and a known expiration date. An optional start date is written only when the source device has one. An unchanged date may need no external update. Missing source dates are not a request to erase the provider's values.

Recurring writeback can run while enabled. A run may skip an asset or fail for a subset, so keep the source dates and provider result under review rather than treating enablement as a guarantee that all assets are current.

## Disable or change the scope

Turn off the relevant switch and select **Save warranty settings** to stop future runs for that target. Previously written provider values remain; disabling is not a rollback of dates or a recall of an already-running update.

Use **Not mapped** to remove a device type from the draft, then save. Saving mappings can enable their asset-type sync even when writeback is off; removing a mapping or disabling writeback does not automatically restore earlier sync choices. Review the surrounding content-sync settings if that is your intention.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Save is disabled | Complete the serial and expiration fields, keep start and end different, and include a mapping when enabling. |
| No asset types or fields | Refresh the provider inventory through the integration workflow; confirm key access and valid active layouts/types. |
| One asset never changes | Successful device warranty check, known expiration, device type, company mapping, usable unique serial and provider update permission. |
| Mappings saved but dates stayed old | Check the background sync/writeback outcome and the provider record; saving is not proof of delivery. |
| Another device-type row changed in the draft | Rows sharing the same asset type share field selections. |
| Dates remain after disabling | Disabling stops future enabled work; it does not restore provider values already written. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does the warranty writeback switch save immediately?">
    No. The enable switch and mappings are a draft until **Save warranty settings** succeeds.
  </Accordion>
  <Accordion title="Does warranty writeback wait until the next daily run?">
    Saving with writeback enabled requests an immediate asset sync and writeback, in addition to recurring runs.
  </Accordion>
  <Accordion title="Will documentation warranty writeback match by device name?">
    No. It uses a unique usable serial within the mapped company and selected asset type. Ambiguous, missing and placeholder serials are skipped.
  </Accordion>
  <Accordion title="Can IT Glue configurations receive warranty dates?">
    Yes, and it is the usual choice. See [Warranty writeback to IT Glue configurations](/user-guides/integrations/itglue-configuration-warranty-writeback). Flexible asset mappings are an optional extra.
  </Accordion>
  <Accordion title="Why did another warranty mapping row change when I selected a field?">
    Device types mapped to the same asset type must share serial and warranty fields. The draft applies those field changes to all rows using that type.
  </Accordion>
  <Accordion title="Does saving warranty mappings leave asset sync settings unchanged?">
    It enables sync for mapped asset types, and enabling writeback also enables the relevant asset dataset. Review content sync and visibility separately.
  </Accordion>
  <Accordion title="Does disabling warranty writeback restore previous dates?">
    No. Save the disabled setting to stop future enabled runs. It does not undo provider writes or recall work already running.
  </Accordion>
  <Accordion title="Does a successful warranty mapping save prove all provider dates were updated?">
    No. Check the background result and an actual mapped provider asset. Missing source dates, unmatched serials or provider failures can prevent updates.
  </Accordion>
  <Accordion title="Which device warranty records are eligible for writeback?">
    The device needs a successful warranty check and an expiration date, plus the configured device type, company mapping and unique serial match.
  </Accordion>
</AccordionGroup>
