Connect Huntress to review Managed EDR agents, escalations, incident reports and summary reports. You can also connect Managed SAT for learner, assignment and phishing information. Setup requires **MSP integration management permission**; Company users access only the resulting views enabled for them.

## Overview

Huntress provides Managed EDR (endpoint detection and response) and Managed Security Awareness Training (SAT) for MSPs. By integrating Huntress with MSPortal.ai, you can:

- Link Huntress agents to devices for endpoint security coverage tracking
- View escalations and incident reports on the Security page
- Include Huntress summary reports in client reporting
- Sync Managed SAT learners, training assignments, and phishing campaign results
- Track security awareness training progress per user and per company

## Prerequisites

- Active Huntress account with API access
- MSPortal.ai account with integration management permissions
- Huntress API key pair (public and private key)
- For Managed SAT: a separate Managed SAT (Curricula) client ID and secret. Your EDR API keys do not work for SAT

## Part 1: Generate Huntress API Keys

Before connecting to MSPortal.ai, create an API key pair in Huntress.

<Steps>
  <Step title="Log into Huntress">
    Access your Huntress dashboard at [huntress.io](https://huntress.io).
  </Step>

  <Step title="Open API Credentials">
    Click your account name in the top-right corner and select **API Credentials**.
  </Step>

  <Step title="Create API Key">
    Click **Setup** (or **Generate New API Key** if you have created keys before) and give the key a descriptive name such as `MSPortal Integration`.
  </Step>

  <Step title="Copy Both Keys">
    Huntress generates a **public key** and a **private key**. Copy both immediately.

    <Warning>
      **Store the private key securely!** Huntress only shows the private key once. If you lose it, you'll need to generate a new key pair.
    </Warning>
  </Step>
</Steps>

<Note>
  If you plan to sync Managed SAT training data, you will also need Curricula OAuth credentials (client ID and client secret). You enter these in **Connect**, below the EDR keys. Contact Huntress support if you don't have SAT API credentials for your account.
</Note>

## Part 2: Set up the connection in MSPortal

Open **Settings > Integrations**, choose the **Directory** tab, find **Huntress** and connect it. To maintain a saved account, open that connection. The **Setup guide** lists these tasks:

1. **Connect** - Add EDR API keys and, optionally, Managed SAT credentials
2. **Choose products** - Choose the datasets to sync
3. **Import or match companies** - Link Huntress EDR organizations to companies
4. **Import or match security awareness accounts** - Link Managed SAT accounts to companies (optional; used only when Managed SAT is connected)
5. **Import devices** - Link agents to devices
6. **Review** - Finish setup

### Connect

<Steps>
  <Step title="Enter API details">
    | Field | Value |
    |-------|-------|
    | **API URL** | `https://api.huntress.io/v1` (pre-filled; only change this if Huntress support directs you to) |
    | **Public API key** | The public key from Part 1 |
    | **Private API key** | The private key from Part 1 |

    <Note>
      Your API keys are stored securely using encrypted vault storage. They are never exposed in logs or API responses.
    </Note>
  </Step>

  <Step title="Choose the Huntress products">
    Under **Huntress products**, choose **Managed EDR**, or **Managed EDR and Managed SAT** if you use Huntress Managed SAT. For SAT, fill in the Curricula API credentials:

    | Field | Value |
    |-------|-------|
    | **SAT client ID** | Your Curricula OAuth client ID |
    | **SAT client secret** | Your Curricula OAuth client secret |
    | **SAT API URL** | `https://mycurricula.com/api/v1` (pre-filled) |
    | **SAT token URL** | `https://mycurricula.com/oauth/token` (pre-filled) |
  </Step>

  <Step title="Test the connection">
    Select **Test connection**. It checks EDR and, when selected, SAT access. Resolve any failure before saving.

    If the connection fails:
    - Verify both keys were copied in full without extra spaces
    - Ensure the key pair has not been revoked in Huntress
    - Confirm the API URL is `https://api.huntress.io/v1`
    - For SAT, confirm the client ID and secret are Curricula credentials, not your EDR keys
  </Step>

  <Step title="Save">
    Select **Save and continue** for a new connection. The product selection and credentials are saved together.

    If the EDR connection saves but SAT fails, reopen the saved connection and fix SAT there. Do not start a second Huntress connection.
  </Step>
</Steps>

### Choose products

Choose which Huntress datasets MSPortal syncs. Each switch saves as soon as you change it. Turned-off datasets stop syncing on the next run.

#### Managed EDR

| Option | Description |
|--------|-------------|
| **Organizations** | Company mapping source for Huntress EDR data |
| **Agents** | Device coverage source |
| **Escalations and incident reports** | Security page source |
| **Summary reports** | Reports page source |
| **Auto-import mapped agents** | Creates devices from mapped Huntress agents during sync (off by default). Appears beneath **Agents** when agent sync is on. |

<Tip>
  Leave **Auto-import mapped agents** off during initial setup. Review and import agents in **Import devices**, then enable auto-import once you're confident in your organization mappings.
</Tip>

#### Managed SAT (Optional)

If you connected Managed SAT, choose which SAT datasets to sync:

| Option | Description |
|--------|-------------|
| **SAT accounts** | Curricula account inventory used for SAT company mapping |
| **SAT learners** | User-level training status and learner profile data |
| **SAT assignments** | Training assignments, episodes, preview links, assignment learners, and learner activity |
| **SAT phishing** | Phishing campaigns and learner attempts |
| **SAT reports** | Managed SAT account summary reports |

### Import or match companies

Map Huntress organizations to your MSPortal companies. This determines which data syncs to which company.

1. Wait for the organizations to appear. The initial sync runs in the background, so check back after a few minutes if they don't appear immediately.
2. Review the suggested matches, then accept them, choose another company in the row, or use **Import company** to create a portal company. **Accept strong matches** accepts every suggestion at 90% confidence or more after you review them.
3. Choose **Ignore** for organizations you never want to map.

Accepted matches and removals save immediately; importing a company is also a saved action.

<Warning>
  Only data from mapped organizations syncs to MSPortal. Unmapped organizations are skipped.
</Warning>

### Import or match security awareness accounts

When Managed SAT is connected, use **Import or match security awareness accounts** to map each Curricula account to its MSPortal company the same way. Mapping an EDR organization does not map its SAT account. Check that each company's EDR organization and SAT account point to the same company.

### Import devices

Open **Import devices** to review synchronized agents and their device links. Opening the task does not import anything.

Huntress agents link to existing MSPortal devices first. Only an agent that cannot be safely matched by Huntress identity, serial number, MAC address, or hostname in the mapped company creates a new device. Confirm the intended companies and link or create choices before importing.

<Tip>
  Set up device type mappings before importing so brand-new devices get the right device type.
</Tip>

See [Import Devices](/user-guides/integrations/import-devices) for the shared import controls.

### Review and finish setup

Open **Review** and select **Finish setup** once the required tasks are complete. Syncs may still be running. Check the Devices, Security and Training pages afterward. An **Agents** count does not mean every agent is linked to a device.

## What Gets Synced

### Managed EDR

| Data Type | Description |
|-----------|-------------|
| **Organizations** | Huntress organizations used for company mapping |
| **Agents** | Endpoint agents with hostname, OS, serial, and MAC details |
| **Escalations** | Security escalations raised by Huntress analysts |
| **Incident Reports** | Detailed incident reports for detected threats |
| **Summary Reports** | Periodic account and organization summary reports |

### Managed SAT

| Data Type | Description |
|-----------|-------------|
| **SAT Accounts** | Curricula accounts used for SAT company mapping |
| **Learners** | User-level training status and learner profiles |
| **Assignments** | Training assignments and per-learner activity |
| **Phishing** | Phishing campaigns and learner attempt results |
| **SAT Reports** | Managed SAT account summary reports |

## Where the Data Appears

| Data | Where to find it |
|------|------------------|
| **Managed EDR agents** | The Devices page, alongside the rest of your device inventory |
| **Managed SAT assignments** | **Training > Security Training > Assignments** |
| **Managed SAT learner progress** | **Training > Security Training > Training Status**, next to your other awareness providers |
| **Your own assigned episodes** | **Training > Course Library**, as course tiles counted with the rest of your training |
| **Awareness metrics in reports** | The Security Awareness blocks and the Security Awareness & Training source on QBR and security review reports |

See [Security Awareness Training](/user-guides/training/security-awareness) for how to work with assignments, learner progress, and reporting.

<Note>
Managed SAT data only appears for Huntress organizations mapped to an MSPortal company. Unmapped organizations are skipped by the sync.
</Note>

## Synchronization Schedule

After initial setup, all enabled datasets sync automatically once per day. To sync now, use **Run sync** in the connection header, and check the result in **Sync activity**.

<Note>
  Only datasets turned on in **Choose products** are synced. Data from unmapped organizations is skipped.
</Note>

## Maintain the connection

Open the Huntress connection from **Settings > Integrations** and choose a task in the **Setup guide** to change its settings. Use **Overview** and **Sync activity** to inspect background results.

- **Update API keys:** in **Connect**, enter your new public and private keys. Saved keys show masked; leave masks unchanged to test the saved credentials. Select **Test connection**, then **Save changes**. An existing connected badge does not mean a fresh test ran.
- **Turn Managed SAT on or off:** change **Huntress products** in **Connect**, test, and select **Save changes**. SAT dataset choices stay in **Choose products**.
- **Map new organizations:** as you onboard new clients in Huntress, open **Import or match companies** after the next sync and match them.
- **Disconnect:** open **More actions** and choose **Disconnect…**. The confirmation lists what is removed from MSPortal. It does not uninstall Huntress agents and is not an endpoint remediation action.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Connection test fails | Verify both API keys are correct and the key pair hasn't been revoked in Huntress |
| SAT connection test fails | Confirm the client ID and secret are valid Curricula OAuth credentials, not your EDR keys |
| EDR works but SAT data is missing | Confirm **Managed EDR and Managed SAT** is saved in **Connect**, the SAT datasets are on in **Choose products**, and the SAT accounts are mapped |
| Test button is disabled with a mask | Keep stored masks unchanged to test saved credentials, or type the actual key; resolve any field or endpoint validation error |
| Sync choices disappeared | Check the saving state and any error in **Choose products**; switches save when changed |
| No organizations appear | Wait a few minutes for the first sync, or use **Run sync** and check **Sync activity** |
| Agents not creating devices | Check that the agent's organization is mapped to a company, device type mappings are set, and whether **Auto-import mapped agents** is on |
| Duplicate devices | Agents link to existing devices by identity, serial, MAC, or hostname first; verify the existing device belongs to the mapped company |
| Data not syncing | Ensure the dataset is on in **Choose products** and the organization is mapped |
| Security counts are zero | Check that the security dataset is enabled, the organization is mapped and a sync has finished. Zero does not prove there are no threats |
| Stale data | Use **Run sync** in the connection header to trigger a manual refresh |

<AccordionGroup>
  <Accordion title="Where do I add Huntress Managed SAT credentials?">
    In **Connect**, choose **Managed EDR and Managed SAT** under **Huntress products**, enter its separate credentials, test and save. Use **Choose products** for dataset choices.
  </Accordion>
  <Accordion title="Can I use Huntress EDR keys for Managed SAT?">
    No. SAT requires its own client ID and secret. EDR uses the public/private API key pair.
  </Accordion>
  <Accordion title="Does mapping an EDR organization also map its SAT account?">
    No. Use the separate **Import or match security awareness accounts** task when SAT is configured and map each account to the correct company.
  </Accordion>
  <Accordion title="Does opening Import devices create devices?">
    No. It shows staged agents. Review and apply the import choices there. Separately, enabled **Auto-import mapped agents** can create devices during sync.
  </Accordion>
  <Accordion title="Does a Huntress Agents count prove all agents are linked to devices?">
    No. Review the device import or coverage view and company mappings. Synchronized agents and linked MSPortal devices are different outcomes.
  </Accordion>
  <Accordion title="Does disconnecting Huntress uninstall agents?">
    No. Disconnecting removes the MSPortal integration. Do not use it as an endpoint uninstall or remediation action.
  </Accordion>
</AccordionGroup>

## Security & Privacy

- **API Key Storage**: Your Huntress and Curricula credentials are encrypted using vault storage and never exposed in logs or responses
- **Data Isolation**: All synced data is tenant-isolated and only visible to your organization
- **Read-Only Access**: MSPortal only reads data from Huntress; it never modifies your Huntress configuration
