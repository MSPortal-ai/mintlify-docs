Connect Huntress to review Managed EDR agents, escalations, incident reports and summary reports. You can also connect Managed SAT for learner, assignment and phishing information. Setup requires **MSP integration management permission**; Company users access only the resulting views enabled for them.

## Prepare the credentials

Obtain a Huntress **public/private API key pair** with access to the intended account. Use [Huntress API credential instructions](https://support.huntress.io/hc/en-us/articles/4416826761235-Generating-API-Keys). For optional SAT, obtain a separate **client ID and client secret** for the Managed SAT API; see [Huntress Managed SAT API](https://support.huntress.io/hc/en-us/articles/46042394584979-Huntress-Managed-SAT-API). EDR keys do not substitute for SAT credentials.

Open **Settings > Integrations**, find Huntress and connect it. To maintain a saved account, use **Configure** on that connection.

## Connect both products

<Steps>
  <Step title="Test Managed EDR">
    On **Connect**, enter **Public API key** and **Private API key**. Keep the supplied **API URL** (`https://api.huntress.io/v1`) unless your verified connection instructions require a change. Select **Test Connection** and review the returned account.
  </Step>
  <Step title="Optionally enable Managed SAT">
    On this same **Connect** step, turn on **Enable Managed SAT**. Enter **SAT client ID** and **SAT client secret**. The supplied SAT API and token URLs are `https://mycurricula.com/api/v1` and `https://mycurricula.com/oauth/token`. Select **Test SAT Connection**. The toggle and tests have not yet saved the connection.
  </Step>
  <Step title="Save the connection">
    Select **Connect Huntress**, or **Save Connection** when editing an existing account. Wait for success, then **Next**. If adding SAT fails after EDR was created, reopen the saved connection and repair SAT there before attempting another connection.
  </Step>
</Steps>

## Choose synchronization on Sync

| Managed EDR option | Purpose |
| --- | --- |
| **Organizations** | Discovery for EDR company mapping. |
| **Agents** | Synchronized endpoint coverage. |
| **Escalations and incident reports** | Security findings. |
| **Summary reports** | Available Huntress reports. |
| **Auto-import mapped agents** | Can create MSPortal devices from mapped agents during sync; off by default for a new connection. |
| **Retire agents that stop checking in** | Removes a device after its Huntress agent has not checked in for 30, 60, 90 or 180 days. **Never** by default. |

With SAT connected, choose **SAT accounts**, **SAT learners**, **SAT assignments**, **SAT phishing** and **SAT reports** as required. Select **Save Sync Settings**. These switches are drafts until saved; **Next** does not replace that save.

## Map EDR organizations and SAT accounts

On **Map Organizations**, choose each EDR organization's MSPortal company. Use **Quick Match** for proposals and review them before applying. Save pending links with **Import Selected**, or **Next** to save pending choices and request follow-on sync.

When SAT is configured, **SAT accounts** is a separate mapping step. Map its accounts independently; mapping an EDR organization does not map a SAT account. Check both products point to the intended company.

<Warning>
Creating an MSPortal company saves that company before its pending provider link is applied. Removing an existing mapping takes effect immediately. Closing setup does not undo those operations.
</Warning>

## Review and import agents

The **Import Agents** step shows Organizations, Agents, Escalations, Incidents and Reports counts, with a Last synced time when available. **Sync Huntress Data** requests background work. **Import Agents as Devices** opens the agent import page; it does not import every agent merely by opening it.

Review company mappings and the link/create choices before importing. Device synchronization, linking to an existing device and creating a device are separate outcomes. Use the [device import guide](/user-guides/integrations/import-devices) for the import controls. Review **Auto-import mapped agents** carefully before enabling unattended device creation.

**Complete Setup** can request follow-on synchronization and returns to Integrations. Verify actual device, Security and training data afterward; a finished wizard or an Agents count does not prove that every agent is linked to an MSPortal device.

## Agents removed from Huntress

Huntress keeps an agent on its list until someone removes it, so a retired computer can stay in MSPortal long after it stopped reporting. Set **Retire agents that stop checking in** to have each sync drop agents that have not checked in for the chosen number of days. You can set it on the wizard's **Sync** step or on the connection's **Choose data** page, where it saves as soon as you pick a value.

When an agent is retired, MSPortal removes its Huntress record and its device link. The device stays while an RMM or another monitoring integration, such as Auvik or Liongard, still reports it. If Huntress created the device, that integration becomes its source. A PSA or IT Glue record keeps the device only when you have no RMM connected. Otherwise the device is removed, along with its history, even if a backup integration such as Axcient matched onto it. An agent with no recorded check-in time is never retired.

## Maintain the connection

Enter replacement credentials on **Connect** and use **Save Connection**. A masked saved secret cannot be used by the separate fresh-test button; enter the actual secret when you need that test. Existing verified badges can describe saved configuration rather than a new provider probe.

Use **Enable Managed SAT** and **Save Connection** to change SAT connection status. Treat sync choices separately with **Save Sync Settings**. Removing the Huntress connection uses the footer **Delete** confirmation; it is not an endpoint remediation or uninstall action.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| EDR works but SAT is absent | Separate SAT credentials saved on Connect, SAT enabled, and the SAT accounts mapping. |
| Test button is disabled with a mask | Enter the actual secret for a fresh test. Do not publish it in a screenshot. |
| Sync choices disappeared | Save them with **Save Sync Settings** before leaving Sync. |
| Agents exist but no devices were created | Check company mapping, manual import choices and whether auto-import is enabled. |
| Security counts are zero | Check scope, datasets, source availability and freshness; zero is not proof of no threats. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Where do I add Huntress Managed SAT credentials?">
    On **Connect**, enable **Managed SAT**, enter its separate client ID and secret, test SAT and save the connection. Sync is where you save dataset choices.
  </Accordion>
  <Accordion title="Can I use Huntress EDR keys for Managed SAT?">
    No. SAT requires its own client ID and secret. EDR uses the public/private API key pair.
  </Accordion>
  <Accordion title="Does mapping an EDR organization also map its SAT account?">
    No. Use the separate **SAT accounts** step when SAT is configured and map each account to the correct company.
  </Accordion>
  <Accordion title="Do Huntress synchronization toggles save immediately?">
    No. Select **Save Sync Settings** before leaving Sync.
  </Accordion>
  <Accordion title="Does opening Import Agents as Devices create devices?">
    Opening it shows the import page. Review and apply the import choices there. Separately, enabled **Auto-import mapped agents** can create devices during sync.
  </Accordion>
  <Accordion title="Does a Huntress Agents count prove all agents are linked to devices?">
    No. Review the device import or coverage view and company mappings. Synchronized agents and linked MSPortal devices are different outcomes.
  </Accordion>
  <Accordion title="What if adding SAT fails after the Huntress EDR connection is saved?">
    Reopen the saved connection and correct SAT there. Check whether EDR already exists before starting another connection.
  </Accordion>
  <Accordion title="Does a verified Huntress badge mean a test just ran?">
    It can reflect existing saved configuration. For a fresh test, enter the actual secret and use the appropriate EDR or SAT test button; save replacements separately.
  </Accordion>
  <Accordion title="Why did a Huntress device disappear from MSPortal?">
    Check **Retire agents that stop checking in**. When it is set, a sync removes agents that have not checked in for that long, along with any device no RMM or other monitoring integration still reports. A PSA record keeps a device only when no RMM is connected. Set it to **Never** to keep every agent Huntress lists.
  </Accordion>
  <Accordion title="Does deleting the Huntress connection uninstall agents?">
    The footer Delete disconnects the MSPortal integration. Do not use it as an endpoint uninstall or remediation action.
  </Accordion>
</AccordionGroup>
