Connect TimeZest to create scheduling requests after client tickets, display appointments in MSPortal calendars and tickets, and provide secure appointment management links.

<Note>
TimeZest is currently a beta integration. If the integration is not available in **Settings > Integrations**, contact support@msportal.ai.
</Note>

## Prerequisites

- A TimeZest account with permission to create API keys
- A TimeZest API key with read and write access
- MSPortal.ai integration management permission
- Client roles or company groups if you plan to restrict scheduling access

<Warning>
Use a read/write API key. MSPortal tests read access during setup, but it does not test write access because doing so would create a real scheduling request.
</Warning>

## Connect TimeZest

<Steps>
  <Step title="Create an API key">
    In TimeZest, create a dedicated read/write API key for MSPortal and copy it to a secure location.
  </Step>
  <Step title="Open the connection page">
    In MSPortal, go to **Settings > Integrations**, open the **Directory** tab, find **TimeZest**, and select **Connect**. If TimeZest is already connected, select **Open** on its row in **Active** instead. The **Setup guide** lists **Connect**, **Configure appointments** and **Review**.
  </Step>
  <Step title="Test the connection">
    In **Connect**, enter the key in the **API Key** field and select **Test connection**. MSPortal verifies read access and reports how many appointment types and scheduling resources it found. Resolve any access error before you continue.
  </Step>
  <Step title="Save the connection">
    After the test succeeds, select **Save and continue**. Credentials are stored in the vault and never shown again. A successful test on its own does not save the key.
  </Step>
</Steps>

## Configure Scheduling Capabilities

Every capability starts off. Turn on each capability independently in **Configure appointments**:

| Capability | What it enables |
|------------|-----------------|
| Schedule from ticket templates | Creates a PSA ticket and then sends the client to TimeZest to select an appointment time |
| Show appointments on calendars | Displays scheduled TimeZest appointments in MSPortal calendars |
| Show appointments on tickets | Adds an Appointments tab to supported ticket details |
| Allow appointment changes | Exposes the secure TimeZest link for scheduling, rescheduling, or canceling an appointment |

When a capability is on, you can optionally select **Client security roles** and **Company groups** for it. Leaving a list empty means all client roles or all company groups. When both restrictions are set, a client must match both rules. MSP staff retain access to enabled capabilities.

Each switch saves as soon as you change it, and a role or company group selection saves when you close the list. Turning a capability on starts the appointment sync.

**Configure appointments** is optional. When you are done, open **Review** and select **Finish setup**.

## Turn On Scheduling in a Ticket Template

Connecting TimeZest does not turn on scheduling for any template. Turn it on in each [request template](/user-guides/ticketing/understand-request-templates) that should offer it.

<Steps>
  <Step title="Open the template">
    Open the ticket template that clients use to request the appointment.
  </Step>
  <Step title="Enable scheduling">
    In **TimeZest appointment scheduling**, turn on **Offer Schedule Appointment for this template**.

    <Note>
      Webhook-only templates cannot offer scheduling, because they do not create a PSA ticket.
    </Note>
  </Step>
  <Step title="Choose the appointment details">
    Select the **TimeZest integration**, an **Appointment type**, and up to four **Scheduling resources**. Selecting more than one resource requires TimeZest Professional.
  </Step>
  <Step title="Save the template">
    Save the template. Clients who use it create the ticket first and then continue to TimeZest to pick a time. The appointment is booked only when the client finishes the TimeZest step.
  </Step>
</Steps>

## Check the Connection

**Test connection** in **Connect** reports how many appointment types and scheduling resources the API key can see. Use it to confirm the key can see the resources you expect to use in ticket templates. The appointment types and resources themselves appear when you choose the appointment details in a ticket template.

Use **Overview** for the connection's status and **Sync activity** to check recent appointment syncs.

## Managing the Connection

- Open **Configure appointments** to change capabilities or audience restrictions. Changes save as you make them.
- To replace the API key, open **Connect**, enter the new key, select **Test connection**, then select **Save changes**.
- **More actions > Disconnect…** opens a confirmation. Confirming removes the stored key and data synced from this connection. It does not remove or cancel appointments in TimeZest.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Connection test fails | Confirm the API key is active and has read access to appointment types and scheduling resources. |
| Scheduling request fails after setup | Replace the key with one that has both read and write access. Setup intentionally tests only read access. |
| A client cannot see a capability | Confirm the capability is turned on in **Configure appointments**, and that the client matches both the selected security-role and company-group restrictions. |
| Clients cannot schedule from a template | Confirm **Offer Schedule Appointment for this template** is on and the template has an appointment type and resource selected. |
| Settings did not persist | Wait for each change in **Configure appointments** to finish saving and check for an error. Key changes use **Save changes** in **Connect** instead. |
| An appointment type or resource is missing | Confirm it is active and visible to the API key in TimeZest, then select **Test connection** again. |
