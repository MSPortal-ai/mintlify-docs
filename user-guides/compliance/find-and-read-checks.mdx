Use this page to find compliance checks and read their results. It is for company users and MSP staff.

## Before you start

- You need Compliance read access. Your MSP decides which companies, checks, and actions you see.
- The checks come from assessment runs your MSP has assigned. See [Compliance](/user-guides/compliance/index).

## Choose the scope

<Steps>
  <Step title="Open Compliance">
    Click **Compliance** in the sidebar.
  </Step>
  <Step title="Check the company selector">
    Choose a company or all companies. A permitted parent company can include its child companies.
  </Step>
  <Step title="Choose the runs to show">
    Use the run filter above the table to pick **Active**, **Completed**, or **All**. Choose **All** to find an older run.

    <img src="/images/product/compliance-run-states.png" alt="Compliance run filter showing Active selected beside Completed and All" width="366" height="70" />
  </Step>
</Steps>

The run filter shows whether an assessment run is complete. It does not mean every check passed. A completed run can contain failed checks.

## Browse the Tree view

<Steps>
  <Step title="Select Tree">
    Click **Tree** in the page header. The tree sits under the summary numbers.
  </Step>
  <Step title="Search">
    Type in **Search compliance checks...** to narrow the tree. The toolbar shows how many checks match, like **12 / 40 checks**.
  </Step>
  <Step title="Expand the levels">
    Expand a company, then a run, then any group, location, or device to reach a check. The levels depend on how the run was assigned. Use **Expand all** or **Collapse all** when they are shown.
  </Step>
  <Step title="Read the counts">
    Each row can show counts for **Past due**, **Passed**, **Failed**, and **In progress**. A count of zero is hidden, but each status keeps its place so the rows line up. Hover a count to read its full number.

    <img src="/images/product/compliance-tree-counts-preview.png" alt="MSP Demo compliance Tree with aligned status counts for company and run rows" width="1280" height="853" />
  </Step>
  <Step title="Open a check">
    Click the check title. See [Read compliance guidance, evidence, and history](/user-guides/compliance/read-evidence-and-history).
  </Step>
</Steps>

The same check can appear in several runs or for several devices and locations. Read the company, run, and target before you compare results.

## Browse the List view

<Steps>
  <Step title="Select List">
    Click **List** in the page header. The table shows one row per assigned check.
  </Step>
  <Step title="Filter the columns">
    Use the column filters. Columns include **Flagged**, **Title**, **Status**, **Priority**, **Due Date**, **Notes**, **Company**, **Run**, **Scope**, **Public Notes**, **Last Updated**, **Group**, **Device**, **Location**, and **Check ID**. MSP staff also see **Private Notes**. Use the column menu to show or hide columns.
  </Step>
  <Step title="Page through the results">
    Use the pager at the bottom. You can show 25, 50, 100, or 250 rows per page.
  </Step>
  <Step title="Open a check">
    On a wide screen, click a row to see it in the **Review pane** beside the list. Click **Open full editor** in the pane to open the full check. On a smaller screen, or with the pane off, clicking a row opens the full check.
  </Step>
</Steps>

### Use the Review pane

The **Review pane** button in the List toolbar turns the docked pane on or off. It shows on wide screens only. The pane has **Review**, **Guidance**, and **History** tabs.

- Move to the next or previous check with the arrows in the pane, with the **Up** and **Down** arrow keys, or with **J** and **K**.
- Press **Enter** to open the full editor and **Esc** to close the pane.
- Users with Compliance write access can change **Status**, **Priority**, and **Due date** and edit notes in the pane. Everyone else sees **You have read-only access to this check.**

A linked Planner shortcut can appear on a check that has linked work, if you have Planner read access. It does not change the assessment.

## Read the results

Statuses come from the status list on each check. Your MSP chooses the names and which statuses count as complete or successful. **Priority** is separate and is **High**, **Medium**, or **Low**. A flag marks a check for attention. It is not a pass or a fail.

The summary above the Tree shows these numbers:

| Metric | What it tells you |
| --- | --- |
| **Compliance Score** | A weighted percentage from the scoring setup, with a letter grade. It shows **N/A** when no score is available. |
| **Total Checks** | The active checks in your scope. |
| **Failed Checks** | Completed checks with a negative result. The line below shows how many are high priority. |
| **Past Due** | Checks past their due date. |
| **Passed Checks** | Checks completed with a positive result. |
| **Completion Rate** | The overall progress of the checks. |

Completion is not passing. A fully assessed set can still contain failures. The score, the summary, and a filtered List are calculated separately, so List column filters do not change the score or summary.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| A check is missing | Switch the run filter from **Active** to **All**, clear search and column filters, and check the company selector. |
| **No compliance checks found matching your filters** | Clear the List column filters. |
| **No compliance data found** | No run has been created for your scope. Ask your MSP to start one. |
| **Failed to load compliance summary** or **Error loading compliance data** | Click **Retry** or reload the page. An error is not a passing result. |
| **Compliance Score** shows **N/A** | No score is available for the scope yet. It is not a failing score. |
| A direct link opens a check I did not expect | The link opens the check even in a completed run. It still needs your access. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Completed mean compliant?">
    No. **Completed** is a run filter. Completed checks can pass or fail. Read each check's status and notes.
  </Accordion>
  <Accordion title="Why does the same check appear several times?">
    The check can be assigned in different runs, or to different companies, locations, or devices. Compare the target and run.
  </Accordion>
  <Accordion title="Why do List filters not change the score?">
    The weighted score and summary are separate from the List column filters.
  </Accordion>
  <Accordion title="What does a flag mean?">
    It marks a check for review. It does not change the pass or fail status.
  </Accordion>
  <Accordion title="Can I configure checks as a company reader?">
    No. Your MSP sets up checks and permissions.
  </Accordion>
  <Accordion title="Can I create a ticket by opening a failed check?">
    No. For a support request, tell the [Home AI Assistant](/user-guides/ticketing/open-a-ticket) and confirm the request when prompted.
  </Accordion>
</AccordionGroup>
