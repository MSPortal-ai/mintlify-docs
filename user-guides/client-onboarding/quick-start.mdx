Follow these six steps to build a template, create a draft client portal, preview it, and go live. This guide is for MSP staff.

<Note>
These steps use the unified Projects experience. If your organization still uses the earlier experience, open **Settings > Client Onboarding** for templates and checklists, and start a portal from the company's **Onboarding** tab with **Start Onboarding**.
</Note>

## Before you start

- Client Onboarding is turned on for your organization.
- Your role has onboarding write access (`write_settings_onboarding`) and your subscription is active.
- You know who should receive the portal invitations. Nothing is emailed until you start the portal.

## 1. Build a template

<Steps>
  <Step title="Open Settings > Projects > Templates > Templates">
    Select **New Template**.
  </Step>
  <Step title="Name the template">
    Enter a **Name**. Add a **Description**, **Tags**, and **Duration (days)** if you want them. Leave **Project type** on **Client onboarding (default)** so projects created from this template get a client portal. Select **Create Template**.
  </Step>
  <Step title="Add phases and tasks">
    Select **Add Phase** and name it, for example **Discovery**. Inside the phase, select **Add Item** and set its **Type**, **Owner** (MSP or Client), and **Title**.
  </Step>
  <Step title="Optional: let AI draft it">
    Select the floating AI button (**AI Onboarding Designer**). Describe the process, for example *"Onboard a 20-person company migrating to M365 with discovery, setup, migration, training, and go-live phases."* Select **Review Template Changes**, check each change, then select **Apply**. Use the undo icon in the sidebar header to reverse the last applied changes.
  </Step>
  <Step title="Save details">
    Phase and item edits save as you work. Select **Save Changes** after you edit the template name, description, tags, duration, or invitation email.
  </Step>
</Steps>

<Tip>
Review every task type, owner, dependency, and linked form after AI proposes changes. Applying a proposal changes the saved template. It does not preview anything for a client.
</Tip>

## 2. Create checklists

<Steps>
  <Step title="Open the Checklists tab">
    Go to **Settings > Projects > Templates > Checklists** and select **New Checklist**.
  </Step>
  <Step title="Add items">
    Name the checklist. Add items one at a time, select **AI Generate** and describe what you need, or select **Import** and paste one item per line. Select **Create**.
  </Step>
  <Step title="Attach it to a task">
    Open your template, expand a task, and choose the checklist in **Checklist (optional)**.
  </Step>
</Steps>

## 3. Create a draft portal

<Steps>
  <Step title="Start a new project">
    Go to **Projects** and select **New project**.
  </Step>
  <Step title="Choose the template and company">
    On the first step, pick your onboarding template, choose the **Company**, enter a **Project name**, and set the **Start date**. Select **Next**.
  </Step>
  <Step title="Name the portal and add contacts">
    Enter the **Portal name** and an optional **Description**. Add each client contact with a name, email, and role, or leave contacts empty for now. Select **Next**.
  </Step>
  <Step title="Create it">
    Review the details and select **Start onboarding**. MSPortal creates a **Draft** portal and its linked MSPortal project. Copy any invite links you want to share by hand, then select **Open project**.
  </Step>
</Steps>

<Note>
The portal name and contacts step appears only when the template's project type has **Onboarding** turned on. You can check this under **Settings > Projects > Project Settings > Project Types**. If your PSA owns project creation for the company, MSPortal creates the portal but not the project. Link the portal to a PSA project on the **Start Portal** screen, or with **Link Project** once the portal is active.
</Note>

A draft portal blocks normal client entry, but it does not undo automation or project actions. Review any onboarding automation before you create test portals. To choose several **Template Modules** or a **Portal Language**, create the portal from **Settings > Projects > Client Portals > Portals** with **Create Portal** instead. See [Managing Portals](/user-guides/client-onboarding/managing-portals#create-a-portal-from-settings).

## 4. Configure tasks

<Steps>
  <Step title="Open the task list">
    In the project, open **Project Plan > Tasks**. Review each phase and task. Portal tasks are copies of the template, so changing the template later does not change this portal.
  </Step>
  <Step title="Assign every MSP task">
    Select the assignee area on a task and choose a team member. To assign many at once, select **Reassign**, check the tasks, then select **Assign**.
  </Step>
</Steps>

<Warning>
Unassigned tasks do not appear in anyone's **My Onboarding Tasks** widget. Assign every MSP task before you go live.
</Warning>

## 5. Preview as a client

<Steps>
  <Step title="Check the overview">
    Open **Overview > MSP Dashboard**. Confirm the phases are in order, no MSP task is unassigned, and each contact's email is correct under **Team & Contacts**.
  </Step>
  <Step title="Open View as">
    In the page header, select **View as** and pick a contact. If the portal has no contacts, pick a role. On a phone, open **Actions** first.
  </Step>
  <Step title="Look around">
    The portal opens in a new tab with a **Preview mode** banner. Check the branding, visible tasks, pages, and documents. Nothing you enter in preview is saved.
  </Step>
</Steps>

**View as** works on a draft portal. It needs onboarding write access.

## 6. Go live

<Steps>
  <Step title="Start the portal">
    On **Overview > MSP Dashboard**, select **Start Portal**. The first screen asks you to link a project. If the portal already has a linked project, select **Skip**.
  </Step>
  <Step title="Send invitations">
    Check the contact count, then select **Start & Send Invites**. MSPortal queues an invitation email for each contact.
  </Step>
  <Step title="Confirm delivery">
    Under **Team & Contacts**, check each contact's **Portal access**. If an email did not arrive, open the **...** menu on the contact and choose **Send invite email**.
  </Step>
</Steps>

Clients follow [Open your onboarding portal](/user-guides/client-onboarding/open-your-onboarding) to sign in.

## What's next

- Follow progress on **Overview > MSP Dashboard** and under **Project Plan > Tasks**.
- Send reminders for overdue tasks. See [Managing Portals](/user-guides/client-onboarding/managing-portals#send-task-emails).
- Review uploads under **Files & Forms > Documents**, and reveal credentials as described in [Retrieve onboarding credentials and secure files](/user-guides/client-onboarding/retrieve-secure-submissions).
- Select **Complete Portal** when everything is done, then optionally **Convert to Client**.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| **New project** skips the portal name and contacts step | Open the template and check its **Project type**. Then confirm the type has **Onboarding** on under **Settings > Projects > Project Settings > Project Types**. |
| The portal was created but not the project | Your PSA owns project creation for that company. Link the portal to a PSA project when you start it. Do not create it again. |
| **Start Portal** opens a **Link Project** screen | Select **Skip** if the portal already has a linked project, or link one. |
| A contact did not get an email | Check the address under **Team & Contacts**, then use **Send invite email** on the contact. |
| A template change is missing from a portal | Portals copy the template when they are created. Create a new draft from the updated template. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Do I have to use AI to create a template?">
    No. Create the template and add phases and items yourself. AI only proposes changes, and you apply the ones you accept.
  </Accordion>
  <Accordion title="Does Start onboarding also start the portal?">
    No. It creates a draft. You start it later with **Start Portal**.
  </Accordion>
  <Accordion title="Can I use more than one template for a portal?">
    Yes. Create the portal from **Settings > Projects > Client Portals > Portals** and select several **Template Modules**.
  </Accordion>
  <Accordion title="Does a draft portal send anything to clients?">
    No invitations go out until you start the portal. Configured onboarding automation and project or ticket actions can still run, so review them before you test.
  </Accordion>
  <Accordion title="Does View as test a real client sign-in?">
    No. It is a read-only preview. To test real access, start the portal and open an invitation.
  </Accordion>
  <Accordion title="Can I reuse the same portal after changing the template?">
    No. Create a new draft from the updated template. Existing portals keep the phases and tasks they were created with.
  </Accordion>
</AccordionGroup>
