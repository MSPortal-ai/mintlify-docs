Use a credential handoff task when your IT provider asks for account details during onboarding. This guide is for Company contacts who have access to the task.

## Before you start

- Open the task in your [onboarding portal](/user-guides/client-onboarding/open-your-onboarding).
- If the task is **Blocked**, finish the items it lists first.
- You cannot create a credential request or reveal a submitted credential. Your provider does that.
- Your details are encrypted when you submit them, and your provider can view them once.

## Submit one set of details

<Steps>
  <Step title="Open the task">
    Read the request so you know which account or service the provider needs. If the task is blocked, complete its listed dependencies first.
  </Step>
  <Step title="Use Single mode">
    Enter the requested **Username**, **Password**, **API Key**, and **Notes**. At least one field must contain information. The Password field has a show/hide control.
  </Step>
  <Step title="Review before submitting">
    Select **Submit Credentials**. This opens a confirmation explaining that the submission cannot be edited afterward.
  </Step>
  <Step title="Confirm the handoff">
    Select **Submit** in the confirmation to send the details. Select **Cancel** if you need to return to the form. Wait for **Credentials submitted securely** before leaving.
  </Step>
</Steps>

Typing into the fields does not save a draft. Only the selected entry mode is submitted.

## Submit several credentials or a file

<Steps>
  <Step title="Choose Bulk">
    In the credential task, select **Bulk**.
  </Step>
  <Step title="Add the information">
    Paste it into **Credentials Text**, use **Choose File** to attach a file up to 10MB, or do both. Check the filename. Use the remove control if you chose the wrong file.
  </Step>
  <Step title="Submit">
    Select **Submit Credentials**, read the confirmation, and select **Submit**.
  </Step>
  <Step title="Confirm">
    Wait for **Credentials submitted securely**.
  </Step>
</Steps>

A Bulk attachment does not upload when you choose it. It is sent with the confirmed submission.

## After submission

The task displays the submitted status and, when available, the submission date. The Company view does not show the submitted values or offer an edit button. Your provider has a separate process for retrieving the handoff.

If something is wrong or missing, contact your provider and ask for a new credential handoff task. A revealed or expired submission cannot be reused.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| **Submit Credentials** is not available | Fill in at least one field in **Single** mode, or add text or a file in **Bulk** mode. Check that the task is not **Blocked** and was not already submitted. |
| "Please fill in at least one credential field." | Enter a username, password, API key, or notes. |
| "File is too large. Maximum size is 10MB." | Attach a smaller file, or split it up. |
| You entered something wrong | Ask your provider for a new credential handoff task. You cannot edit a submission. |
| The task says it was submitted but you cannot see the details | That is expected. The Company view shows status only. |
| The portal is read-only | The onboarding is completed. Contact your provider. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Where can I send passwords or API keys requested during onboarding?">
    Use the credential handoff task your provider created. Choose **Single** for named fields or **Bulk** for pasted details and an optional file. General task comments are a different workflow.
  </Accordion>
  <Accordion title="Are all fields required?">
    No. Single mode requires at least one populated field. Bulk mode requires text or a file. Supply the information your provider actually requested.
  </Accordion>
  <Accordion title="Does the task save as I type?">
    No. Select **Submit Credentials**, then confirm **Submit**. Closing or leaving an unsubmitted form does not create a saved handoff.
  </Accordion>
  <Accordion title="Does Cancel delete a previously submitted credential?">
    No. Cancel closes the confirmation before submission. The completed task does not provide a Company-side delete or edit action.
  </Accordion>
  <Accordion title="Can I read back or correct the details afterward?">
    No. The Company view shows submission status, not the values. Ask your provider for a new request if a correction is needed.
  </Accordion>
  <Accordion title="Does the submitted message mean my provider has used the credentials?">
    No. It confirms your submission. Provider retrieval and use happen separately.
  </Accordion>
  <Accordion title="Why is Submit Credentials unavailable?">
    Check that the selected mode contains information and that the task is actionable. A blocked task, existing submission, expired access, or completed workspace can prevent another submission.
  </Accordion>
</AccordionGroup>
