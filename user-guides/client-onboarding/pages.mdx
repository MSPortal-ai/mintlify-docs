Client Pages are reusable, read-only reference pages. You write a welcome message, support instructions, or a security FAQ once, attach it to your onboarding templates, and every new portal shows it. Clients read each page as an expandable article in their portal. This guide is for MSP staff.

<Note>
Client Pages and the Documentation Hub share one library. A page you create here also appears in your Documentation Hub, and editing it in either place updates the same page. See [Documentation Hub sync](#documentation-hub-sync).
</Note>

<Note>
These steps use the unified Projects experience, where the page library is under **Settings > Projects > Client Portals > Pages**. If your organization still uses the earlier experience, open **Settings > Client Onboarding > Pages** and the company's **Onboarding > Pages** tab.
</Note>

## Before you start

- You need onboarding read access to view the library. Creating or editing pages needs onboarding write access (`write_settings_onboarding`) and an active subscription. Deleting a page needs manage access (`manage_settings_onboarding`).
- Client Pages do not need an external integration.

## Add a page to the library

<Steps>
  <Step title="Open the Pages section">
    Go to **Settings > Projects > Client Portals > Pages**.
  </Step>
  <Step title="Start a new page">
    Select **Add Page** at the top right.
  </Step>
  <Step title="Fill in the page">
    Enter a **Title**, for example "How to contact support". Choose an **Icon** (**Guide**, **Support**, **Security**, **FAQ**, or **Info**). Add an optional **Section label** to group the page, for example "Support", and an optional **Summary** shown in the portal sidebar and page header. Write the client-facing text in **Page content**.
  </Step>
  <Step title="Save">
    Select **Add Page**. Typing does not save anything until you select it. To change a page later, open its **...** menu, choose **Edit page**, and select **Save Changes**. Select **Cancel** to discard an edit.
  </Step>
</Steps>

### Read the pages table

| Column | Shows |
|--------|-------|
| **Page** | Icon, title, and summary |
| **Section** | The section label. It shows **Documentation** when blank |
| **Usage** | How many templates and portals use the page, or **Not referenced** |
| **Last Updated** | When the page was last edited |

Each row has a **...** menu with **Edit page** and **Delete page**.

<Warning>
Deleting a library page removes it from every template and portal that uses it, and archives it in the shared documentation library. Check **Usage** first. A confirmation names the page.
</Warning>

## Attach pages to a template

Pages reach a portal through a template.

<Steps>
  <Step title="Open the template">
    Go to **Settings > Projects > Templates > Templates**, open the template, and choose **Pages** from the template menu.
  </Step>
  <Step title="Link a page">
    Use **Select custom page** to search the library and add a page. Pages already linked do not show again. When everything is linked you see "All custom pages are linked". Select **Manage pages** to create a page first.
  </Step>
  <Step title="Set client visibility">
    Each linked page has a **Visible to client portal** toggle. Turn it off to keep the page attached but hidden. It then shows a **Hidden** badge. Select the eye icon to preview the page.
  </Step>
</Steps>

Linking, unlinking, and visibility save on their own. They do not wait for the template's **Save Changes**.

<Info>
Templates reference library pages. They do not copy the text. Update a page once in the library and every template that links it stays current. Removing a page from a template only removes that link. The library page and existing portals are not touched.
</Info>

## Manage pages on a portal

Portals copy the template's page assignments, visibility, and fallback content when they are created. They keep the link to the library page when there is one. You can then review and adjust pages on the portal itself.

<Steps>
  <Step title="Open the portal's pages">
    Open the project and go to **Client Portal > Pages**.
  </Step>
  <Step title="Review the list">
    The left side lists **Assigned pages** with **Visible** and **Hidden** counts and a search box. The right side previews the selected page. Each page also shows how many contacts have viewed it, for example **Viewed by 2 of 3 contacts**.
  </Step>
  <Step title="Add or remove a page">
    Select the **Add page** menu. Choose **New page** to write a page just for this portal, or **Import page** to add one from your library. Select a page and choose **Remove** to take it off the portal. Removing a shared page keeps it in the library. **Edit** shows for pages that belong only to this portal.
  </Step>
  <Step title="Check the client view">
    Select **View as** in the page header and pick a contact to read the pages as that person.
  </Step>
</Steps>

A source label shows how the page behaves.

- **Shared page** follows the library. Editing the library page changes what the portal shows.
- **Portal snapshot** keeps its own saved content.

Changing a template's page links does not rebuild existing portals. Check the source label before you edit a page that clients already use.

## What clients see

Visible pages appear in a **Pages** section described as "Guides and reference information for this onboarding". Each page is an expandable article with its icon, section label, title, summary, and full content. Pages are read-only. Reading a page does not record an acknowledgment or complete a task. Hidden pages never appear. To collect a response, add a task, approval, or signature.

## Documentation Hub sync

Client Pages and Documentation Hub "inline" documents are the same record, not two synced copies.

- A page you create in **Settings > Projects > Client Portals > Pages** appears in your **Documentation Hub** library.
- An inline page you create in the Documentation Hub appears in your onboarding page library.
- Editing a page in either place updates the one shared page everywhere it is used.

Because one record can serve internal and client audiences, check **Usage** and the content before you save a change.

## Permissions

| Permission | What it allows |
|------------|----------------|
| `read_settings_onboarding` | View the page library |
| `write_settings_onboarding` | Create and edit pages, and link them to templates |
| `manage_settings_onboarding` | Delete pages |

## Troubleshooting

| Problem | What to do |
| --- | --- |
| A page is on the portal list but clients do not see it | Check that it is **Visible**, then use **View as** to see the client's view. Hidden pages still show in the MSP list. |
| An edit changed a different place too | The page is shared with the Documentation Hub and other templates. Check **Usage** before saving. |
| A template page link did not reach an existing portal | Portals copy page assignments when created. Add the page on the portal with **Add page**. |
| A page is missing from **Select custom page** | It is already linked, or it does not exist yet. Select **Manage pages** to create it. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Will editing a library page change existing client portals?">
    It changes portals that show it as a **Shared page**. A **Portal snapshot** keeps its saved content.
  </Accordion>
  <Accordion title="Does removing a page from a template delete the library page?">
    No. It removes only that template link. **Delete page** is the broader action that removes a page from the library.
  </Accordion>
  <Accordion title="Does reading a page mark onboarding complete?">
    No. Pages are references. Use a task, approval, or signature when you need a response.
  </Accordion>
  <Accordion title="Does the template's Save Changes button save page links?">
    No. Page links and visibility save on their own. The page editor has its own **Add Page** or **Save Changes** button.
  </Accordion>
  <Accordion title="Why did a page edit also change the Documentation Hub?">
    Both use the same shared page. Review every audience before you save.
  </Accordion>
</AccordionGroup>
