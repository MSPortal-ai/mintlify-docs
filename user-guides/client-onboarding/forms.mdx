Onboarding Forms are reusable data-collection forms with typed fields, such as text, select, date, and email. You build a form once and attach it to onboarding tasks, so the answers you collect are clean and consistent. You can also map fields to Hudu or IT Glue so you can create or update documentation assets from the answers. This guide is for MSP staff. Clients who fill in a form should read [Complete onboarding tasks and forms](/user-guides/client-onboarding/complete-tasks-and-forms).

<Note>
These steps use the unified Projects experience, where forms are under **Settings > Projects > Templates > Forms**. If your organization still uses the earlier experience, open **Settings > Client Onboarding > Forms**.
</Note>

<Note>
Forms replace linking a survey to a task. When a form task has a form attached, clients fill in the form. If no form is attached, the task falls back to the older inline survey.
</Note>

## Before you start

- You need onboarding read access to view forms and onboarding write access (`write_settings_onboarding`) to create, edit, and map them. Saving needs an active subscription.
- To map fields or create a form from an asset, a Hudu or IT Glue integration must be connected and synced.
- Creating assets from client answers also needs the company mapped to the Hudu or IT Glue company under **Settings > Integrations > Companies**.

## Build a form

The **Forms** workspace lists your forms on the left and the selected form's details on the right.

<Steps>
  <Step title="Open the Forms section">
    Go to **Settings > Projects > Templates > Forms**.
  </Step>
  <Step title="Create the form">
    Select **New Form**. A draft named "New Form" is saved and selected right away. Closing the page does not undo it.
  </Step>
  <Step title="Set the form details">
    In **Form Settings**, set the **Name** and an optional **Description**. For **Repeat Entries**, choose **+ One More** to let clients submit several entries, or **Single** for one.
  </Step>
  <Step title="Add fields">
    Select **Add Field** for each piece of information you want. Each click saves a new default field. Edit its label, type, and other settings.
  </Step>
  <Step title="Save">
    Select **Save** at the top of the form. It saves the form details, field edits, field order, and mapping edits. If it reports incomplete rows, complete them and save again.
  </Step>
  <Step title="Activate">
    Select **Activate** when the form is ready to attach to tasks. Save your edits first, because activation changes the status and reloads the stored form.
  </Step>
</Steps>

### What saves and when

| Action | What changes |
| --- | --- |
| **New Form** | Creates a saved draft |
| **Add Field**, or adding a provider mapping | Creates the default field or mapping right away |
| Editing form details, fields, order, or mapping targets | Waits for **Save** |
| **Save** | Saves valid edits. Incomplete rows are skipped with a warning |
| **Activate**, **Revert to draft**, **Archive**, **Restore** | Saves the status change right away |
| Deleting a field or mapping | Deletes that saved row right away |

Save before you add or delete a row, change status, or switch forms, because those actions can reload the stored form. **Save** is not all-or-nothing. If it reports an error, check the reloaded fields and mappings to see what was kept, then fix the rest.

To find archived forms, use **Show archived**. **Restore** returns a form to **Draft**, and you activate it again yourself. Archiving does not delete submitted entries. Check existing portal tasks before you change a form that is already in use.

### Field types

Each field has a **Type** that decides how clients answer it.

| Type | Use for |
|------|---------|
| **Short Text** | Names, short identifiers |
| **Long Text** | Notes, descriptions |
| **Single Select** | One choice from a list |
| **Multi Select** | Several choices from a list |
| **Yes / No** | True or false answers |
| **Date** | Dates |
| **Email** | Email addresses |
| **Phone** | Phone numbers |
| **Number** | Numeric values |
| **URL** | Web links |
| **Location** | Pick a location from the portal company |
| **Devices** | Pick devices from the portal company |
| **Contact** | Pick a contact from the portal company |
| **Content Block** | Read-only formatted text, such as instructions, terms, or a policy. Clients read it and answer nothing, unless you require acknowledgment |

Location, Devices, and Contact choices load from company data. You do not type their options. If a picker is empty, check the company and its records.

### Field settings

Each field has these settings.

- **Label** is what the client sees.
- **Required** makes an answer mandatory.
- **Placeholder** is example text in the input.
- **Help Text** is guidance under the field.
- **Options** are for select fields. Enter one option per line. Commas stay inside the option.

A **Content Block** field has its own settings instead.

- **Heading (optional)** shows above the block. Leave it blank for no heading.
- **Content** is written in a rich-text editor with bold, italics, colors, alignment, lists, and links. The client sees formatted, read-only text.
- **Require Acknowledgment** adds a checkbox under the block. The client must tick it before the form can be saved.
- **Acknowledgment Text** is the checkbox label. It shows only when acknowledgment is required. Leave it blank to use "I have read and agree".

A content block stores no answer unless acknowledgment is required, and it cannot be mapped to Hudu or IT Glue. Switching an existing field to a content block removes its mappings.

Field keys are made from labels. Give fields clear, different labels, and check existing submissions before you change the structure of a form that is in use.

<Tip>
Write labels and help text from the client's point of view. "Microsoft 365 admin email" is clearer than "M365 UPN".
</Tip>

## Mapping Fields to Hudu or IT Glue

Mapping lets a field's answers fill a documentation asset. Each field has a **Field Mappings** section.

<Steps>
  <Step title="Add a mapping">
    Under a field, select **Hudu** or **IT Glue**. This saves a default mapping right away.
  </Step>
  <Step title="Choose the target">
    Select the **Asset layout** (Hudu) or **Flexible asset type** (IT Glue), then pick the **Field Name** to map to. The options come from your synced documentation data, so you pick from drop-downs and never type IDs.
  </Step>
  <Step title="Save">
    Select **Save** at the top of the form. An incomplete mapping is skipped with a warning, so choose both the asset format and the field.
  </Step>
</Steps>

<Note>
Mapping needs synced documentation data. If you have not synced Hudu or IT Glue yet, MSPortal asks you to run the documentation integration sync first. Then return and map the fields.
</Note>

## Create a form from an asset format

<Steps>
  <Step title="Open From asset">
    On the **Forms** workspace, select **From asset**.
  </Step>
  <Step title="Pick the asset format">
    Choose a synced Hudu asset layout or IT Glue flexible asset type. The dialog shows how many fields will be created and warns about unsupported fields, such as passwords, uploads, links, and lists.
  </Step>
  <Step title="Create the form">
    Select **Create form**. This makes a draft form with the supported fields, provider mappings, and an **Asset name** field. Review required settings and any fields that were left out before you activate it.
  </Step>
</Steps>

This creates a form definition only. It does not create an external asset or copy provider records.

## Attach a form to a task

<Steps>
  <Step title="Open the task">
    In the template builder, open an item and set its **Type** to **Form / Questionnaire**.
  </Step>
  <Step title="Choose the form">
    Under **Reusable Form**, select the form. Only forms you have activated appear.
  </Step>
</Steps>

The form's **Repeat Entries** setting decides whether clients can add more entries. See [Onboarding Templates](/user-guides/client-onboarding/templates).

## Review a submitted entry before creating an asset

<Steps>
  <Step title="Open the form task">
    Open the portal's **Project Plan > Tasks** and open the form task. Select the saved entry.
  </Step>
  <Step title="Open the asset dialog">
    Select **Create asset**. If an asset already exists, select **Assets** to manage it.
  </Step>
  <Step title="Review the values">
    Check the provider, the asset format, the **Asset name**, and each field value. Edits here change only what is sent to the provider. They do not change the saved client entry.
  </Step>
  <Step title="Send it">
    Select **Create in Hudu** or **Create in IT Glue**. An asset that already exists offers **Update in Hudu** or **Update in IT Glue**.
  </Step>
</Steps>

Read the result and any warning about fields with no matching record. A **Saved** badge on the form does not mean an external asset exists. If the target is missing, check the integration, the company mapping, and the synced asset format. Re-syncing the provider and fixing a stale mapping may help. Before you try again, check whether the first attempt already worked.

## Fill in forms from a project

Forms also work on regular projects that have no onboarding portal.

<Steps>
  <Step title="Open the form area">
    Open the project and go to **Files & Forms > Forms**.
  </Step>
  <Step title="Choose a form and fill it in">
    Pick an active form and complete its fields.
  </Step>
  <Step title="Save">
    Select **Save progress** to keep a draft, or **Submit** to finish. The **Responses** table shows the saved entry. Use **Edit** to correct a response while its form is active.
  </Step>
</Steps>

To let clients fill a form in, select it and turn on **Share this form with clients**. You need **Share forms with clients** permission. Clients with project access and form permissions then see only shared forms and their own responses. Internal staff responses stay private, including ones saved before you shared the form. Turn the switch off to remove access.

Archived forms stay readable. **View** opens permitted responses read-only. **Save progress**, **Submit**, and new entries are unavailable. A project response is not sent to Hudu or IT Glue on its own. See [Project forms](/user-guides/projects/forms) for drafts, sharing, response links, and resuming an entry.

## What clients see

When a client opens a form task, the form shows inline with each field laid out by type. Required fields are marked.

- Clients fill in the fields and select **Save Form**.
- Content blocks show as formatted text across the full width. When a block requires acknowledgment, **Save Form** stays unavailable until the client ticks the checkbox. The entry records the acknowledgment as **Yes**.
- Clients wait for the save result. A **Saved** badge can stay visible while they edit, so changed values need another **Save Form**.
- If the form allows repeat entries, saved entries show as **Entry** badges and **One More** adds another.

## Permissions

| Permission | What it allows |
|------------|----------------|
| `read_settings_onboarding` | View forms |
| `write_settings_onboarding` | Create, edit, and map forms |
| `read_projects_forms` | View project forms and permitted responses |
| `write_projects_forms` | Submit and edit project responses |
| `write_projects_form_assignments` | Share or unshare forms with project clients |

## Troubleshooting

| Problem | What to do |
| --- | --- |
| **Save** reports that incomplete fields or mappings were skipped | Open the reloaded form, complete the missing labels or mapping targets, and save again. |
| **Activate** is unavailable | Enter a form name. Save your edits first. |
| A **Location**, **Devices**, or **Contact** picker is empty for the client | Check the portal company and its records. These pickers do not use options you type. |
| The **Hudu** or **IT Glue** target list is empty | Run the documentation integration sync, then return to the mapping. |
| **Create asset** fails or finds no target | Check the active integration, the company mapping under **Settings > Integrations > Companies**, and the synced asset format. |
| A client does not see a form on a project | Check that the form is shared, that the client has project access and form permissions, and that the project is visible to clients. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does New Form only open an unsaved form?">
    No. It creates and selects a saved draft. Archive it if you made it by mistake.
  </Accordion>
  <Accordion title="Do I need to save every field separately?">
    No. Use **Save** at the top for form details, field edits, order, and mapping edits. Adding or deleting a field or mapping is its own immediate change.
  </Accordion>
  <Accordion title="Does Activate also save my edits?">
    No. Save first. **Activate** changes the status and reloads the stored form.
  </Accordion>
  <Accordion title="Does saving a client response create a Hudu or IT Glue asset?">
    No. Review the entry, select **Create asset**, and choose the provider. Configured automation is a separate path.
  </Accordion>
  <Accordion title="Does From asset copy real client assets?">
    No. It creates a draft form from the synced asset format, with supported fields and mappings. It does not import records or create an asset.
  </Accordion>
  <Accordion title="Does Restore make an archived form active?">
    No. **Restore** returns it to **Draft**. Select **Activate** when you are ready.
  </Accordion>
  <Accordion title="Does changing values in Create asset alter the client's answers?">
    No. Those edits change only what is sent to the provider.
  </Accordion>
</AccordionGroup>
