A portal is an onboarding made for one company from a template. This guide shows MSP staff how to create a portal, run it day to day, and finish it. Company users should read [Open your onboarding portal](/user-guides/client-onboarding/open-your-onboarding).

<Note>
These steps use the unified Projects experience, where each portal is linked to a project. If your organization still uses the earlier experience, open the company page and use its **Onboarding** tab. Its **Overview**, **Tasks**, **Documents**, **Pages**, **Activity**, and **Settings** tabs hold the same controls.
</Note>

## Before you start

- Client Onboarding is turned on for your organization.
- You need onboarding read access to view portals. Creating or changing portals needs onboarding write access (`write_settings_onboarding`) and an active subscription. **Convert to Client** needs onboarding manage access (`manage_settings_onboarding`).
- You need a template. See [Templates](/user-guides/client-onboarding/templates).

## Find your way around a portal

Open **Projects**, choose **Project category > Onboarding projects**, and open the project. The portal's controls are spread across these places.

| What you want | Where it is |
| --- | --- |
| Status, progress, phase readiness, needs-attention list, start and complete buttons | **Overview > MSP Dashboard** |
| Tasks, statuses, assignees, reminders | **Project Plan > Tasks** |
| Client contacts, invitations, access, and your team | **Team & Contacts** |
| Client uploads and document review | **Files & Forms > Documents** |
| Forms and form responses | **Files & Forms > Forms** |
| Client pages, activity, key dates, portal settings | **Client Portal** and its **Pages**, **Activity**, **Key dates**, and **Portal settings** sections |
| Preview as a client | **View as** in the page header |

If the project has more than one portal, choose the one you want with **Portal:** at the top of the tab.

## Start from Projects

<Steps>
  <Step title="Start a new project">
    Go to **Projects** and select **New project**.
  </Step>
  <Step title="Choose the template and company">
    Pick an onboarding template, choose the **Company**, enter a **Project name**, and set the **Start date**. Select **Next**.
  </Step>
  <Step title="Name the portal and add contacts">
    Enter the **Portal name** and an optional **Description**. Add each contact with a name, email, and role, or leave contacts empty while you prepare a draft. Select **Next**.
  </Step>
  <Step title="Create it">
    Review the details and select **Start onboarding**. MSPortal creates a **Draft** portal and its linked MSPortal project. Copy any invite links you want to share by hand, then select **Open project**.
  </Step>
</Steps>

The portal name and contacts step appears only when the template's project type has **Onboarding** turned on. If your PSA owns project creation for the company, MSPortal creates the portal and tells you the project was not created. Link the portal to a PSA project when you start it. Do not run the wizard again, because that would create a second portal.

Creation also runs any configured onboarding automation. Linking a project and creating tickets are real actions, even on a draft.

## Create a portal from Settings

Use this path when you want to combine several template modules or set the portal language.

<Steps>
  <Step title="Open the portal list">
    Go to **Settings > Projects > Client Portals > Portals** and select **Create Portal**.
  </Step>
  <Step title="Choose the company">
    Search for the company and select **Continue**.
  </Step>
  <Step title="Choose the template and name the portal">
    Select one or more **Template Modules**. Review the **Portal Name**, optional description, and **Portal Language**.
  </Step>
  <Step title="Add contacts">
    Enter each contact's name, email, and an available role. Rows without both a name and an email are not saved, so check the contact list afterward. Select **Create Portal**.
  </Step>
  <Step title="Link a project">
    The portal is saved as a **Draft** first. On the **Link Project** step, choose a **Project system** and link or create a project, or select **Skip**. Copy the invite links shown, if you want to share them by hand.
  </Step>
</Steps>

If a message says a module or some configuration could not be copied, open the saved draft and check it before you try again. The portal may already exist.

## Start a portal

<Steps>
  <Step title="Open the MSP dashboard">
    Open the project and go to **Overview > MSP Dashboard**.
  </Step>
  <Step title="Select Start Portal">
    **Start Portal** shows while the portal is a **Draft**. If the portal has no linked project, the first screen is **Link Project**. Link or create a project, or select **Skip**. If a project is already linked, **Start Portal** skips that screen and goes to the confirmation.
  </Step>
  <Step title="Choose ticket creation">
    If the portal has a linked project, a checkbox offers to create a project ticket for every task that has no ticket yet. Leave it off if you only want the link.
  </Step>
  <Step title="Send the invitations">
    Select **Start & Send Invites**. This activates the portal and queues an invitation email for each contact. With no contacts, nothing is sent.
  </Step>
</Steps>

The email is queued, not delivered. Check **Team & Contacts** afterward to confirm each contact's **Portal access**.

## Portal lifecycle

| Status | What it means |
| --- | --- |
| **Draft** | Being prepared. Clients cannot open it. |
| **Active** | Live. Clients can open it and complete tasks. |
| **Completed** | You marked it finished. Clients can still read it but cannot change anything. |
| **Converted** | The company was activated and completed tasks were copied into Planner. Existing portal sessions were revoked. |
| **Archived** | Kept for history. Client access is revoked. **Restore** returns it to **Draft**. |

## Read the MSP dashboard

**Overview > MSP Dashboard** shows an **Operational snapshot** with the status, start date, current phase, progress, and key-date countdowns. Next to it you get:

- **Phase readiness**, with progress, target dates, and blockers for each phase.
- **Needs attention**, a list of overdue, blocked, and active tasks. Select one to open it.
- **Client Pages**, the pages assigned to the portal, with a **Review** link.
- A summary of open tasks, unassigned open tasks, pending decisions, action items, and hours.

The snapshot also holds the portal buttons. They appear when they apply.

| Button | Shows when |
| --- | --- |
| **Manage dates** | Always. See [Custom Dates and Countdowns](/user-guides/client-onboarding/custom-dates). |
| **Link Project** | The portal is active and has no linked project |
| **Create N tickets** or **Create N PSA tickets** | The portal has a linked project and some tasks have no ticket |
| **Start Portal** | The portal is a **Draft** |
| **Complete Portal** | The portal is **Active** |
| **Convert to Client** | The portal is **Completed** |
| **Archive** | The portal is **Completed** or **Converted** |

## Manage tasks

Open **Project Plan > Tasks**. Tasks are grouped by phase, with a count and progress bar on each phase. Use **Search tasks...** to filter.

### Change a task's status

<Steps>
  <Step title="Click the status icon">
    Select a task's status icon to move it forward from **Pending** to **In Progress** to **Completed**. Right-click it to choose any status, including **Blocked**.
  </Step>
  <Step title="Update a whole phase">
    Use **Start Phase**, **Complete Phase**, or **Reopen Phase** on the phase header. **Complete All Tasks** marks every task in the phase done at once.
  </Step>
</Steps>

To change which phases and tasks exist, edit the template and create a new draft. The Tasks view manages the work in a running portal. It does not rebuild the structure.

### Assign tasks

<Steps>
  <Step title="Open the assignee area">
    Select the assignee name, or **Unassigned**, on a task.
  </Step>
  <Step title="Choose a team member">
    Search and select a person. Choose **Clear assignment** to remove it.
  </Step>
</Steps>

To assign many tasks, select **Reassign**, check the tasks (hold Shift to select a range), then select **Assign**.

### Work with a task

Select a task to open its details. They show **Status**, **Assignment**, **Evidence**, **Due**, and **Portal comments**. For client tasks you can also choose **Which contacts can see this task?**, with **All contacts** as the default. Set phase target dates with **Set phase dates** or **Edit phase dates**. The change applies to this portal only and does not change the template.

Each task has two comment streams. Use the filter to switch between **Client-facing**, **Both**, and **Internal**.

- **Client-facing** comments are shared with the client, who can reply.
- **Internal** notes are for your team. Clients never see them.

### Send task emails

<Steps>
  <Step title="Choose what to send">
    Select **Send All Tasks** for a summary of every task, **Send Phase Email** on a phase header, or **Send reminder email** on one task.
  </Step>
  <Step title="Check the recipients">
    Review the recipients, subject, and body. You can add other email addresses and edit the text.
  </Step>
  <Step title="Send">
    Select **Send Email**.
  </Step>
</Steps>

### Schedule a meeting

<Steps>
  <Step title="Open the meeting task">
    On a **Meeting / Call** task that has no meeting yet, select the **Schedule** icon.
  </Step>
  <Step title="Set the details">
    Enter the **Subject**, **Date & Time**, and **Duration**. Add optional **Notes**.
  </Step>
  <Step title="Choose attendees">
    Check the portal contacts who should attend. You can add other email addresses.
  </Step>
  <Step title="Schedule">
    Select **Schedule Meeting**. MSPortal emails each attendee an invitation with a calendar file and shows **Meeting invite sent**. The invite has no video call link, so add a link or joining details to the **Notes** if you need them. The date and time in the email use your time zone, with the zone name, so attendees elsewhere can convert them. Use **Cancel Meeting** in the task details to cancel it.
  </Step>
</Steps>

## Review documents

Client uploads and document requests for the portal show in **Files & Forms > Documents**.

<Steps>
  <Step title="Open the request">
    Select the document request. The dialog lists each uploaded file with who uploaded it and when.
  </Step>
  <Step title="Review the file">
    Select **Download file** to open it. Select **Review**, add optional **Review notes (optional)**, then select **Approve** or **Reject**. A rejection reason shows to the client as **Needs Re-upload**.
  </Step>
</Steps>

Document statuses are **Requested**, **Uploaded**, **Approved**, and **Rejected**. Required documents that are still missing are flagged. Use **Show on portal** to control whether a document is visible to the client.

## Review pages on a portal

Open **Client Portal > Pages**. The left list shows **Assigned pages** with **Visible** and **Hidden** counts and a search box. The right side previews the selected page.

- A **Shared page** follows the library page. Editing the library page changes what the portal shows.
- A **Portal snapshot** keeps its own saved content.
- Each page shows how many contacts have viewed it, for example **Viewed by 2 of 3 contacts**.

To change what the portal shows:

<Steps>
  <Step title="Add a page">
    Select the **Add page** menu. Choose **New page** to write one for this portal, or **Import page** to pick one from your library.
  </Step>
  <Step title="Edit or remove a page">
    Select a page. **Edit** is available for pages that belong only to this portal. **Remove** takes a page off the portal. Removing a shared page keeps it in your library.
  </Step>
</Steps>

Template page assignments are copied when the portal is created. Changing a template link does not change existing portals. See [Client Pages](/user-guides/client-onboarding/pages).

## Change portal settings

<Steps>
  <Step title="Open the settings">
    Go to **Client Portal > Portal settings**.
  </Step>
  <Step title="Choose how tasks open">
    Under **Client task editing**, choose **Pop-up** or **Inline editing**.
  </Step>
  <Step title="Control what clients see ahead of time">
    Turn on **Reveal phases progressively**, **Hide blocked tasks**, or **Hide future-dated tasks** as needed.
  </Step>
  <Step title="Save">
    Select **Save Changes**, then use **View as** to check the result. These settings apply to this portal only and do not change the template.
  </Step>
</Steps>

## Review activity

Open **Client Portal > Activity** for a timeline of recorded events, plus flow diagnostics such as average task time. Use **Search activity...** to search by description, actor, or email. Use the type filter, starting at **All Types**, to show only portal, phase, task, document, contact, communication, or approval events. Select **Load more activity** for older entries.

Events include status changes, task completions, document uploads and reviews, invitations and contact access, signatures, credential submissions, meetings, comments, and questions. A recorded event shows that an action happened. It does not prove an email was delivered.

## Manage contacts

Open **Team & Contacts**. Client contacts and your own staff share one list.

### Add a contact

<Steps>
  <Step title="Add a row">
    Select **Add Contact**. A new row opens at the end of the client list.
  </Step>
  <Step title="Fill it in">
    Enter the contact's name and email. Choose a role if you want one.
  </Step>
  <Step title="Save">
    Select the check mark or press Enter. Select the cross or press Escape to discard the row. MSPortal asks before you leave with an unsaved contact.
  </Step>
</Steps>

Roles come from **Settings > Projects > Client Portals > Client roles**. They help identify each person's responsibility and can affect task visibility.

### Send, replace, or revoke access

The **Portal access** column shows **Active**, **Not signed in**, **Link expired**, or **Revoked**, with the last visit and visit count. Change a role from the **Portal role** menu on the row. Open the **...** menu on a contact for these actions.

| Action | What it does |
| --- | --- |
| **Send invite email** | Sends the access link again. It is disabled until the portal is started. |
| **Regenerate invite link** | Creates a new link. The old link and active sessions stop working. |
| **Revoke access** | Blocks the contact right away. **Restore access with new link** then appears. |
| **Remove contact** | Takes the contact off the portal and ends their sessions. |

Under **Your team**, open a staff member's **...** menu to reassign all of their portal tasks to someone else, or to unassign them.

## Preview as a client

<Steps>
  <Step title="Open View as">
    In the page header, select **View as**. On a phone, open **Actions** first. The control stays in the header on every portal section and follows the selected portal.
  </Step>
  <Step title="Pick a contact or role">
    Choose a contact. If the portal has no contacts, choose a client role under **Roles**.
  </Step>
  <Step title="Look around">
    The portal opens in a new tab with a **Preview mode** banner. Click through tasks and forms freely.
  </Step>
</Steps>

Preview works on a **Draft** portal, so you can test a template before any client is invited. Nothing you enter in preview is saved or triggers a notification. Preview needs onboarding write access. It does not test a real invitation, email verification, or a saved submission. You can also preview from the portal list under **Settings > Projects > Client Portals > Portals**.

## Review credentials, secure files, and signatures

For a credential handoff or a secure file, read [Retrieve onboarding credentials and secure files](/user-guides/client-onboarding/retrieve-secure-submissions) before you choose **Reveal & Delete** or **Download & Destroy**. Those actions use up the stored submission.

To review a signature, open the signature task. You see the signature image, the signer's name, email, IP address, and time, and a content hash you can copy. If a document was attached, the signed document is available too.

For a form task, open the saved entry. Select **Create asset** to send the values to Hudu or IT Glue, or **Assets** to manage ones you already created. See [Onboarding Forms](/user-guides/client-onboarding/forms#review-a-submitted-entry-before-creating-an-asset).

## Link a project, create tickets, and log time

Use **Link Project** to choose **MSPortal Projects** or the company's PSA. MSPortal Projects tracks work in MSPortal with no PSA. PSA choices depend on the company's PSA mapping and your PSA defaults.

### Link a portal to a project

<Steps>
  <Step title="Open Link Project">
    On **Overview > MSP Dashboard**, select **Link Project**. It shows for an active portal that has no linked project. For a draft, link on the **Start Portal** screen.
  </Step>
  <Step title="Choose the project system">
    Choose a **Project system**.
  </Step>
  <Step title="Select or create a project">
    On **Select Existing**, search and pick a project, then select **Link Project**. On **Create New**, enter a **Project Name** and optional description, then select **Create & Link**.
  </Step>
</Steps>

Linking saves right away. A badge on the overview shows the linked project with a link to open it.

### Create tickets from tasks

<Steps>
  <Step title="Open the ticket dialog">
    On the MSP dashboard, select **Create N tickets** or **Create N PSA tickets**.
  </Step>
  <Step title="Choose tasks">
    Check the tasks that need tickets. Tasks that already have a ticket are disabled.
  </Step>
  <Step title="Create">
    Select **Create**. Each selected task gets a ticket under the linked project, and its row shows the ticket number. Select the badge to open the ticket.
  </Step>
</Steps>

PSA ticket creation needs the PSA defaults below. The dialog tells you which are missing.

### Log time on a task

<Steps>
  <Step title="Open Log time">
    On a task with a linked ticket, select **Log time**.
  </Step>
  <Step title="Enter the time">
    Set **Date Worked**, **Start Time**, **End Time**, and optional **Notes**. Choose a **Billing status**, and a **Work role** and **Work type** for a PSA.
  </Step>
  <Step title="Save">
    Select **Log Time**. The entry is created on the linked ticket. A single entry cannot exceed 24 hours.
  </Step>
</Steps>

### Set PSA project defaults

Go to **Settings > Projects > Client Portals > PSA projects**. This section appears only when a PSA integration is active. Choose values from the drop-downs. They come from your synced PSA data, so you never type an ID.

| Setting | What it does |
| --- | --- |
| **Auto-create tickets** | Creates a ticket for each task when a project is linked |
| **Status sync** | Keeps ticket status in sync both ways, every 10 minutes |
| **Default billable** | New time entries default to billable |
| **Default billing status** | Billing status for new onboarding time entries |
| **Provider Defaults** | Default board or team, priority, status, and ticket type for each PSA, plus Halo category, impact, and urgency |
| **Time entry defaults** | Default work role and work type for time entries |

Select **Save Changes** when you are done. A stale ticket status can mean a sync has not finished. Check for a sync failure before you treat a ticket as complete.

## Export to Excel

**Audience:** MSP staff with onboarding access. Company users do not see the button, because the workbook includes MSP-only items and every client response.

In the earlier company workspace, open the company's **Onboarding** tab, choose the portal, and select **Export to Excel** in the page header. MSPortal downloads an `.xlsx` workbook for that portal. The export changes nothing in the portal.

<img src="/images/product/onboarding-portal-export-excel-button-branch-preview.png" alt="Export to Excel button in the company onboarding header" width="1304" height="110" />

In the unified experience, the **Export to Excel** button in the project header exports the project workbook. See [Export a project to Excel](/user-guides/projects/export-project-to-excel).

The portal workbook always has an **Overview** sheet. Other sheets appear only when the portal has rows for them.

| Sheet | Contents |
| --- | --- |
| **Overview** | Company, status, progress, start, completion and conversion dates, linked project, a phase summary with target dates and completed items, key dates, client contacts with last access and visit count, and a linked list of the other sheets. |
| **Items** | Every task, document, approval and standalone survey in phase order, with type, owner, assignee, status, required and client-visible flags, priority, milestone, due, started and completed dates, estimated and actual hours, linked ticket, comment count and description. A **Total** row sums hours when any item has them. |
| **Responses** | What the client and your team entered: checklist items with who checked them, form answers per entry, text responses, signatures, approval decisions with notes, and survey answers. |
| **Documents** | Requested documents with status, uploaded file names, uploader, review date, review notes and external link. |

<img src="/images/product/onboarding-portal-excel-items-sheet-branch-preview.png" alt="Items sheet of an exported onboarding workbook" width="1990" height="468" />

Each data sheet has a frozen, filterable header row. Files stay in MSPortal and the workbook lists their names. Credentials and secure file contents are never exported. The workbook uses your tenant's brand color and your current language. To export the plan rather than a client's progress, use the **Excel** tab in the template's **Import / Export** dialog. See [Templates](/user-guides/client-onboarding/templates#import--export).

## Complete, convert, and archive a portal

<Steps>
  <Step title="Review the work">
    Check that tasks are complete and documents are approved.
  </Step>
  <Step title="Complete the portal">
    On **Overview > MSP Dashboard**, select **Complete Portal** and confirm. This marks the portal finished. It does not complete open tasks or approve documents. Clients keep a read-only view.
  </Step>
  <Step title="Convert the client (optional)">
    With onboarding manage access, select **Convert to Client**. This activates the company, copies completed onboarding tasks into Planner, marks the portal **Converted**, and revokes current portal sessions. Review the completed work first.
  </Step>
  <Step title="Archive when you no longer need it">
    Select **Archive** and confirm. Archiving revokes all client sessions. The data is kept.
  </Step>
</Steps>

## Manage portals from Settings

**Settings > Projects > Client Portals > Portals** lists every portal across companies. Filter by **All**, **Active**, **Draft**, **Finished**, or **Archived**, search by name, and select a portal to see its detail.

| Action | What it does |
| --- | --- |
| **Open** | Opens the portal |
| **View as** | Opens a client preview |
| **Archive** | Revokes all client sessions. Data is kept and you are asked to confirm. |
| **Restore** | Returns an archived portal to **Draft** |
| **Delete** | Permanently removes the portal with its phases, tasks, documents, and contacts. You are asked to confirm. |

<Warning>
**Archive** takes effect immediately. Clients lose access until you restore and start the portal again. **Delete** cannot be undone.
</Warning>

## Use the dashboard widgets

Your MSP dashboard shows two onboarding widgets when you have onboarding access and active portals exist.

- **Active Onboarding** shows a tile for each active portal with the company, portal name, and a progress bar. Select a tile to open the portal.
- **My Onboarding Tasks** lists the onboarding tasks assigned to you across active portals. Select a task to open it.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| A completed portal still lets nobody edit | That is expected. **Completed** portals are read-only. Archive and restore it only if you need to reopen it as a draft. |
| **Restore** did not reopen the portal to clients | **Restore** returns the portal to **Draft**. Review it and select **Start Portal** again. |
| A template change is not in this portal | Portals copy the template when created. Create a new draft. |
| Two contacts see different tasks | Check each contact's role, the task's **Visibility**, and **Portal settings**. Use **View as** for each. |
| There is no PSA project option | Check the company's PSA mapping, the active PSA integration, and your permissions. **MSPortal Projects** is the native option. |
| A creation or ticket error left a partial result | Open the saved portal and check its modules and existing tickets. Retry only what is missing. |
| **Send invite email** is disabled | The portal is still a **Draft**. Start it first. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Completed mean every task passed?">
    No. **Complete Portal** is your decision. Check open tasks, evidence, and documents before you confirm.
  </Accordion>
  <Accordion title="Is Convert to Client only a status change?">
    No. It activates the company, copies completed tasks into Planner, marks the portal converted, and revokes current sessions. It needs onboarding manage access.
  </Accordion>
  <Accordion title="Can I undo a new portal by closing the project dialog?">
    No. **Start onboarding** or **Create Portal** already saved the draft. A project link or new project also stays once its action succeeds.
  </Accordion>
  <Accordion title="Can I safely open a credential to see if it arrived?">
    No. Opening the task only shows its status. **Reveal & Delete** and **Download & Destroy** use up the submission. Read the retrieval guide first.
  </Accordion>
  <Accordion title="Why do I see the Link Project screen when I start a portal?">
    The portal has no linked project yet. Link or create one, or select **Skip**. A portal that already has a project goes straight to the confirmation.
  </Accordion>
  <Accordion title="Does Schedule Meeting create a video call?">
    No. It emails a calendar invite with no video link. Add a link to the **Notes** if attendees need one.
  </Accordion>
</AccordionGroup>
