**Audience:** MSP staff configuring and managing client onboarding. Company users should start with [Open your onboarding portal](/user-guides/client-onboarding/open-your-onboarding).

## Before you begin

Your organization must have Client Onboarding enabled. Viewing requires onboarding read access; creating or changing templates and portals requires onboarding write access and active billing. **Convert to Client** requires onboarding management access. Your role and company scope can limit what appears.

Portals are onboarding instances launched for a specific company. When you create a portal from a template, it copies the template's phases and tasks into a draft workspace where you track progress, communicate with clients, and manage the onboarding process.

## Launching a Portal

<Steps>
  <Step title="Open the Company Page">
    Navigate to the company you want to onboard and click the **Onboarding** tab.
  </Step>
  <Step title="Start Onboarding">
    Click **Start Onboarding**. Select one or more **Template Modules**, then review **Portal Name**, description, and **Portal Language**.
  </Step>
  <Step title="Add Client Contacts">
    Add the client contacts who will access the portal. Enter their name, email, and an available role. Contacts may be left empty while preparing a draft. Incomplete name/email rows are not included, so check the saved contact list.
  </Step>
  <Step title="Create and review the draft">
    Click **Create Portal**. The draft is saved before the **Link Project** step. Choose a project system and link or create a project if needed, or click **Skip**. Review any module/configuration warning in the saved draft before trying again.
  </Step>
  <Step title="Activate the Portal">
    On **Overview**, click **Start Portal**. Review or skip project linking, check the contact count and ticket-creation option, then confirm **Start & Send Invites**. This activates the portal and queues invitation emails; it is not a delivery receipt.
  </Step>
</Steps>

<Note>
Portal creation saves a **Draft** first. It also runs configured creation automation. Project linking and ticket creation are real actions even before activation. Closing a later dialog does not undo a draft or project link that has already been saved.
</Note>

## Portal Lifecycle

Portals move through these stages:

| Status | Description |
|--------|-------------|
| **Draft** | Being configured, not yet visible to clients |
| **Active** | Live — clients can access and complete tasks |
| **Completed** | Marked finished by staff; clients can view but cannot modify the portal. The status does not prove every task or document was reviewed. |
| **Converted** | Conversion activates the company, copies completed tasks into Planner, and revokes existing portal sessions. It does not perform a general migration to external systems. |
| **Archived** | Retained historical portal with client access revoked; Restore returns it to Draft |

## The Onboarding Tab

The company onboarding page has six tabs for managing the portal: **Overview**, **Tasks**, **Documents**, **Pages**, **Activity**, and **Settings**. Where a company has multiple portals, select the intended portal on Overview and confirm its name before making changes.

### Overview Tab

The main dashboard showing:

- **Portal status** with progress percentage
- **Phase-by-phase progress bars** showing completion
- **Task summary** with counts by status
- **Quick actions** for managing the portal lifecycle

The Overview action bar is also where you open **Manage dates** (custom milestones and the portal countdown) and link an **MSPortal or PSA project**. See [Custom Dates and Countdowns](/user-guides/client-onboarding/custom-dates).

### Tasks Tab

The primary workspace for managing onboarding tasks.

#### Status Legend

At the top, a legend shows the four task statuses with their icons:

- **Pending** (circle) — Not yet started
- **In Progress** (clock) — Work underway
- **Completed** (checkmark) — Done
- **Blocked** (lock) — Waiting on a dependency

<Tip>
Click a task's status icon to cycle it forward (pending → in progress → completed). Right-click to choose any status from a dropdown menu.
</Tip>

#### Phase Accordions

Tasks are grouped by phase in expandable accordions. Each phase header shows:

- Phase name and status badge
- Task completion count (e.g., "3 of 7 completed")
- Progress bar

Click a phase to expand it and see all tasks within.

Each phase header also has status controls: **Start Phase**, **Complete Phase**, **Reopen Phase**, and **Complete All Tasks** to mark every task in the phase done at once.

<Note>
The Tasks tab manages an active portal's work — task and phase status, assignments, reminders, evidence, and comments. To change the structure (add, rename, reorder, or remove phases and tasks), edit the template before launching the portal.
</Note>

#### Task Rows

Each task row displays:

- **Status icon** — Click to update, right-click for all options
- **Task title** — With evidence type badge (signature, credentials, meeting, etc.)
- **Owner badge** — MSP or Client
- **Due date** — Red if overdue, amber if due within 3 days
- **Assigned user** — Who is responsible
- **Priority indicator** — For high and critical tasks

Click a task row to expand its detail panel, which shows:

- Evidence content (signatures, credentials, uploaded files, form responses)
- Task description
- Comment threads — both client-facing comments and internal notes
- Checklist items (if attached)

#### Task Comments and Internal Notes

Each task has two separate conversation streams:

- **Client-facing comments** — shared between your team and the client. Both sides can post and read, enabling back-and-forth without leaving the portal.
- **Internal notes** — visible only to your MSP team for tracking work, blockers, or handoff notes. Clients never see these.

A toggle (**Client-facing** / **Both** / **Internal**) controls which stream you're viewing. A small indicator on each task shows the comment count and who posted last, color-coded by author so you can spot tasks awaiting a reply.

#### Task Assignment

Assign tasks to MSP team members individually:

<Steps>
  <Step title="Click the Assignee Area">
    Click the assignee name or "Unassigned" on any task row.
  </Step>
  <Step title="Select a User">
    Search and select a team member from the dropdown.
  </Step>
</Steps>

For bulk reassignment, click **Reassign** in the toolbar to enter selection mode. Use checkboxes (with shift-click for range selection) to select multiple tasks, then assign them all at once.

#### Sending Task Emails

Send task summary emails to client contacts:

- **Send All Tasks** — Emails a complete summary of all tasks with status and due dates
- **Send Phase Tasks** — Emails tasks for a specific phase only
- **Send Task Reminder** — Send a reminder for an individual task

Each email includes task descriptions, status badges, due dates, and a link back to the portal.

### Documents Tab

The **document review queue** where you triage files uploaded by clients. Summary tiles across the top show counts for **Uploaded** (needs review), **Approved**, **Requested** (still required), and **Rejected**. Documents are grouped by phase.

- **Search** — find documents by name, phase, or original filename
- **Filter by status** — All Documents, Requested, Uploaded, Approved, or Rejected (each shows a count)
- **Review** — for an uploaded document, click **Review**, optionally add notes, then **Approve** or **Reject**
- **Download** — open the **Files** panel to download each uploaded file (with uploader and upload date)

Required documents that haven't been uploaded are flagged so you can see what's still outstanding.

### Pages Tab

A review view of the **Client Pages** attached to this portal. The left pane lists the portal's assigned pages with **Visible** and **Hidden** counts and a search box; the right pane previews the selected page. A source badge shows whether a page is still a **Shared page** (linked to your library) or a **Portal snapshot**, and the **View as** dropdown opens the client portal as a specific contact so you can read the pages in place.

Pages are copied into a portal from the template when it's created. To change which pages appear, edit the template's Client Pages before launching. See the [Client Pages guide](/user-guides/client-onboarding/pages).

### Settings Tab

Configure this portal's client display sections and task interaction mode, then click **Save Changes**. These settings apply to this portal rather than changing the template defaults. Use **View as** afterward to check the result for the relevant contact or role.

### Activity Tab

Recorded portal activity, with server-side search and type filtering. A recorded event is useful evidence of an action, but is not by itself proof of email delivery or successful storage of a downloaded file.

Events tracked include:

- Portal and phase status changes
- Task completions and assignments
- Document uploads, approvals, and rejections
- Contact access and invitations
- Signatures and credential submissions
- Meeting scheduling
- Comments and questions

Use the **search bar** to find events by description, actor name, or email. Use the **type filter** dropdown to show only specific event categories (Portal, Phase, Task, Document, Contact, etc.).

**Audience:** MSP staff with onboarding access. Company users do not see the button, because the workbook includes MSP-only items and every client response.

Open the company's **Onboarding** tab, pick the portal in the **Portal** selector if the company has more than one, and choose **Export to Excel** in the page header. The button appears on every onboarding tab. MSPortal downloads an `.xlsx` workbook for the selected portal. The export changes nothing in the portal.

The workbook always has an **Overview** sheet. Other sheets appear only when the portal has rows for them.

| Sheet | Contents |
| --- | --- |
| **Overview** | Company, status, progress, start, completion and conversion dates, linked project, a phase summary with target dates and completed items, key dates, client contacts with last access and visit count, and a linked list of the other sheets. |
| **Items** | Every task, document, approval and standalone survey in phase order, with type, owner, assignee, status, required and client-visible flags, priority, milestone, due, started and completed dates, estimated and actual hours, linked ticket, comment count and description. A **Total** row sums hours when any item has them. |
| **Responses** | What the client and your team entered: checklist items with who checked them, form answers per entry, text responses, signatures, approval decisions with notes, and survey answers. |
| **Documents** | Requested documents with status, uploaded file names, uploader, review date, review notes and external link. |

<img src="/images/product/onboarding-portal-excel-items-sheet-branch-preview.png" alt="Branch preview: Items sheet of an exported onboarding workbook" width="1990" height="468" />

Each data sheet has a frozen, filterable header row. Files stay in MSPortal; the workbook lists their names. Credentials and secure file contents are never exported. The workbook uses your tenant's brand color and your current language.

To export the plan rather than a client's run through it, use the Excel tab in the template's **Import / Export** dialog. See [Templates](/user-guides/client-onboarding/templates).

## Contact Management

Manage who has access to the client portal.

### Adding Contacts

<Steps>
  <Step title="Open the Contact List">
    In the portal overview, find the contacts section.
  </Step>
  <Step title="Add a Contact">
    Click **Add Contact** and enter the contact's name, email, and role.
  </Step>
  <Step title="Send Invite">
    After activation, use **Send invite email** on the contact to send their access link. The draft portal disables this control until it is started. Adding a contact is a separate save.
  </Step>
</Steps>

### Contact Roles

Select an available client role configured by your MSP. Roles help identify responsibility and can affect task visibility or assignment. Common examples include:

- Primary Contact
- IT Contact
- Decision Maker
- Finance Contact
- Office Manager

### Managing Access

- **Send invite email** — Send the access link again if the contact lost it
- **Revoke Access** — Immediately disable a contact's portal access
- **Regenerate invite link** — Create a replacement access link; the previous link and active sessions are invalidated. Share the replacement deliberately.

Contact activity is tracked — you can see when each contact last accessed the portal and how many times.

### Previewing as a Client

Use the **View as** dropdown to open the client portal using a selected contact or role context. It appears in three places:

- The portal's **Overview** tab
- The portal's **Pages** tab
- The portal list under **Settings > Onboarding**

Pick a contact from the dropdown, and the portal opens in a new tab in an MSP preview with that contact's visibility context. If the portal has no contacts yet, preview by **role** instead.

**Preview works on Draft portals.** You do not have to start the portal or send invites to see what clients will get, which makes this the right way to test a template before it reaches a real client. Build the template, create a Draft portal on a test or internal company, then **View as**.

<Note>
Preview sessions are **read-only**. The portal shows a "Preview mode" banner and nothing you enter is saved, so you can click through tasks and forms freely without recording progress or triggering notifications. Preview requires onboarding write permission. It does not test a real client invitation, email verification, or saved submission.
</Note>

## Meeting Scheduling

Schedule meetings directly from meeting-type tasks.

<Steps>
  <Step title="Click Schedule Meeting">
    On a meeting task, click **Schedule Meeting**.
  </Step>
  <Step title="Set Meeting Details">
    Enter the date, time, duration, and optional description. Add a meeting link if using a specific platform.
  </Step>
  <Step title="Select Attendees">
    Choose from portal contacts and optionally add external attendees by email.
  </Step>
  <Step title="Send Invitations">
    Click **Schedule** to send calendar invitations (ICS) via email to all attendees.
  </Step>
</Steps>

## Credential & Signature Review

### Reviewing Credentials

When a client submits credentials through a credential handoff task:

1. Open the task detail panel.
2. Read [Retrieve onboarding credentials and secure files](/user-guides/client-onboarding/retrieve-secure-submissions) before choosing **Reveal & Delete** or **Download & Destroy**.
3. Prepare to retain the returned information securely. These actions consume the stored submission; opening a task does not retrieve it.

### Reviewing Signatures

When a client signs a signature task:

1. Open the task detail panel to view the signature image
2. See signer details: name, email, IP address, and timestamp
3. If a document was attached, the signed document is also available

## PSA Integration

Use **Link Project** to choose **MSPortal Projects** or the company's available PSA project system. MSPortal Projects supports native project tracking without a PSA. Provider availability, company mapping, permissions, and PSA defaults determine external options.

**Link Project** and **Create & Link** save when used; they are not unsaved selections awaiting portal activation. Creating tickets is another write action in the chosen project system. Review the target and selected tasks first.

### Linking a Portal to a PSA Project

<Steps>
  <Step title="Open the Portal Overview">
    Navigate to the company's onboarding tab and open the active portal.
  </Step>
  <Step title="Choose a project system">
    In the overview actions, click **Link Project** and choose the intended **Project system**.
  </Step>
  <Step title="Choose an Option">
    - **Select Existing**: Search for and select an existing project in the chosen system, then use the link action
    - **Create New**: Enter a project name and description, then use the create-and-link action to save a project in the chosen system
  </Step>
</Steps>

Once linked, a PSA project badge appears on the portal overview showing the linked project name with a direct link to your PSA.

### Creating PSA Tickets from Tasks

Convert onboarding tasks into PSA tickets to track them in your ticketing workflow.

<Steps>
  <Step title="Open Bulk Create">
    Click the available **Create … tickets** or **Create … PSA tickets** action. This opens a dialog listing all tasks.
  </Step>
  <Step title="Select Tasks">
    Check the tasks you want to create tickets for. Tasks that already have linked PSA tickets are shown but disabled.
  </Step>
  <Step title="Create Tickets">
    Click **Create**. MSPortal creates a ticket in your PSA for each selected task under the linked project. Each task gets a badge showing the PSA ticket number.
  </Step>
</Steps>

Click any task's PSA ticket badge to open the ticket directly in your PSA.

### Logging Time

Log time entries against onboarding tasks directly from the portal.

<Steps>
  <Step title="Click the Clock Icon">
    On any task with a linked PSA ticket, click the time entry icon.
  </Step>
  <Step title="Enter Time Details">
    Fill in duration, description, and whether the time is billable. Billable defaults are configurable in Settings > Onboarding.
  </Step>
  <Step title="Submit">
    The time entry is created in your PSA under the linked project and ticket.
  </Step>
</Steps>

<Note>
PSA integration works with Halo PSA, ConnectWise Manage, and Autotask. For PSA tickets and time entries, the portal must be linked to the corresponding PSA project. Native project tracking is a separate available target; do not assume external provider behavior applies to it.
</Note>

### PSA Project Defaults

Set tenant-wide defaults for how onboarding portals connect to your PSA in **Settings > Onboarding > PSA Projects** (this tab appears only when a PSA integration is active). You can configure:

- **Auto-create tickets** — create a ticket for each task when a project is linked
- **Status sync** — keep ticket status in sync bi-directionally
- **Default billable** — whether new time entries default to billable
- **Provider defaults** — the default board/team, priority, status, and ticket type per connected PSA (plus Halo category, impact, and urgency)

All values are chosen from dropdowns populated from your synced PSA data — there are no IDs to type.

<Info>
When **Status sync** is enabled, linked ticket updates depend on successful background synchronization. Allow for a delay and investigate a failed sync before treating stale status as completion.
</Info>

## Completing a Portal

When all tasks and phases are complete:

<Steps>
  <Step title="Review Completion">
    Verify all tasks show as completed and all documents are approved.
  </Step>
  <Step title="Complete the Portal">
    Click **Complete Portal** in the overview actions and confirm. This marks the portal as finished; it does not automatically complete every outstanding task or approve every document. Clients retain a read-only view.
  </Step>
  <Step title="Convert (Optional)">
    With onboarding management access, **Convert to Client** activates the company, copies completed onboarding tasks into Planner, marks the portal converted, and revokes current portal sessions. This is a data-changing operation, not just a new label or a migration into every external tool. Review the completed work before selecting it.
  </Step>
</Steps>

## Managing Portals from Settings

The portal list in **Settings > Onboarding > Portals** provides a centralized workspace across companies. Use the status filters and search to select a portal, inspect its detail, and open its actions. Available actions depend on its status:

- **Open** — Navigate to the company's onboarding page for this portal
- **Archive** — Deactivate the portal and revoke all client sessions. Portal data is preserved but clients can no longer access it. A confirmation dialog explains the impact before proceeding.
- **Restore** — Return an archived portal to draft status so it can be reactivated. Only available for archived portals.
- **Delete** — Permanently remove the portal and all associated phases, tasks, documents, and contacts. This action cannot be undone. A confirmation dialog requires explicit approval.

<Warning>
**Archiving** revokes all active client sessions immediately. Clients will lose access to the portal until it is restored and reactivated. **Deleting** is permanent and removes all portal data.
</Warning>

## Dashboard Integration

Your MSP dashboard shows onboarding information in two places:

- **Active Onboarding Banner** — Quick-link pills showing each active portal with company name, portal name, and a progress bar. Click to jump directly to the portal.
- **My Onboarding Tasks Widget** — A card showing your personally assigned onboarding tasks across all active portals, ordered by phase and task order. Click any task to go to its portal.

Both are visible only when you have onboarding permissions and there are active portals.

## Best Practices

<AccordionGroup>
  <Accordion title="Start with a draft">
    Create portals in draft mode first. Review the tasks, adjust descriptions for the specific client, and add contacts before activating. This avoids sending premature invitations.
  </Accordion>
  <Accordion title="Assign tasks early">
    Assign MSP tasks to specific team members as soon as the portal goes active. This ensures tasks appear in everyone's dashboard widget.
  </Accordion>
  <Accordion title="Use the activity feed">
    Check the activity feed regularly to stay informed about client progress. You can see exactly when contacts access the portal and complete tasks.
  </Accordion>
  <Accordion title="Send task summaries proactively">
    Don't wait for clients to log in. Use the email features to send task summaries and reminders, especially for overdue items.
  </Accordion>
  <Accordion title="Review documents promptly">
    Clients see document status in their portal. Leaving documents in "pending review" for too long creates a poor experience — aim to review within 24 hours.
  </Accordion>
</AccordionGroup>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Completed mean every task passed?">
    No. Complete Portal is an explicit staff decision. Review outstanding tasks, required evidence, and document approvals before confirming.
  </Accordion>
  <Accordion title="Can clients edit a completed portal?">
    No. Completion leaves a read-only view. Archive and conversion also affect access and existing sessions.
  </Accordion>
  <Accordion title="Is Convert to Client only a status change?">
    No. It activates the company, copies completed tasks into Planner, marks the portal converted, and revokes current portal sessions. It requires onboarding management access.
  </Accordion>
  <Accordion title="Does Restore immediately reopen an archived portal to clients?">
    No. Restore returns the portal to Draft. Review the restored configuration and contacts before starting it again.
  </Accordion>
  <Accordion title="Will changing a template rebuild this portal?">
    No. Its phases and tasks are copies. Review structural template changes in a new draft; check Shared page versus Portal snapshot when reviewing library pages.
  </Accordion>
  <Accordion title="Can I close project setup to undo a new portal?">
    No. Create Portal already saved the draft. Project linking or creation also persists when its action succeeds.
  </Accordion>
  <Accordion title="Why do two contacts see different tasks?">
    Review contact roles, item visibility, ownership, and the portal Settings tab. Use View as to inspect each context; a preview does not prove real client access.
  </Accordion>
  <Accordion title="Why is there no PSA project option?">
    Check the company mapping, active PSA integration, and permissions. MSPortal Projects is the native alternative when offered. Configure required PSA defaults before requesting external tickets.
  </Accordion>
  <Accordion title="What should I do after a partial creation or ticket error?">
    Inspect the saved portal, copied modules, and existing linked tickets first. Retry only the missing work to avoid creating another portal or duplicating tickets.
  </Accordion>
  <Accordion title="Can I safely open a credential to see whether it arrived?">
    Opening the task is separate from retrieval. Reveal & Delete and Download & Destroy consume submissions. Follow the secure retrieval guide and prepare secure local retention before using them.
  </Accordion>
</AccordionGroup>
