Custom dates capture the key milestones of one onboarding portal, such as kickoff, hardware delivery, go-live, or the end of a trial. Mark one date as the countdown and the portal shows the days remaining. This guide is for MSP staff. Clients can see the dates but cannot change them.

<Note>
These steps use the unified Projects experience. If your organization still uses the earlier experience, open the company's **Onboarding** tab and select **Manage dates** on **Overview**.
</Note>

## Before you start

- You need onboarding read access to view dates. Adding, editing, and deleting dates needs onboarding write access (`write_settings_onboarding`) and an active subscription.
- You need an onboarding portal. See [Managing Portals](/user-guides/client-onboarding/managing-portals).

## Why use custom dates

- Anchor the onboarding to a deadline so clients know when it must be done.
- Track milestones beyond the built-in portal status.
- Show clients a days-remaining counter.
- Start every portal with the same milestones from your template.

## Open the dates manager

Use either entry point. Both edit the same dates.

<Steps>
  <Step title="Open the project">
    Go to **Projects**, choose **Project category > Onboarding projects**, and open the project.
  </Step>
  <Step title="Choose where to edit">
    Select **Client Portal > Key dates** to edit in place. Or go to **Overview > MSP Dashboard** and select **Manage dates** to edit in a dialog.
  </Step>
</Steps>

Each date shows in a list. The date marked as the countdown has a **Countdown** badge. A date with no target shows **No date set**.

## Add a date

<Steps>
  <Step title="Start a new date">
    Select **Add Date**.
  </Step>
  <Step title="Fill in the fields">
    Enter a **Label** (required), such as "Go-Live" or "Hardware Delivery". Add a **Description** if you want one. Choose a **Target Date**, or leave it empty if you have not agreed on one.
  </Step>
  <Step title="Choose the countdown">
    Turn on **Show countdown** to use this date as the portal countdown. Only one date per portal can have it on. Turning it on for another date and saving clears it from the earlier date.
  </Step>
  <Step title="Save">
    Select **Add Date** to create it, or **Save Changes** when you edit an existing one. Wait for the success message. **Cancel** discards the edit.
  </Step>
</Steps>

Each date saves on its own. There is no separate save for the whole list. Closing the dialog does not save an edit you have not submitted.

## Edit or delete a date

<Steps>
  <Step title="Edit a date">
    Select **Edit date** on the row. Change the label, description, target date, or countdown, then select **Save Changes**.
  </Step>
  <Step title="Delete a date">
    Select **Delete date** on the row, then select **Delete** to confirm. Deleting a date does not remove portal tasks or phases.
  </Step>
</Steps>

## How the countdown shows

A date with a target date shows how far away it is.

- **Today** or **Due today** on the target date.
- **N days left** before the target date.
- **N days overdue** after it.

A date with no target date cannot show a countdown. A countdown counts calendar days and does not tick like a clock. An overdue date does not complete, block, or reschedule any task. If a save fails when you switch the countdown to another date, check both rows and set the one you want.

## What clients see

The client portal's overview shows up to three key dates as tiles. Each tile has the label, the days left, due today, or days overdue, and the target date. The countdown date comes first, then the others by how soon they are. Dates with no target date are not shown. Clients never see edit controls or internal fields such as template references and timestamps.

To check the client view, select **View as** in the page header and pick a contact.

## Add dates to a template

Template dates give every new portal the same milestones. They use an offset in days from the portal start instead of a fixed date.

<Steps>
  <Step title="Open the template">
    Go to **Settings > Projects > Templates > Templates**, open a template, and choose **Dates** from the template menu.
  </Step>
  <Step title="Add a date">
    Select **Add Date**. Enter a **Label**, an optional **Description**, and **Offset from portal start (days)**. Leave the offset blank to fill the date in by hand on each portal.
  </Step>
  <Step title="Choose a default countdown">
    Turn on **Show countdown** for the date new portals should count down to. Only one date per template can have it on.
  </Step>
</Steps>

For example, "Kickoff = day 0, Hardware = day 14, Go-Live = day 45" gives every new portal those milestones. The offsets turn into real dates when the portal is created. A draft that you start days later does not shift its dates, so check the dates before you start the portal. Existing portals are not affected when you change the template dates.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| No countdown shows for clients | Check that **Show countdown** is on and the date has a **Target Date**. Then use **View as** to check the client view. |
| A milestone is not visible to the client | The client overview shows only three dates with a target date. Add a target date, or turn on the countdown for the one that matters most. |
| Template dates are blank on a new portal | The template date has no offset. Set the **Target Date** on the portal. |
| Moving a date did not move tasks | Dates are separate from tasks. Change task due dates under **Project Plan > Tasks**. |
| The wrong date has the countdown | Turn **Show countdown** on for the date you want and save. The earlier one clears. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can I save a milestone without choosing its date?">
    Yes. Leave **Target Date** empty. It cannot show a countdown until it has a date.
  </Accordion>
  <Accordion title="Does closing the dialog save my edit?">
    No. Select **Add Date** or **Save Changes** and wait for success. **Cancel** discards the edit. Dates you already saved stay.
  </Accordion>
  <Accordion title="Will starting a draft later move its template dates?">
    No. Offsets are worked out when the portal is created. Edit the target dates before you start the portal if the schedule changed.
  </Accordion>
  <Accordion title="Does moving a milestone reschedule tasks?">
    No. A key date is a separate record. Review task due dates and dependencies on their own.
  </Accordion>
  <Accordion title="Does an overdue countdown mean onboarding failed?">
    No. It shows how many calendar days have passed since the date. Check task progress and blockers separately.
  </Accordion>
</AccordionGroup>
