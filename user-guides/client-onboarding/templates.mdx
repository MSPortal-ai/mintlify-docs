Templates are reusable blueprints for your onboarding process. Each template holds phases (stages) and tasks (action items) that are copied into a portal when you create an onboarding for a client. This guide is for MSP staff.

<Note>
These steps use the unified Projects experience, where templates live under **Settings > Projects > Templates**. If your organization still uses the earlier experience, open **Settings > Client Onboarding** instead.
</Note>

## Before you start

- Client Onboarding is turned on for your organization.
- You need onboarding read access to view templates. Creating or changing them needs onboarding write access (`write_settings_onboarding`) and an active subscription.
- Create forms, checklists, and client pages first if you want to attach them to tasks.

## Create a template

<Steps>
  <Step title="Open the template list">
    Go to **Settings > Projects > Templates > Templates** and select **New Template**.
  </Step>
  <Step title="Enter the details">
    Enter a **Name**. Add a **Description**, **Tags**, and **Duration (days)** if you want them. Leave **Project type** on **Client onboarding (default)** so projects created from this template get a client portal. Other project types build a plain project without one.
  </Step>
  <Step title="Create the template">
    Select **Create Template**. You can add phases only after the template exists.
  </Step>
  <Step title="Add phases">
    Select **Add Phase** and name it, for example **Discovery**, **Setup**, **Training**, or **Go Live**. Drag phases to reorder them.
  </Step>
  <Step title="Add tasks to each phase">
    Inside a phase, select **Add Item**. Enter a **Title**, then choose the **Type**, **Owner**, and any other settings described below.
  </Step>
  <Step title="Save the details">
    Select **Save Changes** after you edit the name, description, tags, duration, or invitation email. Phase and item changes save as you work.
  </Step>
</Steps>

<Tip>
Keep phases high level. Three to six phases work well. Put the detailed steps in tasks.
</Tip>

### What saves and when

| Change | When it saves |
| --- | --- |
| New template details | **Create Template** |
| Name, description, tags, duration, invitation email, and portal display defaults of an existing template | **Save Changes** |
| A new phase | **Add Phase** saves it right away |
| Phase edits, item fields, and ordering | Each control saves on its own. Text can save after you pause typing |
| Dependencies | Choosing or removing a dependency saves it |
| AI proposals | **Apply** saves the changes you accepted |
| Template dates and client pages | Their own add, edit, and remove controls |

**Save Changes** does not commit the whole builder. If an item fails to save, stay on the page, note the error, and reopen the item to check what was stored before you create a portal. A new item needs a title before it can save.

## Task types

Each item has a **Type** that decides what the client or your team does. Pick it when you add the item.

| Type | What it does | Use for |
| --- | --- | --- |
| **Task** | A basic task. The assignee marks it complete. Attach a checklist for sub-items | General action items, internal setup steps, verification |
| **Text Response** | The assignee types a response before marking it complete | Questions that need a written answer |
| **Document Upload** | Requests files. Uploads go through upload, review, and approve or reject | Insurance certificates, network diagrams, vendor contracts |
| **Document Link** | Points to an existing reference article or URL. It does not request an upload | Shared guides and reference documents |
| **Approval** | Asks for an approve or reject decision. You can attach a PDF to the portal task for review | Budget approvals, scope sign-offs, change requests |
| **Signature / Contract** | The client draws a signature. The task description is shown as the document, and you can attach a PDF to the portal task | Service agreements, acceptable use policies |
| **Meeting / Call** | You schedule the meeting from the portal. Attendees receive an invitation with a calendar file | Kickoff calls, discovery sessions, training walkthroughs |
| **Training** | **Video / Online** embeds a YouTube, Vimeo, or Loom video. **In Person** shows session instructions | Security awareness, platform walkthroughs |
| **Form / Questionnaire** | Attaches a reusable form so clients submit typed answers inline | IT questionnaires, user and site inventories |
| **Email** | Sends an onboarding email template, manually or on a date offset | Reminders and follow-ups |
| **Report** | Generates a report from a report template. You can show it to the client | Assessment results |
| **Credential Handoff** | The client submits credentials in **Single** or **Bulk** mode | Admin passwords, VPN logins, API keys |
| **Secure File Drop** | The client uploads an encrypted file that you can download once | License keys, certificates, sensitive configuration files |
| **Access Verification** | The client confirms access was set up as the task describes | Confirming admin or account access |

Credential Handoff and Secure File Drop submissions are retrieved once. Read [Retrieve onboarding credentials and secure files](/user-guides/client-onboarding/retrieve-secure-submissions) before you use the retrieval buttons.

For **Form / Questionnaire**, choose a form under **Reusable Form**. The form's **Repeat Entries** setting decides whether clients can add more entries. Build forms under **Settings > Projects > Templates > Forms**. See [Onboarding Forms](/user-guides/client-onboarding/forms).

## Configure a task

<Steps>
  <Step title="Open the item">
    Expand the phase and select the item to open its editor.
  </Step>
  <Step title="Set the basics">
    Set **Title**, **Type**, **Owner** (**MSP** or **Client**), **Required**, and **Description**. Write the description from the client's point of view.
  </Step>
  <Step title="Set scheduling and ownership">
    Set **Priority** (Low, Normal, High, or Critical), **Est. Hours**, **Milestone**, **Category**, **Due Offset (days)**, **Due From** (**Phase Start**, **Portal Start**, or **After Dependencies**), and **Assignee Role**.
  </Step>
  <Step title="Add type-specific settings">
    A **Document Upload** item has **Allowed File Types**, for example `.pdf, .doc, .xlsx`. A **Training** item has **Training Mode** and **Video URL**. A **Form / Questionnaire** item has **Reusable Form**. An **Email** item has **Email Template** and recipient roles. A **Report** item has **Report Template**.
  </Step>
  <Step title="Choose who sees it">
    Set **Visibility** to **Client** or **Internal**. Ownership and visibility are separate settings. An MSP-owned task with **Client** visibility shows in the provider progress section of the portal.
  </Step>
</Steps>

### Assignee role choices

The task owner decides where the **Assignee Role** choices come from.

| Task owner or field | Where to add role choices |
| --- | --- |
| MSP-owned task assignee | [Settings > Users & Roles > Team Roles](https://app.msportal.ai/settings/users?tab=team_roles) |
| Client-owned task assignee | **Settings > Projects > Client Portals > Client roles** |
| Email recipient roles and onboarding contacts | **Settings > Projects > Client Portals > Client roles** |

If only one MSP role appears, add and save the missing roles under **Team Roles**, then reopen the template. Templates offer tenant-wide Team Roles. Company-specific role definitions are not included. Client roles do not add MSP assignee choices, and permission roles do not fill either picker.

### Add a dependency

A dependent task shows as **Blocked** in the portal until its prerequisites are complete.

<Steps>
  <Step title="Open the dependency picker">
    In the item editor, select **Add Dependency**.
  </Step>
  <Step title="Choose prerequisites">
    Pick one or more tasks from any phase. The selection saves as soon as you choose it.
  </Step>
  <Step title="Resolve a cycle">
    If MSPortal reports a circular dependency, change the selection. Only add dependencies where order really matters.
  </Step>
</Steps>

If you set **Due From** to **After Dependencies** without adding dependencies, the editor warns you. Add the dependencies or pick another anchor.

### Link a task to a Standard

A template task can update a linked Standard as it progresses. See [Link an onboarding template task to a Standard](/user-guides/client-onboarding/link-task-to-standard).

## Documents, surveys, and approvals

Beyond tasks, phases can also hold **Document Upload** items, **Approval** items, and linked surveys from your Surveys module. These show in their own sections of the client portal.

## Add client pages

Templates reference reusable client pages. They do not copy the text.

<Steps>
  <Step title="Open the Pages section">
    In the template builder, open **Pages** from the template menu.
  </Step>
  <Step title="Link a page">
    Use **Select custom page** to search your library and add a page. Select **Manage pages** if you need to create one first.
  </Step>
  <Step title="Set client visibility">
    Turn **Visible to client portal** off to keep a page attached but hidden. Use the eye icon to preview it.
  </Step>
</Steps>

Update a page once in the library and every template that links it stays current. See [Client Pages](/user-guides/client-onboarding/pages).

## Add template dates

Template dates give every new portal the same milestones. Each date uses a day offset from the portal start.

<Steps>
  <Step title="Open the Dates section">
    In the template builder, open **Dates** from the template menu and select **Add Date**.
  </Step>
  <Step title="Enter the milestone">
    Enter a **Label** and an optional **Description**. Enter **Offset from portal start (days)**, for example 0 for kickoff, 14 for hardware, 45 for go-live. Leave the offset blank to set the date by hand on each portal.
  </Step>
  <Step title="Choose the countdown">
    Turn on **Show countdown** for the date portals should count down to by default. Only one date per template can have it on.
  </Step>
</Steps>

Offsets turn into real dates when a portal is created. A draft that you start later does not shift its dates. See [Custom Dates and Countdowns](/user-guides/client-onboarding/custom-dates).

## Use the AI Onboarding Designer

The AI designer is a sidebar in the template builder. It works on the template you have open. It is a build tool for your team, and clients never see it.

<Steps>
  <Step title="Open the designer">
    Select the floating AI button (**AI Onboarding Designer**). Responses can take 1 to 2 minutes.
  </Step>
  <Step title="Describe the process">
    Type a request such as "Create an onboarding template for a 50-person law firm migrating from on-prem Exchange to Microsoft 365" or "Add a security hardening phase with MFA enrollment and endpoint protection tasks." You can also start from a prompt helper such as **Standard MSP Onboarding**, **Quick Start**, **Security-Focused**, **M365 Migration**, or **Infrastructure Audit**.
  </Step>
  <Step title="Review the changes">
    Select **Review Template Changes**. Check each added phase, task, and setting. Accept or reject sections, or accept or reject all.
  </Step>
  <Step title="Apply or refine">
    Select **Apply** to save the changes you accepted, or keep chatting to refine them. After applying, select **View Applied Changes** to see what changed, or the undo icon to reverse the last changes.
  </Step>
</Steps>

If an apply reports a partial failure, open the saved template and check what was written before you retry.

<Tip>
Give the designer context about the client type, size, and requirements. You can also ask it to change an existing template, for example "Add a compliance documentation phase after the migration phase."
</Tip>

## Test a template

A template has no preview of its own, because what a client sees depends on the portal built from it. To test one, build a draft portal.

<Steps>
  <Step title="Create a draft portal">
    Go to **Projects > New project**, pick your template and a test or internal company, and finish the wizard. The portal is created as a **Draft**. Review any configured automation first, and skip project or ticket creation if you only need a presentation preview.
  </Step>
  <Step title="Open View as">
    In the page header, select **View as** and pick a contact. With no contacts, pick a client role instead. The portal opens in a new read-only tab.
  </Step>
  <Step title="Adjust and repeat">
    Fix anything that reads wrong, save the template, and create a fresh draft to see the change. Existing portals keep the structure they were created with.
  </Step>
</Steps>

See [Previewing as a client](/user-guides/client-onboarding/managing-portals#previewing-as-a-client).

## Import & Export

Use **Import / Export** in the template builder to share templates, back them up, or build them in a spreadsheet. The dialog has three formats.

<Tabs>
  <Tab title="JSON">
    JSON carries the full template structure, including phases, tasks, documents, approvals, and client page data. It is not a backup of portal progress, submitted files, or provider records. Check linked library items after you import.

    <Steps>
      <Step title="Export">
        Open the **JSON** tab and select **Export JSON**.
      </Step>
      <Step title="Import">
        Select **Select JSON File** and choose the file. A preview shows the phase, task, and document counts. Select **Import Template**. This updates the current template in place.
      </Step>
    </Steps>
  </Tab>
  <Tab title="CSV">
    CSV gives you a flat task table to edit in a spreadsheet.

    <Steps>
      <Step title="Export">
        Open the **CSV** tab and select **Export CSV**.
      </Step>
      <Step title="Import">
        Select **Select CSV File**, then **Import as New Template**. This creates a new template named after the current one with "(imported)" added. It does not overwrite the current template. The file needs `phase_name` and `task_title` columns.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Excel">
    Excel gives you a formatted, read-only workbook for reviewing a template or sharing it with people who do not use MSPortal. It cannot be imported. Use JSON to move a template between tenants.

    Select **Export Excel** on the **Excel** tab to download an `.xlsx` workbook named after the template.

    - The **Overview** sheet lists the template settings, portal settings, key dates, automations, and a linked list of phases.
    - Each phase has its own sheet. Its **Items** table lists every task and document in builder order with type, owner, assignee role, required and client-visible flags, milestone, priority, estimated hours, category, due rule, dependencies, required documents, and type-specific details.
    - Below the items, each phase sheet prints the full content of every linked record, such as checklist items, form fields with options and defaults, survey questions, and email subject and body. A record used by several items prints once and names each item under **Used by**.
    - Templates with client pages add a **Client Pages** sheet with each page's section, summary, visibility, and plain-text content.

    <img src="/images/product/onboarding-template-excel-export-dialog-branch-preview.png" alt="Excel tab of the Import / Export Template dialog with the Export Excel button" width="1344" height="996" />

    <img src="/images/product/onboarding-template-excel-phase-sheet-branch-preview.png" alt="Phase sheet of an exported onboarding template workbook showing the Items table and a linked survey's questions" width="2100" height="810" />

    The workbook uses your tenant's brand color and your current language. It includes the linked records your role can read.
  </Tab>
</Tabs>

## Create checklist templates

Checklist templates are reusable sets of sub-items you can attach to any task.

<Steps>
  <Step title="Open Checklists">
    Go to **Settings > Projects > Templates > Checklists** and select **New Checklist**.
  </Step>
  <Step title="Add items">
    Enter a name and description. Add items one at a time, drag them into order, use **AI Generate**, or use **Import** to paste one item per line. Select **Create**.
  </Step>
  <Step title="Attach it to a task">
    In the template builder, open a task and choose the checklist under **Checklist (optional)**. Its items appear as checkable sub-items. Both MSP staff and clients can check them off.
  </Step>
</Steps>

### Archive or restore a checklist

<Note>Branch preview: archived checklists are visible in the unified Projects settings.</Note>

Open **Settings > Projects > Templates > Checklists**, select a checklist, and select **Archive** to hide it from checklist pickers. To bring it back, choose **Archived**, select the checklist, and select **Restore**. See [Project Settings](/user-guides/settings/projects#restore-an-archived-checklist) for desktop and phone examples.

## Manage templates

<Steps>
  <Step title="Open the actions menu">
    In **Settings > Projects > Templates > Templates**, select the **...** menu on a template row.
  </Step>
  <Step title="Choose an action">
    **Edit** opens the builder. **Duplicate** saves a copy named "(Copy)" and opens it. **Archive** hides the template from new portals. **Restore** brings an archived template back.
  </Step>
</Steps>

Existing portals are not affected when you archive a template. A duplicate shares linked forms and pages with the original, so editing those linked items changes both.

### Review change history

Open **History** from the template menu to see recorded changes. Each entry shows what changed, who changed it, and when. Hover an entry for the exact time and select **Load More** for older history.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| You cannot add a phase to a new template | Enter a name and select **Create Template** first. A phase needs a saved template. |
| Only one MSP role appears under **Assignee Role** | Add roles under **Team Roles**, save them, and reopen the template. |
| An item change did not stick | Reopen the item and check the stored values. Re-enter anything missing. |
| A template change is not in an existing portal | Portals copy the template when they are created. Create a new draft. |
| A client sees a task you meant to hide | Set the item's **Visibility** to **Internal**. Ownership alone does not hide it. Check with **View as**. |
| An AI apply stopped partway | Open the saved template, check what was written, and apply the rest by hand. |

## Best practices

<AccordionGroup>
  <Accordion title="Keep templates focused">
    Make separate templates for different client types, such as SMB onboarding, enterprise migration, and M365 setup only. Avoid one large template full of optional phases.
  </Accordion>
  <Accordion title="Use dependencies sparingly">
    Add dependencies only where order truly matters. Too many blocked tasks slow clients down.
  </Accordion>
  <Accordion title="Balance MSP and client tasks">
    Include MSP-owned tasks so clients can see your team's progress too.
  </Accordion>
  <Accordion title="Write for the client">
    Instead of "Provide AD credentials," write "Please provide your Active Directory administrator username and password so we can begin the migration."
  </Accordion>
  <Accordion title="Use AI for first drafts">
    Start with the AI designer for a baseline, then adjust it to match your process.
  </Accordion>
</AccordionGroup>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Save Changes save everything in the builder?">
    No. It saves the template details and display defaults. Phases, items, ordering, dependencies, dates, pages, and AI changes save through their own controls.
  </Accordion>
  <Accordion title="Does changing a template update existing portals?">
    No. Existing portals keep the phases and tasks they were created with. Linked client pages can still show the latest library content.
  </Accordion>
  <Accordion title="Does Apply only preview an AI suggestion?">
    No. **Review Template Changes** is the preview. **Apply** saves the changes you accepted.
  </Accordion>
  <Accordion title="Can I import an Excel workbook?">
    No. Excel export is for review and sharing. Use JSON to update a template or CSV to create one from a task list.
  </Accordion>
  <Accordion title="Does importing JSON create a separate template?">
    No. JSON import updates the current template. **Import as New Template** on the CSV tab creates a separate one.
  </Accordion>
  <Accordion title="Are MSP-owned tasks hidden from clients automatically?">
    No. Ownership and visibility are separate. Set **Visibility** to **Internal** to hide an item.
  </Accordion>
  <Accordion title="Does archiving a template archive its portals?">
    No. It only removes the template from new portal selection. Portals have their own lifecycle.
  </Accordion>
</AccordionGroup>
