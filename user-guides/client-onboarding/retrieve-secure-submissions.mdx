This guide shows MSP staff how to reveal a credential handoff, download a secure file, and deal with submissions that were already used or have expired. Clients submit through [credential handoff](/user-guides/client-onboarding/hand-over-credentials) and [file uploads](/user-guides/client-onboarding/upload-files). They never see these retrieval controls.

## Before you start

- You need onboarding write access (`write_settings_onboarding`) and an active subscription.
- Each submission can be retrieved once. **Reveal & Delete** and **Download & Destroy** permanently delete the stored copy, so be ready to save what you get.
- Submissions are encrypted with AES-256-GCM and expire 30 days after the client sends them.
- Have the place ready where you will keep the information, such as your password manager or documentation system.

## Find the submission

<Steps>
  <Step title="Open the project">
    Go to **Projects**, choose **Project category > Onboarding projects**, and open the project.
  </Step>
  <Step title="Open the task">
    Go to **Project Plan > Tasks** and open the credential or secure-file task. If the project has more than one portal, pick the right one with **Portal:** first.
  </Step>
</Steps>

The task details show the submission and its controls. In the earlier company workspace, open the company's **Onboarding** tab, choose the portal, and open the task under **Tasks**.

## Reveal a credential handoff

<Steps>
  <Step title="Check the submission">
    Check the **Pending Reveal** status, the person who sent it, the date, and the expiry. A Bulk submission may say **Includes file** with a filename.
  </Step>
  <Step title="Get ready to save it">
    Open the place where you will store the credentials. A reveal is not a preview. It uses up the one retrieval.
  </Step>
  <Step title="Reveal">
    Select **Reveal Credentials**. Read the confirmation, then select **Reveal & Delete**. Select **Cancel** to close it without revealing.
  </Step>
  <Step title="Copy what you need">
    For a Single submission, use the copy button on each field. Use the show and hide control for the password and API key. For a Bulk submission, select **Copy All** for the text, and **Download** for an attached file. Do this while the details are on screen.
  </Step>
</Steps>

After the reveal, the details show for 5 minutes, then hide on their own. The encrypted copy is already deleted. Refreshing or reopening the task does not bring them back, so save what you need right away.

## Download a secure file

<Steps>
  <Step title="Find the file">
    Open the **Secure File Drop** task and find the filename.
  </Step>
  <Step title="Start the download">
    Select **Download Once**.
  </Step>
  <Step title="Confirm">
    In **Download Secure File**, check the filename and task. Select **Download & Destroy** to download, or **Cancel** to leave it waiting.
  </Step>
  <Step title="Check your browser">
    Confirm your browser saved the file where you expect.
  </Step>
</Steps>

The file is marked **Downloaded** when the portal sends it, before your browser finishes saving it. If your browser blocks the download or the transfer stops, check your downloads and ask the client for a replacement.

## Upload a file on an MSP-owned task

An MSP-owned Secure File Drop task can show **Upload Secure File** in its details. Choose a file up to 10MB and the upload starts at once. It has no confirmation step like the client's **Encrypt & Upload**. Wait for the filename to appear. This control is for your own work. It does not change who owns the client's request.

## Understand the statuses

| Submission | Waiting | Used | Expired |
| --- | --- | --- | --- |
| Credentials | **Pending Reveal**, with **Reveal Credentials** available | **Revealed**, with no new retrieval from the task | **Expired**, so arrange a new handoff |
| Secure files | **Download Once** is available | **Downloaded**, with no second download | **Expired**, so arrange a replacement |

If a credential submission is wrong, already revealed, or expired, create a new credential handoff task and ask the client to submit again. The original task cannot be edited or resubmitted. For a missing or expired secure file, create a new upload request.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| You can see the task but not the reveal or download button | You may lack onboarding write access or an active subscription. The submission may also already be used or expired. |
| You revealed a credential and did not copy it | It cannot be retrieved again. Ask the client to submit a new handoff. |
| A file shows **Downloaded** but is not on your computer | Check your browser's downloads. If the file is gone, ask the client to upload it again. |
| The client submitted a mistake | Create a new credential handoff task. Clients cannot edit a submission. |
| A submission shows **Expired** | Submissions expire after 30 days. Create a new request. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can I reveal a credential just to check that the client sent something?">
    No. Check the status and submission details instead. **Reveal & Delete** returns the contents and uses up the retrieval.
  </Accordion>
  <Accordion title="Can another technician reveal the same submission afterward?">
    No. A pending submission can be retrieved once. After it shows **Revealed**, nobody can retrieve it again.
  </Accordion>
  <Accordion title="Can I cancel after opening the confirmation?">
    Yes. Select **Cancel** before **Reveal & Delete** or **Download & Destroy**. Closing the confirmation does not use up the submission.
  </Accordion>
  <Accordion title="Does Downloaded mean the file is on my computer?">
    No. It records that the portal sent it. Confirm your browser saved it.
  </Accordion>
  <Accordion title="Can clients fix an incorrect credential handoff?">
    No. Create a new handoff task and ask the client to submit the correction there.
  </Accordion>
  <Accordion title="Does uploading to an MSP-owned secure-file task need a confirmation?">
    No. Your upload starts when you choose the file. The client's **Encrypt & Upload** confirmation is separate.
  </Accordion>
</AccordionGroup>
