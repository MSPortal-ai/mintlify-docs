A Company user's **Permissions Group** decides what that person can do in the portal. This guide is for MSP staff who manage Company users. Company administrators ask their IT provider to change access. They cannot manage users or permission roles themselves.

## Before you start

- You need write access to Company users in **Users & Roles**. Without it, user names are not clickable and the **Update Permissions** action is missing.
- The permissions group you want must already exist. Company users can only be assigned Company-scoped groups. To create one, see [Create and edit permission roles](/user-guides/getting-started/how-to-create-a-new-user-role).
- **Team Roles** are a separate feature. They are not the Permissions Group in the Company user editor.

## Choose the kind of change

| You want to | Do this |
| --- | --- |
| Give one user a different existing set of permissions | [Change one user](#change-one-user) |
| Give several users the same existing permissions | [Update several users](#update-several-users) |
| Change what everyone in a group can do | [Edit the permission role](/user-guides/getting-started/how-to-create-a-new-user-role) |
| Make a different set for a few users | Create or duplicate a role, set its permissions, then assign it to those users |

## Change one user

<Steps>
  <Step title="Open Company Users">
    Go to **Settings > Users & Roles** and open the **Company Users** tab. Use the company selector and the table filters to find the person. Check the company and email as well as the name.
  </Step>
  <Step title="Open the user">
    Click the user's name, or open the row's menu and click **Edit User**. The **Edit Company User** dialog opens.
  </Step>
  <Step title="Choose the permissions group">
    Under **Permissions**, open **Permissions Group** and pick the group. Nothing is saved yet.
  </Step>
  <Step title="Save">
    Click **Save Changes**. A toast says **User updated successfully**. The **Permissions Group** column in the table shows the new group.
  </Step>
</Steps>

The dialog also holds email, company, location and custom fields. A change to the email updates the user's sign-in. Moving the user to another company is a separate change from the role. Review those fields before you save.

## Update several users

<Steps>
  <Step title="Select the users">
    On the **Company Users** tab, filter to the right company and users, then check each user's box. The selected count shows in the table. If you select every matching result across pages, the count covers all of them.
  </Step>
  <Step title="Open Update Permissions">
    Open the **Actions** menu for the selection and click **Update Permissions**. The **Bulk Update Permissions** dialog opens.
  </Step>
  <Step title="Choose the permissions group">
    Open **Permissions Group** and pick the group to apply to every selected user.
  </Step>
  <Step title="Save">
    Click **Save**. A toast says **Updated permissions for N users**. Check the table to confirm.
  </Step>
</Steps>

<Warning>
The dialog starts on **No permissions group**. Saving it with that choice removes the role from every selected user. Pick the group you want before you click **Save**. A toast says **Removed permissions group from N users** when it clears them.
</Warning>

## Check the result

Confirm the group in the **Permissions Group** column. Then ask the Company user to reopen the area they use. If they still see old access, ask them to sign out and back in.

A permissions group is only part of what a user can reach. The company, enabled modules, integrations and record visibility also apply. A role does not create missing data or turn on an integration.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| User names are plain text, not links | You lack write access to Company users. Ask an administrator |
| **No permissions groups available** or **No company-scoped permissions groups found** | Create a Company role in **Settings > Users & Roles > Roles** first |
| The role I want is missing | Company users only get Company roles. MSP staff roles are a different type |
| A message says you do not have permission to change the permissions group | Ask an administrator for user write access |
| **Failed to update permissions** appears | Reopen the users and check their groups before you try again. Some may have changed |
| A user has **No Permissions Group** in the table | Edit the user and pick a group |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can a Company administrator change another user's permissions?">
    No. The MSP manages Company users. The administrator asks their IT provider for the change.
  </Accordion>
  <Accordion title="Does changing one user's group change other users?">
    No. Picking a different group for one user changes only that user. Editing the group's permissions changes everyone assigned to it.
  </Accordion>
  <Accordion title="Can I give one person extra access without changing the shared role?">
    Yes. Create or duplicate a role, add the permissions, and assign that role to the person.
  </Accordion>
  <Accordion title="Do changes save as soon as I pick a group?">
    No. Click **Save Changes** for one user or **Save** in the bulk dialog. **Cancel** closes the dialog without saving.
  </Accordion>
  <Accordion title="What does No permissions group do?">
    It removes the user's role assignment. It does not delete the user.
  </Accordion>
  <Accordion title="Does a Company role give access to MSP settings?">
    No. Company roles control the Company portal. They do not make a Company user MSP staff.
  </Accordion>
</AccordionGroup>
