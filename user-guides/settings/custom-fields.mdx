Use custom fields to capture information the built-in fields do not cover, such as a contract renewal date on a company or an asset tag on a device. This page is for MSP staff. Open **Settings > Customization > Fields**. The page is titled **Field Definitions**, with a tab for each record type: **Devices**, **Compliance**, **Goals**, **Budgets**, **Planner**, **Users** and **Companies**.

## Before you start

- You need access to Custom Fields settings. Creating, editing, reordering and deleting each need the matching permission.
- Company users cannot change field definitions. They ask their IT provider.
- A new field starts empty on existing records. It does not create a field in your PSA. Set up PSA project fields in [Project Settings](/user-guides/settings/projects).

## Create a field

<Steps>
  <Step title="Choose the record tab">
    Select the entity you want to extend. For example, choose **Devices**, then **Add Devices Field**. The Add button uses the selected tab's name.
  </Step>
  <Step title="Enter the field definition">
    Enter a descriptive **Label**, choose its **Type**, and configure scope. Add opens an unsaved row; it does not create the field yet.
  </Step>
  <Step title="Save the row">
    Select the green checkmark and wait for **Custom field created successfully**. The red X cancels this unsaved row. Each field saves on its own. There is no page-wide Save.
  </Step>
  <Step title="Add choices after saving a choice field">
    For Dropdown, Multi-Select, or Radio Buttons, first save the field as optional. Expand its saved row, select **Add Option**, enter the choice, then use that option's checkmark. Repeat for each choice. After options are saved, edit the field to enable **Required** if needed.
  </Step>
</Steps>

| Type | Typical use |
| --- | --- |
| **Short Text**, **Long Text** | A short value or longer notes |
| **Number**, **Decimal** | Numeric values, including decimals where appropriate |
| **Email**, **Phone**, **URL** | Contact information or a web address |
| **Date**, **Date & Time** | A calendar date or timestamp |
| **Checkbox** | A yes/no value |
| **Dropdown**, **Radio Buttons** | One choice from your saved options |
| **Multi-Select** | Several choices from your saved options |

<Note>
Choose the field type carefully. A saved field's type cannot be changed. For a different type, create a new field and move the values over before you delete the old one.
</Note>

<Note>
New fields are visible to company users. To make a field internal, check **Hide from company users** in the new row, before you enter sensitive values. Fields synced from HaloPSA start hidden.
</Note>

## Scope and Company visibility

| Control | What it controls |
| --- | --- |
| **All Types** or a specific type | Where the field applies. You can pick a type for Devices, Compliance and Planner fields when types exist. Goals, Budgets and Companies have no type list |
| **Both**, **Tenant Users**, **Company Users** | Which kind of user gets a Users field. This is separate from who can see it |
| **Hide from company users** | Makes the field internal (shown as **Internal only**). New fields are visible to company users unless you check it; fields synced from HaloPSA start hidden |
| **Required** | Requires a value in record forms. A choice field needs at least one saved option first |

For Compliance, also choose the fill location when creating the field:

- **Filled on the check (pre-filled)**: configure the value on the check definition; it is shown read-only on runs.
- **Filled on compliance page**: enter the value for the individual run.

The Compliance fill location is fixed after creation. Plan a replacement and preserve needed values before deleting an old definition.

## Company fields from HaloPSA and alerts

A Companies field can follow a HaloPSA customer field or the customer's pop-up notes, and can show its value as a warning banner on the company's pages. A common setup brings HaloPSA pop-up warnings, such as "sensitive client, proceed with care", into MSPortal and alerts the account manager when one changes.

### Before you start

- HaloPSA is connected and active, with **Sync Companies** on in the connection's **Choose data** step. See [Enable the HaloPSA integration](/user-guides/integrations/enable-halo-integration).
- Your HaloPSA customers are linked to MSPortal companies. Only linked companies get values.
- HaloPSA has synced at least once. Its customer fields appear in **Sync from HaloPSA** after a sync, so a field you add in HaloPSA later appears after the next sync.

### Sync a field from HaloPSA pop-up notes

<Steps>
  <Step title="Add a Companies field">
    Open **Settings > Customization > Fields**, choose the **Companies** tab and click **Add Companies Field**. Enter a **Label**, for example **Customer notes**.
  </Step>
  <Step title="Choose the HaloPSA source">
    In **Sync from HaloPSA**, choose **Customer pop-up notes**, or a HaloPSA customer field. The source sets the **Type**: **Long Text** for pop-up notes, **Short Text** for a customer field. The type is locked and reads **Set by the HaloPSA source.**
  </Step>
  <Step title="Check who can see it">
    **Hide from company users** is checked for you, because pop-up notes are often internal warnings about the client. Leave it checked unless the client's own users should read the value.
  </Step>
  <Step title="Turn on the alert (optional)">
    Check **Show as alert** to show the value as a banner on the company's pages. See [Show a field as a company alert](#show-a-field-as-a-company-alert).
  </Step>
  <Step title="Save the row">
    Click the row's checkmark. The field shows a **HaloPSA:** badge with the source name, and **Internal only** while it is hidden.
  </Step>
</Steps>

MSPortal fills the field for every linked company within a minute or so, then updates it with each HaloPSA company sync. Companies without a value stay empty.

To link a saved field instead, click its label, choose the source in **Sync from HaloPSA**, and save. Only a saved **Short Text** or **Long Text** field can be linked; for another type, add a new field. Linking a saved field also checks **Hide from company users**.

### What gets synced

- **Pop-up notes**: the customer's current pop-up notes as plain text, oldest first, with a blank line between notes. Notes outside their HaloPSA date range are left out.
- **Customer fields**: HaloPSA's display text, so a dropdown shows its label and a checkbox shows **Yes** or **No**. Encrypted HaloPSA fields never sync.
- A synced value is read-only in MSPortal. On the company's **Custom Fields** section it shows **Synced from HaloPSA**. Change it in HaloPSA.
- To stop syncing, edit the field and choose **Not synced**. The current values stay and become editable.

### Show a field as a company alert

Check **Show as alert** on any Companies text field (**Short Text** or **Long Text**). It works with HaloPSA, with any other PSA, and with values you type in MSPortal. The field shows an **Alert** badge in the list.

- When a company has a value in the field, a warning banner shows it at the top of the company's **Company** page and its page under **Settings > Companies**. A company with no value shows no banner.
- Anyone can dismiss a banner. It returns on that device when the value changes.
- Company users see the banner only when the field is visible to them. Check **Hide from company users** to keep it for MSP staff.

### Who gets notified

When HaloPSA fills or changes the value of a synced alert field, MSPortal notifies the company's account manager. Values you type in MSPortal, and values HaloPSA clears, send no notification.

- **Where**: an in-app notification under the bell in the top bar, titled with the field and company, for example **Customer notes for Gradient MSP**. It reads **Changed in HaloPSA:** followed by the new value. Click it to open the company. No email is sent.
- **Who**: active MSP staff assigned to the company in a team role that is mapped to HaloPSA's **Account Manager**, or a team role named **Account Manager**. Assign the role on the company's **Team** tab, and map it under **Halo Roles** when you edit the team role. See [Account teams and Team Roles](/user-guides/getting-started/onboarding/company-roles).
- If no one holds that role on a company, the banner still shows but nobody is notified.

## Edit, reorder, or delete

<Steps>
  <Step title="Edit a field">
    Click a saved field's label or its pencil. Change the label, required setting, scope or company visibility, then click the row's checkmark. The X cancels that edit. Save or cancel before you leave the page.
  </Step>
  <Step title="Reorder fields">
    Drag a field row by its handle. The new order saves at once. Options inside a field cannot be reordered by dragging.
  </Step>
  <Step title="Edit options">
    Expand a choice field to see **Field Options**. A checkmark saves an option edit. An option's trash icon removes it at once with no confirmation. Cancelling a field edit does not undo saved option changes.
  </Step>
  <Step title="Delete a field">
    Click the field's trash icon. In **Delete Custom Field**, type the field's name to confirm. **Cancel** keeps it.
  </Step>
</Steps>

<Warning>
Deleting a field permanently removes its stored values on every record. To clear the value on one record, edit that record instead.
</Warning>

## Check the result and recover from errors

Open a record of that type and look for the **Custom Fields** section. Enter a value and save the record with its own save controls. To set one Companies field on many companies at once, see [Set a custom field on many companies](/user-guides/settings/companies#set-a-custom-field-on-many-companies). To check what company users see, review the field as a company user.

If a save or reorder shows an error, reopen the page and check the saved fields and options before you try again. A reorder updates several rows, so some may have changed.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| **Add Devices Field** (or another tab's button) is missing | You lack permission to create fields |
| **Required** is disabled on a choice field | Save the field, expand it, and save at least one option. Then edit the field and check **Required** |
| The field does not appear on a record | Check its type scope and, for Users, its user scope. Check that the record type matches |
| Company users should not see a field | Edit the field and check **Hide from company users** |
| **Failed to save custom field** appears | Check that the label is not empty and is not already used, then try again |
| I need to change a Compliance field's fill location | It is fixed after creation. Create a new field and delete the old one |
| **Sync from HaloPSA** is missing | It appears only on the **Companies** tab while a HaloPSA connection is active |
| A HaloPSA customer field is not in **Sync from HaloPSA** | Wait for the next HaloPSA sync after adding it in HaloPSA, then reopen the page |
| **Sync from HaloPSA** is disabled on a saved field | Only saved **Short Text** and **Long Text** fields can be linked. Add a new field and choose the source there |
| A company has no synced value | Check that the company is linked to a HaloPSA customer and has a current value or pop-up note in HaloPSA |
| A company field cannot be edited and shows **Synced from HaloPSA** | Change the value in HaloPSA, or set the field to **Not synced** |
| **Show as alert** is missing | It is available only for Companies fields of type **Short Text** or **Long Text** |
| Nobody was notified about an alert | Check that the company has an active staff member in a team role mapped to HaloPSA's **Account Manager** or named **Account Manager**. Only changes HaloPSA makes notify |
| Client users can see a HaloPSA warning | Edit the field and check **Hide from company users** |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Add Field save immediately?">No. It opens a draft row. Click the green checkmark to create the field.</Accordion>
  <Accordion title="Why can't I make a dropdown required?">Save the optional field first, expand it, and save at least one option. Then edit the definition to enable Required. If the warning remains after adding an option, reopen the page to reload the saved option count.</Accordion>
  <Accordion title="Does the field's X undo saved options?">No. Field edits and option edits save separately. X cancels only the current unsaved edit.</Accordion>
  <Accordion title="Can I reorder the choices by dragging?">No. Options have add, edit and delete controls only. Field rows can be dragged and save their order at once.</Accordion>
  <Accordion title="Can Company users create their own field definitions?">No. This is MSP settings. Company users need their IT provider to configure definitions and access.</Accordion>
  <Accordion title="Is User scope the same as visibility?">No. User scope chooses which user records receive the field. Hide from company users controls whether Company users can see it.</Accordion>
  <Accordion title="Will deleting a field only remove it from this record?">No. Deleting the definition removes the field and its stored values across records. Clear an individual record's value instead when that is your intent.</Accordion>
  <Accordion title="Does this create a field in my PSA?">No. These are portal field definitions. Supported PSA project fields have their own configuration in Project Settings.</Accordion>
</AccordionGroup>
