Open **Settings > Integrations > Map companies** to match integration records with the correct MSPortal companies. The page title is **Integration Company Mapping**. Linking a source record is different from importing a new portal company.

## Before you start

This is an **MSP staff** task. Your role needs integration company-mapping read access or broader integration-settings access. Linking, unlinking, applying suggestions, and ignoring/restoring records require the corresponding write access. Company users ask their IT provider to correct integration links.

Choose the intended company scope and check the provider connection's name. Different connections to the same provider can have separate columns. Some providers also expose different source types, such as organizations or sites. A missing or unavailable column can depend on connection setup, discovered records, or a feature's availability.

<Warning>
Changing a link changes which company receives integration data. Links save immediately and can trigger follow-up synchronization. Opening a picker is safe to review; selecting a destination or Unlink is a write. There is no final page-wide Save or rollback when you leave.
</Warning>

## Read and filter the grid

| Area | Use it for |
| --- | --- |
| **Company** | Identify the MSPortal company row; use its column filter to narrow the table. |
| Integration source columns | Review the source record linked to that company and connection. Scroll horizontally or use **Columns** for a wide grid. |
| **Blank links** | Show rows missing any integration link, or links in selected source columns. |
| **Company mapping cleanup** | Review unlinked integration records and suggested matches. This is a different queue from portal-company rows with blank cells. |
| **Import** | Open an available provider import workflow when you need to create portal companies. |

**Any integration** finds rows with at least one missing link. If you choose several specific source columns, a row must be missing each selected source to remain visible. Use **Clear filters** to remove the blank-link selections.

The global Company Selector narrows the grid to the selected company or assigned companies. Global View shows the available company rows, including their Company column. Changing company scope resets the blank-link filter.

<Note>
The cleanup queue and recommended-match operation can include tenant-wide integration records. The grid's Company Selector, column filters, and Blank links are not an approval boundary for those dialogs. Review every proposed source and destination before applying changes.
</Note>

## Link, change, or remove a source record

<Steps>
  <Step title="Find the company and connection">
    Locate the correct MSPortal company row and integration source column. Check the connection label when the provider has several instances.
  </Step>
  <Step title="Open the cell">
    Search the available source records. An empty cell offers eligible unlinked records; a disabled empty cell can mean there is nothing left to link from that source.
  </Step>
  <Step title="Choose the correct source">
    Selecting a record saves immediately. Wait for the result, then recheck the cell and any additional-links indicator. Do not assume selecting another source automatically removes every existing link.
  </Step>
  <Step title="Remove an incorrect link explicitly">
    Use **Unlink** for the specific linked record. When a cell indicates additional links, open its reconciliation view and inspect each record. Unlinking is not deletion of the company in the external service.
  </Step>
</Steps>

A successful link does not prove downstream data has finished syncing. If a link or sync reports a problem, recheck the stored mapping before retrying; a follow-up error does not necessarily undo the link.

## Review likely matches

Select **Review likely matches** on the cleanup card. The page requests recommendations for eligible unlinked records from the available integration sources. It does not save those links until you apply them.

<Steps>
  <Step title="Review the suggested source and destination">
    Check each integration record, connection label, proposed MSPortal company, and confidence score. Similar names are not proof that two records represent the same customer.
  </Step>
  <Step title="Set confidence before fine-tuning selections">
    The slider ranges from **70 to 100 percent** on this page and starts at 70. It automatically selects returned suggestions at or above the chosen threshold. Changing the slider replaces your current selections; do this before manually checking or unchecking rows.
  </Step>
  <Step title="Search and inspect the whole selection">
    Search matches by source or destination text. **Select All** and **Clear All** affect the visible search results. Hidden selections remain selected. Clear the search and review the total selection before applying; search alone does not narrow what will be saved.
  </Step>
  <Step title="Apply or cancel">
    Apply the checked suggestions and inspect the result. Cancel leaves those proposed links unapplied. If the result reports errors, some links may have succeeded: inspect the refreshed grid and remaining queue before retrying.
  </Step>
</Steps>

No recommendations means no returned eligible suggestions, not that every connection synced successfully or every company is correctly mapped. Use **Review unlinked records** and the provider's setup when records are still missing.

## Review unlinked records

Select **Review unlinked records** to open **Unlinked customer records**. Records that appear to represent the same customer are grouped, but expand a group and inspect its members before deciding what to do.

Use **To review** for outstanding groups and **Ignored groups** for records set aside. Search and integration/company-type filters help narrow the list. A company-type filter keeps the whole matching customer group together, including records from other integrations.

<Note>
Inline company linking below is a branch preview for PR #1633. Until it is released, use the mapping grid or provider setup to link records.
</Note>

- Use **Link to company…** to search for an existing MSPortal company and link one record. A group picker labelled **Link all [count] records to company…** links every listed record; expand the group to link individual records.
- Linking from **Ignored groups** restores each record before linking it. If you later unlink it, it returns to **To review**.
- Wait for the queue to finish refreshing before linking another record. If a group link fails partway through, successfully linked records leave the queue; review the remaining records before retrying.
- **Ignore from cleanup** sets aside the records in that group. It does not import a company, create a link, delete the provider's record, or disable an integration.
- **Restore** returns an ignored group to the review queue.
- For bulk ignore/restore, review selected groups and their expanded members before using the bulk action. Hidden selected groups can remain selected after filtering; clear filters and inspect the total selection first. These writes are separate from recommended-match Apply and may partially succeed if an error occurs.

The **Your Companies** dashboard can show a **Likely customer matches to review** banner that opens this review workflow.

## Microsoft 365 column

The unfiltered provider workspace also has a Microsoft 365 connection column. It reports per-company cloud connections rather than a normal PSA/RMM source mapping. Provider-specific mapping workspaces hide this column.

Its menu can offer **Sign in with Microsoft**, **Add tenant**, or **Copy link** for the consent workflow. These are deliberate setup actions: review the company and any displayed consent/compliance prompt before proceeding. Copy link creates a shareable connection link; it is not an unlink action.

For a company with no connection, **Mark not applicable** saves that classification and removes it from the missing-Microsoft-365 calculation. **Restore** reverses the classification. Not applicable is not a successful connection or evidence of security coverage.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| The grid is empty | Company scope, Company column filter, Blank links, and available company records. |
| A provider is missing | Connection setup, supported sources, feature availability, and whether you opened a provider-only workspace. Use **View all providers** to leave that narrowed workspace. |
| No source record appears in a picker | Source discovery/sync, the connection, ignored state, and whether it is already linked. |
| Several links appear in one cell | Inspect the additional-links view and unlink only the incorrect record. |
| Apply reports errors | Recheck successful links and remaining records; the batch is not all-or-nothing. |
| The company is linked but data is absent | Check subsequent provider sync, record-type permissions, imports, and device mappings separately. |
