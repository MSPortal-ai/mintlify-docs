Automation rules run repeatable work for you on a schedule or when specific data conditions are met. A rule combines three things:

1. A **trigger** (when to run)
2. Optional **conditions** (which records to match)
3. One or more **actions** (what to do)

Rules can target the entity types offered by your editor, including Devices, Companies, Compliance Controls, Planner Tasks, Users, Goals, Training, Tickets, Meetings, Survey Responses and Onboarding. Most selectors are guided dropdowns, including PSA values like service boards, ticket categories, and issue types which populate from your connected PSA integration. A few fields (the Update Field `field`/`value` pair, Custom Email, ConnectWise issue-type IDs, and template bodies) are free-text inputs.

## Accessing Automation

Navigate to **Settings > Automation** from the sidebar. The main page lists every rule in your tenant.

Each row shows:

- **Rule Name** and description
- **Trigger** type badge (including Date Threshold, Scheduled and supported event triggers)
- **Entity** type badge (Device, Ticket, Meeting, etc.)
- **Actions** summary (either the single action label or "N actions")
- **Scope** badge (All Companies or Specific)
- **Enabled toggle** to turn the rule on or off without deleting it

## Row Actions

Hover over any rule row for the action menu:

| Action | What it does |
|--------|--------------|
| **Edit** | Opens the wizard for that rule |
| **Run Now** | Queues a real execution of an enabled rule; actions can send messages, create records or write to your PSA |
| **Duplicate** | Creates a copy of the rule named "Copy of {original}", disabled by default |
| **Delete** | Permanently removes the rule and its execution history |

The **enabled toggle** on each row takes effect immediately. A disabled rule keeps its configuration and history but will not fire.

## Permissions

Three permissions control access to Automation:

| Permission | Grants |
|------------|--------|
| **Read Settings Automation** | View rules and their execution history |
| **Write Settings Automation** | Create, edit, and run rules |
| **Manage Settings Automation** | Full access including delete and approval routing |

Set these under **Settings > Users & Roles** on the role you want to grant access to. Users without Write or Manage permission open the wizard in read-only mode.

## Execution Logs

Click **Logs** in the top-right of the rules page to open the execution history. Every rule run is logged with:

- Timestamp and rule name
- How many entities were matched
- Which actions ran and whether each succeeded
- Any error messages if an action failed

Logs are scoped by the company selector, so switching companies changes the visible execution history; it does not rewrite a rule’s saved scope.

## AI Rule Designer

While editing or creating a rule, open the page’s **AI Rule Designer** from the assistant control available in your account. Describe what you want the rule to do in plain English, for example:

> Remind account managers 30 days before each company's warranty expires, and send them the device list.

The designer proposes a complete rule (trigger, conditions, actions, templates) as a diff against your current configuration. Review each section, accept the parts you want, and reject the rest. Useful for getting started quickly on complex rules or for generating email and planner templates.

## How Rules Fire

- **Date Threshold** rules check every date on the chosen field and fire when it matches the configured window (for example, 30 days before warranty expiration). They are evaluated in the background; check execution logs for the actual run time.
- **Scheduled** rules run on a fixed frequency: every hour, every 6 hours, every 12 hours, daily, or weekly. You set the time of day for daily and weekly runs. Weekly runs are anchored to a fixed day managed by the system; there is no day-of-week picker.

Both trigger types respect the rule's **scope**. A rule scoped to specific companies only evaluates records belonging to those companies.


## Questions and troubleshooting

<AccordionGroup>
  <Accordion title="Does Run Now just preview the rule?">
    No. It queues a real execution and may send email, create a ticket or modify records. Use Run Test in the editor to preview matching records without executing actions.
  </Accordion>
  <Accordion title="Can a disabled rule be run manually?">
    No. Run Now requires the rule to be enabled. Review its scope and actions before enabling it; a recent or running execution may also block another manual request.
  </Accordion>
  <Accordion title="Does an AI proposal save the rule?">
    Accepting proposed changes updates the editor. Review the resulting configuration, test the matches and save the rule explicitly.
  </Accordion>
  <Accordion title="Does changing the company selector limit an All Companies rule?">
    No. A rule’s saved Scope determines which companies it evaluates. The selector can filter logs without changing the rule.
  </Accordion>
  <Accordion title="Why did a run match records without sending anything?">
    Inspect each action result, recipient resolution, approval state and duplicate suppression. A match count is not a delivery receipt or proof that a PSA ticket was created.
  </Accordion>
  <Accordion title="How should I handle a partially failed run?">
    Inspect successful and failed actions and any external records before retrying. A failure does not roll back emails or tickets already created; do not assume a retry is side-effect free.
  </Accordion>
</AccordionGroup>
