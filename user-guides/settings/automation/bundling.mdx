Bundling groups matching records so an automation can create company-level work or a digest instead of repeating the same action for every record. Use the options shown in your rule editor; available periods depend on whether the entity has a suitable date field.

## Configure a bundle

1. Open **Settings > Automation** and create or edit a rule.
2. Choose **Date Threshold** or **Scheduled**, set the company scope and conditions, then enable **Combine matching records**.
3. Choose company-only grouping, or a day, week, month or quarter period when available. For a scheduled rule with period grouping, choose its date field.
4. Configure the actions and templates. Review recipient choices separately from record scope.
5. Use **Run Test** and any available bundle preview to inspect the sample, dates, company groups and Planner outcome.
6. Check the Active setting, save, and inspect execution logs after the intended run.

Company grouping keeps different clients separate. Period grouping uses the selected record date: devices expiring in April and May can form different groups even if the rule runs on the same day.

## What happens to each action

| Action | Bundled behavior |
| --- | --- |
| Open Ticket | Creates work for a company group using the configured PSA routing |
| Add to Planner | Creates or updates linked bundle work; supported refreshable rules can keep the same Planner item current |
| Send Email, Send Survey, In-App Alert | Delivery is partitioned by recipient; a recipient’s digest contains the records they are permitted to receive |
| AI Transform | Uses bundle context for downstream bundled actions |
| Update Field, Set Relative Date | Still updates each matched record individually |

A bundled rule is not necessarily one email to everyone or one action total. Companies, periods, recipient sets and action types all affect the result.

## Write templates for a group

| Variable | Meaning |
| --- | --- |
| `{{entity_count}}` | Number of records in the relevant bundle |
| `{{entity_list}}` | Rendered list of its records and relevant dates |
| `{{group_period}}` | The group’s period label |

Example title:

```text
Warranty review: {{entity_count}} devices — {{group_period}}
```

Example body:

```text
Review the following devices for renewal or replacement:

{{entity_list}}
```

Use bundle variables for group summaries. Inspect the preview instead of assuming a single-record field, such as one serial number, represents the whole group. For recipient digests, counts and lists can differ between recipients.

## Planner dates and refreshes

The Planner action can offer a description, Planner Type, due offset, future-date restriction and past-due handling. Check the preview’s calculated dates: a bundled Planner date can be derived from the record date and trigger/action offsets, rather than simply the day the rule runs.

A refreshable Planner bundle can update an existing linked item’s generated title, description, dates, type and other managed details. Do not treat those generated fields as permanent manual notes. Complete successful refreshes can archive stale linked bundles; a failed or incomplete result does not prove cleanup finished.

## Failures and retries

Inspect action-level execution results and the created Planner/PSA records. Some actions can succeed before another fails. A failed bundle can remain eligible for retry, while action receipts and linked Planner items affect what repeats. Do not assume a failed run rolled back earlier sends or that a new run guarantees no duplicates.

The test and bundle preview may be sampled. A large match count does not mean every record is visible in the preview. If a refresh reports incomplete matching, resolve that issue before relying on its generated forecast.

## Questions and troubleshooting

<AccordionGroup>
  <Accordion title="Can I bundle a Scheduled rule?">
    Yes, when the editor offers Bundle matches for that rule. Choose company-only grouping or a supported period and date field. Bundling is no longer limited to Date Threshold rules.
  </Accordion>
  <Accordion title="Are only tickets and Planner items bundled?">
    No. Email, surveys, alerts and AI transforms can also use bundle context. Field and relative-date updates still run for each matched record.
  </Accordion>
  <Accordion title="Will everyone receive the same device list?">
    Not necessarily. Digest delivery is partitioned by recipient and permitted records. Review the intended recipients and do not use a portfolio count as the expected count for every email.
  </Accordion>
  <Accordion title="Will each run create a new Planner item?">
    A supported refreshable rule can update its existing linked bundle item. Review the preview and actual linked outcome instead of assuming every run creates a new item.
  </Accordion>
  <Accordion title="Can I manually rewrite an automation-managed Planner description?">
    A later bundle refresh can replace generated details. Keep durable manual context outside fields the rule manages, or change the rule’s template to alter its generated wording.
  </Accordion>
  <Accordion title="Why did a bundle disappear from the active Planner list?">
    A complete successful refresh can archive linked bundles that are no longer current. Check archived items, rule scope, date grouping and execution results before recreating work.
  </Accordion>
  <Accordion title="Does a failed bundle mean nothing happened?">
    No. Earlier actions may have succeeded. Inspect their results and external records before retrying, especially where a run sends messages or opens tickets.
  </Accordion>
</AccordionGroup>
