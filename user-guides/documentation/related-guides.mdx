Related guides are documents the AI Assistant offers while a ticket is being drafted, so the requester can try a known fix before the ticket is picked up. The ticket is still created. You import the documents that take part, AI writes a description, keywords and matching rules for each one, and a person reviews that text before any requester sees it.

<Note>
Related guides are turned on per organization by MSPortal. The **Related guides** tab appears in **Settings > Documentation** once it is on. Contact MSPortal support to enable it.
</Note>

## Before you start

- You need permission to manage Documentation settings.
- AI must be on for your portal (**Settings > Tenant > AI**). Without it, you can still edit, enable and review guides, but **Import** and **Regenerate metadata** stay off.
- The documents come from folders you already have in Documentation: portal pages, Hudu articles or IT Glue documents. Images inside IT Glue documents do not render in MSPortal.
- Company users only ever see guides whose document they can already open, following the same folder and document sharing rules as the **Documents** tab. Share the folder with the right client roles before expecting clients to see its guides.

## The Related guides table

Open **Settings > Documentation** and click **Related guides**. The tab is one table of your guides. Each row shows the document, its first three keywords, its review status and an **Enabled** switch. Filter any column from its header, and use **Columns** to add the **Description** column.

## Import a folder's documents as guides

<Steps>
  <Step title="Open Import">
    Click **Import** above the table. The **Import guides** dialog opens.
  </Step>
  <Step title="Choose a folder">
    Pick a folder of shared documents in **Folder**. Only folders that contain documents are listed. The line below tells you how many documents the folder holds and how many are already imported. Documents that are already imported are always skipped.
  </Step>
  <Step title="Import the documents">
    Click **Import N documents**. AI reads each document and writes a description of one to three sentences, up to fifteen keywords, and a **When to suggest** rule. The button shows progress while it works through the folder.
  </Step>
  <Step title="Check the result">
    The dialog closes when every document is imported, and each one appears in the table with **Needs review**. A document that could not be processed is listed in the dialog so you can import the folder again to retry it.
  </Step>
</Steps>

<Frame caption="Branch preview on the Demo tenant: the Import guides dialog before a folder is chosen.">
  <img src="/images/product/settings-related-guides-import-desktop.png" alt="Import guides dialog with a Folder picker, a note that documents already imported are skipped, and Cancel and Import buttons." width="2880" height="1920" />

A guide is suggested to requesters only once it is both reviewed and enabled.

## Review and edit a guide

Requesters never see a guide until a person has marked it reviewed. Open the row menu (**⋯**) and click **Edit**. The editor's title is the document's name.

<Steps>
  <Step title="Read the description">
    **Description** is required. Requesters see it with the guide, and the AI reads it to decide whether the document fits a request. Keep it to the problem the document solves and the product it covers.
  </Step>
  <Step title="Tune the keywords">
    **Keywords** are the words a requester would type: symptoms, product names, error text. A request that contains two keywords, or one multi-word phrase, always shows the guide; otherwise the AI picks from the best keyword matches. Add a keyword by typing it and pressing Enter; remove one with its ×.
  </Step>
  <Step title="Set the matching rules">
    Open **Matching rules** to see **When to suggest**. Requesters never see it. It tells the AI which requests the guide fits and which it does not, for example "Sign-in errors in Procore only; not for other apps."
  </Step>
  <Step title="Mark it reviewed and save">
    Leave **Show as a related guide** on, tick **Reviewed and accurate** once the text matches the document, then click **Save**. The row changes to **Reviewed**. Saving without the tick keeps the guide hidden from requesters.
  </Step>
</Steps>

<Frame caption="Branch preview on the Demo tenant: the guide editor with the AI-written description, keywords and matching rules for an onboarding checklist.">

Use the **Enabled** switch in the table to pause a guide without losing its text; the switch saves immediately and keeps the review. Choose **Delete** from the row menu to remove a guide; the document itself is kept.

## Update several guides at once

Tick the rows you want, or the header checkbox for every row, then open **Actions (n)**.

| Action | What it does |
| --- | --- |
| **Enable** | Turns on the selected guides. Their review status stays as it is. |
| **Disable** | Turns off the selected guides without losing their text or review. |
| **Mark reviewed** | Marks the selected guides reviewed by you. |
| **Regenerate metadata** | Has AI rewrite the description, keywords and matching rules from the current document, and sets each guide back to **Needs review**. Needs AI to be on. |
| **Delete** | Asks you to confirm how many guides to remove. The documents themselves are kept. |

## What requesters see

When someone describes a request to the AI Assistant, on the **New Ticket** page or from **Home**, the assistant starts the ticket draft and shows up to three matching guides beneath its reply, each with its reviewed description. Clicking a guide opens the document in MSPortal. The ticket draft continues as normal.

<Frame caption="Branch preview on the Demo tenant: the assistant drafting an offboarding ticket and showing the matching Employee Offboarding Procedure under its reply.">
  <img src="/images/product/related-guides-assistant-preview.png" alt="New Ticket page with the Assistant drawer open. The reply says a draft was started and a Related guides card lists Employee Offboarding Procedure with its description." width="1440" height="900" />

Guides are matched against the request text only. A guide with no keyword in the request can still be chosen by the AI from its description and matching rules, but the keyword rule above is the one to rely on when a document must always appear for a known phrase.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| No **Related guides** tab | The feature is not on for your organization. Contact MSPortal support. |
| **Import** in the dialog is disabled | Choose a folder, and check that AI is on for your portal. If the dialog says every document in the folder is already imported, use **Regenerate metadata** on those guides instead. |
| A guide never appears for requesters | It must be **Reviewed** and **Enabled**, and the requester must be able to open the document. Check the folder's sharing on the **Documents** tab and try a request containing two of its keywords. |
| A client sees a guide they should not | Guides follow document sharing. Remove the client role from the folder or document on the **Documents** tab. |
| The description is wrong | Edit it, or select the guide and choose **Regenerate metadata**, then review it again. Images in IT Glue documents are not read. |
| **Save** is disabled in the editor | Fill in **Description**. It is required. |
