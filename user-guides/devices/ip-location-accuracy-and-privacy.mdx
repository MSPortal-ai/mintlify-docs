Device IP location shows where a device appears to connect to the internet. MSPortal looks up the external IP address that the device's integration reported and uses MaxMind GeoIP City Plus to return an approximate location. This page is a reference for company users and MSP staff. To run a lookup, see [Find a device by its approximate IP location](/user-guides/devices/ip-location).

Use the result as a clue. Do not use it alone to make security, employment, compliance, or emergency decisions.

## The fields in the IP location section

Open a device from **Devices** and look at **Overview**.

| Field | Meaning |
|---|---|
| **External IP** | The public address most recently reported by a connected device integration |
| **IP observed** | When MSPortal recorded that external IP from the integration |
| **Approximate location** | The city, region, and country found for the external IP |
| **Accuracy** | The approximate radius around the returned point, shown as "Within about N km" |
| **Last checked** | When the location provider last looked up the external IP |

<Note>
The **IP Address** shown elsewhere in the device details can be an internal network address. The **External IP** in this section is the one used for the lookup.
</Note>

## Why a result can differ from the device's location

An external IP describes a network connection, not the device itself.

| Cause | What happens |
|---|---|
| Office NAT | Many devices at one office share one external IP and one location. |
| VPN or secure gateway | The result can be the VPN or security service exit point. |
| Mobile networks | Carrier traffic can exit far from the device and cover a large area. |
| ISP address allocation | Providers can register address ranges to a nearby city or regional hub. |

Read the pin together with the accuracy radius. A larger radius means a broader estimate.

## How long results are reused

MSPortal reuses recent results for the same public IP, so devices that share one internet connection do not cause duplicate lookups.

| Result | Reuse period |
|---|---|
| Location found | 30 days |
| No location available | 24 hours |
| Temporary lookup error | Retry after 15 minutes |
| Forced refresh by a device manager | Five-minute cooldown |

Automatic background checks are off by default. When your MSPortal environment turns them on, eligible external IPs are checked daily up to a set limit. Opening a device only shows the saved result. **Last checked** tells you how old it is.

## Privacy and access

- MSPortal sends the public IP to MaxMind for the lookup. It does not send device names or internal IPs, and it does not request device GPS data.
- Private, reserved, malformed, and network-range addresses are rejected before the lookup.
- MSPortal keeps normalized location fields, not the provider's full response.
- Access follows the same tenant, company, and device permissions as the device.
- Users who can manage devices can force a refresh. Other users who can view the device can see available results.
- **Open map** opens an external OpenStreetMap page. The link holds approximate coordinates, not the device name or IP.

## Good ways to use it

- Check whether a device appears near a known client office.
- Treat a surprising country or region as a reason to review VPN, sign-in, and RMM records.
- Spot devices that share an office firewall or gateway.
- Add network context when you troubleshoot a remote device.

Check **IP observed** before acting. An old IP may no longer match the device's current connection. Avoid repeated forced refreshes, because a new lookup cannot make a broad IP range exact.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Do portal users need a MaxMind API key?">
    No. The provider is set up centrally for MSPortal. You run lookups from the device details without credentials.
  </Accordion>
  <Accordion title="Does MSPortal track the device continuously?">
    No. It looks up an external IP reported during device sync. It does not receive GPS coordinates or track movement.
  </Accordion>
  <Accordion title="Why do several devices show the same location?">
    They likely share the same office firewall, VPN gateway, or ISP connection.
  </Accordion>
  <Accordion title="Why is there no city or accuracy radius?">
    Some address ranges only support a regional or country result. MSPortal shows only what the provider returns.
  </Accordion>
  <Accordion title="Does Last checked tell me when the device moved?">
    No. It dates the location lookup. **IP observed** dates the address the integration reported. Neither is a movement event.
  </Accordion>
  <Accordion title="Can a newer lookup make a VPN address identify the device?">
    No. It can still resolve to the VPN exit point. A newer result is not more precise.
  </Accordion>
  <Accordion title="Can a saved location stay visible if the provider is down?">
    Yes. An existing saved result stays readable. A displayed result does not mean a fresh lookup just succeeded.
  </Accordion>
</AccordionGroup>
