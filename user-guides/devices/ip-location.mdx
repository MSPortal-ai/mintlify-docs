MSPortal can estimate where a device connects to the internet by looking up the external IP address its integration reported. Use it to confirm a device appears to be at an expected office, or to spot a connection that needs a closer look. This guide is for company users and MSP staff who can open the device.

<Warning>
IP location is an estimate of the internet exit point. It is not the device's GPS position, street address, or proof of where a person is.
</Warning>

## Before you start

- You can open **Devices** and the device's company.
- The device came from an integration that reports an external IP address.
- The IP location service is available in your MSPortal environment.
- Your portal has active billing for new lookups.
- You do not enter a geolocation API key. The service is set up centrally.

## Find an approximate location

<Steps>
  <Step title="Open Devices">
    Click **Devices** in the sidebar.
  </Step>
  <Step title="Open the device">
    Click the device **Name**. The panel opens on **Overview**.
  </Step>
  <Step title="Check the external IP">
    Find the **IP location** section. Read **External IP** and **IP observed** to see which address will be checked and when the integration last reported it.

    <Frame caption="A device with no external IP reported. No lookup was run.">
      <img src="/images/product/device-missing-public-ip.png" alt="Device IP location section explaining that no external IP has been reported." width="1118" height="180" />
    </Frame>
  </Step>
  <Step title="Click Find approximate location">
    MSPortal shows the city, region, country, and **Accuracy** it finds. Some fields can be missing. If a saved result is already shown, you can open the map right away.
  </Step>
  <Step title="Click Open map">
    This opens one approximate point in a new OpenStreetMap tab. It does not show all your devices together.
  </Step>
</Steps>

<Tip>
Compare **IP observed** with **Last checked**. The first is when the integration reported the address. The second is when that address was last looked up.
</Tip>

## Check a location again

<Steps>
  <Step title="Click Check again">
    MSPortal reuses recent results to avoid extra lookups. If you can manage devices, **Check again** asks for a fresh lookup, with a short cooldown for the same IP. Other users can also click **Check again**, but they get the saved result until it is old enough to refresh.
  </Step>
  <Step title="Wait if a lookup is already running">
    If another lookup for the same IP is in progress, wait a moment and click **Check again** to get its result.
  </Step>
</Steps>

## When no external IP is available

The **IP location** section shows "No external IP has been reported by this device's integrations yet." In that case:

<Steps>
  <Step title="Check the integration">
    Confirm the device's integration is connected and syncing.
  </Step>
  <Step title="Check the source">
    Check that the source tool reports an external or public IP for the device.
  </Step>
  <Step title="Wait for the next sync">
    After the next device sync finishes, reopen the device.
  </Step>
</Steps>

MSPortal ignores private, reserved, malformed, and network-range addresses because they cannot give a public location.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| No external IP has been reported | The source has not sent a usable public IP. Check the integration sync and the device in the source tool. |
| No approximate location is available | The IP is valid but the provider has no result for it. This happens with new or privacy-managed ranges. Try again later. |
| The location service is temporarily unavailable | Wait a few minutes and try again. MSPortal delays retries after an error. |
| The map shows the wrong city | The IP may belong to an ISP gateway, VPN, or mobile carrier exit. Use the accuracy radius and compare with other device details. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can company users see device IP locations?">
    Yes, when their role lets them view the device. Your MSP controls company user permissions.
  </Accordion>
  <Accordion title="Does opening Overview run a paid lookup?">
    No. Opening the device only shows the saved result. **Find approximate location** and **Check again** start a lookup.
  </Accordion>
  <Accordion title="Does Check again always contact the location provider?">
    No. Most users get the saved result. Users who can manage devices can force a refresh, subject to the cooldown.
  </Accordion>
  <Accordion title="Do I need to save the device to keep a result?">
    No. The result is saved on its own.
  </Accordion>
  <Accordion title="Can I type a different IP address?">
    No. The lookup always uses the external IP on the device record.
  </Accordion>
  <Accordion title="Does Open map show all devices?">
    No. It opens one point on OpenStreetMap.
  </Accordion>
</AccordionGroup>
