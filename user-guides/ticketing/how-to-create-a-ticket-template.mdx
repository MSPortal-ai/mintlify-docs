Ticket templates give requesters a pre-built form with the questions your team needs. This guide is for MSP staff. It covers creating a template, configuring PSA defaults and access, adding sections and fields, company branches, and import and export.

For a short first template, follow [Create and preview a ticket template](/user-guides/ticketing/create-and-preview-ticket-template). Company users should read [Understand your available request templates](/user-guides/ticketing/understand-request-templates).

## Before you start

- Your role needs permission to write or manage ticket settings (**Settings > Tickets**).
- If you use an external ticketing system, connect your PSA integration first. PSA defaults only appear after it is connected.
- Set up ticket categories under **Settings > Tickets > General** if you want to group templates.

## Create a template

<Steps>
  <Step title="Open Templates">
    Go to **Settings > Tickets > Templates**.
  </Step>
  <Step title="Click New Template">
    Click **New Template** at the top right.
  </Step>
  <Step title="Fill in Template Details">
    Under **Template Details**, enter:
    - **Template Name**, such as "New Employee Setup"
    - **Category** (or leave **No Category**)
    - **Description**, a short note on when to use the template
    - **AI Description**, which tells the AI Assistant when to pick this template. Click **Generate** to write one from the template's fields. **Generate** works after you enter a name and add at least one field.
    - The **Template is active and available for use** switch. New templates start active. Turn it off while you draft.
  </Step>
  <Step title="Set PSA Integration Settings">
    Open **PSA Integration Settings** and pick the defaults for tickets created from this template. See [Set PSA defaults](#set-psa-defaults).
  </Step>
  <Step title="Add sections and fields">
    Under **Sections & Fields**, click **Add Section**, then **Add field** in each section. See [Add sections and fields](#add-sections-and-fields).
  </Step>
  <Step title="Preview the form">
    Click **Preview** in the page header and try the form. **Reset** clears your preview answers. Click **Close**, or click outside the panel, to return to editing.
  </Step>
  <Step title="Save Template">
    Click **Save Template** and wait for "Template created successfully". The editor returns to the Templates list.
  </Step>
</Steps>

The editor shows each setting group as a collapsible section. In order, they are **Template Details**, **PSA Integration Settings**, **Subject Configuration**, **Priority Override** (when a PSA is connected), **Flow Webhook (JSON)**, **TimeZest appointment scheduling** (when TimeZest is enabled for your portal), **Company Visibility**, **Role Access**, **Branches** and **Import / Export** (after the first save), then **Sections & Fields**.

## Set PSA defaults

Open **PSA Integration Settings** to choose defaults for tickets created from this template. The fields depend on your connected PSA.

<Tabs>
  <Tab title="ConnectWise">
    - **Service Board**
    - **Default Priority**
    - **Default Status**
    - **Default Ticket Type**
    - **Default Ticket Subtype**
  </Tab>
  <Tab title="Autotask">
    - **Queue**
    - **Default Priority**
    - **Default Status**
    - **Default Ticket Type**
    - **Default Ticket Category**
  </Tab>
  <Tab title="Halo PSA">
    - **Team** (when your Halo teams have synced)
    - **Default Priority**
    - **Default Status**
    - **Halo Category**
    - **Halo Impact**
    - **Halo Urgency**
  </Tab>
</Tabs>

Two controls apply to all providers:

- **Use Client's PSA Defaults.** When on, tickets use the board, priority, and status from the company's own settings instead of the template defaults.
- **Clear PSA defaults.** Removes every default on this template so the tenant or client settings take over.

<Note>
If a default status is not active on the selected board, the editor warns you and blocks saving until you pick a valid status.
</Note>

## Set a subject

Open **Subject Configuration**.

<Steps>
  <Step title="Enter a Subject Template">
    Type the subject, for example `New Employee: {{employee_name}} - {{department}}`. Use **Variables** to insert a field's value at the cursor. **Ticket Context** variables include **Reporting User** and **Company Name**.
  </Step>
  <Step title="Lock the subject (optional)">
    Turn on **Lock subject (users cannot modify it)**. Requesters then see the subject marked **Auto-generated** and cannot edit it.
  </Step>
  <Step title="Check the result">
    The **Preview** line shows the subject with sample values.
  </Step>
</Steps>

## Control who can use a template

### Company Visibility

Open **Company Visibility** in the editor to choose which companies can use the template.

<Steps>
  <Step title="Set the New Companies default">
    Under **New Companies**, choose **Enabled** (the default) or **Disabled**. This sets the template's visibility for any company added later.
  </Step>
  <Step title="Search for companies">
    Use **Search companies...** to find a company, then use its switch to turn the template on or off.
  </Step>
  <Step title="Use bulk buttons if needed">
    **Enable All** and **Disable All** change every company. **Enable All Except Branched** appears when the template has branches.
  </Step>
  <Step title="Save">
    Click **Save Template**. If some existing companies are off while **New Companies** is on, a "New companies will receive this template" prompt appears. Click **Save Anyway** to accept it, or **Cancel** to go back.
  </Step>
</Steps>

<Tip>
When you use company branches, click **Enable All Except Branched** so companies with a branch use their branch and every other company uses the parent template.
</Tip>

<Note>
A company with a branch uses its branch version whether or not the parent template is enabled for it.
</Note>

### Role Access

Open **Role Access** to limit the template to certain company roles.

- With no roles selected, the template is **Open** and every role can use it.
- Turn a role on to switch to **Restricted**. Only the selected roles can use the template.
- Click **Allow All Roles** to go back to open access. You cannot remove the last selected role. Use **Allow All Roles** instead.
- Branches inherit role restrictions from the parent template. Edit them on the parent.

Role Access limits who sees the template. It does not give anyone permission to create tickets.

### Company Gating (Types and Industries)

To limit a template to groups of companies, use the **Groups** column in the Templates list.

<Steps>
  <Step title="Open Company Gating">
    Go to **Settings > Tickets > Templates**. In the template's row, click the link in the **Groups** column (it shows **None** or a count such as "2 restrictions"). The **Company Gating** dialog opens.
  </Step>
  <Step title="Pick Types">
    Under **Types**, turn on one or more company groups. Types are the company groups you create under **Settings > Companies**. Click **Clear All** to remove every type.
  </Step>
  <Step title="Pick Industries">
    Under **Industries**, turn on one or more industries. The list comes from the industry set on your companies. Set it under **Settings > Companies**. ConnectWise companies fill it from the PSA market field.
  </Step>
  <Step title="Close the dialog">
    Each switch saves as you click it. The template now appears only for companies that match.
  </Step>
</Steps>

How gating combines:

- Types and industries are ANDed. A template gated to the type "Managed Services" and the industry "Healthcare" shows only for companies that match both.
- Inside one list, values are ORed. Pick three types and any company in any of the three matches.
- Industry matching ignores capitalization, so "healthcare" and "Healthcare" match.
- A template with no gating is available to every company that is not switched off in **Company Visibility**.

Gating applies on the New Ticket page, in the AI Assistant, and in the browser extension. If you remove a company from a group, the template stops showing for it on the next page load. Existing tickets are not affected.

## Create a company branch

A branch is a company-specific copy of a template. Use one when a client needs different fields, labels, or PSA routing.

<Steps>
  <Step title="Open Branches">
    Open the template, then expand **Branches**. This section appears after the template has been saved.
  </Step>
  <Step title="Click Create Branch">
    Click **Create Branch**.
  </Step>
  <Step title="Select the company">
    Use **Search companies...** to find the company and click it. Companies that already have a branch are not listed.
  </Step>
  <Step title="Click Create & Edit">
    Click **Create & Edit**. MSPortal copies the template and opens the copy for editing.
  </Step>
  <Step title="Edit the branch">
    Change fields, labels, help text, defaults, and PSA routing. You can also set a **Branch Name**, which shows in the Templates list.
  </Step>
</Steps>

A branch is a full independent copy. It is visible only to its company, its version history starts fresh, and later changes to the parent do not sync to it.

| Action | How |
|--------|-----|
| **Edit** a branch | Click the edit branch icon in the Branches section. |
| **Delete** a branch | Click the trash icon and confirm. The company goes back to the parent template. Deleting cannot be undone. |
| See branches in the list | In the Templates list, click the number in the **Branches** column to expand the rows. |

## Manage templates in the list

The Templates list at **Settings > Tickets > Templates** shows these columns: **Name**, **Category**, **Companies**, **Roles**, **Groups**, **Branches**, **PSA Board**, and **Status**.

- Click a **Companies**, **Roles**, or **Groups** value to open **Company Access**, **Role Access**, or **Company Gating**.
- Use the row's action menu for **Edit**, **Copy Permalink**, **Duplicate**, **Export / Import**, and **Delete**.
- Select several rows for bulk actions: **Set Category**, **Company Access**, **Role Access**, **Set Active**, **Set Inactive**, **PSA Settings**, **Generate AI Descriptions**, and delete.
- **Check for Issues** scans every template against your PSA configuration and lists problems that would make a submission fall back to email.
- **Import** creates a template from a file.

## Import and export a template

Open **Import / Export** in the editor (after the first save), or use **Export / Import** in a row's action menu.

**Export**

<Tabs>
  <Tab title="JSON">
    Click **Export JSON** for a complete backup: sections, fields, rules, PSA defaults, and optionally company branches. Use it before major changes or to share a template between tenants.
  </Tab>
  <Tab title="CSV">
    Click **Export CSV** for a spreadsheet of fields. Edit labels, help text, and options in a spreadsheet, then import it back.
  </Tab>
</Tabs>

**Import**

<Tabs>
  <Tab title="JSON">
    Click **Select JSON File**. Choose an **Import Mode**:
    - **Replace existing (overwrites all content)**
    - **Create new (fails if key exists)**

    Options: **Generate New Key** adds a timestamp to avoid conflicts. **Include Branches** imports company branches and needs matching companies.

    Importing over an existing template shows a **Changes Preview** with added, modified, and removed sections and fields. Review it, then click **Update Template**. Company visibility, role settings, and branches are kept.
  </Tab>
  <Tab title="CSV">
    Click **Select CSV File**, then **Import CSV**. CSV updates existing field labels, help text, and options. It cannot create a template or change structure. Use JSON for structure changes.
  </Tab>
</Tabs>

<Tip>
Export a JSON backup before you make major changes. You can import it later to restore the old version.
</Tip>

## Add sections and fields

<Steps>
  <Step title="Add a section">
    Under **Sections & Fields**, click **Add Section**. Click the section title to rename it. Use a section for each group of questions, such as Employee Information, Hardware, or Access.
  </Step>
  <Step title="Add a field">
    In the section, click **Add field**. Enter the **Field Label** and pick a **Type**.
  </Step>
  <Step title="Set the requirement">
    Set **Required** to **Optional**, **Required**, or **Conditional**. See [Show or require a field conditionally](#show-or-require-a-field-conditionally).
  </Step>
  <Step title="Add guidance and defaults">
    Add **Placeholder** text, **Help Text**, and a **Default Value** if needed. For dropdown, multi-select, and radio fields, click **Add Options** (or **Edit Options**) to list the choices.
  </Step>
  <Step title="Reorder">
    Drag sections and fields to reorder them. Click **Collapse All** to fold the sections while you organize, and **Expand All** to open them again.
  </Step>
</Steps>

The field **Key** is generated from the label and cannot be changed after the first save. Keys must be unique in a template. Use **Use in variables as** to see the name to use in subject variables.

**Field types**

| Type | Use it for |
|------|------------|
| **Text** | A short single-line answer |
| **Long Text** | A multi-line answer |
| **Number** and **Decimal** | Numeric input |
| **Dropdown** | One choice from a list |
| **Multi-Select** | Several choices from a list |
| **Radio Buttons** | One choice from a short visible list |
| **Checkbox** | A yes or no box |
| **Date** and **Date & Time** | Calendar and time pickers |
| **Email**, **Phone**, **URL** | Validated contact and link fields |
| **Contact phone update** | Collect a phone number to save to the requester's PSA contact |
| **Priority**, **Impact**, **Urgency** | PSA-driven choice fields |
| **User**, **Device**, **Location**, **Project**, **Site**, **Asset** | Pickers for existing records |
| **File Upload**, **File Attachment**, **Screenshot** | Attachments |
| **PSA Classification** | Let the requester choose an allowed PSA type, and optionally a subtype or Halo category |
| **Hudu / IT Glue Asset Field** | Shown only when Hudu or IT Glue is connected |
| **Microsoft 365 / Google Group** | Shown only when Microsoft 365 is connected |
| **Embedded Template** | Pull another template's questions inline as a sub-card. Each embedded template creates its own ticket. See [Embedded Templates](#embedded-templates). |
| **Label (display text)** | Read-only rich text for a notice or instructions. Write it in **Label Content**. Turn on **Require acknowledgment** to add a checkbox (default text "I have read and agree") that the requester must tick before submitting. The ticket records the acknowledgment. |

## Show or require a field conditionally

A rule has the form **When** *field* *equals* *value* **then** *show this field* or *make required*.

<Steps>
  <Step title="Open the field">
    Click the field row to expand its editor.
  </Step>
  <Step title="Choose what the rule does">
    To show the field only sometimes, check **Only show this field when another field has a specific value**. To make it required only sometimes, set **Required** to **Conditional**.
  </Step>
  <Step title="Build the rule">
    Under **When**, pick a trigger field, an operator such as **equals**, **not equals**, **includes**, or **is checked**, and a value. Trigger fields must come earlier in the template and be a checkbox, dropdown, multi-select, radio, priority, impact, or urgency field.
  </Step>
</Steps>

If no earlier field qualifies, the editor tells you to add a checkbox, dropdown, radio, priority, impact, or urgency field above to use as a trigger. A conditional field with no trigger blocks saving.

## Set a priority override

If a PSA is connected, open **Priority Override** to raise the PSA priority automatically when conditions are met.

<Steps>
  <Step title="Turn it on">
    Check **Enable Priority Override**.
  </Step>
  <Step title="Add a rule">
    Click **Add Rule**. Pick **When field**, an **Operator**, and a value. For a time-based operator, enter **Hours**. Then pick the priority under **Override to**.
  </Step>
  <Step title="Order the rules">
    Rules run from top to bottom and only the first match applies. Put the most urgent rule first, for example 24 hours before 72 hours.
  </Step>
</Steps>

## Embedded Templates

The **Embedded Template** field type lets one template pull in another template's questions inline, gated by the parent field's conditional logic. Each embedded template fires its own separate ticket on submit using its own PSA routing.

<Info>
Use embedded templates when a single user request can spawn multiple PSA tickets that need different routing. Classic example: a "New Hire" parent template asks "Will this person need a new computer?" and "Will this person need software access?" Each "Yes" reveals an embedded template (New Computer Request, Software Access Request) and each lands a separate ticket on its own service board with its own approver workflow.
</Info>

### How Embedded Templates Behave

| Behavior | Detail |
|----------|--------|
| **Visibility** | The parent field's conditional logic gates the embed. If the parent field isn't visible, the embed doesn't render and no child ticket fires. |
| **One ticket per embed** | Every visible embedded template field creates exactly one separate PSA ticket. Two embed fields pointing at the same target template create two tickets. |
| **PSA routing** | Each embed uses the **embedded template's** own service board, priority, status, ticket type, ticket subtype, and category, not the parent's. |
| **Same PSA integration** | Both parent and embed land in the tenant's currently selected PSA integration. There is one selected PSA per tenant. |
| **Attachments** | File uploads, screenshots, and attachment fields placed inside an embedded template are uploaded to that embed's PSA ticket, not the parent's. |
| **Company gating inheritance** | Embedded templates do **not** need to be enabled for every company the parent applies to. The parent's gating rules already govern visibility; the embed is treated as part of the parent flow. |
| **Parent ticket reference** | Every child ticket prepends "Related to ticket #N in template Foo" to its description so support staff can trace the relationship in the PSA. |
| **Parent ticket summary note** | After the embed loop runs, MSPortal posts an internal note on the parent PSA ticket listing every related ticket number, fallback-emailed embed, and any failures. |

### Adding an Embedded Template Field

<Steps>
  <Step title="Add a Field">
    Click **Add field** in the section that should host the embed, then click the field row to expand the editor.
  </Step>
  <Step title="Set the Type to Embedded Template">
    Open the **Type** dropdown and select **Embedded Template**.
  </Step>
  <Step title="Pick the Child Template">
    A teal **Embedded template** picker appears below the field's Help Text. Choose the template you want to embed. The picker lists every other active template in your tenant. Templates that already contain their own embedded templates are disabled in the picker (depth-1 cap, see below).
  </Step>
  <Step title="Configure the Conditional (Recommended)">
    Check **Only show this field when another field has a specific value**, then build the rule so the embed only renders when a specific parent field has the right value. For example: **When** "Need a new computer?" **equals** "Yes". Without a rule, the embed always renders and always fires a child ticket.
  </Step>
  <Step title="Save">
    Click **Save Template**. MSPortal validates the embed reference before saving and surfaces clean inline errors if anything is wrong (missing target, cross-tenant reference, depth-1 violation).
  </Step>
</Steps>

### The Depth-1 Cap

An embedded template **cannot** itself contain embedded templates. This is enforced at three layers so it cannot be bypassed:

- The picker disables any candidate template that already has an embed reference, with a `(contains embeds)` label so admins know why
- The save flow blocks the upsert with a clear inline error if the picker is bypassed
- The runtime renderer drops nested embeds defensively, surfacing a soft-warning card so the issue is visible

<Tip>
If you need a deeper hierarchy, model it with conditional fields inside the embedded template instead of trying to nest a third level. Conditional fields support arbitrary depth and don't change the ticket count.
</Tip>

### Embedded Templates and PSA Routing

Each embedded template is a normal ticket template, so all of its PSA settings apply when the embed fires:

- **Service board / queue**: the embed's `default_board` is used. If the parent goes to "Service Desk" and the embed's default board is "Procurement", the parent ticket lands on Service Desk and the embed lands on Procurement.
- **Priority and status**: the embed's `default_priority` and `default_status` are used.
- **Ticket type / subtype / category**: the embed's defaults are used.
- **Halo Category / Impact / Urgency**: the embed's Halo-specific routing is used.
- **Use client's PSA defaults toggle**: if the embed has this toggle on, the embed reads board/priority/status from the client's company-level defaults instead of the embed's own template defaults.
- **Per-company branches on the embed**: if the embed has a branch for the parent's company, the branch's overrides apply.

<Warning>
**ConnectWise specifically:** the embed's default status must be active on the embed's default board. If they don't match, the embed throws a clear error like "Template status X is not active on the selected ConnectWise board" and the child ticket fails. The parent ticket still succeeds. Verify each embed's board+status combination in the editor's PSA Integration Settings.
</Warning>

### Attachments Inside Embeds

File Upload, Screenshot, and Attachment fields placed inside an embedded template attach their files to the **embed's** PSA ticket, not the parent's. This lets you capture supporting documents per child request:

- Parent: "New Hire" template, no attachments
- Embed 1: "New Computer Request", attach the approved hardware quote
- Embed 2: "Software Access Request", attach the user's training certificate

Each PSA ticket receives only the attachments uploaded to its corresponding form section.

### Form Preview Renders Embeds

The Form Preview panel (click **Preview** in the page header) renders embedded templates inline as teal-bordered sub-cards. The preview runs the embed's own conditional engine against the values you fill in, so you can verify show/hide behavior before saving.

If the embed reference can't be resolved (deleted target, depth-1 cap drop, cross-tenant), the preview shows a clear warning instead of silently rendering nothing.

### What Happens on Submit

When a user submits a parent ticket form:

1. The parent ticket is validated and created in the PSA first.
2. For each embedded template whose parent field's conditional is satisfied, MSPortal fires a separate `submitTicketFromTemplate` call using the embed's templateId.
3. Each child ticket is created with its own routing, attachments, and "Related to ticket #N" prefix on the description.
4. After the embed loop completes, MSPortal posts a single internal note on the parent ticket summarizing each child:
   - Successes with their PSA ticket numbers
   - Embeds that fell back to email (when the PSA call failed)
   - Embeds that failed to create (with the error so support can manually retry)
5. The submitter sees a toast indicating how many related tickets were created, fell back, or failed.

<Tip>
If only some embeds succeed, the parent ticket is still created and tracked. Use the parent's summary note to find which embeds need manual follow-up.
</Tip>

### Validation Errors When Saving

When you save a template with embedded fields, MSPortal validates each embed reference and shows clean inline errors next to the offending field if anything is wrong:

| Reason | What it means | Fix |
|--------|---------------|-----|
| **Missing target** | The referenced template no longer exists or was deleted | Pick a different template |
| **Self-reference** | The field tries to embed the template into itself | Pick a different template |
| **Depth-1 violation** | The referenced template itself contains embedded templates | Pick a non-embedding template, or restructure the deeper template |
| **Cross-tenant** | The referenced template is in a different tenant (rare; usually only seen during template imports) | Pick a template from your own tenant |

The error appears as a red banner inside the embed picker card and clears optimistically as soon as you pick a different template.


## Offer appointment scheduling

If TimeZest is enabled for your portal, open **TimeZest appointment scheduling** to let requesters pick a time after the ticket is created.

<Steps>
  <Step title="Turn it on">
    Check **Offer Schedule Appointment for this template**.
  </Step>
  <Step title="Choose the TimeZest settings">
    Pick the **TimeZest integration**, the **Appointment type**, and the **Scheduling resources**. You can select more than one resource only with TimeZest Professional.
  </Step>
  <Step title="Save">
    Click **Save Template**. Requesters then see **Schedule appointment** on the form. They create the ticket first and then continue to TimeZest.
  </Step>
</Steps>

Appointment scheduling is not available on webhook-only templates, because no PSA ticket is created. See [Flow Webhook Recipient](/user-guides/ticketing/flow-webhook-recipient) for the **Flow Webhook (JSON)** section.

<Steps>
  <Step title="Open the AI Template Designer">
    Click the floating AI button on the right side of the editor.

## Activate and verify a template

<Note>
Branch preview: choose multi-select defaults using the **Default Value** checkboxes. The Form Preview starts with the configured defaults, and **Reset** restores them after testing. All fields, including embedded fields, use their configured conditions to determine when they appear in the form and preview.
</Note>

<Steps>
  <Step title="Review the template">
    Check every section, field, PSA default, and access setting.
  </Step>
  <Step title="Save as inactive first (optional)">
    Turn off **Template is active and available for use**, click **Save Template**, and test with the preview.
  </Step>
  <Step title="Activate">
    Reopen the template, turn the switch on, and click **Save Template** again. You can also use **Set Active** in the Templates list.
  </Step>
  <Step title="Verify availability">
    Open **Tickets > New Ticket** for the intended company and confirm the template appears. Preview does not submit a ticket.
  </Step>
</Steps>

## Best practices

<AccordionGroup>
  <Accordion title="Use Descriptive Names">
    Name templates so requesters can pick the right one. Include the purpose, such as "Password Reset - Standard" and "Password Reset - VIP".
  </Accordion>
  <Accordion title="Group Related Fields">
    Organize fields into logical sections so long forms stay manageable.
  </Accordion>
  <Accordion title="Use Conditional Fields">
    Show a field only when it matters. For example, show "Manager Approval" only when the request is over a budget.
  </Accordion>
  <Accordion title="Test Before Activating">
    Save the template as inactive, preview it, and activate it when the fields capture the right information.
  </Accordion>
  <Accordion title="Use Branches Sparingly">
    Create a company branch only for significant differences. Conditional fields handle minor variations.
  </Accordion>
  <Accordion title="Use Embedded Templates for Multi-Ticket Workflows">
    Use **Embedded Template** fields when one request should create several PSA tickets with different routing. For variations that share routing, use conditional fields in one template.
  </Accordion>
  <Accordion title="Verify Embed Routing Before Activating">
    Each embed's board, priority, status, and type must be a valid PSA combination. For ConnectWise, the status must be active on the chosen board. Preview each conditional path and review the embedded template's **PSA Integration Settings** before you go live.
  </Accordion>
</AccordionGroup>

## Troubleshooting

| Issue | What to do |
|-------|------------|
| Template not appearing | Check that it is active, enabled for the company under **Company Visibility**, allowed for the role under **Role Access**, and not excluded by **Company Gating**. |
| Conditional field not showing | Check the trigger field and value. The trigger must come earlier in the template. |
| Cannot save: "needs a trigger field selected" | A conditional field has no trigger. Pick one or remove the condition. |
| Cannot save: field key used more than once | Field keys must be unique. Rename one of the fields. |
| PSA fields not loading | Check that your PSA integration is connected and synced. |
| Cannot save: default status not active on this board | Pick a status that is active on the selected board. |
| Import fails | The JSON must match the export format. CSV needs an existing template. |
| Embedded template option disabled in the picker | That template already contains its own embeds (depth-1 cap). Pick a template without embeds. |
| "Embedded template references need attention" on save | An embed field points to a missing, cross-tenant, or self-referencing template. The red banner in each embed picker says which. Pick another template and save again. |
| Embed ticket failed but the parent succeeded | Open the parent ticket in your PSA. MSPortal posts a summary note listing each embed's result. For ConnectWise, a common cause is a default status that is not active on the embed's board. Fix the embed's PSA Integration Settings and create the missing ticket by hand. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Where do I create a template?">
    Go to **Settings > Tickets > Templates** and click **New Template**.
  </Accordion>
  <Accordion title="Does Preview create a ticket?">
    No. Preview only shows the form. It does not test PSA creation, webhooks, embedded tickets, or scheduling.
  </Accordion>
  <Accordion title="Can I disable a template by turning every role off?">
    No. With no roles selected, every role can use the template. Turn off **Template is active and available for use** instead.
  </Accordion>
  <Accordion title="Why can't I edit a field key?">
    Keys are locked after the first save so existing tickets and subject variables keep working. Change the label or help text instead.
  </Accordion>
  <Accordion title="Do changes to the parent template reach branches?">
    No. A branch is an independent copy. Edit each branch separately.
  </Accordion>
</AccordionGroup>
