Use this guide to connect GitHub Copilot Chat in VS Code, or the GitHub Copilot CLI, to MSPortal's MCP tools. It is for MSP staff and API consumers. The connection uses browser OAuth, so you do not create or store an API key.

<Warning>
GitHub Copilot's cloud coding agent and code review do not support remote MCP servers that use OAuth. Connect MSPortal through Copilot Chat in your local VS Code or through Copilot CLI.
</Warning>

## Before you start

- An MSPortal account you can sign in to.
- The **MCP Server** write permission in MSPortal. If the setup cards are disabled, ask your MSP administrator for it.
- Your **Server URL** from **Settings > MCP Server**.
- For VS Code, a current VS Code with GitHub Copilot installed and signed in.
- For Copilot CLI, GitHub Copilot CLI installed and signed in. Run `copilot login` if needed.

## Connect GitHub Copilot in VS Code

<Steps>
  <Step title="Open the MSPortal MCP settings">
    In MSPortal, go to **Settings > MCP Server**. Under **Connect your client**, click **GitHub Copilot (VS Code)**.
  </Step>
  <Step title="Add the server to VS Code">
    Click **Add to GitHub Copilot (VS Code)** in the dialog and allow VS Code to open the configuration.

    You can also open the VS Code Command Palette, run **MCP: Add Server**, choose **HTTP**, and paste your Server URL. Name the server `msportal`, then choose whether to install it globally or in the current workspace. Choose global if you want MSPortal in every workspace.
  </Step>
  <Step title="Trust and authenticate the server">
    Allow VS Code to start the server. When your browser opens, sign in to MSPortal, review the access you are asked for and click **Allow access**.
  </Step>
  <Step title="Enable the MSPortal tools">
    Open GitHub Copilot Chat, select **Agent** mode, and click **Configure Tools** in the chat input. Make sure the MSPortal tools you want are enabled.
  </Step>
  <Step title="Test the connection">
    Ask Copilot to call **get_current_user**. The answer should show your user, tenant and company. A list of tool names without a real tool call does not prove the connection works.
  </Step>
</Steps>

### Configure VS Code by hand

If you prefer, run **MCP: Open User Configuration** from the Command Palette and add:

```json
{
  "servers": {
    "msportal": {
      "type": "http",
      "url": "YOUR_SERVER_URL"
    }
  }
}
```

Save the file. Then use the actions above the `msportal` entry to start and authenticate the server.

## Connect GitHub Copilot CLI

<Steps>
  <Step title="Copy your Server URL">
    In MSPortal, go to **Settings > MCP Server** and copy the **Server URL**.
  </Step>
  <Step title="Add the remote server">
    Run this command, with your URL in place of the placeholder:

    ```bash
    copilot mcp add --transport http msportal YOUR_SERVER_URL
    ```
  </Step>
  <Step title="Authenticate with MSPortal">
    Start Copilot CLI with `copilot`, then enter:

    ```text
    /mcp auth msportal
    ```

    In the browser window that opens, sign in to MSPortal, review the access and click **Allow access**. Signing in to GitHub does not authorize MSPortal, so you need this separate step.
  </Step>
  <Step title="Verify the connection">
    In Copilot CLI, enter:

    ```text
    /mcp show msportal
    ```

    Check that the server is connected and lists its tools. Then ask Copilot to call **get_current_user** and check the user and tenant.
  </Step>
</Steps>

### Configure Copilot CLI by hand

You can set up the same connection in `~/.copilot/mcp-config.json`:

```json
{
  "mcpServers": {
    "msportal": {
      "type": "http",
      "url": "YOUR_SERVER_URL",
      "tools": ["*"]
    }
  }
}
```

<Note>
VS Code and Copilot CLI use different formats. VS Code uses a `servers` object in its `mcp.json`. Copilot CLI uses an `mcpServers` object in `~/.copilot/mcp-config.json` and does not read `.vscode/mcp.json`.
</Note>

## Use the grouped tools

The MSPortal catalog groups operations into up to **93 public tools** that cover 260 existing operations. Copilot sees tools such as `query_projects` and `manage_planner` and picks the action from each tool's schema. What you see depends on the server version and your access.

Calls with the old single-operation names, such as `list_projects`, still work with their original arguments. Pending confirmations keep their operation and expiry. You do not need a new Server URL or more access.

When you move to the grouped catalog, refresh Copilot's tool list. In VS Code, open **Configure Tools** and enable the new tool names. In Copilot CLI, check any explicit `tools` list. The `"tools": ["*"]` example above does not name old tools and grants no extra permissions. A custom client that needs the old names in `tools/list` must update its discovery logic. See the [tool reference](/user-guides/mcp-server/tools-reference).

## Ask Copilot for changes safely

<Steps>
  <Step title="Start with read tools">
    Ask Copilot to use read tools for the company you name. Check the tool calls and what they returned.
  </Step>
  <Step title="Request a change">
    Ask for the change. Most changes return a proposal first. Read it.
  </Step>
  <Step title="Approve, then check">
    Approve only a proposal that matches your intent. Then open the record to check the result.
  </Step>
</Steps>

Copilot's tool-approval prompt, MSPortal's access prompt and a proposal confirmation are three different steps. A client-wide approval setting does not replace the proposal. Some tools run at once. Marking notifications changes state, and feedback submission sends the message you asked for. See [Confirmation before changes](/user-guides/mcp-server/index#confirmation-before-changes).

## Review or remove the connection

<Steps>
  <Step title="Open MCP Server settings">
    In MSPortal, go to **Settings > MCP Server** and find **Connected clients**.
  </Step>
  <Step title="Revoke the Copilot connection">
    Click **Revoke** beside the Copilot client and confirm.
  </Step>
</Steps>

The access you approve is limited by your MSPortal role, tenant and company visibility. Revoking does not delete your local Copilot configuration or take back data already returned. An issued access token can work for up to about 15 minutes. Ask your MSP administrator to remove your MCP permission if requests must stop sooner.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| The browser sign-in did not open | In VS Code, run **MCP: List Servers**, select **msportal** and choose the authentication action. In Copilot CLI, run `/mcp auth msportal`. |
| MSPortal does not appear in Copilot | In VS Code, run **MCP: List Servers** and check that `msportal` is started. In Copilot CLI, run `/mcp show msportal`. The two clients use separate configuration files. |
| Copilot cannot see a tool | Find its grouped tool name in the [tool reference](/user-guides/mcp-server/tools-reference). In VS Code, check **Configure Tools**. Update any list of old tool names, then check your approved access and your MSPortal role. |
| Your organization blocks the server | GitHub and VS Code policies can limit which MCP servers are allowed. Ask your administrator to allow the MSPortal Server URL. |
| The connection stopped working | Authenticate again. If that fails, revoke the Copilot connection in **Settings > MCP Server** and connect again. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does signing in to GitHub also authorize MSPortal?">
    No. Sign in to MSPortal and approve access separately for the server connection.
  </Accordion>
  <Accordion title="Can VS Code and Copilot CLI share one configuration?">
    No. The formats and file locations differ. Do not copy one into the other.
  </Accordion>
  <Accordion title="Does enabling a tool bypass company scope?">
    No. MSPortal still applies your OAuth access, role permissions, company scope and tool limits.
  </Accordion>
  <Accordion title="Does Revoke delete my local MCP setup?">
    No. It revokes the MSPortal grant and refresh sessions. Remove the local entry yourself if you do not want it.
  </Accordion>
  <Accordion title="Does Copilot listing tools prove the connection works?">
    No. Check the server status and ask Copilot to call **get_current_user** with the right user and tenant before you ask for company data.
  </Accordion>
  <Accordion title="Does Copilot's approval prompt replace the proposal confirmation?">
    No. They are separate. Review the proposal before you approve it.
  </Accordion>
</AccordionGroup>
