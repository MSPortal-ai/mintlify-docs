The MSPortal MCP server lets a compatible AI client, such as Claude, Cursor, Codex or Gemini CLI, use portal tools under your account's access. This guide is for MSP staff and API consumers who connect an external AI client. It is separate from the built-in Home assistant. Sign-in uses a browser and OAuth, so there is no API key to copy.

## Before you start

- You need an MSPortal account and a role with **MCP Server** write permission. Without it you can open **Settings > MCP Server** and see the page, but the setup cards are disabled and the page says "You have view-only access."
- Your MSP administrator manages roles in **Settings > Users & Roles**, including for company users.
- Your AI client must support remote **Streamable HTTP** MCP servers with browser OAuth sign-in. Local-server support alone is not enough.
- Data that tools return goes to the AI client you connect. It is handled under that service's terms and your organization's policies. Connect only the areas you need.

## Connect your client

<Steps>
  <Step title="Open MCP Server settings">
    In MSPortal, go to **Settings > MCP Server**. The page shows **MSPortal MCP server** with the badges **OAuth 2.1 + PKCE**, **Streamable HTTP** and **Scoped to your permissions**.
  </Step>
  <Step title="Copy the Server URL">
    Click the copy button beside **Server URL**. The same URL works for everyone in your organization, and each person signs in with their own account. Use the URL shown by your own regional portal.
  </Step>
  <Step title="Open the setup card for your client">
    Under **Connect your client**, click your client. A dialog titled **Set up** and the client's name opens with a ready-made command or configuration. Copying a snippet does not connect anything yet.
  </Step>
  <Step title="Add the server to your client">
    Follow the section for your client below. Where the card has a one-click button, such as **Add to Cursor**, it opens the client app, which may ask you to trust and start the server.
  </Step>
  <Step title="Sign in and approve access">
    Your browser opens **Authorize MSPortal MCP access**. Complete sign-in and any account verification. Under **Choose which areas this client can use**, tick only the areas you need. The page shows **Tools selected** and warns when the count may exceed your client's tool limit. Click **Allow access**, or **Deny** if you do not expect this request.
  </Step>
  <Step title="Check that it works">
    In your client, check the server status and the tool list. Then ask it to call **get_current_user**. The result shows the connected user, tenant and company. An answer that only lists tool names, with no tool call, does not prove the connection works.
  </Step>
</Steps>

### Add the server to your client

Replace `YOUR_SERVER_URL` with the **Server URL** you copied. The setup card in MSPortal fills in your URL for you.

<Tabs>
  <Tab title="Claude Code">
    1. Run this command in your terminal:
       ```bash
       claude mcp add --transport http msportal YOUR_SERVER_URL
       ```
    2. In Claude Code, run `/mcp` and select **msportal** to authenticate.
    3. Approve access in the browser window that opens.
  </Tab>
  <Tab title="Claude Desktop & Web">
    1. Open **Settings**, then **Connectors**.
    2. Click **Add custom connector**.
    3. Name it **MSPortal**, paste the Server URL, then click **Add**.
    4. Click **Connect** and approve access in your browser.
  </Tab>
  <Tab title="Cursor">
    1. Click **Add to Cursor** on the setup card, or paste this into `~/.cursor/mcp.json`:
       ```json
       {
         "mcpServers": {
           "msportal": { "url": "YOUR_SERVER_URL" }
         }
       }
       ```
    2. Open **Cursor Settings**, then **MCP**, and click **Connect** next to **msportal**.
    3. Approve access in the browser window that opens.
  </Tab>
  <Tab title="GitHub Copilot (VS Code)">
    1. Click **Add to GitHub Copilot (VS Code)** on the setup card, or run:
       ```bash
       code --add-mcp '{"name":"msportal","type":"http","url":"YOUR_SERVER_URL"}'
       ```
    2. When VS Code asks, allow it to start the server and sign in.
    3. Approve access in the browser window that opens.

    For the complete VS Code and Copilot CLI steps, see [Connect GitHub Copilot](/user-guides/mcp-server/github-copilot).
  </Tab>
  <Tab title="OpenAI Codex">
    1. Run these commands:
       ```bash
       codex mcp add msportal --url "YOUR_SERVER_URL"
       codex mcp login msportal
       ```
       Or add this to `~/.codex/config.toml`:
       ```toml
       [mcp_servers.msportal]
       url = "YOUR_SERVER_URL"
       ```
    2. Approve access in the browser window that opens.
  </Tab>
  <Tab title="Gemini CLI">
    1. Run this command in your terminal:
       ```bash
       gemini mcp add --transport http msportal YOUR_SERVER_URL
       ```
    2. In Gemini CLI, run `/mcp auth msportal` and approve access in your browser.
  </Tab>
  <Tab title="Windsurf">
    1. Open **Windsurf Settings**, then **Cascade**, and click **Add Server**.
    2. Paste this into `mcp_config.json` and save:
       ```json
       {
         "mcpServers": {
           "msportal": { "serverUrl": "YOUR_SERVER_URL" }
         }
       }
       ```
    3. Refresh the server list and approve access in your browser.
  </Tab>
  <Tab title="Other clients">
    1. Add a remote MCP server in your client and paste the Server URL.
    2. Most clients accept a JSON entry like this:
       ```json
       {
         "mcpServers": {
           "msportal": { "type": "http", "url": "YOUR_SERVER_URL" }
         }
       }
       ```
    3. Authenticate when prompted and approve access in your browser.
  </Tab>
</Tabs>

Configuration formats differ between clients. Do not paste one client's JSON or command into another.

## What an assistant can do

Tools cover tickets, devices, reporting, Planner, goals, budgets, meetings, compliance, projects, financial data, cloud services, security, backup, surveys, training, onboarding and more. The [MCP Tools Reference](/user-guides/mcp-server/tools-reference) lists every action and how it behaves.

What you actually get depends on the server version, the areas you approved, your role, your company access, your integrations and your client's tool selection. A company identity does not get MSP-only tools, even with broader scopes. List results can be paginated or cut short, so a small result does not prove a search was complete.

A good first request is: "Use read tools to find the company I name and summarize the available evidence. Do not change records or send messages." Then check the cited records, dates and gaps before you ask for follow-up work.

### Grouped tools and existing connections

The catalog groups related operations into **93 public tools** that cover **260 existing operations**. Read tools have names such as `query_planner`. Changes use names such as `manage_planner`, with an action for creating, editing or archiving. The assistant reads each tool's input schema to pick the action and its arguments.

The full catalog fits under a 128-tool client limit. The consent screen counts the tools for the areas you pick. Other servers connected to your client also count toward its limit.

Existing tool names keep working with their original arguments and response shapes, including the two compatibility aliases. Pending confirmations keep their original operation and expiry. You do not need a new server URL or broader access because of the grouping.

When your client refreshes its tool list, it sees the grouped names. Update any tool-name allowlist to include them. A custom client that needs old names in `tools/list` must change its discovery logic, because old calls still work but the old discovery response does not. See [grouped calls and legacy compatibility](/user-guides/mcp-server/tools-reference#existing-connections-and-legacy-names).

### Confirmation before changes

Most changes use a two-call proposal and confirmation flow.

<Steps>
  <Step title="Request the change">
    The client calls the `manage_*` tool without `confirm`. MSPortal returns a proposal with a preview, the company, the records and the effects. Nothing is saved yet.
  </Step>
  <Step title="Review and approve">
    Read the proposal. Approve it only if it matches what you intended.
  </Step>
  <Step title="Confirm before it expires">
    The client calls the same tool and action again with `confirm: true` and the returned `confirmationId`. A proposal expires after ten minutes.
  </Step>
  <Step title="Check the result">
    Open the resulting record or background job. An accepted job request does not prove the provider delivered it.
  </Step>
</Steps>

The confirmation applies the **stored proposal**. To change the target or values, request a new proposal and review it again. An expired or used confirmation cannot be reused.

<Warning>
Not every tool has a confirmation step. **mark_notification_read** changes your notification state at once. **draft_compliance_notes** generates drafts and does not save them. **submit_feedback** sends a message to MSPortal at once and is for MSP staff only. Use it only when you explicitly ask to send feedback. Finding a missing feature does not authorize a message.
</Warning>

If a change times out or the result is unclear, check the target record before you ask the assistant to repeat it. Steps in a multi-step workflow are not rolled back together.

## Install the Ron skill (optional)

The Ron skill is a set of instructions that guides an assistant through client briefings, risk reviews, QBR preparation and planning. It does not connect to MSPortal or grant permissions. You still connect the MCP server first.

<Steps>
  <Step title="Download the three files">
    Get the [Ron skill](https://app.msportal.ai/skills/ron-vcio/SKILL.md), the [playbooks](https://app.msportal.ai/skills/ron-vcio/references/playbooks.md) and the [tool map](https://app.msportal.ai/skills/ron-vcio/references/tool-map.md). On an EU portal, use the same paths on your regional portal address.
  </Step>
  <Step title="Keep the folder layout">
    Put `SKILL.md` in a folder named `ron-vcio`, and the other two files in a `references` folder inside it.
  </Step>
  <Step title="Add it to your client">
    Install the folder with your client's skill or custom instruction feature. Do not paste the files at the end of an existing instruction file.
  </Step>
  <Step title="Test it">
    Ask the assistant for a client briefing and check that it calls MSPortal tools. If it answers without any tool calls, check the server connection and the enabled tools first.
  </Step>
</Steps>

## Manage connected clients

Open **Settings > MCP Server** and scroll to **Connected clients**. It lists the applications you have authorized, each with an **MSPortal** or **External app** badge, the **Last authorized** time, the number of active sessions and the number of scopes. It shows only your own connections, not those of other users.

<Steps>
  <Step title="Find the client">
    Look for the client name in **Connected clients**.
  </Step>
  <Step title="Revoke it">
    Click **Revoke** on its row. The dialog **Revoke access for** the client name asks you to confirm. Click **Revoke** again. You see **Access revoked**.
  </Step>
  <Step title="Reconnect if needed">
    To connect it again, add the server in the client and approve access in the browser.
  </Step>
</Steps>

Revoking ends the client's grant and refresh sessions. An access token already issued can work until it expires, up to about 15 minutes. To block access sooner, ask your MSP administrator to remove your **MCP Server** permission, which MSPortal checks on every request. Revoking does not take back data the client already received, undo finished actions or remove the client's local server entry.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| The setup cards are disabled | You have view-only access. Ask your MSP administrator for the **MCP Server** write permission. |
| The consent page says MCP access is not permitted | Your role does not include the MCP Server permission. Ask your MSP administrator. |
| The browser sign-in does not open | Run your client's authenticate step again, such as `/mcp` in Claude Code, `codex mcp login msportal` in Codex or **Connect** in Cursor. Check that your client supports remote HTTP and OAuth. |
| You see the wrong company or tenant | Stop. Call **get_current_user**, check the identity and the regional URL, then reconnect if needed. |
| A tool is missing | Find its grouped tool in the reference. Then check the server version, the areas you approved, your permissions, integrations and your client's tool selection. |
| Your client has too many tools | Refresh the client's tool list. Reconnect and approve fewer areas, and check other connected servers. |
| A confirmation expired | Request a new proposal and review it. The old one was not saved. |
| The assistant answers without calling tools | Ask it to list the MSPortal tools it can see. If the list is empty, the connection is not live. Reconnect. |
| **Failed to revoke access** | Reload the list and check whether the client is still there before you assume access ended. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does copying the Server URL connect a client?">
    No. You must add the URL in a compatible client, sign in and approve access.
  </Accordion>
  <Accordion title="Can a view-only user connect clients?">
    No. Connecting needs the **MCP Server** write permission.
  </Accordion>
  <Accordion title="Do broader OAuth scopes override my permissions?">
    No. Scopes, role permissions, company scope and tool-specific limits all apply.
  </Accordion>
  <Accordion title="Will the grouped catalog break calls with the old tool names?">
    No. The 260 old names still work with their original arguments and results. Only discovery changed, so client allowlists and custom discovery checks may need updating.
  </Accordion>
  <Accordion title="Does a proposal mean a record was created?">
    No. A proposal waits for confirmation. Check the record after you confirm.
  </Accordion>
  <Accordion title="Can I change a proposal by changing the confirmation arguments?">
    No. The confirmation commits the stored proposal. Request a new proposal instead.
  </Accordion>
  <Accordion title="Does every action need a second confirmation call?">
    No. Some run at once, including marking notifications read and sending requested feedback.
  </Accordion>
  <Accordion title="Will the assistant report missing features to MSPortal by itself?">
    It should not. **submit_feedback** is for MSP staff and needs your explicit request.
  </Accordion>
  <Accordion title="Does Revoke cancel every token right away?">
    It ends the grant and refresh sessions. An issued access token can last up to about 15 minutes.
  </Accordion>
  <Accordion title="Does Revoke erase data the client already has?">
    No. It does not recall data, undo work or delete the client's local setup.
  </Accordion>
  <Accordion title="Does the Ron skill replace sign-in or permissions?">
    No. It is optional guidance. Connection, consent and access checks stay separate.
  </Accordion>
</AccordionGroup>
