Use this page to find software vulnerabilities found by Cork, Action1, RoboShadow, and Cyrisma, and to read what each column means. It is for company users and MSP staff.

## Before you start

- You need Security read access.
- Cork, Action1, RoboShadow, or Cyrisma must be connected and its companies mapped. Without one of them, the **Vulnerabilities** tab does not appear. See [Configure Cork Integration](/user-guides/integrations/enable-cork-integration), [Configure Action1 Integration](/user-guides/integrations/enable-action1-integration), or [Configure RoboShadow Integration](/user-guides/integrations/enable-roboshadow-integration).

## Find a vulnerability

<Steps>
  <Step title="Open Vulnerabilities">
    Open **Security > Vulnerabilities** and check the company selector.
  </Step>
  <Step title="Search by CVE or software">
    Type in the **CVE** or **Software** column filter. When both are filled, a row must match both.
  </Step>
  <Step title="Narrow the list">
    Use **Company** to pick companies, **Source** to pick Cork, Action1, RoboShadow, or Cyrisma, **Priority** to pick a Cork priority, **Known Exploited** to pick **Yes** or **No**, and **CVSS** to set a score range. **Source** lists only the scanners you have connected.
  </Step>
  <Step title="Choose open or resolved findings">
    **Status** shows **Open** findings by default. Choose **Resolved** to see Cork findings that Cork stopped reporting.
  </Step>
  <Step title="Sort and page">
    Click a column header to sort. The table shows 20 vulnerabilities per page.
  </Step>
</Steps>

A link from the Security Dashboard can open the list already filtered to **Critical** priority or **Known Exploited**. Clear the filter to see every finding.

## Read the columns

| Column | What it shows |
| --- | --- |
| **CVE** | The vulnerability ID. Click it to open its National Vulnerability Database page in a new tab. |
| **Software** | The product, with its vendor underneath. |
| **Company** | The mapped company. |
| **Source** | The scanner that reported the finding: **Cork**, **Action1**, **RoboShadow**, or **Cyrisma**. |
| **CVSS** | The severity score to one decimal place. A dash means no score. |
| **Priority** | The Cork priority: Critical, Accelerated, or Routine. Action1, RoboShadow, and Cyrisma findings have no priority and show a dash. |
| **Known Exploited** | **Yes** when the scanner flags the vulnerability as known to be exploited. For Action1, this follows the CISA Known Exploited Vulnerabilities list. |
| **Status** | **Open**, or **Resolved** with the date the finding was resolved. |

Action1 lists one row for each endpoint and CVE, so the same CVE can appear once per affected device. Cyrisma lists one row for each CVE in each company: **Device** shows a sample of the affected assets, or how many there are, and **Software** shows what causes the CVE. The same CVE can also appear once per source.

**Known Exploited** describes the vulnerability, not your company. It does not mean you were attacked. A missing score or a **No** does not mean the software is safe.

## Resolved findings

A Cork finding becomes **Resolved** when a complete Cork sync no longer reports it. MSPortal keeps resolved Cork findings for a year, and the **Status** column shows **Resolved** with the date. Action1, RoboShadow, and Cyrisma findings are listed only while they are open.

MSP staff can also report on resolved findings with a custom report block that uses the **Resolved vulnerabilities** data source. See [Custom blocks](/user-guides/reporting/custom-blocks).

The table is read-only. You cannot patch, mark a finding fixed, or export a CSV here.

## Plan follow-up

Select rows from one company, then open **Actions (N)** in the page header.

- **Add to Planner** creates one Planner item for the selected vulnerabilities. Cork findings are linked to the item. Action1, RoboShadow, and Cyrisma findings are listed in the item's **Private Notes**. See [Add security findings to Planner](/user-guides/security/add-to-planner).
- **Add to Meeting** adds one agenda entry per vulnerability. Action1, RoboShadow, and Cyrisma findings are added as text entries. See [Add Cork findings to a meeting agenda](/user-guides/security/add-to-meeting).

Finishing the Planner item does not patch the software or rescan it in the scanner.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| The list is empty | Clear every filter, including any set by a dashboard link, and check the company selector. |
| **No vulnerabilities found** for a company you expect to have data | Check **Source** and **Status**, then ask your MSP to check the scanner's sync and company mapping. |
| **No resolved vulnerabilities** | Only Cork keeps resolved findings. Clear **Source** or choose Cork. |
| **Failed to load vulnerabilities** | Select **Retry**. If it keeps failing, report it through the [Home AI Assistant](/user-guides/ticketing/open-a-ticket). |
| **Priority** shows a dash | The finding comes from Action1, RoboShadow, or Cyrisma, which have no priority. Filtering by **Priority** shows Cork findings only. |
| **Security integration unavailable** | No vulnerability scanner is connected, or you lack Security read access. Ask your MSP admin. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Why does the same CVE appear more than once?">
    Each source reports its own findings, and Action1 lists one row for each endpoint. Check **Source** and **Company**.
  </Accordion>
  <Accordion title="Does Known Exploited mean our company was compromised?">
    No. It flags the vulnerability. Your MSP must check your environment.
  </Accordion>
  <Accordion title="Where does the CVE link go?">
    To the National Vulnerability Database page for that CVE, in a new tab. It changes nothing in MSPortal.
  </Accordion>
  <Accordion title="Does adding a vulnerability to Planner patch it?">
    No. It creates follow-up work. Patching and rescanning happen outside MSPortal.
  </Accordion>
  <Accordion title="I am a company user. How do I ask about a vulnerability?">
    Tell the [Home AI Assistant](/user-guides/ticketing/open-a-ticket) the CVE, company, and software, then confirm the request when prompted.
  </Accordion>
</AccordionGroup>
