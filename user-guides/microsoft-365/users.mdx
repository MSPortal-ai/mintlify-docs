Open **Cloud > Users** to review Microsoft 365 accounts. Existing `/m365/users` links open Cloud Users with Microsoft selected.

**Audience:** Company users with Microsoft 365 read access and MSP staff.

1. Open **Cloud > Users** and choose the relevant company if you can change the company scope.
2. Select **Microsoft 365** in the Provider column when shown. The column is omitted when only one provider is available.
3. Find the person with the **Name** or **Email** filter.
4. Change **Status** from Enabled to **All** or **Disabled** when reviewing disabled accounts.

Use the current guides for detailed instructions:

- [Read cloud user accounts](/user-guides/cloud/users): field meanings, full license-name tooltips, column preferences, and security-data limits.
- [Find and filter cloud users](/user-guides/cloud/find-users): supported filters, default status, and missing-account checks.
- [Export cloud users](/user-guides/cloud/export-users): all matching pages, exported fields, progress, and read-access requirements.

Your MSP manages account and license changes. [Open a support ticket](/user-guides/ticketing/open-a-ticket) to request a change. Cloud identity records do not grant MSPortal logins or portal permissions.

## Linked MSPortal account status

For an existing linked Company user, Microsoft 365 account status takes priority over PSA contact status. Blocking the Microsoft account disables its linked portal login. Re-enabling it can restore a recorded automatic disable on the next successful user sync. Explicit administrator disables and access-rule restrictions remain in place.

Aliases can connect directory and PSA records to the same portal login within the mapped company. Synchronization keeps the existing login and its history; conflicting existing logins need staff review. This does not create a portal account or grant new permissions.
