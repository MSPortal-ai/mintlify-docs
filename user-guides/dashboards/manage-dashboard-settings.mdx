Use **Settings > Dashboards > Internal Dashboards** to manage dashboards built inside MSPortal. Use **Edit Settings** for sharing, roles and availability. Use **Edit Dashboard** for widgets and layout. This guide is for MSP administrators.

## Before you start

- Open **Settings > Dashboards**. You need Dashboards access under Settings in your role (**Read**, **Write** or **Manage**).
- Creating, editing, deleting, defaults, pins and bulk actions all need **Manage**. A user with only **Write** can see these controls, but the save is rejected.
- Setting **Visibility** also needs **Manage** on **Internal Dashboards** in your role. Without it, the **Visibility** field is hidden.
- **Duplicate** and **Edit Dashboard** also need **Write** on Dashboards in the main navigation group of your role.
- Company users read dashboards through [Read and filter a dashboard](/user-guides/dashboards/read-a-dashboard). Company administrators ask the MSP to change access.
- This is an MSP-wide catalog. The company selector does not limit it.

## Find the right settings tab

| Tab | Purpose |
| --- | --- |
| **Internal Dashboards** | Dashboards built inside MSPortal: personal, shared and system. The name does not mean MSP-only. |
| **External Dashboards** | Links to other services. See [Configure external dashboards](/user-guides/dashboards/configure-external-dashboards). |
| **Exclusions** | Tenant-wide widget exclusions. See [Configure dashboard exclusions](/user-guides/dashboards/configure-dashboard-exclusions). |

The **Internal Dashboards** table shows **Name**, **Description**, **Roles** and **Status**. Badges mark **Personal**, **System**, **Default** and **Sidebar**. **All roles** means no role restriction.

## Create a shared dashboard

<Steps>
  <Step title="Open the dialog">
    Go to **Settings > Dashboards > Internal Dashboards** and click **Add Dashboard**.
  </Step>
  <Step title="Enter the details">
    Type a **Name** (up to 100 characters). Add an optional **Description** (up to 500 characters). Choose an **Icon**.
  </Step>
  <Step title="Set sharing and visibility">
    Keep **Shared Dashboard** on if others should use it. If you see **Visibility**, choose **Both** or **Internal (MSP Team)**.
  </Step>
  <Step title="Choose roles">
    Under **Role Access**, tick **MSP Team Roles** and, when visibility is **Both**, **Client Roles**. Leave all boxes clear to allow every role.
  </Step>
  <Step title="Click Create Dashboard">
    The dashboard is saved as active and the list reloads.
  </Step>
  <Step title="Add content">
    Open the row's **... > Edit Dashboard** to add widgets. Save in the editor. See [Create and edit a dashboard](/user-guides/dashboards/create-and-edit-dashboard).
  </Step>
</Steps>

The dialog starts with sharing on. The **+** button in the dashboard icon rail creates a personal dashboard instead. A new dashboard starts empty and is not a draft.

If **Shared Dashboard** is off, **Role Access** is unavailable because personal dashboards have no roles.

## Choose visibility and roles

<img src="/images/product/dashboard-visibility-options.png" alt="Dashboard visibility choices: Both and Internal (MSP Team)" width="700" height="140" />

| Setting | Meaning |
| --- | --- |
| **Both** | MSP staff and Company users can open the dashboard, subject to sharing, roles and status. |
| **Internal (MSP Team)** | Company users cannot open it. Client role choices are hidden and any already ticked are cleared. MSP staff need **Read** or **Manage** on **Internal Dashboards** to open it. |
| Ticked **Role Access** boxes | Only those roles can open the shared dashboard. |
| No ticked boxes | No role restriction. Ownership, visibility and module permissions still apply. |

Dashboard access does not open every widget's module or records. Check the saved dashboard as the intended user. To change a Company user's access, see [Change a Company user's permissions](/user-guides/settings/change-company-user-permissions).

## Edit settings and availability

<Steps>
  <Step title="Open the dialog">
    Click the dashboard name, or open **... > Edit Settings** on its row.
  </Step>
  <Step title="Change the fields">
    Besides the creation fields, you can set **Enabled**, **Pin to Sidebar** and, when pinned, a **Sidebar Label** of up to 30 characters. A blank label uses the dashboard name.
  </Step>
  <Step title="Click Save Changes">
    Nothing is saved until you click **Save Changes**. **Cancel** closes the dialog without saving.
  </Step>
</Steps>

System dashboards have **Shared Dashboard** and **Enabled** locked. Their row menu has no **Disable** or **Delete**. Use **Duplicate** for a custom copy you can change.

If you turn **Shared Dashboard** off for a dashboard with no owner, you become its owner.

## Use row actions

<img src="/images/product/dashboard-settings-row-menu.png" alt="Dashboard row menu with View Dashboard, Edit Settings, Duplicate, Edit Dashboard, Set as Default, Pin to Sidebar, Disable, and Delete" width="318" height="568" />

Open **...** on the dashboard row. Row actions apply as soon as you click them.

| Action | Result |
| --- | --- |
| **View Dashboard** | Opens the dashboard in a new tab. |
| **Edit Settings** | Opens the settings dialog. Use **Save Changes**. |
| **Duplicate** | Needs **Write** on Dashboards in your role. Creates a personal copy named "... (Copy)". It copies the description, icon and layout only. It has no roles, default or pin, and default visibility. |
| **Edit Dashboard** | Opens the widget editor. It has its own **Save**. |
| **Set as Default** | Shown on active dashboards that are not the default. Makes this the default and clears the previous internal or external default. |
| **Remove Default** | Clears the default without picking a replacement. |
| **Pin to Sidebar** / **Unpin from Sidebar** | Adds or removes the shortcut in the main navigation. |
| **Disable** / **Enable** | Hides or restores a custom dashboard without deleting it. |
| **Delete** | Opens a confirmation that names the dashboard. Click **Delete** to remove it for good. |

Pinning allows at most 8 pins across internal and external dashboards combined. This applies to the row action and to **Pin to Sidebar** in the dialog. If you hit the limit, unpin another shortcut first.

The default is shared configuration, not a personal preference. Readers still need access to it. A pin is a shortcut and grants no access.

## Update several dashboards

<Steps>
  <Step title="Select the rows">
    Tick the checkbox on each dashboard. The header checkbox selects the current page only.
  </Step>
  <Step title="Open Actions">
    Click **Actions (n)** and check that the count is right.
  </Step>
  <Step title="Choose an action">
    Pick **Edit Permissions**, **Enable**, **Disable** or **Delete**.
  </Step>
</Steps>

<img src="/images/product/dashboard-bulk-actions.png" alt="Dashboard bulk menu with Edit Permissions, Enable, Disable, and Delete" width="450" height="276" />

| Bulk action | What to know |
| --- | --- |
| **Edit Permissions** | Opens **Role Access** with client roles only. Click **Update Permissions** to replace the selected dashboards' roles. |
| **Enable** / **Disable** | Applies at once. System dashboards are skipped. |
| **Delete** | Opens **Delete selected dashboards** with the count. System dashboards are skipped. Deleting cannot be undone. |

<Warning>
Bulk **Edit Permissions** replaces every role assignment on the selected dashboards, including MSP team roles. An empty selection removes all role restrictions. Use **Edit Settings** on one dashboard to keep or set both MSP and client roles.
</Warning>

## Troubleshooting

| Problem | What to do |
| --- | --- |
| Saving fails | Check that your role has **Manage** for Dashboards under Settings. |
| A Company user cannot see a shared dashboard | Check **Enabled**, **Both** visibility, role access, module access and company scope. |
| An MSP user cannot see a shared dashboard | For internal ones, check the user has **Read** or **Manage** on **Internal Dashboards**. Also check the MSP team roles selected. |
| A pin or default seems missing | Check the dashboard is **Enabled** and the user has access. Pins do not override permissions. |
| Two roles have the same name | Confirm which one you want before assigning it. Tenant roles and global roles can share a name. |
| Pinning fails with a limit message | Unpin another dashboard or external item. The limit is 8 pins in total. |
| A role update says it worked but access is wrong | Reopen **Edit Settings** and check the saved roles. |
| Delete removed fewer dashboards than selected | System dashboards are skipped. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does the Internal Dashboards tab mean MSP-only?">
    No. It lists dashboards built inside MSPortal. **Both** visibility lets Company users in. **Internal (MSP Team)** is the MSP-only setting.
  </Accordion>
  <Accordion title="What is the difference between Add Dashboard and the plus button?">
    **Add Dashboard** in settings starts shared. The **+** in the dashboard icon rail creates a personal one. Both save at once.
  </Accordion>
  <Accordion title="Does leaving Role Access empty deny everyone?">
    No. It removes role restrictions.
  </Accordion>
  <Accordion title="Does Both mean external dashboards?">
    No. It is an audience setting for dashboards built inside MSPortal. External services are set up under **External Dashboards**.
  </Accordion>
  <Accordion title="Does Enabled in Edit Settings save immediately?">
    No. Dialog changes need **Save Changes**. The row **Enable** and **Disable** actions apply at once.
  </Accordion>
  <Accordion title="Does disabling delete the widgets?">
    No. The configuration stays. **Enable** brings the dashboard back.
  </Accordion>
  <Accordion title="Does Remove Default pick another dashboard?">
    No. Readers fall back to another available dashboard.
  </Accordion>
  <Accordion title="Does a duplicate keep the roles and visibility?">
    No. It starts personal, with default visibility and no roles, default or pin. Review **Edit Settings** before you share it.
  </Accordion>
  <Accordion title="What is the difference between Edit Settings and Edit Dashboard?">
    **Edit Settings** changes name, sharing, access and availability. **Edit Dashboard** opens the widget editor.
  </Accordion>
  <Accordion title="Can I delete a system dashboard?">
    No. Single and bulk delete both skip them.
  </Accordion>
  <Accordion title="Does bulk Edit Permissions add to existing roles?">
    No. It replaces them.
  </Accordion>
  <Accordion title="Can Company administrators grant dashboard permissions?">
    No. They ask their MSP.
  </Accordion>
</AccordionGroup>
