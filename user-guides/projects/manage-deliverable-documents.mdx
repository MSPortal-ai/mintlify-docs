This page shows MSP staff how to attach files to a deliverable, choose which files clients can see, and remove old ones.

## Before you start

- You need permission to edit project collaboration content (project overlay edit).
- The deliverable must exist. If it does not, [create it first](/user-guides/projects/manage-project-deliverables).
- Company users [download files that have been shared](/user-guides/projects/read-project-deliverables). They cannot upload.
- For files that belong to the whole project, use [Project documents](/user-guides/projects/documents) instead.

## Upload a document

<Steps>
  <Step title="Prepare the deliverable">
    Finish the title, description, status, dates, and **Client Visible** setting first. To share files with clients, turn **Client Visible** on before you share them. New files start internal either way.
  </Step>
  <Step title="Open Documents">
    Open **Projects**, click the project, then **Project Plan** and **Deliverables**. Click the deliverable. Find **Documents** and click **Upload**.
  </Step>
  <Step title="Choose a file">
    Pick one file from your device. The upload starts as soon as you choose it. There is no Save step.
  </Step>
  <Step title="Wait for the result">
    The file must have content, use an accepted extension, and be 4 MB or smaller. When it finishes, the file shows under **Documents** and a message says it was uploaded (internal only).
  </Step>
  <Step title="Check the file">
    Check the name, date, size, and uploader. Click **Download** to check the content. Uploading a file with the same name adds another attachment. It does not replace the first one or keep versions.
  </Step>
</Steps>

| File category | Accepted extensions |
| --- | --- |
| Documents and text | `.pdf`, `.doc`, `.docx`, `.odt`, `.rtf`, `.txt`, `.md` |
| Tables and spreadsheets | `.csv`, `.xls`, `.xlsx`, `.ods` |
| Presentations | `.ppt`, `.pptx`, `.odp` |
| Images | `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg` |
| Archives and structured text | `.zip`, `.json`, `.xml` |

## Share a document with Company users

<Steps>
  <Step title="Check the deliverable is client-visible">
    Open the deliverable and make sure **Client Visible** is on. While it is off, each file's sharing switch is disabled and reads **This deliverable is internal, so none of its documents reach the client**.

    <img src="/images/product/project-document-sharing-blocked.png" alt="MSP tooltip explaining that an internal deliverable prevents any of its documents reaching the client" width="902" height="68" />
  </Step>
  <Step title="Share the file">
    Turn on **Share with client** next to the file. A message confirms that the file is now shared. Share each file separately. Sharing one does not share the others.
  </Step>
  <Step title="Check who can see it">
    Company users also need access to the project. They see the file only when the project, the deliverable, and the document are all shared with them. Sharing sends no email and gives no permissions.
  </Step>
</Steps>

To make a file internal again, turn **Share with client** off. That does not take back copies people already downloaded.

## Download or remove a file

<Steps>
  <Step title="Download">
    Click **Download** on the file. New uploads use links that expire after about five minutes. Click **Download** again if one expires.
  </Step>
  <Step title="Delete one file">
    Click **Delete** on the document, check its name, and confirm. Reopen the deliverable to check the file is gone. Use the document's **Delete**, not the deliverable's, so you do not remove the whole output.
  </Step>
</Steps>

## Troubleshooting

| Problem | What to do |
| --- | --- |
| The upload failed | Check that the file is 4 MB or smaller, has an accepted extension, is not empty, and that you have edit access. Reopen the deliverable to see if the file was added before you retry. |
| **Share with client** is disabled | The deliverable is internal, or another file action is still running. Turn **Client Visible** on. |
| The client sees the deliverable but not the file | New files start internal. Turn on **Share with client** for that file, and check the client's project access. |
| A file disappeared | Reopen the deliverable. If it is still missing, upload it again and tell support, because a file should stay attached when you edit the deliverable. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can I upload a file larger than 4 MB or an executable?">
    No. Files must be 4 MB or smaller and use one of the accepted extensions. Executables are not accepted.
  </Accordion>
  <Accordion title="Does uploading the same file name replace the old file?">
    No. It adds another attachment. Delete the old one yourself.
  </Accordion>
  <Accordion title="Does sharing a file notify the client?">
    No. It only changes what they can see in the portal. Use a [decision or action item](/user-guides/projects/manage-project-actions) if you need a response.
  </Accordion>
  <Accordion title="Can I remove one file without deleting the deliverable?">
    Yes. Use **Delete** on that document.
  </Accordion>
</AccordionGroup>
