This page shows MSP staff how to ask Project AI about a project, apply the changes it proposes, connect external AI tools through MCP, and bring project content into QBR reports and meeting agendas.

## Before you start

- Project AI appears on a project when AI is enabled for your portal and you have project read access. Company users see it only when client AI is enabled.
- Only MSP staff with a project write permission can apply changes. Everyone else gets a read-only assistant that answers questions.
- Reports and meetings need a selected company.

## Ask Project AI about a project

<Steps>
  <Step title="Open the project">
    Open **Projects** and select the project.
  </Step>
  <Step title="Open Project AI">
    Click **Open Project AI**, the button at the right edge of the project page. The panel opens on the right and shows the project name and the tab you are on.
  </Step>
  <Step title="Ask a question or pick a quick prompt">
    Type in the box that reads **Ask about this project or propose a change...**, or click a prompt under **Start with**. Read-only users see **Summarize health** and **Review tickets**. Users who can write also see **Draft update**, **Draft actions**, **Draft deliverables**, **Draft milestone**, **Draft decision**, **Generate details**, and **Organize tickets**.
  </Step>
  <Step title="Read the answer">
    The assistant uses details from every project tab, tickets, time entries, and notes that your account can see.
  </Step>
</Steps>

## Draft and apply a weekly update

<Steps>
  <Step title="Ask for the draft">
    In Project AI, click **Draft update**, or type a request such as "Draft a weekly update for the week of Monday using the latest tickets, time entries, and notes."
  </Step>
  <Step title="Open the proposal">
    The panel switches to **Review changes** and shows a **Proposed change** card with the week, summary, completed work, next steps, risks, and whether it is client visible. If you went back to the chat, click **Review changes** to return.
  </Step>
  <Step title="Check the details">
    Confirm **Client Visible** is what you want. Weekly update proposals can come back client visible.
  </Step>
  <Step title="Apply or discard">
    Click **Apply** to save the update, or **Discard** to drop it. The card then reads **Applied** or **Discarded**. To get a different version, ask Project AI to adjust it.
  </Step>
  <Step title="Confirm the saved update">
    Open the **Updates** tab and check the new entry.
  </Step>
</Steps>

You can ask for milestones, deliverables, decisions, action items, project details, and ticket status, owner, or priority changes the same way. Each one arrives as its own **Proposed change** card. Nothing changes until you click **Apply**.

## Connect an external AI tool through MCP

<Steps>
  <Step title="Open MCP Server settings">
    Open **Settings > MCP Server** and follow the [MCP Server guide](/user-guides/mcp-server/index) to connect your AI client.
  </Step>
  <Step title="Ask for project work">
    In your AI client, ask for a project task, such as "Find the Acme network refresh project and propose a weekly update."
  </Step>
  <Step title="Review the proposal before confirming">
    Project write tools stage a proposal first. Read the target and the changes, then confirm in your AI client.
  </Step>
  <Step title="Check the result in MSPortal">
    Open the project and look in the matching tab, such as **Updates**.
  </Step>
</Steps>

The connected user's permissions, the OAuth scopes you grant, and company access decide which tools and records the client can use.

| What you want | Project tools |
| --- | --- |
| Read project context | Project list, project detail, tickets, time entries, assignable users, Kanban options, and project display settings |
| Edit collaboration records | Project outcome fields, client visibility, deliverables, milestones, client actions, weekly updates, and document visibility |
| Change delivery fields | Ticket status, owner, and priority, and project status |
| Notes and settings | Read and add project ticket notes, and update project display settings |

MCP does not create native projects, design templates, or add and delete native phases and tickets. Use the app for those. See the [MCP tool reference](/user-guides/mcp-server/tools-reference) for the full catalog.

## Add project blocks to a QBR report

<Steps>
  <Step title="Select the company">
    Pick the company in the company selector at the top of the app.
  </Step>
  <Step title="Open the report builder">
    Open **Reports**, click **New Report**, and choose **Builder**. To change an existing report, open it instead.
  </Step>
  <Step title="Add a project block">
    Add the block that answers the client's question.

    | Block | Use it to show |
    | --- | --- |
    | **Project Health Overview** | Which projects need attention |
    | **Project Task Progress** | How delivery is progressing |
    | **Project Timeline** | What is scheduled and when |
    | **Project Costs** | Budget and cost records |
    | **Project Trend** | How project metrics change over time |
    | **Project Completed Tasks** | Work that is done |
    | **Project Weekly Activity** | Activity in the reporting period |
  </Step>
  <Step title="Set the block options">
    Pick the project where the block has a project selector, set the date range, and turn on **Include Closed Projects** where it is offered.
  </Step>
  <Step title="Save the report">
    Save the report, then check the output before you share it. See [Reporting](/user-guides/reporting/index) for sharing and delivery.
  </Step>
</Steps>

## Add a project to a meeting agenda

<Steps>
  <Step title="Open the meeting">
    Open the company meeting. If you are creating a new meeting, make sure the company shows in **Select company** before you save the draft.
  </Step>
  <Step title="Add an agenda item">
    Click **Add Item** and choose **Project**.
  </Step>
  <Step title="Pick the project">
    Search for the project, select it, and click **Add Selected**. The project appears in the agenda.
  </Step>
  <Step title="Preview the project slide">
    Click **Present** and move through the slides to check what participants will see. The project view shows health, dates, milestones, outcome, and client actions that are waiting.
  </Step>
</Steps>

A meeting note does not change a project ticket or complete a client action. Record decisions and follow-up work on the project itself. See [Meeting Pages](/user-guides/calendar/meetings) and [Meeting Summaries](/user-guides/calendar/meeting-summaries).

## Troubleshooting

| Problem | What to do |
| --- | --- |
| **Open Project AI** does not appear | Ask an admin to check that AI is enabled for your portal, and that your role has project read access. |
| Project AI answers but has no **Apply** button | Your account is read-only for this project. Ask for a role with a project write permission. |
| An applied change is missing | Open the right project tab, check that the card reads **Applied**, and reopen the tab. |
| A tool is missing from the MCP connection | Check the scopes you granted, the user's permissions, and whether your PSA supports the operation. |
| A project is missing in a report or meeting picker | Check the selected company, the project's visibility, and any open or closed filter in the picker. |
| A report block is empty | Check the selected project, the date range, and whether the project has time, cost, or history data. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Does Project AI change my project on its own?">
    No. Every change appears as a **Proposed change** card. Nothing is saved until you click **Apply**.
  </Accordion>
  <Accordion title="Can a company user apply AI changes?">
    No. Company users get a read-only assistant, and only when client AI is enabled.
  </Accordion>
  <Accordion title="Does a client-visible update send an email?">
    No. Client Visible controls what the client sees in the portal. It does not send a message.
  </Accordion>
  <Accordion title="Can MCP create a native project?">
    No. Create native projects in the app. See [Native Projects](/user-guides/projects/native-projects).
  </Accordion>
</AccordionGroup>
