Select a project from **Projects** to open its workspace. The header contains the available tabs and, when your role permits changes, **Edit Project Details**.

## Before you start

You need access to the project. Company users can read shared content and respond to their own assigned pending requests; the MSP manages project editing and user permissions. Editing project details and collaboration items requires project overlay-edit permission; changing PSA statuses requires status-edit permission. Assignment changes and supported PSA rescheduling require project write access.

Tabs also depend on display settings, provider support, and the project's data. Native project editors can use Phases to manage their delivery plan. Other views depend on settings, permissions, and available data.

## Choose a work area

The workspace has at most two navigation rows. The top row uses an underline to mark the current work area; the second row uses rounded tabs for its destinations. Overview and Team open directly.

| Work area | Destinations |
| --- | --- |
| **Overview** | Project dashboard. MSP staff can switch between MSP Dashboard and Client Dashboard. |
| **Project Plan** | Tasks, Phases, Board, Schedule, Milestones, and Deliverables, when available. |
| **Team** / **Team & Contacts** | The available project roster and onboarding contacts. |
| **Client Portal** | Pages, Activity, Key dates, and Portal settings for a linked onboarding. |
| **Collaboration** | Chat, Updates, Decisions, and Action Items, when available. |
| **Files & Forms** | Documents and Forms, when available. |

On a phone, use the **…** button beside the project title for project actions. Scroll each tab row horizontally to reach the other destinations; the selected tab remains visible when the row resizes.

### One Documents destination

<Note>The unified library requires its database migration before it can be enabled and verified in a live workspace.</Note>

Open **Files & Forms > Documents** for one library containing project files, client uploads, and outstanding document requests. Use the same search, filters, folders, and file actions across both upload sources. The request column keeps each client upload connected to its portal and phase; open the request to review evidence, approve or reject it, or change its client visibility. Available files and actions follow your Projects and Onboarding permissions. Older onboarding document links open this library.

For a project file, open its row menu and choose **Client sharing**. Select a linked portal and phase, then choose **Share file**. Sharing uses the original file, so there is no second upload to maintain. Return to **Client sharing** and choose **Revoke access** to stop new client downloads while retaining the original project file. A download link already issued can remain valid for up to five minutes; downloaded copies cannot be recalled.

Deleting the last file uploaded for a request keeps the request and returns it to Requested. Moving files or removing a folder does not change client access.


For native creation, editing, time tracking, and closeout, follow [Native Projects: Start to Finish](/user-guides/projects/native-projects).

For ConnectWise staffing, use [Read the project team](/user-guides/projects/read-project-team). This MSP-only reader explains assignment rows, roles, hours, filters, and dates; linked onboarding contacts are reached through **Team & Contacts**.

## Read the Overview

Use [Read the project overview](/user-guides/projects/read-project-overview) to interpret summaries, dates, progress measures, and contact links. MSP staff can [edit the goal and description](/user-guides/projects/edit-project-details) or [maintain contacts](/user-guides/projects/manage-project-contacts). Each of those forms uses its own Save Changes button.

## Read progress and milestones

Use [Read project updates](/user-guides/projects/read-project-updates) for shared weekly summaries, next steps, risks, and decision bullets. Use [Read the project timeline](/user-guides/projects/read-project-timeline) for milestones, status filters, and planned-date indicators.

MSP authors can follow [Write and share project updates](/user-guides/projects/write-project-updates) and [Manage project milestones](/user-guides/projects/manage-project-milestones). Items added with Add Update or Add Milestone on those tabs save immediately with Client Visible off; sharing is controlled by that toggle. Phase and ticket menu shortcuts have different defaults.

## Find deliverables and files

Open **Deliverables** to [read shared outputs and download project files](/user-guides/projects/read-project-deliverables). MSP staff can [manage deliverables](/user-guides/projects/manage-project-deliverables) and [upload or share documents](/user-guides/projects/manage-deliverable-documents). Deliverable status and document visibility are separate: a Complete output does not mean every attached file is shared or approved.

## Respond to a request

Open **Decisions** for approvals, questions, access requests, scheduling confirmations, and decisions, or **Action Items** for work to complete. Expand an item to read its description. A green response button appears when a pending item is assigned to you. Follow [Respond to project decisions and action items](/user-guides/projects/respond-to-project-actions) to confirm and check the saved result.

For MSP creation, autosave, assignment, notifications, cancellation, and deletion, use [Manage project decisions and action items](/user-guides/projects/manage-project-actions). Assignment does not notify the user automatically.

## Review phases, tickets, and time

Use [Read project phases and tickets](/user-guides/projects/read-project-phases) for phase expansion, sorting, task filters, and the difference between status, hours usage, and task completion. Detailed ticket time history is restricted; Company users should ask their MSP for an appropriate shared summary.

MSP staff can [use phase and ticket action menus](/user-guides/projects/use-phase-ticket-actions) to understand immediate creation, visibility, and destination checks. **Mark as Milestone** currently has a recorded failure; use the guide's recovery steps. Menu-created updates and milestones are configured to start client-visible, unlike the destination tabs' internal defaults.

## Use ticket Kanban

<img src="/images/product/projects-workspace-kanban.png" alt="Demo project ticket Kanban with status columns and security assessment tasks" width="2340" height="1400" />

Use [Read and filter project ticket Kanban](/user-guides/projects/read-ticket-kanban) for search, closed-ticket visibility, grouping, density, column totals, and missing-card troubleshooting. The owner grouping label can be Member, Resource, Agent, or Technician depending on the portal's PSA terminology.

MSP drag controls depend on provider support and editing permissions. ConnectWise assignments remain limited to the project team and the administrator's roster filters. Native MSPortal projects use **Phases > Edit ticket** for status, priority, and assignment changes; the current ticket board does not expose native drag controls.

## Read scheduled work

Use [Read a project schedule](/user-guides/projects/read-project-schedule) to interpret date spans and open their details. [Filter the project schedule](/user-guides/projects/filter-project-schedule) explains all-day visibility, saved hidden titles, staff filters, and weekends. Company cross-project Schedule contents differ from the individual project tab.

## Edit project details

Select **Edit Project Details**, update **Project Goal**, **Project Description**, **Current Phase**, and the available client-visibility option, then select **Save Changes**. Contacts are managed from their own control on Overview.

PSA-backed fields and MSPortal collaboration items have different destinations. A project status or supported ticket change can write back to the PSA; do not assume a weekly update, deliverable, or client decision becomes a PSA record.

## Use Project AI

Open **Project AI** from the right edge of the workspace to ask about the project or draft an update, action item, deliverable, milestone, or decision.

The assistant can use the project information available to your account. Proposed changes appear for review before they are applied. Read each proposal, check its details and visibility, and approve only the changes you intend to make. Read-only users can ask questions but cannot apply changes.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| Phases or ticket Kanban is missing | Project data, **Display Configuration**, **Kanban Board Settings**, and role permissions. |
| Team is missing | Team is an MSP staff tab for ConnectWise projects. |
| A custom field is missing or read-only | The field's visibility, view/edit role access, writeback setting, and your project permission. |
| A technician is unavailable | The configured roster, active PSA user sync, and the ConnectWise project team. |
| AI cannot apply a change | Your edit permission and whether you have reviewed and approved the proposal. |

## FAQs

<AccordionGroup>
  <Accordion title="Do the badges on project tabs count unread items?">
    No. They count project items, including resolved items, rather than unread messages. The Timeline badge counts client-visible milestones and can be lower than an MSP staff member’s Timeline Total. The separate actions-waiting button counts pending work across Decisions and Action Items, not only work assigned to you.
  </Accordion>
  <Accordion title="Can I respond without permission to edit project details?">
    Yes, if you can access the project and the shared pending item is assigned to your user. Use its response button; see the [response guide](/user-guides/projects/respond-to-project-actions).
  </Accordion>
  <Accordion title="Why does a small project have no Phases or Kanban tab?">
    Projects with no phases and at most one ticket use the simpler overview. Display settings and permissions also affect these tabs. Native project editors can still receive Phases to manage their plan.
  </Accordion>
  <Accordion title="Can Company users use Project AI to edit the project?">
    Company users receive read-only Project AI when available. They can ask about accessible project information; MSP changes require the appropriate permission and proposal review.
  </Accordion>
</AccordionGroup>
