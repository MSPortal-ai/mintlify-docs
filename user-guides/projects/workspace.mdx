Select a project from **Projects** to open its workspace. The header contains the available tabs and, when your role permits changes, **Edit Project Details**.

## Before you start

You need access to the project. Company users can read shared content and respond to their own assigned pending requests; the MSP manages project editing and user permissions. Editing project details and collaboration items requires project overlay-edit permission; changing PSA statuses requires status-edit permission. Assignment changes and supported PSA rescheduling require project write access.

Tabs also depend on display settings, provider support, and the project's data. Native project editors can use Phases to manage their delivery plan. Other views depend on settings, permissions, and available data.

## Choose a section

| Section | Destinations |
| --- | --- |
| **Overview** | **MSP Dashboard** and **Client Dashboard**, according to your role |
| **Team & Contacts** (or **Team**) | Project staffing and onboarding contacts, when available |
| **Client Portal** | **Pages**, **Activity**, **Key dates**, **Portal settings**, for linked portals |
| **Project Plan** | **Tasks**, **Board**, **Schedule**, **Milestones**, **Deliverables** |
| **Collaboration** | **Updates**, **Decisions**, **Action Items** |
| **Files & Forms** | **Documents**, **Forms** |

The active section keeps its destinations visible in a second row. Returning to a section restores the last destination used while this project is open. On phones, swipe either navigation row to reach destinations beyond the screen edge.

**Overview** includes **MSP Dashboard** and **Client Dashboard**. MSP staff switch between them locally; company users receive their permitted dashboard without an internal-view switch. **Team** remains a full staffing page (shown as **Team & Contacts** for linked onboarding projects).

**Board** is the project ticket Kanban. **Milestones** is the former Timeline destination; **Schedule** continues to show dated project work. Action Items remain a separate collaboration register, and Deliverables stay with the project plan.

## Onboarding and project forms

The onboarding section of **Overview > MSP Dashboard** and **Client Portal** appear only when the project has a linked portal and your staff role can read it. MSP Dashboard itself is available to staff on every project. Company users continue through their existing onboarding entry point; the staff management tabs are not shared with them.

In **Files & Forms > Forms**, select **Fill a form** in the response-table toolbar, choose a form, complete its fields in the dialog, and choose **Save progress** for an unfinished entry or **Submit** when it is ready. Close the dialog and check the response table for the saved entry. Select **Edit** beside a permitted response to an active form to correct it. After the archived-response update is rolled out, **View** opens saved responses to archived forms as read-only; it does not allow new entries, Save progress, or Submit. Form definitions are managed under **Settings > Projects > Templates > Forms**. Saving a response does not itself create or update an external documentation asset.

Forms work on ordinary projects without an onboarding portal. Staff with **Share forms with clients** permission can select a form and enable **Share this form with clients**. Turn it off to revoke access. Clients also need project access and the relevant form permissions. They see only shared forms and their own responses; existing internal responses remain private. Hiding the project from clients also blocks their form access.

A form that permits one entry retains one internal staff response and one response per client. Saving again updates the permitted existing response. **Save progress** returns a submitted response to **In progress**; select **Submit** after finishing revisions. Forms that permit multiple entries create additional responses; use **Edit** to change a particular entry.

Old company-onboarding links open the corresponding project tab when a linked project is available. A link to client uploads opens the shared **Files & Forms > Documents** destination.

See [Project Forms](/user-guides/projects/forms) for draft status, sharing, response links, and resuming an entry.

## Read the MSP Dashboard

Open **Overview** and select **MSP Dashboard**. The compact summary rail shows open tasks, open tasks without an owner, pending decisions, pending action items, actual hours, and budget hours. Select a pending-work tile to open its register. A dash means hours are unavailable. On projects without a portal, the expanded dashboard also shows up to five open tasks, pending decisions and action items, the latest update, and project context. Select **Unassigned open tasks** to narrow the task preview, or **Open tasks** to restore it. See [Dashboard details](/user-guides/projects/read-project-overview#read-the-msp-dashboard).

When time-entry display is enabled, **Time logged** summarizes the loaded entries by total, billable hours, and top tickets; **Recent entries** shows recent work. Native-project editors without an active PSA integration can **Log time**. Existing permitted entries remain manageable when a PSA is connected. The time breakdown uses the latest entries returned by the project, so it can differ from the project’s recorded Actual hours.

On linked onboardings, the authorized onboarding overview appears above the time cards. Use it to review progress, phase readiness, and work needing attention. Client contacts and staff assigned to portal tasks live under **Team & Contacts**. The single **View as** control is in the page header; on phones, open **Actions** to find it. **Client Portal** remains the editing workspace.

## Read the Client Dashboard

Use [Read the project overview](/user-guides/projects/read-project-overview) to interpret summaries, dates, progress measures, and contact links. MSP staff can [edit the goal and description](/user-guides/projects/edit-project-details) or [maintain contacts](/user-guides/projects/manage-project-contacts). Each of those forms uses its own Save Changes button.

## Read progress and milestones

Use [Read project updates](/user-guides/projects/read-project-updates) for shared weekly summaries, next steps, risks, and decision bullets. Use [Read project milestones](/user-guides/projects/read-project-timeline) for milestones, status filters, and planned-date indicators.

MSP authors can follow [Write and share project updates](/user-guides/projects/write-project-updates) and [Manage project milestones](/user-guides/projects/manage-project-milestones). Items added with Add Update or Add Milestone on those tabs save immediately with Client Visible off; sharing is controlled by that toggle. Phase and ticket menu shortcuts have different defaults.

## Find deliverables and files

Open **Project Plan > Deliverables** to [read shared outputs and download project files](/user-guides/projects/read-project-deliverables). MSP staff can [manage deliverables](/user-guides/projects/manage-project-deliverables) and [upload or share documents](/user-guides/projects/manage-deliverable-documents). Deliverable status and document visibility are separate: a Complete output does not mean every attached file is shared or approved.

## Respond to a request

Open **Collaboration > Decisions** for approvals, questions, access requests, scheduling confirmations, and decisions, or **Action Items** for work to complete. Expand an item to read its description. A green response button appears when a pending item is assigned to you. Follow [Respond to project decisions and action items](/user-guides/projects/respond-to-project-actions) to confirm and check the saved result.

For MSP creation, autosave, assignment, notifications, cancellation, and deletion, use [Manage project decisions and action items](/user-guides/projects/manage-project-actions). Assignment does not notify the user automatically.

## Review phases, tickets, and time

Use [Read project phases and tickets](/user-guides/projects/read-project-phases) for phase expansion, sorting, task filters, and the difference between status, hours usage, and task completion. Detailed ticket time history is restricted; Company users should ask their MSP for an appropriate shared summary.

MSP staff can [use phase and ticket action menus](/user-guides/projects/use-phase-ticket-actions) to understand immediate creation, visibility, and destination checks. **Mark as Milestone** currently has a recorded failure; use the guide's recovery steps. Menu-created updates and milestones are configured to start client-visible, unlike the destination tabs' internal defaults.

## Use ticket Kanban

Use [Read and filter project ticket Kanban](/user-guides/projects/read-ticket-kanban) for search, closed-ticket visibility, grouping, density, column totals, and missing-card troubleshooting. The owner grouping label can be Member, Resource, Agent, or Technician depending on the portal's PSA terminology.

MSP drag controls depend on provider support and editing permissions. ConnectWise assignments remain limited to the project team and the administrator's roster filters. Native MSPortal projects use **Project Plan > Tasks > Edit ticket** for status, priority, and assignment changes; the current ticket board does not expose native drag controls.

## Read scheduled work

Use [Read a project schedule](/user-guides/projects/read-project-schedule) to interpret date spans and open their details. [Filter the project schedule](/user-guides/projects/filter-project-schedule) explains all-day visibility, saved hidden titles, staff filters, and weekends. Company cross-project Schedule contents differ from the individual project tab.

## Edit project details

Select **Edit Project Details**, update **Project Goal**, **Project Description**, **Current Phase**, and the available client-visibility option, then select **Save Changes**. Contacts are managed from their own control on Client Dashboard.

PSA-backed fields and MSPortal collaboration items have different destinations. A project status or supported ticket change can write back to the PSA; do not assume a weekly update, deliverable, or client decision becomes a PSA record.

## Use Project AI

Open **Project AI** from the right edge of the workspace to ask about the project or draft an update, action item, deliverable, milestone, or decision.

The assistant can use the project information available to your account. Proposed changes appear for review before they are applied. Read each proposal, check its details and visibility, and approve only the changes you intend to make. Read-only users can ask questions but cannot apply changes.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| Phases or ticket Kanban is missing | Project data, **Display Configuration**, **Kanban Board Settings**, and role permissions. |
| Team is missing | Team is an MSP staff tab for ConnectWise projects. |
| A custom field is missing or read-only | The field's visibility, view/edit role access, writeback setting, and your project permission. |
| A technician is unavailable | The configured roster, active PSA user sync, and the ConnectWise project team. |
| AI cannot apply a change | Your edit permission and whether you have reviewed and approved the proposal. |

## FAQs

<AccordionGroup>
  <Accordion title="Do the badges on project tabs count unread items?">
    The grouped navigation does not display record-total badges. Totals remain inside the destination pages. The separate actions-waiting button counts pending work across Decisions and Action Items, not only work assigned to you.
  </Accordion>
  <Accordion title="Can I respond without permission to edit project details?">
    Yes, if you can access the project and the shared pending item is assigned to your user. Use its response button; see the [response guide](/user-guides/projects/respond-to-project-actions).
  </Accordion>
  <Accordion title="Why does a small project have no Phases or Kanban tab?">
    Projects with no phases and at most one ticket use the simpler overview. Display settings and permissions also affect these tabs. Native project editors can still receive Phases to manage their plan.
  </Accordion>
  <Accordion title="Can Company users use Project AI to edit the project?">
    Company users receive read-only Project AI when available. They can ask about accessible project information; MSP changes require the appropriate permission and proposal review.
  </Accordion>
</AccordionGroup>
