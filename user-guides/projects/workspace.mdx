This page shows Company users and MSP staff how to move around a project workspace and where to find each task guide. Open a project from **Projects** to see its sections.

## Before you start

- You need access to the project. Company users read shared content and answer requests assigned to them. The MSP manages editing and permissions.
- Editing project details and collaboration items needs project overlay-edit permission. Changing PSA statuses needs status-edit permission. Assigning people and PSA rescheduling need project write permission.
- Which sections you see also depends on project display settings, PSA support, and the project's data.

## Choose a section

The top row of the project page lists sections. The row under it lists the destinations in the active section. On a phone, swipe either row to reach the rest.

| Section | Destinations |
| --- | --- |
| **Overview** | **MSP Dashboard** and **Client Dashboard**. MSP staff see both. Company users see the Client Dashboard. |
| **Project Plan** | **Tasks**, **Board**, **Schedule**, **Milestones**, **Deliverables** |
| **Team & Contacts** (or **Team**) | The project team, plus client contacts when the project has a client portal. MSP staff only. |
| **Client Portal** | **Pages**, **Activity**, **Key dates**, **Portal settings**, for projects with a linked portal. MSP staff only. |
| **Collaboration** | **Updates**, **Decisions**, **Action Items**, **Chat** |
| **Files & Forms** | **Documents** (MSP staff), **Forms** |

Going back to a section reopens the last destination you used while the project stays open. **Milestones** was the **Timeline** tab and **Board** was **Kanban**. Old project links still open the right place.

## Use the page header

The header holds buttons for the whole project. You see the ones your role allows.

| Button | What it does |
| --- | --- |
| **Edit Project Details** | Edits the goal, description, current phase, health, and client visibility. See [Edit the project goal and description](/user-guides/projects/edit-project-details). |
| **Export to Excel** | Downloads the project as a workbook. MSP staff only. See [Export a project to Excel](/user-guides/projects/export-project-to-excel). |
| **Apply template** | Adds a template's work to a plain project. MSP staff with project write permission. See [Project Templates](/user-guides/projects/templates). |
| **actions waiting** | Opens **Decisions**, or **Action Items** when none are pending there. Its count covers both lists, not only your items. |
| **Chat** (bottom-right corner) | Opens the project chat without leaving the current tab. |

## Read the dashboards

<Steps>
  <Step title="Open Overview">
    Click **Overview**. MSP staff click **MSP Dashboard** or **Client Dashboard** in the row below. Company users get the Client Dashboard.
  </Step>
  <Step title="Read the MSP Dashboard">
    The top rail shows **Open tasks**, **Unassigned open tasks**, pending **Decisions** and **Action Items**, **Actual hours**, and **Budget hours**. Click a pending tile to open that list. On projects with a client portal, the portal's progress shows under the rail. See [Read the project overview](/user-guides/projects/read-project-overview).
  </Step>
  <Step title="Read the Client Dashboard">
    This is what clients see: the summary, milestones, deliverables, and contacts.
  </Step>
</Steps>

<Frame caption="The linked onboarding dashboard sits beneath the project summary rail.">
  <img src="/images/product/projects-workspace-dashboard-desktop-preview.png" alt="MSP Dashboard for a linked onboarding project with operational metrics, progress, and phase readiness" width="2880" height="1920" />
</Frame>

When time entries are turned on, the MSP Dashboard also shows **Time logged**, with totals, billable hours, top tickets, and recent entries. On native projects without an active PSA integration, MSP staff can click **Log time**. The breakdown uses the latest entries, so it can differ from the project's recorded actual hours.

## Use Project chat

<Steps>
  <Step title="Open the chat">
    Click **Collaboration** and **Chat**, or click **Chat** in the bottom-right corner to chat from any tab.
  </Step>
  <Step title="Send a message">
    Type in **Ask a question or share an update...** and click **Send**, or press Ctrl or Cmd plus Enter.
  </Step>
  <Step title="Choose notifications">
    Use the notifications button to follow the chat and pick **In-app notification**, **Email**, or both. You are notified when someone posts a new message.
  </Step>
</Steps>

Everyone with access to the project can read the chat. Your own messages have a menu to edit or remove them.

## Use Project AI

<Steps>
  <Step title="Open Project AI">
    Click **Open Project AI** at the right edge of the project page.
  </Step>
  <Step title="Ask or pick a prompt">
    Ask about the project, or pick a quick prompt such as **Draft update**.
  </Step>
  <Step title="Review changes">
    Proposed changes appear as **Proposed change** cards. Click **Apply** only on the ones you want.
  </Step>
</Steps>

Read-only users can ask questions but cannot apply changes. See [Project AI, MCP, and client reviews](/user-guides/projects/ai-and-client-reviews).

## Troubleshooting

| Problem | What to do |
| --- | --- |
| **Tasks** or **Board** is missing | Check project data, **Display Configuration**, **Kanban Board Settings**, and your role. A project with no phases and at most one ticket uses the Client Dashboard. |
| **Team** is missing | It is for MSP staff, on ConnectWise projects or projects with a client portal. |
| **Documents**, **Client Portal**, or **Forms** is missing | They need MSP staff access and the right permission, and the unified Projects update must be enabled. |
| A custom field is missing or read-only | Check the field's visibility, role access, and write-back setting, and your project permission. |
| A technician is unavailable | Check the configured roster, the PSA user sync, and the ConnectWise project team. |
| Project AI cannot apply a change | You need an edit permission, and you must click **Apply** on the proposal. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Do the badges on sections count unread items?">
    No. The sections show no unread badges. The **actions waiting** button counts pending items in **Decisions** and **Action Items**, not only yours.
  </Accordion>
  <Accordion title="Can I answer a request without permission to edit project details?">
    Yes, if you can access the project and the pending item is assigned to you. See the [response guide](/user-guides/projects/respond-to-project-actions).
  </Accordion>
  <Accordion title="Why does a small project have no Tasks or Board?">
    A project with no phases and at most one ticket uses the simpler Client Dashboard. Display settings and permissions also matter. Native project editors always get **Tasks**.
  </Accordion>
  <Accordion title="Can Company users use Project AI to edit the project?">
    No. They get a read-only Project AI when it is enabled. Changes need an MSP edit permission and your approval of each proposal.
  </Accordion>
</AccordionGroup>
