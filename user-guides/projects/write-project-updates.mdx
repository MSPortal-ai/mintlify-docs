**Audience:** MSP staff with permission to edit project collaboration content. Company users [read shared updates](/user-guides/projects/read-project-updates); their MSP manages editing access.

Use **Projects > select a project > Updates**. These updates are maintained in MSPortal. Writing a progress bullet does not close a PSA ticket, schedule work, or send an email.

## Create an internal update

<Steps>
  <Step title="Add Update">
    Select the **+** control labeled **Add Update**, or the empty-state **Add Update** button. This immediately creates an update and opens its editor. Closing it does not discard the record.
  </Step>
  <Step title="Check the reporting week">
    **Week Of** initially uses Monday of the current week. Select the date control to change the reporting date. Keep a valid date; this is not a scheduled publication date. Multiple updates can use the same week.
  </Step>
  <Step title="Write the summary">
    Add a short **Summary** of the week's progress. Text saves shortly after you stop typing. There is no separate Save or Publish button.
  </Step>
  <Step title="Add list entries">
    Under **Completed This Week**, **Coming Up Next**, **Risks & Concerns**, or **Decisions Needed**, type an entry and select the adjacent **+**, or press **Enter**. Text still sitting in the add-item field has not been added to the list.

    <img src="/images/product/project-update-list-editor.png" alt="MSP Demo Completed This Week editor with a saved pilot workstation checklist entry and the adjacent add control" width="1094" height="256" />

    This synthetic example shows the MSP editor. Company users receive a reading view.

    Each added entry saves immediately.
  </Step>
  <Step title="Correct a saved entry">
    Select the entry's text and edit it in place. The change saves when you press **Enter** or click away. Press **Shift+Enter** for a line break, or **Escape** to undo your change before it saves. Clearing all the text restores the original entry; use the entry's delete control to remove it.

    <img src="/images/product/project-update-list-item-edit-preview.png" alt="Branch preview: MSP Demo Risks & Concerns entry being edited in place to show a verified outstanding balance, with its delete control beside it" width="1110" height="302" />

    Branch preview of the MSP editor using Demo sample text. On phones and tablets, the delete control stays visible; on desktop, it appears when you hover over or focus the entry. Editing a **Decisions Needed** entry also renames its pending request in **Decisions** and keeps that request's assignees, due date, and response. If the old title still appears in another update, MSPortal treats the edit as a new decision instead; check **Decisions** afterward.
  </Step>
  <Step title="Check the saved result">
    Collapse and reopen the update, then revisit the project to check persistence. An error means you should verify the saved content before repeating an operation. Changes to reporting week, list entries, and visibility save as you make them.
  </Step>
</Steps>

Updates added with **Add Update** on the Updates tab start with **Client Visible** off. The phase/ticket menu **Create Update** shortcut is configured to start shared; see [phase and ticket action menus](/user-guides/projects/use-phase-ticket-actions). Finish the content and check the intended audience before enabling it. Turning it on makes the update available to Company users who can access the project; it does not grant access to the project itself.

Once an update is client-visible, later edits are also saved to that shared update. There is no separate draft copy or approval stage. Turn **Client Visible** off before substantial private revisions, then review the whole update before sharing it again. This does not retract copies people may already have read.

## Understand Decisions Needed

Adding a **Decisions Needed** bullet can create a linked pending item in **Decisions**. Open that register to set the request's details, due date, urgency, and assignees using [Manage project decisions and action items](/user-guides/projects/manage-project-actions).

The related request follows the source update's audience. Assignment does not automatically notify anyone. Use the request's explicit notification controls only when you intend to send a message.

Decision titles are matched across updates, ignoring letter case and extra spaces. Repeated titles can represent the same pending request. Removing a bullet or an update can remove a pending request that was generated from it; resolving or deleting a linked request can remove matching bullets from more than one update. Give distinct decisions clear, distinct titles and check **Decisions** after changing these bullets.

## Delete an update

Select the update row's delete control and confirm. Wait for the result, revisit **Updates**, and verify the intended update is gone. Also check **Decisions** when the update contained decision bullets. Deleting an update is not an undoable draft cancellation or a way to delete the project.

## FAQs

<AccordionGroup>
  <Accordion title="Where is Save or Publish?">
    There is no separate button. Add Update creates the record immediately, Summary saves after a short typing pause, and the other controls save their changes directly. Client Visible controls whether eligible Company users can read it.
  </Accordion>
  <Accordion title="Does Client Visible send the update to clients?">
    It shares the update in the portal. The update editor does not automatically email or notify clients when you add, edit, or share it.
  </Accordion>
  <Accordion title="Why did my typed bullet disappear?">
    You must select its adjacent + or press Enter to add it. Leaving text in the add-item field does not save a list entry.
  </Accordion>
  <Accordion title="How do I fix a wrong figure in an AI-drafted update?">
    Open the update, select the entry that contains the figure, and edit it in place. Check the **Summary** for the same figure, since AI drafts can repeat a detail in several places.
  </Accordion>
  <Accordion title="Does Completed This Week update ticket status?">
    No. These are narrative bullets. Manage the ticket separately through the supported ticket workflow.
  </Accordion>
  <Accordion title="Why did removing a decision bullet change the Decisions tab?">
    Decision bullets and linked requests synchronize. A generated pending request can disappear when its source bullet is removed. Check the register after changing or deleting a source update.
  </Accordion>
  <Accordion title="Does the posted time change when I edit or share an update?">
    The displayed posted time comes from when the update was created. Do not use it as a publication timestamp, last-edit timestamp, or delivery receipt.
  </Accordion>
</AccordionGroup>
