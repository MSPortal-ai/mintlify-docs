Open **Settings > Projects > Templates > Templates** to maintain reusable plans. The same library supplies **Projects > New project** and the plain-project **Apply template** workflow.

## Before you start

Use an MSP staff role with the relevant project-settings or onboarding-settings permission. Project creation has separate write permissions and subscription requirements. Client Portal libraries such as pages and checklists can require onboarding-settings access even when you can edit a project template.

## Create the template

1. Select **New Template** and enter **Name**, optional **Description**, **Duration (days)**, and tags.
2. Choose **Project type**. A type with **Onboarding** enabled, or **Client onboarding (default)**, includes portal settings, dates, pages, and invitations. A plain project type shows project **Default status** and ticket defaults.
3. Select **Create Template**. This creates the saved template; you can then add its phases, items, and actions.

Project types are managed under **Settings > Projects > Project Types**. Archived types are excluded from new choices. Changing the type changes the available editor sections; review the resulting structure before applying the template.

## Understand what saves

| Edit | Save behavior |
| --- | --- |
| Template name, description, type, status, duration, tags, and portal defaults | Use the header **Save Changes**. |
| Add a phase | Creates a saved phase immediately. |
| Task fields | Save through the inline editor; allow the save to finish before leaving. |
| Add an action | Starts an unsaved, untitled row. Giving it a title creates it after a short delay; later field changes save automatically. |
| Remove a saved structure item | Uses that item's removal workflow; changing header metadata does not undo it. |

The header Save button is not a batch save for every child editor. Reopen the template when you need to confirm the saved result.

## Build phases and tasks

Select **Add Phase**, then **Add Item** inside the phase. Expand the item to enter its title, description, priority, category, due offset and reference point, assignee role, estimated hours, and milestone flag.

Plain-project tasks also expose **Ticket defaults**: **Budget hours**, **Start offset (days)**, **Default assignee**, and **Billable**. These configure the ticket generated from the task. Review generated dates and assignments on the actual project.

Onboarding templates support additional task and document types, client ownership, dependencies, pages, dates, and visibility controls. See [Onboarding Templates](/user-guides/client-onboarding/templates) for those workflows.

## Add project actions

In **Actions register**, select **Add action**, enter a title, and choose the **Type**. Configure description, due offset, its reference point, linked phase, and **Urgent** as needed. An untitled action remains a local draft.

Actions hold approvals, questions, access requests, scheduling, decisions, and action items outside phase tasks. They are separate from generated delivery tickets. Plain-project creation and template application copy this register. After the accompanying rollout, onboarding portals also copy their template Actions when linked to a native or PSA project. The creation summary reports the saved count; an unlinked portal reports zero until you link a project. Relinking preserves existing responses and avoids duplicate Actions. Unlinking does not delete project Actions.

## AI design

Use the template designer to propose a plan for the selected project type. Review proposed changes before applying them. Check phases, tasks, ticket defaults, actions, and any client-facing content. Project and onboarding design modes maintain separate chat/proposal state; switching mode does not apply an old proposal automatically.

## Import, export, and maintain

Use **Import from PSA** when a supported connected provider offers source templates. Review the imported plan, project type, task defaults, and actions before using it. Import and source refresh are distinct from writing delivery work back to a PSA.

The template's import/export controls support the formats described in [Onboarding Templates](/user-guides/client-onboarding/templates#import--export). Review the format's behavior before importing: an update and a new-template import have different outcomes.

Use the template row menu to duplicate, archive, restore, or delete as available to your role. Archive hides a template from new-project choices. Updating a reusable template does not rewrite projects already created from it.

## Create or extend a project

**Projects > New project** lists active templates. Plain project templates proceed through the project destination review. Onboarding templates add a **Client portal** step. Where native creation is allowed, they create a portal and linked MSPortal project. If a PSA owns project creation, the portal is retained and the wizard asks you to link it to a PSA project. Use **Client Portal** to open that retained portal; do not repeat creation. Review contacts before starting a portal or sending invitations.

For an existing plain project, select **Apply template**, choose the template and work to add, then review the result. Onboarding templates are excluded from this plain-project picker. Native projects receive local work; supported PSA-backed projects can create records in the connected PSA. Check partial results before retrying.

## Troubleshooting

| Problem | Check |
| --- | --- |
| Template not listed | Archive state, permissions, project type, and whether this picker accepts onboarding templates. |
| A phase or action already exists | Structural edits save separately from the header; reopen before adding it again. |
| Portal controls are missing | The selected type must have Onboarding enabled. |
| A library cannot be edited | Pages, checklists, and other portal libraries have their own onboarding-settings permissions. |
| Creation reports partial failure | Inspect the project and item results before retrying. |
