**Audience:** MSP staff. Company users [read shared project phases and tickets](/user-guides/projects/read-project-phases); the MSP manages project editing and permissions.

Use **Projects > select a project > Phases**. The **...** beside a phase is **Phase actions**. Expand a phase to reach **Ticket actions** beside one of its tickets. Available options depend on your editing permissions and the project source.

## Understand the shortcuts before selecting one

These creation shortcuts attempt an immediate save. They do not first open an unsaved form or request confirmation. Treat the resulting item as shared project content and review its destination after any click.

<img src="/images/product/project-phase-linked-actions.png" alt="MSP Phase actions menu with Reschedule, Mark as Milestone, Create Deliverable, Create Update, Create Action Item, and Decision Needed" width="344" height="442" />

This is the MSP Demo phase menu. A visible menu option does not itself confirm the operation succeeded.

| Option | Destination and starting content |
| --- | --- |
| **Mark as Milestone** | Attempts to open an existing linked milestone, or create one on **Timeline**. The intended new item uses the phase or ticket title, starts client-visible, copies an available end date (otherwise start), and starts Complete only if the source is complete; otherwise Pending. Verify dates independently. See the current failure above. |
| **Create Deliverable** | Attempts to add a Planned item to **Deliverables**, linked to the phase or ticket. It starts client-visible. A ticket shortcut copies the ticket summary into the description. |
| **Create Update** | Attempts to add an **Updates** entry for Monday of the current week, linked to the phase or ticket. It starts client-visible with a generated summary and empty progress lists. |
| **Create Action Item** | Attempts to add a Pending item to **Action Items**, linked to the phase or ticket. It starts without an assignee or due date. |
| **Decision Needed** | Attempts to add a Pending decision to **Decisions**, linked to the phase or ticket. It starts without an assignee or due date. |

The creation defaults above describe the shortcuts' configured behavior. Check that the saved record actually appears; successful creation through each shortcut has not been verified. Their behavior differs from **Add Update** and **Add Milestone** on the destination tabs, which start with Client Visible off.

## Finish and verify the result

<Steps>
  <Step title="Check the source row">
    Confirm the project, phase or ticket, and intended destination before selecting an action. For content that must begin privately, create it on its destination tab and review its visibility there.
  </Step>
  <Step title="Inspect the destination">
    Wait for the destination tab and new item. If it does not open, visit that tab yourself and check the available list before trying again. Use Total or clear filters where relevant; do not create another copy just because navigation failed.
  </Step>
  <Step title="Complete the fields">
    Review the generated title and description, dates, status, and client visibility. Finish [deliverables](/user-guides/projects/manage-project-deliverables), [updates](/user-guides/projects/write-project-updates), [milestones](/user-guides/projects/manage-project-milestones), or [decisions and action items](/user-guides/projects/manage-project-actions) using the destination guide.
  </Step>
  <Step title="Revisit to confirm the save">
    Check the saved item after reopening the project. Closing a row or returning to Phases does not undo a successful creation. Use the destination's delete control only for an unwanted record you have identified.
  </Step>
</Steps>

## Change or remove a link

Open the item on its destination tab: **Updates**, **Timeline** (milestones), **Deliverables**, **Decisions** or **Action Items**. Use **Linked phase** and **Linked ticket** at the bottom of its editor. Search and choose a different phase or ticket, or choose **No phase** or **No ticket** to remove the link. Each change saves immediately, and the row's phase or ticket label updates to match.

<img src="/images/product/project-item-link-fields-preview.png" alt="Branch preview: deliverable editor with Linked phase set to Discovery and design and Linked ticket set to No ticket" width="2261" height="145" />

Branch preview of the MSP editor on a Demo deliverable. Changing a link does not move, reschedule or update the phase or ticket itself.

Creating these collaboration items does not close the source ticket, update its PSA status, or automatically notify a client. Requests need assignees and an explicit notification action when a message is intended. Client-visible content still requires the reader to have project access.

## Reschedule and native-project editing

**Reschedule** is a separate action available to MSP staff with project write permission and a supported connected project system. It opens the rescheduling workflow; use [Project calendar](/user-guides/projects/calendar) for its preview and confirmation steps. Changing a milestone date is not the same as rescheduling a PSA phase or task.

For MSPortal-native projects, authorized MSP editors can also use **Add Phase**, **Add Ticket**, and native edit/delete controls. Follow [Native Projects: Start to Finish](/user-guides/projects/native-projects). These controls are not a general editor for all PSA-synchronized projects. Company users cannot gain these actions by changing their own role.

## FAQs

<AccordionGroup>
  <Accordion title="Why did Mark as Milestone do nothing?">
    This failure was observed in Demo. Check Timeline for an existing or newly saved item before retrying. If none exists, use Timeline > Add Milestone and enter the fields manually; automatic linking is not assured by that fallback.
  </Accordion>
  <Accordion title="Are phase-menu updates private drafts?">
    No. Create Update is configured to save immediately with Client Visible on. Add Update on the Updates tab starts internal instead. Check the saved visibility before adding sensitive content.
  </Accordion>
  <Accordion title="Does closing the destination editor cancel a new item?">
    No. A successful shortcut has already saved the item. Identify and delete an unwanted record using the destination tab's control.
  </Accordion>
  <Accordion title="Does Mark as Milestone keep copying future PSA date changes?">
    Do not rely on continuous synchronization. The shortcut copies available dates when creating an item; changing the Timeline milestone does not reschedule the source. Verify its planned and actual dates separately.
  </Accordion>
  <Accordion title="Can repeated clicks create duplicates?">
    Yes, creation shortcuts can add another item. Mark as Milestone is intended to find an existing link first, but you should still inspect Timeline and other destination lists before retrying a failed operation.
  </Accordion>
  <Accordion title="Does Decision Needed email or assign someone automatically?">
    No. The new decision starts without an assignee. Open Decisions to set details and assignees, then use an explicit notification control only when you intend to send a message.
  </Accordion>
  <Accordion title="Why are some menu actions missing?">
    Collaboration editing, project writes, native editing, and supported PSA rescheduling have different requirements. Ask an MSP administrator to check the relevant project permission and provider support.
  </Accordion>
  <Accordion title="Can I attach private files immediately to a shortcut-created deliverable?">
    First review its title, description, and client visibility. Then use the [document guide](/user-guides/projects/manage-deliverable-documents), which explains the separate file-sharing controls and the current risk when editing a deliverable that already has attachments.
  </Accordion>
</AccordionGroup>
