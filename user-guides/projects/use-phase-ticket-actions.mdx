This page shows MSP staff how to use the shortcuts on a phase or ticket to start a linked milestone, deliverable, update, action item, or decision. Company users [read shared project phases and tickets](/user-guides/projects/read-project-phases).

## Before you start

- You need MSP staff access. The collaboration shortcuts need project overlay-edit permission. **Reschedule** needs project write permission and a PSA that supports it.
- Every shortcut saves the new item at once. It does not open an unsaved form first.
- Open **Projects**, click the project, then click **Project Plan** and **Tasks**. The **...** on a phase row is **Phase actions**. The **...** on a task row is **Ticket actions**.

## What each shortcut creates

| Option | What it creates |
| --- | --- |
| **Mark as Milestone** | Opens the phase's or ticket's existing linked milestone. If there is none, it creates one on **Project Plan > Milestones**, titled after the phase or ticket, client visible, with its end date (or start date) as the planned date. It starts **Complete**, with that date as the actual date, only if the source is complete. Otherwise it starts **Pending**. |
| **Create Deliverable** | Adds a **Planned** deliverable on **Project Plan > Deliverables**, linked to the phase or ticket. Check its **Client Visible** switch before you share anything. |
| **Create Update** | Adds an entry on **Collaboration > Updates** for the Monday of this week, linked to the phase or ticket, **Client Visible** on, with a generated summary and empty lists. |
| **Create Action Item** | Adds a **Pending** item on **Collaboration > Action Items**, linked to the phase or ticket, with no assignee or due date. |
| **Decision Needed** | Adds a **Pending** decision on **Collaboration > Decisions**, linked to the phase or ticket, with no assignee or due date. |

Updates and milestones from these shortcuts start client visible. **Add Update** and **New Milestone** on their own tabs start with **Client Visible** off. For content that must start private, create it on its own tab.

## Use a shortcut

<Steps>
  <Step title="Check the row">
    Make sure you are on the right project, and the right phase or ticket.
  </Step>
  <Step title="Open the menu and choose an option">
    Click the **...** and choose an option. MSPortal saves the item and opens the destination tab on it.
  </Step>
  <Step title="Finish the fields">
    Review the generated title, description, dates, status, and **Client Visible**. Finish it with the destination guide: [deliverables](/user-guides/projects/manage-project-deliverables), [updates](/user-guides/projects/write-project-updates), [milestones](/user-guides/projects/manage-project-milestones), or [decisions and action items](/user-guides/projects/manage-project-actions).
  </Step>
  <Step title="Delete a copy you do not want">
    Clicking a shortcut again can add another item. If you made one by mistake, open it on its tab, click **Delete**, and confirm. Closing the editor does not undo a saved item.
  </Step>
</Steps>

## Change or remove a link

<Steps>
  <Step title="Open the item">
    Open the item on its tab: **Updates**, **Milestones**, **Deliverables**, **Decisions**, or **Action Items**.
  </Step>
  <Step title="Change the link">
    Under the fields, use **Linked phase** and **Linked ticket**. Search and pick another one, or pick **No phase** or **No ticket** to remove the link. Each change saves at once.
  </Step>
</Steps>

These items do not close the source ticket, change its PSA status, or notify a client. A request needs an assignee and an explicit notification if you want to send a message.

## Reschedule and native-project editing

**Reschedule** opens the rescheduling dialog for MSP staff with project write permission on a supported project system. See [Project calendar](/user-guides/projects/calendar). Changing a milestone date is not the same as rescheduling a PSA phase or task.

On MSPortal-native projects, MSP editors also get **Edit phase**, **Delete phase**, **Add phase**, **Add ticket**, and **Edit or delete ticket**. See [Native Projects: Start to Finish](/user-guides/projects/native-projects). The ticket menu also has **Visibility and scheduling**. See [Read project phases and tickets](/user-guides/projects/read-project-phases#control-task-visibility-and-scheduling-msp-staff).

## Troubleshooting

| Problem | What to do |
| --- | --- |
| A menu option is missing | Collaboration shortcuts, native editing, and **Reschedule** each have their own permission and provider needs. Ask an admin to check your role. |
| I do not see the new item | Open the destination tab and clear **Search**. Check before you click the shortcut again. |
| **Mark as Milestone** did not create a milestone | Check **Project Plan > Milestones**. If none exists, add one with **New Milestone** and link it to the phase. |
| A new update is visible to clients | Shortcut updates start client visible. Turn **Client Visible** off in the editor. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can I cancel an item the shortcut created by closing its editor?">
    No. The item is already saved. Delete it from its tab.
  </Accordion>
  <Accordion title="Does Mark as Milestone keep following PSA date changes?">
    No. It copies the dates once. Later changes to the milestone do not move the source, and PSA changes do not move the milestone.
  </Accordion>
  <Accordion title="Does Decision Needed email or assign someone?">
    No. Open **Decisions**, set the assignees, and use **Notify Assignee** only when you want to send a message.
  </Accordion>
</AccordionGroup>
