Use [Read a project schedule](/user-guides/projects/read-project-schedule) for dates and item types, and [Filter the project schedule](/user-guides/projects/filter-project-schedule) for search, staff filters, hidden titles, and saved preferences. Company users receive shared milestones in the cross-project Schedule; a project’s own Schedule can show additional dated work allowed by its client display settings. MSP staff receive the broader project schedule feed.

## Before you start

Your role needs access to the project Schedule view. The calendar uses the dates and work available from your projects and PSA; missing dates or unsynced work can leave an item off the calendar.

## Navigate the calendar

<Steps>
  <Step title="Choose the scope and period">
    Select the company scope, then open **Projects > Schedule**. Use **Day**, **Week**, **Month**, or **Year** and the previous/next arrows to change the visible period. Select **Today** to return to the current date.
  </Step>
  <Step title="Choose how items are grouped">
    Select **Projects**, **Tasks**, or **Start dates** in the toolbar. See [Group the schedule](#group-the-schedule) for what each shows.
  </Step>
  <Step title="Find the scheduled work">
    Select the magnifier icon to open the project search, then type a project, company, or outcome. The icon turns teal while a search is active. **Hide items**, in the **Filter** panel, hides matching titles from the view and survives Reset; unhide titles separately.
  </Step>
  <Step title="Inspect an item">
    Select a calendar item to open its relevant details. Projects, phases, and milestones link to the project workspace; tasks and supported service calls open ticket details.
  </Step>
</Steps>

The cross-project schedule can include project date spans, phases, tasks, milestones, and Autotask service calls. Service calls represent timed bookings; a project date span is not itself a technician booking.

## Group the schedule

Choose a grouping in the toolbar. **Projects** is the default, and your browser remembers your choice.

| Grouping | What appears |
| --- | --- |
| **Projects** | One line per project for each run of consecutive days with scheduled work. The line shows the project name and how many items fall in that run, such as "Office rollout · 20 items". Hover over it to see the first item titles. A project with no scheduled work in the period shows its project date span instead. |
| **Tasks** | Every project span, phase, task, milestone, and service call on its own line. |
| **Start dates** | Each project once, on its start date. Tasks, phases, and project end markers are left out. Upcoming opportunities still appear when you include them. |

Projects and Start dates lines are summaries, so they don't offer **Reschedule**. Switch to **Tasks** to change an individual item's dates.

In Month view, each day lists its items as text lines with a colored dot. Timed items show their start time first. When a day has more items than fit, select **+N more** to see the rest.

## Change scheduled dates

MSP staff use an item's **... > Reschedule** menu in a view that exposes the item menu, such as Week. There is no project-calendar drag-and-drop step.

1. Open the item menu and select **Reschedule**.
2. Check the item title. Set **New date range**, or **New milestone date** for a milestone.
3. Select **Save Changes** and wait for success, then verify the new date in Schedule and the item's details. Use **Cancel** to leave the dates unchanged.

ConnectWise and Autotask project, phase, and task dates require project write permission and an active subscription; they write back to the PSA. Native MSPortal, Halo, and Syncro items do not receive this calendar rescheduling control. Native editors can use the relevant Phases edit form.

Milestones are different: MSP staff need project overlay-edit permission, and rescheduling updates the milestone's planned date in MSPortal. It does not reschedule PSA tasks, change the actual date, or complete the milestone. Service-call bookings and upcoming opportunities cannot be rescheduled from this menu.

Company users cannot reschedule project work. Ask the MSP for date changes. A visible item is not proof that the current account can edit it.

## Project tracker, when enabled

Some ConnectWise tenants have an additional **Project tracker** above the cross-project calendar. It is an MSP staff feature and must be enabled for the tenant.

Use its **Role**, **Team member**, and **Status** filters to review project team assignments. Select a tracked project to inspect its team and end date, then choose **Open project** for the full workspace.

**Show upcoming projects** adds eligible open ConnectWise opportunities expected to become projects. Filter them by **Sales stage**. These are opportunities, not confirmed project schedules, and only deals for companies already imported into MSPortal appear.

<Note>
The Project tracker is not enabled in the Demo screenshot above. Its absence does not prevent use of the regular Schedule calendar.
</Note>

## Troubleshooting

| Problem | What to check |
| --- | --- |
| The calendar is empty | Visible date range, company scope, search, Staff selection, hidden items, and source dates. |
| A day shows **+N more** | Select it to see the day's remaining items, or switch to Week view. |
| One project hides its tasks | The **Projects** grouping combines them. Select **Tasks** to see each item. |
| Reschedule is missing | Select **Tasks** grouping and use the item menu; check MSP access, the relevant edit permission, provider support, and item type. |
| Project tracker is missing | Tenant feature availability, ConnectWise connection, and MSP staff access. |
