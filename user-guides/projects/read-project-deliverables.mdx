Open **Projects**, select a project, and choose **Deliverables** to review the outputs your MSP has shared. Expand a deliverable to read its description and find its **Documents**.

**Audience:** Company users and MSP readers. Your MSP manages deliverables, uploads, sharing, and user permissions.

## Find an output

<Steps>
  <Step title="Show All">
    When deliverables exist, select **All** to see every deliverable available to your account. Select **Planned**, **In Progress**, **Review**, or **Complete** to filter by status. Select the active filter again, or All, to clear it.
  </Step>
  <Step title="Read the status">
    Rows show **Planned**, **In Progress**, **In Review**, or **Complete**. The **Review** filter finds In Review rows. On wider screens, a row may also show a due date, phase or ticket reference, and document count.
  </Step>
  <Step title="Expand the deliverable">
    Select the row or its expand arrow to read the description and Documents. On smaller screens, row dates, references, and counts may be hidden; use a wider display when you need that metadata.
  </Step>
</Steps>

**Deliverables Progress** measures the number marked Complete out of all deliverables available to you. Each deliverable counts equally. Filtering the rows does not recalculate that progress bar. It is not a measure of hours, uploaded files, formal approvals, or overall project completion.

The MSP controls the list order. A due date is context, not a guaranteed sort order. Company views exclude internal deliverables and unshared documents, so counts can differ from those seen by MSP staff.

## Download a document

<Steps>
  <Step title="Find Documents">
    Expand the deliverable and locate the file by name. Upload date, size, and uploader may appear beneath it when available.
  </Step>
  <Step title="Select Download">
    Use the file's **Download** control. The portal requests access to that file and opens the result. Depending on the file and browser, it may download or open in another tab.
  </Step>
  <Step title="Check the result">
    Check your browser's downloads or newly opened tab. If an old download link has expired, return to the deliverable and select Download again. Share the project location with other authorized users rather than treating a temporary download address as a permanent document link.
  </Step>
</Steps>

Newly uploaded documents use temporary download links. Older linked documents may open their existing external location. Downloading a file does not approve it, mark the deliverable Complete, or acknowledge that you have read it.

## If you cannot find or open a file

| What you see | What to check |
| --- | --- |
| No deliverables match this filter | Select **All**. |
| No deliverables yet | Ask the MSP whether any outputs have been shared on this project. |
| A deliverable but no documents | The MSP must share the individual file as well as its deliverable. Some outputs have no attached file. If a file disappeared after the MSP edited the deliverable, ask them to check the known attachment-removal issue. |
| Document not found or access error | The file may have been removed, unshared, or become unavailable to your account. Reopen the project and ask the MSP to check. |
| Nothing opens after Download | Check browser downloads and popup handling, then retry from the portal. |
| A document needs a correction | Contact the MSP. Company users do not replace files here. |

For a formal response, use a separate assigned request in [Decisions or Action Items](/user-guides/projects/respond-to-project-actions). For support, [start with the Home AI Assistant](/user-guides/ticketing/open-a-ticket).

## FAQs

<AccordionGroup>
  <Accordion title="Does Complete mean I approved the deliverable?">
    No. It is the deliverable's recorded status. A formal request for your response appears separately in Decisions or Action Items when assigned to you.
  </Accordion>
  <Accordion title="Why can my MSP see more deliverables or documents than I can?">
    Your view includes shared content on accessible projects. Deliverables and their individual documents have separate visibility settings.
  </Accordion>
  <Accordion title="Why does the progress bar stay the same when I filter?">
    It uses all deliverables available to your account, while the filter only narrows the rows shown below it.
  </Accordion>
  <Accordion title="Can I upload or replace a handover document?">
    The MSP manages documents in Deliverables. Contact the MSP if you need to provide a replacement or correct an output.
  </Accordion>
  <Accordion title="Does downloading a file notify the MSP that I read it?">
    The download control does not provide a read receipt or complete a review request. Send a response through the agreed workflow.
  </Accordion>
  <Accordion title="Can I reuse a saved download URL indefinitely?">
    Do not rely on it. New uploads use temporary links. Return to the project's Documents section and select Download for a fresh link.
  </Accordion>
</AccordionGroup>
