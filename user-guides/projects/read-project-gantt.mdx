The Gantt view shows one project's whole plan on a single timeline. The project sits at the top, its phases sit under it, and each phase lists its tasks and milestones. Use it to see how the work lines up across weeks or months. Use the calendar when you want one day, week or month at a time.

**Audience:** Company users with project Schedule access and MSP staff.

## Before you start

The Gantt view lives on a project's own **Schedule** tab. It is not available in **Projects > Schedule**, which shows the calendar across projects.

You see the same project items in the Gantt view as in the project's calendar. Company users see the project, shared milestones, and the phase and task dates their MSP's client display settings allow. See [Read a project schedule](/user-guides/projects/read-project-schedule#choose-the-right-schedule) for what each audience receives.

The Gantt view is for reading. You cannot drag bars, resize them or draw links on the chart.

## Open the Gantt view

<Steps>
  <Step title="Open the project's schedule">
    Open a project and select the **Schedule** tab.
  </Step>
  <Step title="Switch to Gantt">
    Select **Gantt** at the start of the schedule toolbar. Select **Calendar** to go back.

    MSPortal remembers your choice in this browser, so the **Schedule** tab opens in the same view next time.
  </Step>
  <Step title="Choose the scale">
    Select **Days**, **Weeks** or **Months** to change how much time each column covers. The chart opens at **Weeks**.
  </Step>
</Steps>

## Read the chart

The left side lists every item with its **Item**, **Start** and **End** dates. The right side draws a bar for each item across the timeline.

| Row | What it shows |
| --- | --- |
| Project | The project's start and due dates. The bar grows to cover any phase, task or milestone that falls outside them. |
| Phase | The phase's scheduled dates, widened to cover the dated tasks and milestones inside it. |
| Task | A project ticket's scheduled start and end dates. A task with no end date, or an end before its start, shows as one day. |
| Milestone | A single day. The chart uses the planned date, or the actual date when there is no planned date. |

The project and any phase that holds work are violet. Tasks are teal, and milestones are amber.

Start and end dates include the last day, so a task scheduled Monday to Wednesday fills three days. The chart uses the same timezone as the project's calendar.

### Read progress

The darker fill inside a bar shows progress.

- A task's progress compares its actual hours to its budget hours. It stays below 100% until the task is closed, then shows 100%.
- A phase's progress compares its actual hours to its budget hours in the same way.
- A milestone shows 100% when it is complete.
- Open tasks and phases without budget hours show no fill, and the project bar never shows a fill.

## Find and open work

Type in **Search items…** to narrow the chart. A matching task keeps its phase and project rows above it, so you can still see where it belongs. A matching phase keeps all of its tasks and milestones. **No items match your search.** means nothing matched, so clear the search to see the whole plan.

Select a row to open the item. Each row opens the same place as the matching calendar item.

| Row | Opens |
| --- | --- |
| Project | The **Overview** tab |
| Phase | The **Phases** tab, when the project shows it |
| Task | The ticket details. Native MSPortal tasks open in **Phases**, or **Overview** when the project has no Phases tab. |
| Milestone | The **Timeline** tab |

Moving through rows with the keyboard selects them without opening them.

## Change the schedule

MSP staff with project write permission see **Plan schedule** at the right end of the Gantt toolbar. It opens the [Schedule workspace](/user-guides/projects/plan-project-schedule), where you can move tasks, set owners and dependencies, and save to your PSA or MSPortal.

The workspace has its own **Timeline** view for dragging tasks week by week. That view is part of the workspace draft and is separate from this Gantt view.

Company users cannot change dates. Ask your MSP to reschedule work.

## Troubleshooting

| What you see | What to check |
| --- | --- |
| A task has no bar | A task needs a scheduled start date to draw a bar. A due date alone is not enough. Closed tasks without dates are left out. MSP staff can add dates in the [Schedule workspace](/user-guides/projects/plan-project-schedule). |
| A milestone is missing for a Company user | Only milestones shared with the client appear for Company users. |
| An Autotask service call is missing | The Gantt view shows the project, phases, tasks and milestones. Timed service calls appear only in the calendar. |
| The chart opens in Calendar on another computer | Your view choice is saved per browser. Select **Gantt** again on that browser. |

## FAQs

<AccordionGroup>
  <Accordion title="Why does a long phase appear in Gantt but not in the calendar?">
    The calendar leaves out phase and task spans longer than 120 days, and project spans longer than 400 days. The Gantt view draws the whole plan, so those long items still appear there.
  </Accordion>
  <Accordion title="Does the Gantt view show dependency links?">
    No. The chart does not draw lines between tasks. MSP staff can review links in the **Dependencies** view of the [Schedule workspace](/user-guides/projects/plan-project-schedule).
  </Accordion>
  <Accordion title="Does a long bar mean someone is booked the whole time?">
    No. A bar shows a planned date span, not staff availability or timed appointments.
  </Accordion>
</AccordionGroup>
