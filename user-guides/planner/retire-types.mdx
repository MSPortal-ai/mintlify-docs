description: 'Review type usage, choose a replacement where required, and verify Planner and budget classifications afterward.'

Delete a Planner type you no longer use, and move any work that uses it to another type. This guide is for MSP staff. Company users ask their MSP to review classifications.

## Before you start

- You need **Manage** for Planner Types settings. Deleting also needs active billing.
- Renaming a type with the pencil is often better than deleting it. See [Manage Planner types and defaults](/user-guides/planner/manage-types).
- If the type is in use, create the replacement type first.
- A Planner type is shared across all companies. It is also a budget category.

<Warning>
If clicking the trash button shows a "Failed to check usage" message and no dialog opens, stop. Nothing has changed. Ask your MSP administrator or support to look into it.
</Warning>

## Delete an unused type

<Steps>
  <Step title="Open the Planner Types tab">
    Go to **Settings > Customization > Types** and choose **Planner Types**.
  </Step>
  <Step title="Click the trash button">
    Find the exact row and click its trash button.
  </Step>
  <Step title="Read the confirmation">
    **Delete Planner Type** names the type and says the action cannot be undone.
  </Step>
  <Step title="Click Delete">
    Click **Cancel** to keep the type, or **Delete** to remove it.
  </Step>
  <Step title="Verify">
    Check that the row is gone from the list.
  </Step>
</Steps>

Opening the dialog does not delete anything. If you delete the default type, deletion does not pick a new default. Click the star on the type you want afterward.

## Reassign work and delete a used type

<Steps>
  <Step title="Click the trash button">
    The dialog lists how many Planner items and budget line items use the type. Archived items count too.
  </Step>
  <Step title="Choose a replacement">
    Under **Reassign to:**, pick a different existing type. The type you are deleting is not in the list.
  </Step>
  <Step title="Check the replacement">
    Make sure the new type makes sense for every affected company.
  </Step>
  <Step title="Click Reassign & Delete">
    The button stays turned off until you pick a replacement.
  </Step>
  <Step title="Verify">
    Check the type list, a few affected Planner items and the relevant budgets.
  </Step>
</Steps>

If no suitable replacement exists, click **Cancel**, create the new type and start again. Cancelling reassigns nothing.

## What the dialog does not reassign

When the type is used by Planner templates or Standards categories, the dialog adds a second box that says "These records only lose their type link. They are not reassigned." It lists the number of **planner templates** and **Standards categories** affected.

After deleting, open those templates and Standards categories and choose a new type where you want one. See [Create and manage Planner templates](/user-guides/planner/manage-templates).

## Budget history

**Draft** and **Pending Approval** budget lines move to the replacement type. **Approved** and **Obsolete** budget lines keep their saved snapshot. Deleting the type clears their live link but does not rewrite the recorded name, so an old budget can still show the old category name.

<Warning>
Reassignment and deletion are not all-or-nothing. Planner or budget changes can save before a later step fails. If an error appears, look at the old type's usage and the affected records before you retry. An error does not mean nothing changed.
</Warning>

Deleting a type reclassifies or unlinks records. It does not delete the Planner items or budgets. Confirm the final classifications before you call the task done.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| "Failed to check usage" and no dialog | Keep the type and report the error to your MSP administrator or support. |
| The trash button is missing | You need Manage for Planner Types settings. |
| **Reassign & Delete** is turned off | Pick a different type under **Reassign to:**. |
| No replacement is listed | Click **Cancel** and add the replacement type first. |
| The dialog shows usage you did not expect | Archived Planner items and budget lines across all companies count. |
| Reassignment or deletion fails | Check your permissions, billing and the current records. Earlier changes may already have saved. |
| A template or Standards category lost its type | They are unlinked, not reassigned. Choose a type for them again. |
| An approved budget kept the old name | Its snapshot keeps the recorded category. |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Where do I delete a Planner type?">
    **Settings > Customization > Types > Planner Types**, then the row's trash button.
  </Accordion>
  <Accordion title="Does opening Delete Planner Type remove the type?">
    No. Nothing changes until you click **Delete** or **Reassign & Delete**.
  </Accordion>
  <Accordion title="Why must I choose another type?">
    Planner items or budget lines still use this one. Pick a replacement first.
  </Accordion>
  <Accordion title="Can I reassign a type to itself?">
    No. Pick a different type, or create the replacement first.
  </Accordion>
  <Accordion title="Does deleting a type delete the Planner items?">
    No. They move to the replacement type.
  </Accordion>
  <Accordion title="Does the dialog cover Planner templates and Standards categories?">
    It lists them and says their type link will be cleared. It does not reassign them.
  </Accordion>
  <Accordion title="Will the replacement apply to approved budgets?">
    No. Approved and Obsolete budget lines keep their snapshot. Draft and Pending Approval lines move.
  </Accordion>
  <Accordion title="Does an error mean no reassignment saved?">
    No. Some changes can save before a later step fails.
  </Accordion>
  <Accordion title="Will deleting the default type pick a new default?">
    No. Click the star on the type you want.
  </Accordion>
  <Accordion title="Can a company administrator delete a shared type?">
    No. Your MSP manages shared types.
  </Accordion>
</AccordionGroup>
