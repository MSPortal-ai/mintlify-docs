This guide is for MSP staff and developers who connect a billing or quoting system that has no MSPortal integration. Each call carries one record and its PDF:

| What you upload | Where it appears | Who sees it |
| --- | --- | --- |
| Invoice | A row in the **Invoices** table, next to invoices synced from your PSA. **View PDF** opens the PDF you uploaded. | MSP staff, and the company's portal users whose role can view invoices |
| Quote | A row in the **Quotes** table and its quote page, next to synced quotes. **View quote** opens the PDF you uploaded. | MSP staff, and the company's portal users whose role can view quotes |
| Order or any other document | A file in the company's **Documentation** library | MSP staff, and the company's portal users who can open Documentation |

Uploaded invoices and quotes sort, filter, search and export with the synced ones. Push the same record again to update it, for example when an invoice is paid.

## Before you start

- **Create an API key.** Go to **Settings > Integrations**, find **API Access**, click **Manage API Keys**, then **Create New Key**. Pick these scopes:
  - **Write Financial** (`financial.write`) for invoices and quotes.
  - **Write Documentation** (`documentation.write`) for orders and other documents.
  - **Read Companies** (`companies.read`) to look up company IDs.
  - Optional: **Read Financial** (`financial.read`) to list what you uploaded.
- **Use an MSP staff account with the right permissions.** A key acts as the user who created it. Invoice and quote uploads need **Integrations** write permission; document uploads need **Documentation settings** write permission. A company user's key cannot upload.
- **Use your region's address.** US tenants call `https://app.msportal.ai`, EU tenants `https://eu.msportal.ai`. The examples use the EU address.
- **No PSA or quoting integration is needed.** The **Invoices** and **Quotes** pages appear after your first upload. To let a client's portal users open them, give their role the **Invoices** or **Quotes** permission.

Every request sends the key as a Bearer token:

```bash
export MSPORTAL=https://eu.msportal.ai/api/public/v1
export KEY=your-api-key
```

The **API Reference** tab lists every field, under **Financial** and **Documentation**.

## Find the company ID

Each record belongs to one company (your client). List your companies once, match them to your clients by `name`, and store each MSPortal `id` next to the client in your system:

```bash
curl -s "$MSPORTAL/companies?limit=100&page=1" -H "Authorization: Bearer $KEY"
```

The answer's `pagination.hasNextPage` tells you whether to fetch `page=2`. Use the matching company's `id` as `companyId` below.

## Upload an invoice

Send the invoice and its PDF in one request. The PDF goes in `pdf.contentBase64` as standard base64, up to 3,000,000 bytes.

```bash
PDF=$(base64 -w0 invoice-2026-1042.pdf)   # macOS: base64 -i invoice-2026-1042.pdf

curl -s -X POST "$MSPORTAL/financial/invoices" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d @- <<EOF
{
  "externalId": "INV-2026-1042",
  "invoiceNumber": "2026-1042",
  "companyId": "3f0c2a5e-0000-4000-8000-000000000001",
  "invoiceDate": "2026-10-01",
  "dueDate": "2026-10-31",
  "status": "Open",
  "currency": "EUR",
  "subtotal": 1000,
  "salesTax": 190,
  "total": 1190,
  "pdf": { "fileName": "invoice-2026-1042.pdf", "contentBase64": "$PDF" }
}
EOF
```

The answer is `201` with the MSPortal `id`:

```json
{ "data": { "id": "b8c1…", "externalId": "INV-2026-1042", "created": true } }
```

| Field | Required | Notes |
| --- | --- | --- |
| `externalId` | Yes | Your system's ID. It identifies the invoice on later calls. |
| `invoiceNumber`, `companyId`, `invoiceDate`, `total` | Yes | `total` must be greater than 0. Dates are `YYYY-MM-DD`. |
| `pdf` | The first time | `fileName` must end in `.pdf`. |
| `dueDate`, `status`, `currency`, `subtotal`, `salesTax`, `payments`, `balance`, `reference`, `customerPo`, `invoiceType` | No | `balance` defaults to `total`. `invoiceType` defaults to Standard. |

### Mark an invoice paid

Send the same `externalId` again with the new values. Leave out `pdf` to keep the stored PDF, or send a new one to replace it. The answer is `200` with `"created": false`.

```bash
curl -s -X POST "$MSPORTAL/financial/invoices" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{
    "externalId": "INV-2026-1042",
    "invoiceNumber": "2026-1042",
    "companyId": "3f0c2a5e-0000-4000-8000-000000000001",
    "invoiceDate": "2026-10-01",
    "total": 1190,
    "balance": 0,
    "paidDate": "2026-10-15",
    "status": "Paid"
  }'
```

## Upload a quote

```bash
PDF=$(base64 -w0 quote-A-77.pdf)

curl -s -X POST "$MSPORTAL/financial/quotes" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d @- <<EOF
{
  "externalId": "Q-77",
  "companyId": "3f0c2a5e-0000-4000-8000-000000000001",
  "name": "Firewall refresh",
  "number": "A-77",
  "stage": "Sent",
  "contactName": "Erika Muster",
  "ownerName": "Thomas Beispiel",
  "currency": "EUR",
  "oneTimeTotal": 4800,
  "monthlyTotal": 120,
  "quoteDate": "2026-10-20T09:00:00Z",
  "pdf": { "fileName": "quote-A-77.pdf", "contentBase64": "$PDF" }
}
EOF
```

- `externalId`, `companyId`, `name` and, the first time, `pdf` are required.
- Push the same `externalId` again to change the stage (for example `Won`) or replace the PDF.
- `contactName` is the client contact the quote is for. Roles that only show users their own quotes match it against the portal user's full name.
- Roles that only show some stages hide quotes without a `stage`, so send one.
- `url` is an optional `https` link to the quote in your system; the quote page shows it as **Open quote**.

## Upload an order or another document

Orders have no table of their own, so they go into the company's **Documentation** library. A document upload takes three calls, so files up to 50 MiB fit: prepare, send the bytes, finalize. PDF, DOCX, XLSX, XLS and CSV files are accepted.

<Steps>
  <Step title="Prepare the upload">
    ```bash
    SIZE=$(stat -c%s order-5501.pdf)   # macOS: stat -f%z order-5501.pdf

    curl -s -X POST "$MSPORTAL/documentation/files" \
      -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
      -d "{\"name\": \"Order 5501\", \"fileName\": \"order-5501.pdf\", \"fileSize\": $SIZE,
           \"contentType\": \"application/pdf\", \"companyId\": \"3f0c2a5e-0000-4000-8000-000000000001\"}"
    ```
    The answer holds a `documentId`, an `uploadUrl` valid for 2 hours and the `contentType` to send.
  </Step>
  <Step title="Send the file to uploadUrl">
    ```bash
    curl -s -X PUT "$UPLOAD_URL" -H "Content-Type: application/pdf" --data-binary @order-5501.pdf
    ```
    This request goes to storage directly. Do not send the `Authorization` header.
  </Step>
  <Step title="Finalize">
    Send the same body as in step 1 to the finalize address:
    ```bash
    curl -s -X POST "$MSPORTAL/documentation/files/$DOCUMENT_ID/finalize" \
      -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
      -d "{\"name\": \"Order 5501\", \"fileName\": \"order-5501.pdf\", \"fileSize\": $SIZE,
           \"contentType\": \"application/pdf\", \"companyId\": \"3f0c2a5e-0000-4000-8000-000000000001\"}"
    ```
    The document now appears in the company's Documentation library. A retry after a timeout returns the same document, so it is safe.
  </Step>
</Steps>

- `companyId` is required. A document without a company would be visible to every client, so it is refused.
- To file orders in their own folder, create an **Orders** folder under **Documentation** once, read its ID from `GET /documentation/folders`, and pass it as `folderId`.

## Delete an upload

Delete an invoice or quote you uploaded by its MSPortal `id`. The PDF is removed with it. Invoices synced from your PSA cannot be deleted this way.

```bash
curl -s -X DELETE "$MSPORTAL/financial/invoices/b8c1…" -H "Authorization: Bearer $KEY"
curl -s -X DELETE "$MSPORTAL/financial/quotes/7d42…" -H "Authorization: Bearer $KEY"
```

## Errors

Every error answers with `error` (a readable message) and `code`.

| Status | Meaning | What to do |
| --- | --- | --- |
| 400 | A field is missing or invalid, for example no PDF on the first upload, a `total` of 0, or a file that is not a PDF | Read `error`, fix the request and send it again |
| 401 | The key is missing, wrong or revoked | Check the `Authorization` header |
| 403 | The key lacks the scope, or its user lacks the permission | Add the scope, or create the key as a user with the permission named in [Before you start](#before-you-start) |
| 404 | The company, folder or record does not exist in your tenant | Check the ID |
| 413 | The PDF is over 3,000,000 bytes | Compress the PDF |
| 429 | Too many requests | Wait until the time in `X-RateLimit-Reset`, then retry |
